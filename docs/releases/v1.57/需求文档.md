## 1. 版本定位

官方 UX 标准要求可滚动内容显示在底部导航条（小白条）下方，仅固定交互控件避让。本仓次级页面（设置等）的滚动内容目前止步于安全区下沿，底部 80px 手势条区只显示根容器底色，与标准不符、用户观感是「一条没用上的灰带」。本版让次级页面的可滚动内容延伸到屏幕物理下沿，滚动时内容从小白条下方穿过；固定控件仍避让。

## 2. 完成判定

API26 模拟器上打开设置页，滚动到底：内容延伸至屏幕物理下沿（dump 边界到窗口底），小白条区域可见滚动内容；最后一条设置项可完整滚动到小白条上方不被遮挡；UndoBar 等浮层控件位置不变（仍在安全区内）。其他次级页面（统计/库管理/Agent/版本记录/隐私政策）同口径抽查。XT2 / API24 由用户手动验收。

## 4. 明确不做

- ~~**不改工作区（三栏笔记视图）**~~：**2026-11-13 撤回**——原判断依据「现状底部 80px 由根容器铺 bg_page 作为小白条的沉浸背景，已满足官方标准」实测不成立：铺 bg_page 本身就是用户看到的「底部灰色条」（状态条 bg_card 与侧栏 bg_navigation 均与 bg_page 存在色阶），观感不连续。工作区范围由追加的 57.6（Y-02）承接，只动底部安全区延伸，不改状态条信息架构。
- **不改 Agent 页**（验收时确认）：页面底部是固定输入区（正确避让小白条），聊天滚动容器底部被输入区隔开、不与安全区边界重合，无可延伸对象。
- **不改隐私政策页**（验收时确认）：整页 WebView，滚动在 Web 内部，`expandSafeArea` 对 Web 组件行为未验证；如后续需要再立项。
- 不做 `setWindowLayoutFullScreen`、不改 `navigationBarContentColor` / `navigationBarColor`（见 57.3 理由）。
- 不重排次级页面信息架构；只动底部安全区延伸。
- 不改并行版本 v1.56（分享接收）涉及的 EntryAbility 分享处理与 Index.ets 分享入口区域；编辑共用文件用内容寻址。

- 环境事实：HarmonyOS API 24 / ArkTS；API26 模拟器仅用于 UI 验收，证据不外推 API24 / XT2 真机（AGENTS.md ABI 节）。

- Index.ets 正被并行工作流编辑（v1.56 分享接收，行号漂移 +50），所有编辑内容寻址（字符串匹配），不按行号。

### 6.3 57.6 工作区区带连续（2026-11-13）

- **防线测试**：`tools/tests/test_nav_indicator_immersion.mjs` 增第 4 组断言（Index.ets 不得出现 `.clip(true)`；bg_navigation×2 / bg_card×1 / mask×1 的「背景色 + expandSafeArea」配对存在性），4/4 通过。
