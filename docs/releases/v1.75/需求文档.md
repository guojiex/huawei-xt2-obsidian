# v1.75 需求文档 —— Git 同步：推送前逐行差异

> 状态：文档立项（2026-11-16）；原生实现进行中。
> 设计真源：[Git 同步页设计 §2A](../../prototype/v2/Git同步页设计.md)；原型入口见该文档。需求来源：用户 2026-11-16 提出「git 同步的时候，我要能看到笔记变更，像 git diff 那样」，同日拍板「就地展开 + 仅本地未提交改动 + 完整真实实现」。

## 1. 版本定位

Git 同步弹窗的「本地改动」清单目前只列文件名 + `M/A/D`（[`Git2FileChange`](../../../entry/src/main/cpp/types/libgit2_napi/Index.d.ts) 的 `path/status`），用户无法判断每个文件具体改了什么，推送前只能盲提交。本版让每个改动文件可就地展开**行级 unified diff**（红绿增删行、双行号、增删统计），在提交推送前逐文件核对将写入远端的内容。

口径固定为 **HEAD（上次提交）vs 当前工作区（含已暂存）**，只覆盖尚未提交的改动，与改动清单一一对应；已提交待推送的提交、远端跟踪分支净变化都不在本版视图内（设计稿 §2A 已拍板）。

需求池：Git 同步相关条目在 [§C 同步与数据](../../requirements_backlog.md#c-同步与数据)；本版只做「查看差异」，不改变 v0.3 push-only、v1.73 fast-forward pull 的安全边界。

## 2. 完成判定

在一个已 clone 的 Git 知识库里改动 / 新增 / 删除若干 `.md`，打开同步弹窗 → 「本地改动」列出这些文件，每行显示增删统计 → 点某文件就地展开红绿逐行差异（旧行号 / 新行号 / `−` `+` 标记 / 正文）→ 再点收起，同一时刻只展开一个；切换文件时提交说明草稿不丢。修改 / 新增 / 删除三类都显示正确（新增全绿、删除全红、修改红绿配对 + 上下文）。无改动时不显示清单。深色模式可读。笔记正文只在该 UI 内展示，不进日志 / 埋点。

native 双架构（arm64-v8a、x86_64 Windows 宿主）编译通过；签名 HAP 构建通过；相关 Node 单测与 ohosTest 用例通过；API24 / XT2 真机验收待用户。

## 4. 明确不做

- 不改变 push-only 语义、不做自动后台拉取、不做合并 / 冲突解决 UI。
- 不做已提交待推送提交的 diff、不做远端分支对比（口径仅 HEAD↔工作区未提交改动）。
- 不做跨 commit 历史 diff、不做图片 / 二进制文件的可视化 diff（跳过并标 `truncated`）。
- 不做 diff 内就地编辑 / 挑选部分行提交（只读）。
- 不新增权限（沙箱内 git 操作无需权限）。
- 笔记正文（路径 / 内容）不进 `hilog` / 埋点（硬约束 16）；native 与 ETS 侧均不日志化 diff 文本。

## 5. 技术约束与依赖

- **Native**：复用已 include 的 `git2/diff.h`；`git_diff_tree_to_workdir_with_index` 得已跟踪差异；untracked 文件用 `git_blob_create_from_workdir` + `git_blob_rawcontent` 读全文作为新增行；行回调 `git_diff_foreach` 的 `GIT_DIFF_LINE_ADDITION/DELETION/CONTEXT`，忽略 `FILE`/`HUNK`/`EOFLF` 元行。用 `pthread_mutex_lock(&g_clone_mutex)` 保护仓库打开（与 getRepositoryState 一致，防并发 clone/checkout）。
- **内存与 UI 上限**：单文件文本字节上限（默认 1MB）、单文件行数上限（默认 2000）、最大文件数（默认 50），超限时该文件 `truncated=true` 且行只取到上限，UI 提示「此文件差异过大，仅显示前 N 行」。上限经 options 传入，默认常量写在 native。
- **类型声明两份同步**：`entry/src/main/cpp/types/libgit2_napi/Index.d.ts` 与 `entry/src/ohosTest/cpp/types/libgit2_napi/Index.d.ts`。
- **ArkTS 边界**：`getFileDiffs` 是同步调用但在弹窗已拿到 repositoryState 后触发，文件读取可能涉及磁盘 IO；放在 `GitNativeService` 的 async 包装中 await，UI 展开前先取数并缓存，避免每次展开重复读盘。
- **设计 token**：颜色 / 圆角 / 间距 / 字号只引用 `app.color.*` / `app.float.*` 或 `Tokens` 常量，不散写数值；红绿底复用既有 diff 语义色（与 v1.70 编辑不一致弹窗一致）。
- 真机验收（API24 / XT2 + 真实 Git 库）由用户执行后回填 §6.2。

## 6. 验收记录

### 6.1 本地实现与自动验证（2026-11-16）

- **75.1 Native 逐行 diff**：`libgit2_napi.c` 新增同步导出 `getFileDiffs(path, options?)`——`git_diff_tree_to_workdir_with_index` 取已跟踪文件 HEAD↔工作区差异，`git_diff_foreach` 的 line callback 收集 `+`/`-`/上下文行（旧/新行号，缺失记 0，content 按 `content_len` 精确拷贝）；untracked 新增文件经 `git_status_list` 识别后 `git_blob_create_from_workdir` 读全文切为全新增行；`.trash` 与二进制（`GIT_DIFF_FLAG_BINARY`）过滤；默认上限 50 文件 / 1MB / 2000 行，options 可覆盖，超限置 `truncated=true`；仓库打开复用 `g_clone_mutex`，返回 `{files:[{path,status,lines,truncated}], truncatedFiles}`。函数指针签名按 v1.9.7 `git_diff_line_cb`（首参 `const git_diff_delta*`）对齐，arm64 / x86_64 双架构重编通过（类型警告消除，仅余 clang 的 `--gcc-toolchain` 参数提示）。`README.md` API 段待补该接口说明。
- **75.2 类型与 ArkTS 服务**：两份 `Index.d.ts` 同步新增 `Git2DiffLine` / `Git2FileDiff` / `Git2FileDiffs` / `Git2DiffOptions` 与 `getFileDiffs`（逐字一致）；`GitNativeService.fileDiffs()` 经动态 import 包装，`GitSyncDialog` 打开时一次预取全部文件 diff 并缓存，失败降级为空统计 / 展开时「无法读取」提示，不阻断提交推送。
- **75.3 同步弹窗就地 diff UI**：改动清单每行成为可点行，行尾 `+N −M` 统计；点按就地展开 unified 逐行差异（双行号列 + 标记列 + 正文列，红绿整行底，等宽字体，限高内部滚动，全部引用 `app.color.*` / `app.float.*` token）；手风琴单开，缓存命中不再读盘；切换只改展开状态与当前数据，提交说明 / 作者草稿不动；`accessibilityText` 标注展开/收起与增删行数，增删行有读屏前缀；展开时清单可视区适度放高，键盘避让 `nestedScroll(SELF_FIRST)` 保留。
- **75.4 测试与验证**：新增 `tools/tests/test_git_diff_native_ui.mjs` 6/6（native diff 路径、上限、双份类型一致、服务包装、手风琴与无日志隐私红线）；`test_git_sync_dialog` 14/14、`test_prototype_git_diff` 8/8；全仓 1363 测 1352 过、11 失败经逐项核对全为既有基线类别（品牌图标 74/76、Icon allowlist 452、v1.58 统计 1139/1145/1270、v1.37 备份 938/941 等，与 v1.74 §6 记录一致），本版零新增失败。`Git2Native.test.ets` 新增 getFileDiffs 用例（干净库空 diff + 修改/新增/删除三态行断言），随 ohosTest hypium 待设备执行。
