# v1.12 需求文档 —— 预览缩放与遮挡体验

> 状态：🟡 原生缩放控件与左右栏独立比例状态已实现。2026-11-03 刷新 v2 原型并将原生控件移到正文滚动区外的独立底栏，简单模式控件显隐与设计对齐；定向测试 9/9、签名调试 HAP 构建通过（33 项任务，21 执行 / 12 up-to-date）。本轮未取得当前布局的浏览器目视证据；旧 API26 单屏截图来自此修正之前。API26 模拟器目视因 Mac 锁定跳过；API24 / XT2 待用户手动验收。ArkWeb 与 ArkUI 手势仲裁未证实，不接入触控缩放。排期见 [实施总清单](../实施总清单.md)。

## 1. 范围

承接 [需求池“预览正文缩放”](../../requirements_backlog.md) 和 [v2 设计](../../prototype/v2/设计说明.md)：预览提供左右栏独立缩放比例、50%–200% 预设及重置，并评估触控缩放；滚动时控件不持续遮挡正文。焦点在控件内应保持可见，停止滚动后恢复，编辑模式隐藏控件。

## 2. 验收

- 缩放控件放在正文滚动区域外的独立底栏，不覆盖正文；简单模式与专业模式预览可见，专业模式源码编辑时隐藏。
- 单屏 / 双屏 / 三屏分别检查左右预览比例、独立性、切换编辑 / 预览后的状态和正文底部可读；记录实际可用输入方式。
- 验证滚动期间与停止后的显示、控件焦点及选择交互；不以原型的约 0.9 秒表现作为设备实测。
- 先核实 API24 手势与缩放方案；如果双指手势或系统缩放冲突，记录限制并回到需求评估，不编造 API 或宣称已支持。
- 分别记录自动测试、模拟器、API24 / XT2 设备验证；设备验收由用户手动执行。

## 3. 明确不做

不修改 Markdown 正文、图片或文件，不把编辑器、导航和工具栏随预览一起缩放；不借本版改动既有保存链路。
