### v0.3：能同步（Native App 接入已落码；完整验收仍待完成；[需求文档](v0.3/需求文档.md)）

- [x] 归档领域专家规格回复，更新 [api_notes C1](../harmonyos/api_notes.md#c1-原子写--用官方-atomicfile-替换自研-tmprename)；停止将修改 encoding 当作二进制写入修复方案。收到回复不代表 clone 已恢复。
- [x] **写入策略收口**：新 clone 的 Git 元数据、工作区文本与二进制都写入未登记的 `vaults/<id>__importing`；本次导入可在隔离目录内用 `openSync` + `writeSync(ArrayBuffer)` 保持任意原始字节。普通写入不推广到已有库。
- [x] **API 与 Git 行为核对**：本机 API 26 SDK 的 `openSync`、`writeSync`、`closeSync`、`renameSync` 和 `rmdirSync` 均标注 `@since 9`；同步二进制写返回实际写入字节数，须循环处理短写并关闭 fd。SDK 对 `rmdirSync(path)` 的说明为递归删除目录树；本实现仍逐层移除以限制清理范围。`renameSync` 声明未承诺原子覆盖。isomorphic-git clone 使用 write/unlink/mkdir/rmdir，不依赖 rename；App 仅在 clone 校验后将导入目录改为正式目录。
- [x] **新 clone 隔离写入实现**：clone/checkout、队列 flush、清缓存后从磁盘重新读取 Git 状态校验全部成功后才登记。失败清理只触及导入标记对应的临时/未登记正式目录；注册表持久化失败回滚内存登记，重启时恢复标记残留。rename 只用于预先确认不存在的正式目标，不作为已有文件原子覆盖保证。
- [x] **已有库写入边界**：已有 Markdown 保存继续走 `NoteService` AtomicFile 字符串路径；非导入 Git 写入仅将可无损 UTF-8 往返文本交给 AtomicFile，其他字节在打开目标前拒绝。已有库二进制覆盖不在本次范围，旧内容保护不变。
- [x] **隔离 Node 仓库验证**：fixture 覆盖中文 Markdown、空文件、PNG、pack/Git object；按 SHA-256 核对字节，重读后 `git status` 干净且 `git fsck --full` 通过。可控 PNG 写失败返回 clone 失败。此为 Node 文件系统模拟器，不代替设备上的 native backend、库登记或应用重开。
