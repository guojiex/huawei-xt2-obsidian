# v1.91 需求文档 —— 分享预览去掉每段 64ms 死等（P2）

> 状态：规划中（2026-11-19 立项）。需求来源：v1.90 后真机打点实测——PDF 63 段连跑两轮，`waitMs` 中固定 64ms 等待占 68%、累计约 4s，而旧帧重试率仅 0.8%。
> 归属分享域；本版只删 Web 侧一段无条件等待，**不改捕获/校验语义、不动端侧逻辑**。判据与完整数据见 `docs/engineering/分享预览渲染性能优化.md` §3.3 / §4 P2。

## 1. 版本定位

PDF / 长图预览走的 `ShareFlowPanel` 分段捕获，每段先 `setShareCaptureScrollTop` 滚动 + 双 rAF，再无条件 `setTimeout(64)`「给渲染服务留合成时间」（53.10 为修「一页渲染两页且重复」加的）。真机实测证明这 64ms 是确定性浪费：常态段三段耗时 `wait 94 / snap 73 / tail 68ms`，64ms 占 `wait` 的 68%，63 段累计约 4s（占总 15s 的 26%）；而真正防旧帧的是端侧 `captureSegmentVerified` 的像素比对 + 180ms 退避重试，125 段只触发 1 次。删掉这段等待，旧帧兜底仍由端侧承担，语义不变。

## 2. 完成判定

- 真机 XT2 上同一篇笔记 PDF 导出：**无重复页、无缺页、末页水印与页缝正常**（53.10/53.12/53.13 的回归点全过）。
- `waitMs` 单段均值显著下降（预期从 ~94ms 降到 ~30ms），63 段总耗时下降约 3~4s。
- `retries` 旧帧重试率仍在低位；即使上升，新增重试总耗时小于省下的 64ms×N。若净收益为负则回退本版。
