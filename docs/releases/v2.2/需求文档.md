# v2.2 需求文档 —— 版本历史与恢复（设计稿：按次保存留档 + 版本列表 + 只读预览 + 恢复）

> 状态：开发中（2026-11-21 立项）
> 版本号说明：初立 v1.101（三位制）；2026-11-21 用户拍板统一采用 R1 两位制顺延口径，改号 **v2.2**。仅内部迭代编号，非破坏性变更、非对外 2.2（对外版本真源仍是 `changelog.json`）。
> 来源：需求池 A 节「版本历史/快照（按次保存留档）」。用户提问「笔记是否需要支持历史版本和恢复」，对照现状（回收站管删、草稿快照管崩、Git 库自带历史但无手机端 UI）后拍板：**先出设计稿再定实现**。本版只交付 v2 原型设计与留档口径定义，**不落任何 ArkTS / 端侧代码**；实现版未排期，以本稿评审结论为准。

## 1. 版本定位

「改坏之后想回到之前」的兜底能力：按次保存留档、随时只读预览、一键恢复且恢复本身可再来回。与既有保护互补——回收站管「删」、草稿快照管「崩」、Git 管「同步历史」，版本历史管「改」。

## 2. 完成判定

在 v2 原型（`?ui=2`）中：笔记级菜单（单屏更多菜单「当前笔记」组 / 桌面左右栏「⋯」）可打开「版本历史」弹窗；列表按时间倒序展示「自动 / 手动 / 恢复前留档」三类版本；点行只读预览，预览内可恢复或删除该版本；「保存当前版本」手动留档即时生效；恢复后原内容自动留档（可再恢复回来）；永久删除笔记时历史一并清除；防线测试全绿且既有原型测试零回归。

## 3. 需求清单

### 2.2.1 入口（原型）

- 三个笔记级菜单各加「版本历史」入口（沿用 [v1.54](../历史版本归档.md#v154-需求文档) 收藏切换的布点先例）：`mobileMore`「当前笔记」组（带图标 + `menu-label`，跟随激活栏笔记）、`leftMore`、`rightMore`（纯文字行，跟随各自栏内笔记）；无笔记时入口禁用（与收藏 / 反链同一 `updatePaneChrome` 刷新链）。
- 打开 `utility-dialog` 弹窗「版本历史」（与回收站弹窗同范式，不新造容器语言）。

### 2.2.2 版本列表与只读预览（原型）

- 列表按时间倒序（最新在前）；行 = 来源标签 + 相对时间（刚刚 / N 分钟前 / N 小时前 / 昨天 / N 天前）+ 字数（与当前一致时标注）；行尾「恢复」图标按钮。
- 行主体点击 → 只读预览弹窗（复用 [v1.74](../历史版本归档.md#v174-需求文档) 回收站只读预览的结构与 CSS：`trash-preview-scroll` 只读滚动区 + `renderMarkdown` 渲染，不可编辑）；预览内提供「恢复此版本」「删除此版本」。
- 空态：「还没有历史版本」；首次打开自动 seed 三条演示版本（自动 / 手动 / 恢复前留档各一）。

### 2.2.3 保存版本与恢复（原型）

- 弹窗底部「保存当前版本」：手动留档当前内容，toast 确认。
- 恢复（列表行或预览内均可发起）：**先把当前内容自动留档一份（来源=恢复前留档）**，再写入目标版本内容；恢复后停留于弹窗，列表即时刷新——恢复永远可再来回，不存在「恢复错了回不去」。
- 删除单条版本：预览内「删除此版本」，直接删除（版本不是笔记，不做二次确认）。

### 2.2.4 留档口径（定义，供实现版沿用）

- **三类来源**：`自动`（自动保存成功后留档；同一笔记两次自动留档最小间隔 **10 分钟**——口径起点，防 800ms 自动保存 debounce 把快照刷爆，实现版可调）、`手动`（「保存当前版本」，不节流）、`恢复前留档`（恢复旧版本前自动保存当前内容，不节流）。
- **上限**：每篇笔记最多保留 **20 份**（口径起点），超出按最旧淘汰，三类一视同仁（不做「手动版本豁免淘汰」）。
- **存储**（端侧，实现版）：App 私有目录按「库 + 笔记相对路径」隔离（沿用草稿 `drafts/` 与回收站 `trash/<vaultKey>` 的 App 私有先例）；**不进库目录**——不污染 Git 同步、分享 / 导出 ZIP、外部目录授权（硬约束 14：上层不碰用户目录之外的东西）。外部目录库同样只写 App 私有目录。
- **删除联动**：移入回收站 → 历史保留（路径未变）；从回收站恢复 → 历史保留；**永久删除 → 历史一并清除**；改名 / 移动 → 历史跟随（同 [v1.54](../历史版本归档.md#v154-需求文档) 收藏 retarget 先例）。
- **恢复写入**：端侧实现必须走 `AtomicFile`（硬约束 15），禁止 `openSync(TRUNC)` 覆盖。
- **完整应用备份**（[v1.66](../历史版本归档.md#v166-需求文档)）：版本历史默认**不打包**（体积翻倍风险），实现版如需打包单独评审。

### 2.2.5 防线测试

- 新增 `tools/tests/test_prototype_history.mjs`：结构断言（弹窗 / 三入口 / 来源标签）+ 逻辑断言（上限淘汰、恢复先留档、按笔记隔离、seed 三类来源）+ 红线（URL 不携带笔记内容、历史 CSS 只用 token）。

## 4. 明确不做（本版）

- **不落端侧代码**：`NoteHistoryService` / App 私有快照目录 / ArkTS 组件——全部留给实现版。
- 不做 **diff 对比视图**（两版本并排、差异高亮）——先验证「看快照 + 恢复」的最小闭环是否够用；diff 回需求池。
- 不做版本**备注 / 命名 / 锁定保护**；不做「清空全部历史」（单删已够；回收站清空有误删风险叙事，历史单删无此风险）。
- 不做自动留档间隔 / 上限的**设置项**——口径写死为版本内常量，设置项回需求池。
- 不做 **Git 提交历史查看 / 单文件回滚**——那是需求池 C 节独立条目（`提交历史查看`），与本条正交。
- 不做跨库历史聚合、云端历史。

## 5. 红线

- 快照内容是笔记内容：**禁止进埋点**（硬约束 16），不写入 URL，原型演示数据不落 localStorage。
- 颜色 / 圆角 / 间距 / 字号只引用 token（硬约束 17）；来源标签色复用既有语义色（手动=品牌蓝、自动=muted、恢复前留档=danger 系）。
- 原型只演示交互形态，不宣称端侧能力已实现。

## 6. 技术约束与依赖

- 唯一改动面：`docs/prototype/v2/index.html`（两个新弹窗 + 三个菜单入口 + CSS + JS + `panel=history` URL 态）、新增 `docs/prototype/v2/版本历史设计.md`、新增 `tools/tests/test_prototype_history.mjs`、本需求文档、需求池 / 实施总清单登记。
- 既有原型测试（`test_prototype_v2_url.mjs`、`test_prototype_favorites.mjs` 等）必须保持零新增失败。
- 实现版前置：无新增权限；快照读取复用统一库访问层（`VaultRegistry.accessFor`），快照写入只进 App 私有目录；自动留档挂在既有自动保存链路（800ms debounce 之后），不新增保存时机。
