# v1.18 需求文档 —— 简单模式块编辑底座

> 状态：⚪ 规划中；2026-11-02 用户要求所有复杂块逐类排期，本版承担它们共用的机制，未实现、未验收、未发布。
> 前置：[v1.7](../v1.7/需求文档.md) 简单模式、块源码映射与复杂块保护；[v1.10](../v1.10/需求文档.md) 读屏名称口径。
> 统一设计：[简单模式复杂块编辑设计](../../engineering/简单模式复杂块编辑设计.md)（格式栏改造、各块交互规格、安全不变式）。

## 1. 版本定位

v1.7 17.4 把表格、代码、公式、图片、链接、HTML、frontmatter、callout 等整类划为简单模式只读。
2026-11-02 用户否决了「永久只读」这个定位，要求逐类排期；但每类各做一遍会各自造出一套
「识别块 → 解析 → 改结构 → 写回」的轮子。本版先把这套共用机制立起来，后续 v1.14 / v1.19 /
v1.20 / v1.21 各自只实现自己那类块的解析与操作。

本版不开放任何一类块的可编辑能力（表格除外也没有例外）：做完本版，简单模式的外观与今天一致。

## 2. 完成判定

光标或选区落在复杂块内时，简单模式能识别块的身份与源码区间、把块显示成选中态、在 Aa 浮层顶部
显示该块的上下文区（本版只有通用的「以源码编辑此块」），并通过块级源码抽屉安全回写；
区间外源码逐字不变。识别失败或重叠时退回只读并说明，不静默保护。

## 3. 需求清单

| 编号 | 交付范围与验收要求 |
| --- | --- |
| 18.1 | **块注册表。** 把 `web/mdeditor/src/simpleMode.ts` 的 `collectSimpleModeRanges()` 升级为注册表：每类块一个匹配器，产出 `{ from, to, type, id }`；语法树能识别的走语法树，识别不了的走行模式（现状在 `customProtectedRanges()` 内）。区间沿用现有 `mergeProtected` 去重合并且互不重叠。语法树未就绪时维持现状：整篇只读并提示「正在安全解析，请稍后继续编辑」，不给结构操作。 |
| 18.2 | **块模型接口。** 定义 `parse(source, range) → Model \| null` 与 `stringify(model) → string` 的纯函数契约与类型；本版只落接口与一个空实现，**不实现任何具体块**。`parse` 返回 `null` 时该块降级只读。 |
| 18.3 | **块操作与回写。** `applyBlockEdit(state, range, op)` 只产出落在 `range` 内的 changes，底座统一校验越界即拒绝；回写后选择位置由 op 指定。撤销 / 重做、草稿、保存沿用 v1.7 的同一编辑状态，不新增状态机。 |
| 18.4 | **块选中态。** 光标或选区进入复杂块时，该块在正文里加描边（沿用 `brand` / `line_strong` token），离开时撤销；不改变块的渲染内容，不拦截块内点击（双链、复选框等既有交互优先）。 |
| 18.5 | **Aa 浮层上下文区。** `Index.ets` 的 `FormatMenu()` 顶部新增上下文区：显示「当前块：<类型名>」与该类块的操作；无块时整区不渲染，面板与今天完全一致。键盘 Tab 顺序在原有三组之前，Esc 关闭并回到块内光标。所有按钮带 `accessibilityText`（对象 + 方向），口径同 v1.10。 |
| 18.6 | **块级源码抽屉。** 上下文区提供「以源码编辑此块」：只显示该块源码的编辑抽屉，保存时回写该区间；不切换模式、不暴露整篇源码。这是所有未排期语法与结构不规范块的兜底出口。 |
| 18.7 | **安全不变式与单测。** 断言结构操作只改写目标区间（区间外子串相等）、解析失败即只读并说明、不清空也不用降级文本覆盖原文。沿用 `web/mdeditor/test/*.test.mjs` 的 esbuild harness 写法。 |

## 4. 明确不做

- 不开放任何具体块的编辑能力（表格归 v1.14，代码 v1.19，链接图片 v1.20，公式与扩展块 v1.21）。
- 不做整篇所见即所得，不引入富文本副本，不新增第二份 Markdown 解析。
- 不新增独立浮层：上下文区放进现有 Aa 浮层，不引入工具条避让规则（设计文档 §4.4 记录了备选方案与取舍）。
- 不改专业模式行为，不申请新权限，不改包版本与发布状态。

## 5. 技术约束与依赖

- 块区间须兼容 BOM、CRLF 与转义，并与 v1.7 的块源码映射、滚动跟随共用同一套解析。
- 上下文区在 ArkWeb 中的定位与软键盘避让须在模拟器和 API24 / XT2 上验证，浏览器结果不能代替。
- 复杂块提示文案沿用 v1.7 的两个常量（`PROTECTED_HINT_TABLE` / `PROTECTED_HINT_DEFAULT`），
  实施到哪一类就撤掉那一类的只读提示。
