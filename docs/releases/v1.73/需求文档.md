# v1.73 需求文档 —— 手动拉取（fast-forward pull）

> 状态：文档立项（2026-11-16）；原生实现进行中。

## 1. 版本定位

Git 同步弹窗新增「拉取」按钮，让手机端能**手动**消费远端在跟踪分支（`main` 等克隆分支）上的新增提交。
语义由用户 2026-11-16 拍板（[Q9 修订](../../open_questions.md#q9-v03-是否把已有-git-库的手机-pullcheckout-纳入本版验收---已决定2026-11-01)）：

- **本地有提交，不让合并**（ahead>0 一律拒绝，交 PC 处理）；
- **没有冲突就可以合并**：工作区干净、本地无未推送提交、远端跟踪分支可快进时，快进合并到远端跟踪分支。

需求池条目：[§C 手动拉取（fast-forward pull）](../../requirements_backlog.md#c-同步与数据)。与「打开 App
自动后台拉取 + 冲突合并」条目正交（那条指**自动**拉取 + 冲突合并，仍未分配）；与既有 fetch
（检查远端状态）、push（非快进拒绝）互补。

## 2. 完成判定

两台设备场景：PC 在 `main` 上提交并推送 → 手机端 Git 同步弹窗点「拉取」→ 手机本地分支快进到远端
`main` 新提交，工作区文件内容更新，文件树 / 打开栏 / 搜索索引反映远端新文件与改动。

拒绝路径：本地有未提交更改 → 拉取被拒并提示先提交推送；本地有未推送提交（ahead>0）→ 拉取被拒并提示
交 PC 处理；网络 / 认证失败 → 分类复用现有错误提示（401/403 走令牌编辑流程，重试动作为拉取）。

签名 HAP 构建（native 双架构）通过；相关 Node 测试与 ohosTest 用例通过；API24 / XT2 真机验收待用户。

## 4. 明确不做

- 不做合并提交 / 变基 / 冲突解决 UI（ahead>0 一律拒绝，交 PC 处理）。
- 不做后台自动拉取（需求池「自动后台拉取 + 冲突合并」条目维持未分配）。
- 不做强推 / reset / 历史回滚。
- 不新增权限（沙箱内 git 操作无需权限）。
- 不做拉取历史 / 撤销拉取。

## 5. 技术约束与依赖

- **Native 分发结构**：`execute_git_operation`（stage/commit/fetch/push）扩展 `pull`；复用
  `fetch_target_branch` 拉取目标分支；工作区干净检查可抽 helper 与 push 路径复用（`.trash` 排除口径一致）。
- **进度上报**：复用 `progress_phase_t`（FETCH 阶段）；`Git2Progress.operation` 扩展 `'pull'`。
- **类型声明两份同步**：`entry/src/main/cpp/types/libgit2_napi/Index.d.ts` 与
  `entry/src/ohosTest/cpp/types/libgit2_napi/Index.d.ts`。
- **ETS 错误分类**：native reject 中文错误文本，ETS 按关键词分类（local / stale / auth / network），
  与现有 fetch/push 分类框架一致；`GitSyncRetryAction` 扩展 `'pull'`。
- **刷新链**：打开弹窗前 `flushWorkspaceSaves` 已保证弹窗打开时编辑落盘，与「脏工作区拒绝 pull」自洽
  （有改动先提交推送再拉取）；拉取后刷新复用 xiaoyi 外部变更后的既有链路，不新写第二套。
- **安全边界**（Q9 修订依据）：checkout 只重写两端都已提交的内容，中途失败留下两个已提交版本的混合态、
  status 变脏、重试自愈，不丢未提交用户数据；不采用 v0.3 草案的整库代际方案。
- 颜色 / 圆角 / 间距 / 字号只引用现有 token。
- 真机验收（API24 / XT2 + 真实远端）由用户执行后回填本节。
