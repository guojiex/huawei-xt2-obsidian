# v0.5 需求文档 —— 共享样例库与渲染基线

> 状态：🟡 实施中（2026-10-25）；对应里程碑：M4.6
> 来源：需求池 K 节。执行顺序提前于 v0.3 同步，不更改历史版本承诺。

## 1. 版本定位

一份静态 Markdown 样例库同时供给交互原型、首次安装的默认本地库，并作为当前与未来渲染能力的对照样本。样式参考用户指定的 Obsidian 库，内容原创，不复制其私人笔记。

## 2. 完成判定

原型与 App 预置内容由同一份样例文件生成，可检查一致性；自动预置只在首次新建默认库时写入；用户明确执行设置内重置后，重新打开同样恢复样例。旧安装、新建空库及用户后续修改不被覆盖；能力矩阵准确标注现状和目标。新增语法不在本版自动视为实现。

## 3. 需求清单

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| 1 | 样例单一真源 | `sample_vault/notes/` + 清单，生成原型数据与 ArkTS 静态数据；生成检查可发现漂移 |
| 2 | 原型来源统一 | 文件树、标题、正文、元信息均来自清单；不再手抄私人内容，Git 页面仍仅是示意 |
| 3 | 首次安装样例 | 预置至新创建的 `vaults/local`；走统一解析器和已有 AtomicFile 保存，失败不阻止打开 App |
| 4 | 数据保护 | 旧安装/已有目录跳过；每次启动不自动补回被删除文件；新建本地库保持空白 |
| 5 | 样式矩阵 | 见本目录 `样式基线.md`，样例覆盖真实库语法；标记基础渲染与扩展语法目标，未支持时保留源码 |
| 6 | 设置内重置数据 | 二次确认并输入“重置”才可执行；清本地库、草稿、回收站、最近打开、同步配置和应用 Git 令牌，系统关闭 App；重新打开按首次安装恢复样例，不影响远端仓库 |
| 7 | 数据驱动版本记录 | changelog.json 单一真源生成关于最近 3 条、App 内完整记录、原型与 CHANGELOG.md；包版本仍取安装包；记录状态不冒充发布；文档沉淀生成技术 |

## 4. 明确不做

- 本版不实现所有 Obsidian 语法，不把公式、Mermaid、双链跳转和任意 HTML 当成已支持。
- 不修改用户原 Obsidian 库，不打包其私人内容，不自动迁移已有库，不接远端同步。
- 不执行模拟器崩溃、强杀或写入中断实验；重置功能由用户主动确认，不作为这类测试手段。

## 5. 技术约束

API ≤24、路径与 AtomicFile 规则见 AGENTS.md 和 [API 笔记](../../harmonyos/api_notes.md)。原型数据与编译数据可重复生成；安装失败记录简明提示，不静默覆盖已有文件。样例中的小艺练习不代表已连接小艺。

- SettingsView 数据管理区 → 独立确认框；只有输入精确的“重置”才能点确认，取消不执行操作，执行中按钮禁用。

- `assembleHap` 仍被上文 Index.ets 两处既有类型错误阻塞；本次新增 ResetDataDialog / AppDataResetService 未报告编译错误。未实际清空模拟器、真机或用户数据，未宣称设备重置通过。
