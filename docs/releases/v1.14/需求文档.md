## 1. 版本定位

v1.7 17.5 规定简单模式下表格整体只读，附近提示“请在专业模式编辑”。表格是笔记里常见的块，用户为了改一个单元格就要切到专业模式、面对 `| a | b |` 源码，与简单模式“用户不需要知道 Markdown 底层”的目标不符。本版让简单模式可以在渲染后的表格里直接改文字、增删行列，其余仍保持保护。

设计入口：[v2 设计说明](../../prototype/v2/设计说明.md)；当前原型已同步支持简单表格单元格编辑及复杂单元格保护，行列操作与新建表格仍未启用。浏览器原型只证明原型交互，不代表原生设备行为。

## 2. 完成判定

在简单模式下，用户能在排版后的表格中点选单元格输入或修改文字，能在表格内加粗 / 斜体，能增删行和列；所有修改只落到表格对应的源码区间，表格之外的 Markdown 逐字不变；结构不规范或含复杂内容的表格 / 单元格保持只读并有明确说明。保存、草稿、撤销沿用 v1.7 的同一编辑状态与保存链路。

## 3. 需求清单

| 编号 | 交付范围与验收要求 |
| --- | --- |
| 14.1 | **单元格内改文字。** 点选渲染后的单元格可定位光标、选择文字、输入和删除；支持空单元格输入。修改只替换该单元格的源码区间（不含两侧空格），同行其他单元格、同表其他行、分隔行（含 `:---:` 对齐标记）和表格之外的内容逐字保留。单元格内容中的 `\|` 在显示时还原为 `|`，输入 `|` 写回时自动转义为 `\|`；单元格内不产生换行，粘贴多行文本时换行折为空格。格内可应用粗体、斜体，其他块级格式（标题、列表、引用）不对单元格生效并给出简短提示。中文输入法组合期间不提交、不跳格、不重建表格。 |
| 14.2 | **行列增删。** 光标在单元格内时显示表格工具条：上方加行、下方加行、左侧加列、右侧加列、删除行、删除列。表头行不能删除，表头上方不能插入行（表头下方加行即成为首个数据行）；只剩一列时不能删除列，并提示原因。加列时分隔行同步补充 `---`，已有列的对齐标记保留。结构操作只重写当前这张表，采用紧凑规范格式（`\| a \| b \|`：单元格两侧各一个空格，**不按列宽补空格对齐**，分隔行保留原对齐标记）；必须原样保留单元格内容（含 `\|` 转义）、已有对齐标记、原换行风格和行首前缀（引用 `> `、列表缩进），表格之外的源码逐字节不变；单元格内输入不触发整表重写（2026-11-05 决定）。操作后焦点落到合理的单元格。工具条随表格滚动定位，表格移出可视区或失去焦点后隐藏，不遮挡正在编辑的单元格。 |
| 14.3 | **键盘与触控。** Tab / Shift+Tab 在单元格间前后移动；Enter 移到下一行同列，最后一行保持原位；在最后一个单元格按 Tab 在表末追加一行并落到新行首列。触控下工具条按钮不小于系统最小触控目标，窄屏可横向滚动，不换行挤压。 |
| 14.4 | **新建表格与粘贴转换。** 入口为简单模式停靠格式栏「待办」之后的「插入表格」按钮（不放进 Aa）：点开为行列网格选择器，最多 8 行 × 6 列、行数含表头，点按格子即插入；在光标所在块之后插入表头占位为「列 1 / 列 2…」、带分隔行的空表；光标在表格单元格内时提示「表格内不能再插入表格」。从表格 / 电子表格复制的制表符分隔文本（至少 2 行、每行制表符数一致）粘贴到正文段落时**直接转为表格、不先询问**：空段落被替换，非空段落在其后插入；随后显示「已转为表格（N 行 × M 列）· 撤销」提示条，撤销恢复到粘贴前；不满足条件按普通文本粘贴（2026-11-05 决定）。 | 选择器可用方向键移动；插入与转换各为一个撤销步；表格单元格内粘贴不触发转换 |
| 14.5 | **保护范围与降级。** 以下表格或单元格保持只读，并在附近说明“请在专业模式编辑”（不得每次输入弹窗）：缺少分隔行的伪表格、各行列数不一致且无法安全补齐的表格、单元格内含行内代码、链接、图片、双链、公式、HTML、脚注或除支持的 `\|` 外其他转义等复杂语法的单元格（同表其他单元格仍可编辑）、表格内含多行内容或围栏标记的情况。转换或解析失败时保留原文，不清空、不用降级文本覆盖。 |
| 14.6 | **撤销与保存。** 一次单元格修改、一次结构操作各为一个撤销步；撤销后源码完全恢复到操作前。接入既有自动保存、草稿恢复、保存失败保护与 VaultAccess，沿用 AtomicFile；外部库走同一适配层，不按 rootKind 分叉。内容不得进入埋点或日志。 |

## 4. 明确不做

- 不做合并单元格、列宽拖动、单元格内多行、表内嵌套块、排序 / 筛选 / 公式计算；Markdown 不支持这些。
- 不做列对齐的图形化切换（左 / 中 / 右）；已有对齐标记只保留不修改，后续有需求再登记。
- 结构操作后不保留手写的按列对齐空格（紧凑格式，见 14.2）；这是有意取舍，不作为缺陷验收。
- TSV 粘贴不做先询问的对话框，也不识别 CSV / HTML 表格。
- 不新增 Markdown 方言，不引入富文本副本；仍以同一份 Markdown 为唯一真源，不做整篇 HTML 反向转换。
- 不改变专业模式的表格编辑方式，不为专业模式增加表格辅助（需求池「表格编辑辅助」仍后置）。
- 不借此重写保存、附件、Git 或外部授权服务，不申请新权限，不改包版本与发布状态。

## 5. 技术约束与依赖

- 渲染器已为每个单元格输出源码起止偏移，并通过 BOM、CRLF、无外围管道符及转义 `\|` 的定向测试；沿用表格块整体偏移和既有预览回写桥，不另建第二套文档解析。
- 单元格偏移在每次编辑后需随后续内容平移，包含该单元格的表格范围同步变化；整表结构重写后整体重新渲染。
- 中文输入法组合、跨块选择、粘贴纯文本、撤销 / 重做的约束沿用 v1.7 17.3 与 [api_notes](../../harmonyos/api_notes.md) 的 C1 / Q1 条目。
- 单屏宽表格的显示方式（横向滚动或整表缩放）需在设计评审中确定；不得因表格过宽造成页面水平溢出。
- 工具条在 ArkWeb 中的定位（fixed 与滚动容器、软键盘避让）须在模拟器和 API24 / XT2 上验证，浏览器原型结果不能代替。
