# v1.25 单篇分享图片水印、长图宽度与分享面板

> 状态：单篇图片水印的原型与本地源码已落地；分享范围与格式选择层（25.12–25.14）已接入现有服务，定向测试与签名 arm64-v8a HAP 构建通过。格式详情、固定宽度 / 外观原生实现及固定宽度截图前置仍未完成；模拟器、API24 / XT2、接收端和发布待验。
> 对应里程碑：独立优化；按用户要求优先处理，领取顺序见[实施总清单](../实施总清单.md)。
> 需求来源：需求池「分享图片加『曜石笔记』水印」（2026-10-31）及 [S-01 / S-02](../../requirements_backlog.md#s-长图宽度选择与分享面板重做2026-11-03)（2026-11-03）。
> 设计规格：[分享图片水印设计](../../prototype/v2/分享图片水印设计.md) · [分享面板设计](../../prototype/v2/分享面板设计.md)；现行设计入口：[v2 原型](../../prototype/v2/index.html)。

## 1. 版本定位

保留已落地的单篇长图末尾水印，并把长图排版宽度与当前屏幕形态解耦，重做分享范围、格式和详情面板；不改变源笔记、单 JPEG 交接或其他导出语义。

## 2. 完成判定

单篇笔记选择「图片」后，预览及最终交给 Share Kit 的单张 JPEG 都在正文之后显示一次「曜石笔记」水印；同一宽度预设在单屏、双屏、三屏和不同栏宽下得到一致的长图宽度与换行。分享面板在单 / 双 / 三屏与浅 / 深色下呈现范围分段、格式列表和格式详情。源码、自动测试、构建、模拟器、API24 / XT2、接收端与发布证据分开记录。

## 4. 明确不做

- 文件夹或整个知识库生成图片、水印，以及 ZIP、Markdown、文本分享水印。
- 可关闭水印、用户自定义文案 / 位置 / 透明度、重复平铺或逐捕获分段盖章。
- 社媒尺寸模板、上传托管、自动发送或任何网络分享能力。
- 改变 v1.9 的长图尺寸预算、分页 / 缩放策略、临时文件生命周期或 Share Kit 交接语义。
- 修改源笔记、v0.8 或 v1.9 的历史验收记录；用原型或构建结果替代模拟器、API24 / XT2、接收端证据。
- 任意宽度、字号、页边距、页眉页脚、二维码或社媒尺寸模板；文件夹 / 知识库长图；按笔记记忆分享设置；恢复 Git 远端链接入口。

## 5. 技术约束与依赖

- 环境：HarmonyOS API 24、ArkTS、Stage 模型；包名 `com.jxg.huaweiobsidian`。
- 依赖 v1.9 已有的单篇连续长图合成与单 JPEG 交接；PixelMap API 与预算依据见 [api_notes O3](../../harmonyos/api_notes.md#o3-pixelmap-可拼接为单张长图--设备与接收限制待验)。
- 只在分享专用渲染内容中增加末尾水印，并在获取最终图像尺寸之前完成布局；不引入未核实 HarmonyOS API，不扩大组件 / 服务边界。
- 颜色、间距、字号遵循 v2 token；设计行为见[分享图片水印设计](../../prototype/v2/分享图片水印设计.md)。
- 长图固定宽度实施前，先核实专用分享渲染 Web 能否在大于当前窗口的固定宽度下离屏快照，以及是否能独立使用浅 / 深 token。当前 SDK 核对见 [api_notes O4](../../harmonyos/api_notes.md#o4-固定宽度-arkweb-长图离屏截图能力未证实2026-11-03-sdk-核对)：API 声明存在 Surface 与离屏 Builder 路径，但固定宽度完整捕获仍未证实。若安全隔离探针不成立，只交付面板与「跟随当前栏」，固定宽度重新拍板。
- 分享面板只改布局、外观与界面接线，继续调用 v0.8 / v1.9 服务；新增选择仅存应用偏好，不进入笔记或库数据。
