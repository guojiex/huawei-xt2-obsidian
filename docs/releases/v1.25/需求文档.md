# v1.25 单篇分享图片水印

> 状态：原型与本地源码已落地；mdpreview 定向回归与签名 arm64-v8a HAP 构建通过。API26 模拟器、API24 / XT2、接收端和发布待验。
> 对应里程碑：独立优化；按用户要求优先处理，领取顺序见[实施总清单](../实施总清单.md)。
> 需求来源：需求池「分享图片加『曜石笔记』水印」，原登记日期 2026-10-31。
> 设计规格：[分享图片水印设计](../../prototype/v2/分享图片水印设计.md)；现行设计入口：[v2 原型](../../prototype/v2/index.html)。

## 1. 版本定位

在单篇笔记导出的连续长图末尾添加低干扰的「曜石笔记」品牌水印，不改变源笔记或其他分享格式。

## 2. 完成判定

单篇笔记选择「图片」后，预览及最终交给 Share Kit 的单张 JPEG 都在正文之后显示一次「曜石笔记」水印；长图分段数量、整体缩放与取消流程不导致水印重复、遮挡正文或被截掉。源码、自动测试、构建、模拟器、API24 / XT2、接收端与发布证据分开记录。

## 3. 需求清单

## 4. 明确不做

- 文件夹或整个知识库生成图片、水印，以及 ZIP、Markdown、文本分享水印。
- 可关闭水印、用户自定义文案 / 位置 / 透明度、重复平铺或逐捕获分段盖章。
- 社媒尺寸模板、上传托管、自动发送或任何网络分享能力。
- 改变 v1.9 的长图尺寸预算、分页 / 缩放策略、临时文件生命周期或 Share Kit 交接语义。
- 修改源笔记、v0.8 或 v1.9 的历史验收记录；用原型或构建结果替代模拟器、API24 / XT2、接收端证据。

## 5. 技术约束与依赖

- 环境：HarmonyOS API 24、ArkTS、Stage 模型；包名 `com.jxg.huaweiobsidian`。
- 依赖 v1.9 已有的单篇连续长图合成与单 JPEG 交接；PixelMap API 与预算依据见 [api_notes O3](../../harmonyos/api_notes.md#o3-pixelmap-可拼接为单张长图--设备与接收限制待验)。
- 只在分享专用渲染内容中增加末尾水印，并在获取最终图像尺寸之前完成布局；不引入未核实 HarmonyOS API，不扩大组件 / 服务边界。
- 颜色、间距、字号遵循 v2 token；设计行为见[分享图片水印设计](../../prototype/v2/分享图片水印设计.md)。
