# v1.1 需求文档 —— 当前库全文搜索

> **状态**：🟡 本地实现与构建完成；API26 模拟器搜索模式可打开，键盘输入与 XT2/API24 待验；未发布
> **对应里程碑**：M6

## 1. 版本定位

建立当前库的正文索引，让笔记多起来后仍能找到内容。

## 2. 完成判定

搜索当前库的 Markdown 正文能返回正确文件和匹配片段；编辑、移动、删除、切库后结果及时更新，重启后可恢复索引。

## 3. 需求清单

| # | 需求 | 来源 | 验收点 |
| --- | --- | --- | --- |
| 1 | 全文关键词搜索 | 需求池 B「全文搜索（关键词）」 | 仅搜索当前库；结果能打开目标笔记并展示匹配上下文 |
| 2 | 索引增量更新 | 需求池 E「索引增量更新」 | 保存、移动、重命名、删除后结果与文件一致；切库只展示目标库结果；索引损坏可重建，不改动笔记原文件 |

## 4. 明确不做

- 正则、大小写和路径过滤：需求池 B 的高级搜索项留待后续。
- 双链、标签和图谱：待 v1.2 或之后的独立版本。

## 5. 技术约束与依赖

索引是可重建的派生数据，Markdown 文件仍是笔记真源；库路径仍经同一解析器。整体边界见 [`mvp_design.md`](../../mvp_design.md)。

## 6. 验收记录

### 实现与自动检查

- ✅ `SearchIndex` / `FullTextSearchService` 提供当前库内存索引；首次搜索从当前库 Markdown 重建，按批次异步扫描，进程重启后首次查询重新生成。索引不落入用户笔记目录，也不持久化正文副本。
- ✅ 创建、保存、重命名、移动、永久删除、移入回收站与恢复均接入增量更新；结果在搜索时重新读取候选文件，切库按库 ID 切换索引。索引异常时可重新扫描源文件。
- ✅ `hvigorw test --mode module -p module=entry -p product=default` 完成；搜索相关 Hypium 套件包含 5 项索引与服务测试，覆盖中文片段、保存、移动、删除、切库隔离与失败后重建。
- ✅ `python3 tools/build_sample_vault.py --check`、`python3 tools/build_changelog.py --check` 与 `git diff --check` 通过。
- ✅ `hvigorw assembleHap --mode module -p product=default` 完成，生成未签名 HAP；构建保留工程中既有 ArkTS 告警。

### 模拟器与性能

- ✅ API 26 arm64 `Huawei_TripleFold_v05Clean` 安装当前 HAP 后，可打开快切面板、切到“正文 · v1.1”，空查询状态显示“输入关键词搜索当前库正文”。当前设备库为 10 篇笔记，交互未改动笔记内容。
- 🟡 前一轮同模拟器运行记录：HDC 注入“没有配置”后显示 1 条 `欢迎使用.md` 结果和匹配片段，选择结果打开对应笔记。重建当前 HAP 后复验查询输入时弹出小艺输入法首次使用协议；未同意，选择“退出应用”恢复笔记应用。因此当前 HAP 的文本输入与结果跳转仍待直接复验；模拟器记录见 `.local/shots/v11_search_query_ui.md`、`.local/shots/v11_search_open_result_ui.md`。输入法协议页不是应用错误，也不能算真实键盘输入通过。
- 🟡 本机合成样本微基准（1000 篇）：首次建索引约 15.73 ms，20 次查询约 0.63 ms；仅为开发主机结果，不代表模拟器或 XT2 性能。
- ⏸ XT2 / API 24 三形态交互和设备性能待验；不据 API 26 模拟器结果宣称设备验收完成。

本地实现与代码/构建验证已完成；真实键盘输入、当前 HAP 的结果跳转复验及 XT2/API24 仍待验，故 v1.1 尚未达到发布验收状态。
