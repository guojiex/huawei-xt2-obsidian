# v1.70 需求文档 —— 编辑不一致弹窗展示差异并可选保留一边

> 状态：2026-11-15 用户提出实现。承接 [需求池 §AC](../../requirements_backlog.md#ac-编辑不一致弹窗展示差异并可选保留一边2026-11-15)，收口 [v1.7 17.6](../v1.7/验收记录.md) 已知问题的用户出口。

## 1. 版本定位

「编辑内容与笔记不一致」恢复弹窗（`showEditorMismatchRecovery`）目前只有一句「内容未保存」的说明与两个出口（留在当前页面 / 放弃并重新载入）：用户既看不到到底差在哪，也无法选择保留编辑区一边。本版把该弹窗升级为**带差异对照的三出口选择**：

- 窗上展示结构化差异（两侧长度、首个差异位置与码点）+ 首个差异附近的转义内容窗口；
- 三个出口：留在当前页面 / 以笔记文件为准（原「放弃并重新载入」）/ 以编辑区为准（新增，把编辑区内容保存到笔记）。

这是防串写防线的**用户出口细化**，不是放松防线：触发条件、会话身份校验、revision 配对、恢复草稿快照、STALE_CONTENT 磁盘校验全部保持；「以编辑区为准」只是让用户在看到差异后**显式选择**把编辑区内容写入，且为一次性放行。

## 2. 完成判定

模拟器复现「切笔记触发不一致弹窗」时，弹窗窗上可见具体差异（长度 / 首个差异位置 / 差异附近内容窗口），且三个出口各自可达：留在当前页面不落盘；以笔记文件为准重新载入磁盘版本；以编辑区为准把当前编辑区内容走正常保存链（含恢复草稿快照与 STALE_CONTENT 校验）写入笔记，保存后基线推进、后续切换不再弹窗。自动回归覆盖差异描述、三出口分支与一次性放行不越权；签名 HAP 构建通过。API24 / XT2 真机验收待用户。

## 4. 明确不做

- 不做双栏并排的全量 diff 视图（窗上仅结构化摘要 + 首个差异附近的转义窗口）。
- 不改弹窗触发条件、会话 / revision 校验与恢复草稿链路。
- 不给「以编辑区为准」加二次确认弹窗（差异已上窗，选择即确认）。
- 不自动续接被打断的笔记切换（选边后停在当前笔记，用户重新点击目标笔记）。
- 不新增权限、不改 token / 设计真源映射。

## 5. 技术约束与依赖

- `promptAction.showDialog` 最多 3 按钮，现有 2 按钮 → 3 按钮在支持范围内；message 为纯文本，`\n` 分行。
- 放行键为 string 成员字段（`editorMismatchApprovalKey`），键构造与判等用 file-scope 纯函数（`editorMismatchApprovalKeyOf`），供测试 harness 提取。
- 清除放行用 `promise.then(clear, clear)`，不用 `.finally`（仓库既有代码未用过，保守起见）。
- 差异窗口转义与 `TrashService.escapeAround`（v1.34 先例）口径不同是有意为之：日志侧转义不可打印字符（含 CJK 转义），弹窗侧面向用户保留中文可读、只转义控制字符。
- 颜色引用沿用 `$r('app.color.text_secondary')` / `$r('app.color.brand')`，不散写数值。
