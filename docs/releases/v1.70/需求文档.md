# v1.70 需求文档 —— 编辑不一致弹窗展示差异并可选保留一边

> 状态：2026-11-15 用户提出实现。承接 [需求池 §AC](../../requirements_backlog.md#ac-编辑不一致弹窗展示差异并可选保留一边2026-11-15)，收口 [v1.7 17.6](../v1.7/验收记录.md) 已知问题的用户出口。

## 1. 版本定位

「编辑内容与笔记不一致」恢复弹窗（`showEditorMismatchRecovery`）最初只有一句「内容未保存」的说明与两个出口（留在当前页面 / 放弃并重新载入）：用户既看不到到底差在哪，也无法选择保留编辑区一边。本版把该弹窗升级为**git diff 式双栏对照的三出口选择**（2026-11-15 用户追加要求：弹窗太小、要看两版完整差异，取代同日早先的「摘要 + 转义窗口上窗」方案）：

- 双栏逐行 diff：左 = 笔记文件版本（删侧红），右 = 编辑区内容（增侧绿），LCS 行对齐、相邻增删配对、长 run 折叠、总量截断；
- 窗上同时保留结构化差异摘要（两侧长度、首个差异位置与码点）；
- 三个出口：留在当前页面 / 以笔记文件为准（原「放弃并重新载入」）/ 以编辑区为准（把编辑区内容保存到笔记）。

同时修复一个**真实误报根因**（2026-11-15 模拟器 hilog 定位）：带 UTF-8 BOM 的笔记（Windows 工具产物）被 Web 侧 `TextDecoder` 默认吞掉开头 U+FEFF，编辑器内容比基线少 1 字符且无脏标 → 每次切换笔记都误弹「内容不一致」。修复为 Web 侧无损解码（`ignoreBOM: true`）+ ArkTS 侧等价豁免（BOM / CRLF 口径差不构成不一致）。

这是防串写防线的**用户出口细化**，不是放松防线：触发条件、会话身份校验、revision 配对、恢复草稿快照、STALE_CONTENT 磁盘校验全部保持；「以编辑区为准」只是让用户在看到差异后**显式选择**把编辑区内容写入，且为一次性放行。

## 2. 完成判定

模拟器复现「切笔记触发不一致弹窗」时，弹窗为 git diff 式双栏大弹窗：左右列头（笔记版本 / 编辑区版本 + 行数）、结构化差异摘要、行级红绿对照（删红 / 增绿 / 一致无底色），三个出口各自可达：留在当前页面不落盘；以笔记文件为准重新载入磁盘版本；以编辑区为准把当前编辑区内容走正常保存链（含恢复草稿快照与 STALE_CONTENT 校验）写入笔记，保存后基线推进、后续切换不再弹窗。带 BOM 的笔记打开 / 切换 / 保存全链路不再误弹「内容不一致」。自动回归覆盖差异行构建（对齐 / 配对 / 折叠 / 截断）、等价豁免、三出口分支与一次性放行不越权；签名 HAP 构建通过。API24 / XT2 真机验收待用户。

## 4. 明确不做

- 不做逐字符级 word-diff（行级 LCS 对齐 + 相邻配对已满足「看出差在哪」；字符级对照在 720vp 双栏内可读性差）。
- 不改弹窗触发条件、会话 / revision 校验与恢复草稿链路。
- 不给「以编辑区为准」加二次确认弹窗（差异已上窗，选择即确认）。
- 不自动续接被打断的笔记切换（选边后停在当前笔记，用户重新点击目标笔记）。
- 不新增权限；颜色 / 尺寸只经 token（新增 `diff_del_bg` / `diff_add_bg` / `Size.mismatchDialogW`，真源同步进原型）。

## 5. 技术约束与依赖

- 弹窗挂载走 `CustomDialogController` + `@CustomDialog`（`openGitSyncDialog` 先例）：`autoCancel` + `cancel` / `onWillDismiss` 复位防重入守卫，`alignment` 按单屏 / 宽屏选 Bottom / Center，`customStyle: true`。
- 行对模型独立成 `model/EditorMismatchDiff.ets`（纯函数、无依赖），避免 Index ↔ 弹窗组件循环引用；测试整文件加载（无需切片）。
- 放行键为 string 成员字段（`editorMismatchApprovalKey`），键构造与判等用 file-scope 纯函数（`editorMismatchApprovalKeyOf`），供测试 harness 提取。
- 清除放行用 `promise.then(clear, clear)`，不用 `.finally`（仓库既有代码未用过，保守起见）。
- BOM 修复注意：OHOS `util.TextDecoder` 的 `TextDecoderOptions.ignoreBOM` 官方文档语义与 WHATWG 相反（OHOS：默认 false = 保留 BOM），ArkTS 侧 `BridgeCodec.decode` 不动，等价豁免保证两种行为都不误报；结论记 `docs/harmonyos/api_notes.md`。
- 颜色 / 尺寸只引用 token：`$r('app.color.diff_del_bg' / 'diff_add_bg' / 'danger' / 'success')`、`Size.mismatchDialogW`；真源同步进 `docs/prototype/v2/index.html`（`--mismatch-width` / `--diff-del-bg` / `--diff-add-bg` + `#editorMismatchDialog` + `panel=mismatch` 触发）。
