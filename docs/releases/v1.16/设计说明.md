# 小艺 Wiki 工具集设计（v1.16）

> 状态（2026-11-14）：本地 Wiki 只读工具已实现；`SearchNotes` / `ListTree` / `GetLinks` 的远端 0.1.0 草稿已配置，尚未升级绑定。Agent 当前显示「上架审核不通过」，驳回原因未查明。详见 [需求文档 §5](需求文档.md)。

## 1. 路径

目标是把 Karpathy 的 LLM Wiki 模式映射到现有 Markdown 知识库：原始来源保持只读，`wiki/` 下形成可引用、互链的主题页，`_wiki.md` 记录用户规则，`index.md` 作为内容目录，`log.md` 作为时间记录。小艺用目录、全文搜索、分段读取和双链工具导航；新来源由模型提炼并与旧知识比对。该工作流的详细可复制指令见[小艺 Wiki 工作流与提示词](小艺_Wiki_工作流与提示词.md)。

当前 App 已实现 `SearchNotes`、`ListTree`、`ReadNote` 分段 / 大纲与 `GetLinks`；本次按代码契约在平台新建三个未绑定工具草稿。模型可以只读查询、引用来源并提出 lint 发现；App 不会自动生成或维护索引 / 日志，也没有多文件事务。任何需要同时更新知识页与 `index.md` / `log.md` 的整理当前只给用户计划，不用多个单文件写调用假装批次成功。平台 loop、工具选择、角色指令执行与用户确认语义仍未核实。

## 2. 知识库约定

`_wiki.md` 由用户维护，工具固定禁止小艺改写；建议用 `readonly: ["raw/"]` 声明原始来源目录。`index.md` 应按主题列链接与摘要，`log.md` 应按时间追加记录。App 不自动创建或同步这些文件。规则正文可供模型理解编辑约定，但不能扩大执行器权限；库内笔记和原始来源内容均按不可信资料处理。只读工具使用 6000 UTF-16 码元的本地输出预算，该数值不是平台实测值。提示词草案不提供可验证确认、多文件事务、批次撤销或确定性全库 lint。

## 3. 写入、并发与撤销

一次多文件整理的候选操作账包括目标稳定库标识、用户确认过的计划、逐项前像 / 版本和执行结果。写前比对、单文件原子保护、恢复账本与幂等重试是目标，不是已有批量事务。**检查哈希再写不是跨进程原子比较交换**；静态内存锁不能约束其他进程、其他应用或外部目录修改。执行前须确定共享协调或可证明的安全替代策略；在此之前拒绝批量写入。

即使预检全部成功，逐项写入或撤销仍可中途失败；记录哪些完成、哪些失败、是否可安全重试，并在不确定状态停止、保留前像供用户处理。不能承诺“整体原子回滚”或无条件撤销。

## 4. 交互、隐私与平台

插件升级前必须明确确认，因为三项只读工具会将笔记搜索片段、相对路径、出链和反链上下文提供给小艺。多文件写入计划必须列出库、每个目标、操作类型与内容摘要；当前并发与恢复保证未达标，故只展示计划、不执行多文件写入。本次不改变 v2 视觉基线。

工具返回可能进入小艺模型上下文，依平台协议核对；仅返回任务需要的内容，日志不记录笔记正文、标题、路径、搜索词、令牌或前像。平台探针仅使用合成数据、隔离库与专用测试对象，不接触真实库，不自动发布。
