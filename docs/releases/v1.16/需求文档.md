## 1. 定位与前提

承接 [需求池](../../requirements_backlog.md) 中的小艺知识库级上下文、检索和 Wiki 工具增量：让小艺在用户指定的库中查找、阅读、关联内容，并在有安全门槛时协助整理。按 [LLM Wiki 模式](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)拟采用不可变原始来源、互链 Markdown 知识页、`_wiki.md` 规则、`index.md` 内容目录与 `log.md` 时间记录；具体端侧边界见[工作流与提示词草案](小艺_Wiki_工作流与提示词.md)。不声称平台已具备循环、批量事务、可验证用户确认或任意参数能力。

小艺可能把工具返回内容交给平台模型处理；具体传输、留存和用途按平台协议核对，并与 [隐私政策上架核对](../上架准备清单.md) 联动。不能把本方案写成纯本地或声称不出设备。

## 3. 数据保护和兼容

- 笔记仅经 `VaultRegistry.accessFor(vaultId)` 与现有统一访问层处理，按库隔离；沙箱单文件写入沿用 `AtomicFile`，外部库按 [v1.5](../v1.5/需求文档.md) 访问层与其已验证边界处理。旧工具契约及用户既有小艺体验不能静默破坏。
- 本地只读工具返回体按所有字符串字段合计最多 6000 个 UTF-16 码元裁剪，并通过 `truncated` / `hasMore` / 游标明确表达不完整；不可裁剪的元信息本身超限时拒绝返回。该值是 App 本地安全预算，不是小艺平台限制实测值。
- `_wiki.md` 固定对小艺写保护。其 `readonly` frontmatter 当前只接受 JSON 兼容的 YAML 内联字符串数组（如 `readonly: ["raw/", "资料/"]`）；配置重复、格式错误或路径不安全时拒绝小艺正向写入。正文是用户资料，不作为扩大执行器权限或执行危险动作的授权；不解析或执行正文指令。
- 批次账与前像属于 App 私有数据，不进入库内容分享；账本持久化、清理、恢复和与前台编辑 / 其他进程的并发控制须逐项证明。固定数值、日志字段仍为候选；共享搜索索引持久化已于 2026-11-07 分配 [v1.40](../v1.40/需求文档.md)，本版复用其后续实现，不另建小艺索引。
- 不新增权限、自动启动平台工作流、发布 Agent 或修改在线政策。本轮仅按用户要求建立三项只读工具草稿；将草稿升级到已上架插件会扩大 Agent 对笔记路径、搜索片段及双链上下文的读取能力，须在升级动作前取得用户确认。
