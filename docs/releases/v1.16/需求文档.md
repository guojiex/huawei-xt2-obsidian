## 1. 定位与前提

承接 [需求池](../../requirements_backlog.md) 中的小艺知识库级上下文、检索和 Wiki 工具增量：让小艺在用户指定的库中分步查找、阅读、关联内容，并在用户许可的范围内协助整理。候选详细方案见 [设计说明](设计说明.md)，原包详细材料留存为待审参考；不声称平台已具备循环、批量事务、用户确认或任意参数能力。

小艺可能把工具返回内容交给平台模型处理；具体传输、留存和用途按平台协议核对，并与 [隐私政策上架核对](../上架准备清单.md) 联动。不能把本方案写成纯本地或声称不出设备。

## 2. 阶段与验收

| 16.1 查询与导航 | 评估名称 / 全文搜索、目录浏览、分段读取与链接关系，沿用当前库边界及 v1.1 / v1.2 的实际语义；分页、输出截断与旧工具兼容行为均需定义并验证。先形成只读闭环。 |
| 16.2 修改计划与保护 | **批量修改多篇前必须向用户展示具体计划并获得确认**：明确目标库、目标文件与拟执行操作；发生目标或内容实质变化时重新确认。平台无法提供可验证确认时，不执行批量写入，可继续只读查询；角色提示词不能替代确认。 |

| 16.4 Wiki 工作流 | 在平台实际支持且用户授权的条件下，评估先读规则 / 索引、生成计划、确认、逐项执行与汇报；若无法保证顺序、确认或安全恢复，不用提示词假装具备该能力。模板由用户主动选择，绝不覆盖已有同名文件。 |

完成判定：以上按最终确认的范围分别通过契约测试、构建、适用模拟器、用户手动设备及真实平台闭环验证；每项独立记录，不以候选包的描述或模拟器代替 XT2 / 平台证据。移动笔记、新建库、跨库搜索、平台自动发布与语义检索均不在本版已承诺范围。

## 3. 数据保护和兼容

- 笔记仅经 `VaultRegistry.accessFor(vaultId)` 与现有统一访问层处理，按库隔离；沙箱单文件写入沿用 `AtomicFile`，外部库按 [v1.5](../v1.5/需求文档.md) 访问层与其已验证边界处理。旧工具契约及用户既有小艺体验不能静默破坏。
- 本地只读工具返回体按所有字符串字段合计最多 6000 个 UTF-16 码元裁剪，并通过 `truncated` / `hasMore` / 游标明确表达不完整；不可裁剪的元信息本身超限时拒绝返回。该值是 App 本地安全预算，不是小艺平台限制实测值。
- `_wiki.md` 固定对小艺写保护。其 `readonly` frontmatter 当前只接受 JSON 兼容的 YAML 内联字符串数组（如 `readonly: ["raw/", "资料/"]`）；配置重复、格式错误或路径不安全时拒绝小艺正向写入。正文是用户资料，不作为扩大执行器权限或执行危险动作的授权；不解析或执行正文指令。
- 批次账与前像属于 App 私有数据，不进入库内容分享；账本持久化、清理、恢复和与前台编辑 / 其他进程的并发控制须逐项证明。固定数值、日志字段和索引是否持久化均为候选，需评估并确认。
- 不新增权限、自动启动平台工作流、创建工具、绑定 / 发布 Agent 或修改在线政策；这些动作需要各自的授权与平台核对。

## 4. 待决定与不做

待设计评审：逐库访问范围、批次上限和前像保留方式、索引持久化、是否支持 `MoveNote`、计划确认能力及无循环节点时的安全降级。`QueryNotes` 保留原查询语义并增加预算截断标记；规则解析范围见 §3。只读搜索可独立推进，不能因此默认开放批量写入。用户已决定批量修改计划须确认，不作为待选项。

不做 App 内自建聊天页、不接入新的自有模型 / MCP 云服务、不为此新增整库删除或 Git 操作；不重开此前已确认完成的小艺验收。
