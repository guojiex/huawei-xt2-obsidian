# v1.69 需求文档 —— Git 导入中途可取消

> 状态：2026-11-15 用户提出实现。解锁 [v1.68 68.2](../v1.68/需求文档.md) 中「clone 发起后必须跑到终态」的忙碌锁定。

## 1. 版本定位

为 `ImportVaultDialog` 的 Git 导入补上中途取消能力：clone 进行中「取消」按钮转为「取消导入」并可点击，触发 native 取消机制中止下载。这是 [需求池 §C「Git 导入中途可取消」](../../requirements_backlog.md#c-同步与数据) 的直接落地，解锁 v1.68 68.2 因 `libgit2_napi.so` 无取消 API 而刻意设计的全锁定。

## 2. 完成判定

clone 进行中「取消导入」可点击并实际中止下载；中止后 `__importing` 目录清理干净、不登记、不切库，弹窗回显「已取消导入」且可重试；取消不破坏下一次导入（含取消标志复位）。本地目录 / ZIP 导入、Git 同步其他流程、导入成功路径行为不变。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 69.1 | native 取消机制 | `git2_napi` 导出 `cancelClone`；调用后置位全局取消标志，`transfer_progress` / 认证回调检查标志并以 `GIT_EUSER` 中止 libgit2；clone Promise 以含 `clone cancelled by user` 的错误 reject；每次新 clone 排队前复位标志，陈旧取消不影响后续 clone |
| 69.2 | 取消导入交互 | clone 进行中 footer「取消」转为「取消导入」且可点；点击后按钮禁用、clone 中止；其余忙碌锁定（来源切换、字段、关闭、遮罩、Esc、系统返回）在 clone 阶段保持锁定直到中止生效 |
| 69.3 | 取消后状态 | 取消结果按失败路径复用既有清理：`__importing` 清理、无登记、不切库、恢复标记处理与既有失败一致；弹窗显示「已取消导入」，表单输入保留，重试可用 |
| 69.4 | 边界与不变量 | clone 已进入校验 / 登记阶段后点「取消导入」不打断已完成的克隆（按失败不处理，罕见）；取消错误文案不含令牌；本地目录 / ZIP 导入与 Git 同步弹窗行为不变 |

## 4. 明确不做

- 不改远端认证协议、Git 凭据存储格式、发布 / 登记 / 切库流程（沿用 v0.3 与 v1.68）。
- fetch / push（`gitAction`）不接入取消机制，后续版本单独排期。
- 不新增权限、不新增取消确认弹窗、不做进度百分比估算。
- 不以源码级证据替代 API24 / XT2 或真实 provider 验收。

## 5. 技术约束与依赖

- 取消标志跨线程读写：JS 线程置位、libgit2 工作线程检查，用原子内建操作（clang `__atomic`），不复用 `g_clone_mutex`（cancel 从 JS 线程调用时 clone 持锁会死锁）。
- `GIT_EUSER`(-7) 为 libgit2 v1.9.7 既有错误码，从 `transfer_progress` / credentials 回调返回非 0 即中止当前操作。
- 取消检测在 ArkTS 侧按错误 detail 包含 `clone cancelled by user` 判定，`GitImportOutcome.status` 沿用 string 类型加 `'cancelled'` 值。
- 颜色 / 圆角 / 间距 / 字号只引用现有 v2 token。

## 6. 验收记录

2026-11-15 实现（源码级 + Node 测试验收；XT2 真机验收待用户侧进行）：

- **69.1 native 取消机制**：`libgit2_napi.c` 落地 `g_clone_cancel_flag`（`__atomic` SEQ_CST，不依赖 `g_clone_mutex`）+ `request_clone_cancel` / `clear_clone_cancel` / `clone_cancel_requested`；`report_transfer_progress` 与 `acquire_credentials` 检查标志、置 `cancel_aborted` 并返回 `GIT_EUSER`(-7)；`execute_clone` 持锁后早退检查，`git_clone` 失败后按 `cancel_aborted || clone_cancel_requested()` 归因为 `mark_clone_cancelled(work, -17)`（detail `clone cancelled by user`）；`clone_async` 排队前 `clear_clone_cancel()`；napi 导出 `cancelClone`。双架构（arm64-v8a / x86_64）native 构建通过。
- **69.2 取消导入交互**：`ImportVaultDialog` 加 `gitCancelling` 状态与 `cancelGitImport()`（仅 working + git 源 + 未在取消中时置位一次）；footer 取消按钮经 `UIUtils.makeBinding` 变为绑定式：clone 进行中 label「取消导入」、enabled，点击走 `Index.cancelGitImportClone()` → `GitNativeService.cancelClone()`；其余忙碌锁定不变。`importGit()` 的 `finally` 复位 `gitCancelling`。
- **69.3 取消后状态**：`GitImportService` catch 中按 `detail.includes('clone cancelled by user')` 判定，hilog `clone-cancel`，走既有 cleanup 后返回 `status: 'cancelled'` outcome；弹窗回显「已取消导入」、`retryAvailable`、`focusGitFailure('retry')`、不关弹窗、表单输入保留。
- **69.4 边界与不变量**：取消生效窗口为下载 / 认证阶段；校验 / 登记阶段点取消不打断已完成克隆。取消文案不含令牌（detail 为固定字符串）。
- **测试**：重写 `tools/tests/test_import_vault_dialog_design.mjs`（旧文件 v1.68 起模块级加载失败，stale），新增 69.1–69.4 取消用例与端到端 source wiring 断言，27/27 通过；全量 Node 测试中 11 个失败经 `git stash` 基线对比确认为 HEAD 预先存在，与本次改动无关。
- **构建**：`arkts_check` 仅 `SettingsView.ets` 的 `BuildProfile` 已知误报（hvigor 生成声明）；`devecocli build` BUILD SUCCESSFUL（entry CMake 重编 `libgit2_napi.c`，HAP 吃到 C 源改动）。

遗留：XT2 真机 + 真实 provider（GitHub/Gitee）的取消实测（大仓库 clone 中点取消，确认中止、`__importing` 清理与重试）未做，待用户验收。
