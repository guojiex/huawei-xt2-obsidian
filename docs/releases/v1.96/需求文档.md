# v1.96 需求文档 —— 分享长图入口按内容预估隐藏

> 状态：开发中
> 对应里程碑：无（独立优化，来源 [需求池 §分享](../../requirements_backlog.md)「分享长图入口按内容预估隐藏」）

## 1. 版本定位

打开分享面板时按当前宽度偏好预估笔记渲染高度，超过 [v1.9](../历史版本归档.md#v19-需求文档) 长图预算的最小宽度拒绝线（96 MiB / 640px，等价高宽比 > 约 61.44:1）就不在格式列表展示「长图」行——超长笔记不再「点了才知道生成不了」。[v1.90](../历史版本归档.md#v190-需求文档) 只把生成失败时的事后报错文案补全，本版把拦截前移到入口。

用户 2026-11-20 提出并拍板 **B 方案**：按内容估算超限即隐藏入口，接受误伤风险（估算偏保守可能藏掉实际能用的入口）；A 方案（维持现状靠报错引导）与 C 方案（打开面板时预排版探测真实高度）被否决——C 与 v1.94 分享预览性能优化方向相反。

2026-11-25 追加 **96.4**：用户指出分享列表「文件」行显示合并标签「Markdown / ZIP」令人困惑（「是 ZIP 才显示 ZIP」）。原型 v2 本就按快照动态显示「ZIP 压缩包 / Markdown 文件」（`shareFileLabel`，`renderShareOptions`），原生 v1.25 迁移分享面板时落成了合并标签——本条消除该原型与原生漂移，生成逻辑零改动。

## 2. 完成判定

v1.90 同类超长笔记（约 4 万 CJK 字）在手机宽度（360vp）打开分享面板时格式列表**没有**「长图」行，其余格式不受影响；同一篇在宽版宽度（720vp）下「长图」行**保留**（预估未超限）；正常长度笔记「长图」行始终保留；估算读取失败时「长图」行保留（fail-open），由生成阶段沿用 v1.90 报错兜底。96.4：引用本地图片的笔记「文件」行显示「ZIP 压缩包 / 保留目录关系，包含引用的本地图片」，无图片引用的笔记显示「Markdown 文件 / 保留 Markdown 源码，方便继续编辑」，合并标签「Markdown / ZIP」不再出现（正文读取失败时除外，fail-open）；实际生成格式与预判一致（v0.8 8.3 口径不变）。

## 4. 明确不做

- **不做预排版探测**（C 方案）：不打开面板渲染笔记量真实高度——与 v1.94 分享预览性能优化方向相反，用户已否决。
- **不改长图生成本身**：v1.9 的 96 MiB / 640px 预算、`longImageGeometry` 缩放逻辑与 v1.90 报错文案全部冻结；估算只在入口层新增判断。
- **不隐藏其他格式**：PDF（syscap 条件不变）、文本、Git 远端链接零改动；「文件」行 96.4 起按预判显示具体格式，**生成逻辑**零改动（v0.8 8.3 口径冻结）。
- **估算不追求精确**：图片渲染高度、表格单元格换行、Mermaid、双链展开不计入。误伤方向（估算超限而实际可用）按拍板接受；漏判方向（图片撑高超限但入口仍展示）由 v1.90 生成时报错兜底，不算回归。
- **不改宽度偏好逻辑**（v1.25 / S-01）：估算只读当前偏好，不因估算结果建议切换宽度。

## 5. 技术约束与依赖

- 拒绝线来源：`NoteImageShareService.longImageGeometry`（`entry/src/main/ets/model/NoteImageShareService.ets`，常量 `MAX_PIXEL_MAP_BYTES = 96×1024×1024`、`MIN_IMAGE_WIDTH = 640`）。拒绝条件缩放后宽 < 640px，等价 `H_px/W_px > 96MiB/(4×640²) ≈ 61.44`；dpr 在高宽比两侧同乘抵消，vp 比即 px 比。
- 排版度量真源：`entry/src/main/resources/rawfile/mdpreview/index.html`——`--body:16px` × `--leading:1.85`（正文行 29.6vp）、`--small:14px`（代码行 25.9vp，pre 不换行）、`#content` padding `24px 40px 64px`（水平共 80vp）；块级规则：`p` margin `0 0 20px`、`h1` `32px×1.35 / margin 12 0 16`、`h2` `20px×1.35 / margin 32 0 12`、`h3~h6` `16px×1.35 / margin 20 0 8`、`ul/ol` `margin 0 0 20 / padding-left 24`、`li` `margin-bottom 8`、`pre` `padding 16 / margin 0 0 20`、`blockquote` `margin 24 0 / padding 16 20`、`table` `margin 0 0 20` + 行高 `caption 12×1.85 + td padding 16 + border 1`、`hr` `margin 32 0`、`.share-watermark` `margin-top 32 + padding-top 12 + 1px + caption 行`。相邻块垂直 margin 按 CSS 折叠取 max。改预览排版须同步估算常量。
- 正文读取复用 `noteMarkdownForShare`（v1.53 53.6：编辑器桥就绪走桥，未就绪读库文件）；双链展开（`WikiLinkParser.renderForPreview`）只增不减文本，原始 Markdown 估算仍是下界。
- 宽度偏好来源：`ShareImagePreferenceStore`（`shareCaptureWidthId`，'phone'=360vp / 'wide'=720vp / 'pane'=当前栏宽）。
- 文件行预判来源（96.4）：`NoteShareService.hasLocalImageRefs`（`scanMarkdownImages` 纯语法扫描 + `isRemoteImage` 过滤，零 IO、复用 96.2 正文快照）；文案真源 = 原型 v2 `renderShareOptions` 的 `shareFileLabel` / `shareFileHint`。
- 隐藏仅当估算已超限（漏判由 v1.90 兜底，误伤按拍板可接受）；读取失败 fail-open。
