# v1.96 需求文档 —— 分享长图入口按内容预估隐藏

> 状态：开发中
> 对应里程碑：无（独立优化，来源 [需求池 §分享](../../requirements_backlog.md)「分享长图入口按内容预估隐藏」）

## 1. 版本定位

打开分享面板时按当前宽度偏好预估笔记渲染高度，超过 [v1.9](../历史版本归档.md#v19-需求文档) 长图预算的最小宽度拒绝线（96 MiB / 640px，等价高宽比 > 约 61.44:1）就不在格式列表展示「长图」行——超长笔记不再「点了才知道生成不了」。[v1.90](../历史版本归档.md#v190-需求文档) 只把生成失败时的事后报错文案补全，本版把拦截前移到入口。

用户 2026-11-20 提出并拍板 **B 方案**：按内容估算超限即隐藏入口，接受误伤风险（估算偏保守可能藏掉实际能用的入口）；A 方案（维持现状靠报错引导）与 C 方案（打开面板时预排版探测真实高度）被否决——C 与 v1.94 分享预览性能优化方向相反。

## 2. 完成判定

v1.90 同类超长笔记（约 4 万 CJK 字）在手机宽度（360vp）打开分享面板时格式列表**没有**「长图」行，其余格式不受影响；同一篇在宽版宽度（720vp）下「长图」行**保留**（预估未超限）；正常长度笔记「长图」行始终保留；估算读取失败时「长图」行保留（fail-open），由生成阶段沿用 v1.90 报错兜底。

## 4. 明确不做

- **不做预排版探测**（C 方案）：不打开面板渲染笔记量真实高度——与 v1.94 分享预览性能优化方向相反，用户已否决。
- **不改长图生成本身**：v1.9 的 96 MiB / 640px 预算、`longImageGeometry` 缩放逻辑与 v1.90 报错文案全部冻结；估算只在入口层新增判断。
- **不隐藏其他格式**：PDF（syscap 条件不变）、Markdown / ZIP、文本、Git 远端链接零改动。
- **估算不追求精确**：图片渲染高度、表格单元格换行、Mermaid、块间距、标题加高不计入（下界模型）。误伤方向（估算超限而实际可用）按拍板接受；漏判方向（图片撑高超限但入口仍展示）由 v1.90 生成时报错兜底，不算回归。
- **不改宽度偏好逻辑**（v1.25 / S-01）：估算只读当前偏好，不因估算结果建议切换宽度。

## 5. 技术约束与依赖

- 拒绝线来源：`NoteImageShareService.longImageGeometry`（`entry/src/main/ets/model/NoteImageShareService.ets`，常量 `MAX_PIXEL_MAP_BYTES = 96×1024×1024`、`MIN_IMAGE_WIDTH = 640`）。拒绝条件缩放后宽 < 640px，等价 `H_px/W_px > 96MiB/(4×640²) ≈ 61.44`；dpr 在高宽比两侧同乘抵消，vp 比即 px 比。
- 排版度量真源：`entry/src/main/resources/rawfile/mdpreview/index.html`——`--body:16px` × `--leading:1.85`（正文行 29.6vp）、`--small:14px`（代码行 25.9vp，pre 不换行）、`#content` padding `24px 40px 64px`（水平共 80vp）。改预览排版须同步估算常量。
- 正文读取复用 `noteMarkdownForShare`（v1.53 53.6：编辑器桥就绪走桥，未就绪读库文件）；双链展开（`WikiLinkParser.renderForPreview`）只增不减文本，原始 Markdown 估算仍是下界。
- 宽度偏好来源：`ShareImagePreferenceStore`（`shareCaptureWidthId`，'phone'=360vp / 'wide'=720vp / 'pane'=当前栏宽）。
- 隐藏仅当下界已超限（宁漏判不误伤为第一目标，误伤按拍板可接受为第二目标）；读取失败 fail-open。
