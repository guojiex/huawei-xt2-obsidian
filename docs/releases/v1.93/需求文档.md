# v1.93 需求文档 —— PDF 导出捕获页宽脱离窗口约束（任意形态固定 700vp 大页）

> 状态：**立项**（2026-11-20）。需求来源：需求池 AG-01（2026-11-20 登记，用户同日拍板「立项」）。
> 用户复测反馈「预览的一页很短」= 每页正文内容少；`pdfgeo` 打点（优化文档 §3.6）证明分页几何
> 本身正常（63/63 页 `fillPct=100`、`aspectMilli=706`），根因是 `updatePdfPageSize` 的页宽
> 自适应——2026-11-11 修复「分页高度不足」时约定**捕获层必须待在窗口布局内**，XT2 窄窗
> 380vp → 页宽 380 / 页高 538，每页容量小、页数多（63 页）。
> 归属分享域；本版**只改 PDF 捕获页的尺寸决策与捕获层挂载形态**，长图、等待、scale、分页
> 算法、合成与预览弹窗零改动。

## 1. 版本定位

- 现状（`ShareFlowPanel.ets` `updatePdfPageSize`，`:791`）：
  `pdfPageWidthVp = Math.min(700, 窗口宽, 窗口高 × A4宽/高)`，页高取整。
  窄窗（380vp）→ 页 380×538vp；展开三折叠（宽窗）→ 页宽自动升到 700vp。
- 目标：**任意窗口形态页宽固定 700vp**（A4 竖版 700×990.59vp，页高 `Math.round` 取整 991），
  每页容量约为窄窗的 3.4 倍面积，页数显著下降，窄窗形态不再「每页只装几行字」。
- **硬前提（2026-11-11 旧病不可复发）**：当初自适应的根因是窗口高不足页高（模拟器 776vp、
  XT2 折叠 / 展开横屏均 < 990.59vp）时，捕获层超出布局边界，`#content` 实际视口被压矮，
  分页要求 `scrollHeight ≥ 末页顶 + 页高` 永远补不齐（PDF 分页高度不足）。本版必须先证明
  **脱离窗口约束后 `#content` 视口不再被压矮**，证明不出来就整版回需求池，不硬上。

## 2. 完成判定

真机 XT2 窄窗形态（保持当前窄窗，不展开三折叠），装本版 HAP 导出同一篇 63 页笔记（页宽
380vp 的既有基线）：

1. **页宽生效**：`pdfgeo start` 行 `pageVp=991`（不再 538），逐页 `w=2100 h≈2973`（700vp ×
   dpr3 × scale0.5），`aspectMilli≈707`、`fillPct=100` 保持；
2. **分页完整**：页数显著下降（约 63 ÷ 3.4 ≈ 19 页量级，以实测为准），末页内容到笔记结尾
   不缺失、页间不重复；「分页高度不足」旧病（提前截断 / `scrollHeight` 补不齐）不出现；
3. **性能不失控**：`snapMs` / `tailMs` 因像素 ×3.4 会上升，记录实测值并与 v1.92（37/21ms
   量级）对比；总时长明显劣化时回本文件 §5 决策，不默认回退。

## 3. 需求清单

### 93.1 spike：脱离窗口约束的视口验证（先行，出结论才继续）

- 用最小改动验证固定 700×990.59vp 的 `PreviewWebView` 在窄窗下 `#content` 视口
  （`clientHeight`）真实等于页高、不被压矮。候选方案：
  - **a. 捕获层 Stack 不裁剪 + 子组件固定尺寸超界渲染**：确认 ArkWeb 视口跟随组件自身尺寸
    而非可见裁剪区（`clip(false)` / 超界渲染）；
  - **b. overlay / OverlayManager 或独立挂载点**：彻底脱离面板 `Stack(100%×100%)` 布局。
- spike 结论（选定方案 + `clientHeight` 实测值）记录到本文件 §6 与 `api_notes.md`；
  两方案都失败 → 整版回需求池（AG-01 恢复「未分配」），本文件标注终止。

### 93.2 页宽决策改固定值

- `updatePdfPageSize` 改为固定 `pdfPageWidthVp=700`、`pdfPageHeightVp=Math.round(700 ×
  A4_HEIGHT_PT / A4_WIDTH_PT)=991`；方法与字段注释重写（2026-11-11 的「窗口自适应」叙述
  更新为「脱离窗口约束」的新依据，引用 spike 结论），不留旧约束的过时注释。

### 93.3 捕获层挂载形态

- `build()` 捕获层（`Stack` + `PreviewWebView` 定尺寸）按 spike 选定方案改造；

  PDF 模式分支之外的表达式不动；
- 确认「组件截图只截目标自身内容，遮住它的兄弟节点不会进入快照」的既有结论
  （`api_notes.md`）在选定挂载形态下仍成立。

### 93.4 防线测试

  （如 `clip`、overlay 关键字）；既有 38 条零回退。

## 4. 明确不做

- **不动长图路径**：用户可选宽度、96 MiB 预算、`MAX_PAGES`、scale 固定 1.0 全保持。
- **不动 `waitMs`**：64ms 死等是 XT2 合成表面的必要等待，P2（`f8a56c5` 回退）已实测净亏。
  ⛔ 不再提议删或缩短。
- **不动 `PDF_SNAPSHOT_SCALE=0.5`**：P6 已验收（15.5s→10.0s），本版沿用。
- **不动分页算法**（按段落贪心，`web/mdpreview/src/pdfPagination.mjs`）、不动 `quality: 92`、
  不动 `SharePdfPreviewDialog` 预览形态（A4 白纸衬底顶对齐）。
- **不做页宽用户设置项**：AG-01 只要求任意形态固定 700vp 上限，不加偏好存储 / UI。
- **不改 Web 侧 rawfile**：分页在 Web 内按 `pageHeightVp` 动态计算，无需重建 mdpreview。
- 零新增权限、零埋点零日志零上报（硬约束 16）；诊断打点只记数字不记笔记内容。

## 5. 技术约束与风险

- **主风险**：ArkWeb 视口压缩机制无官方明文（2026-11-11 是实测结论，非文档），spike 是
  唯一证据来源；失败即回池，不做无依据的猜测性实现。
- **快照纯度风险**：捕获层超界 / overlay 渲染后，遮挡关系改变可能让背景进入快照；
  93.3 的既有结论复核是必做项。
- **性能回退风险**：单页像素 ×3.4，`snapMs`+`tailMs` 按比例上升；scale=0.5 下预计总时长
  仍与 v1.92 相当量级（页数 ×1/3.4 对冲），以 §2.3 实测为准。
- **打点清理**：`ShareDbg` / `pdfgeo` 打点保留至整条分享优化链路收尾统一删
  （优化文档 §6），本版验收数据也依赖它们。
- `SHARE_PERF_TRACE` 诊断期为 `true`，随收尾约定删除。
