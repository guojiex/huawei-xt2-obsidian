# v1.55 需求文档 —— 清空回收站

> 状态：⚪ 规划中；v2 原型设计稿已完成（2026-11-11），原生未实现，未验收。
> 对应里程碑：独立优化。领取顺序以 [实施总清单](../实施总清单.md) 为准；依赖 [v1.47 回收站条目永久删除](../v1.47/需求文档.md)（复用其确认弹窗与 `TrashService.purge`）。
> 需求来源：[需求池 B 节「清空回收站」](../../requirements_backlog.md)（2026-11-11 用户提出）。v1.47 立项时登记「不做清空全部 / 批量」，本版按用户新决定单独承接，v1.47 范围不变。

## 1. 版本定位

v1.47 补上了单条永久删除，但回收站积了十几条时只能一条条点、一条条确认。本版在回收站底部加「清空回收站」，一次永久删除**当前知识库**回收站里的全部笔记，确认弹窗列出将被删除的内容。

## 2. 完成判定

回收站展开时底部可见「清空回收站（N）」；点按后弹确认，确认后当前库回收站全部条目被永久删除、回收站区收起隐藏、toast 告知数量；取消或 Esc 不删任何内容；其他知识库与未删除笔记不受影响。原型、原生与设备分别验收。

## 4. 明确不做

- 不做多选批量删除、自动过期清理（如 30 天自动清空）、回收站容量提示。
- 不做「清空所有知识库的回收站」；只作用于当前库（与回收站按库隔离一致）。
- 不做清空后的撤销 / 二次恢复：确认弹窗是唯一保护，与 v1.47 单条永久删除口径一致。
- 不改「移入回收站」与「恢复」的现有行为；不改回收站弹窗向统一外壳的迁移归属（[v1.32 32.1](../v1.32/需求文档.md)）。
- 清空操作不进埋点；被删笔记的标题 / 路径不进 hilog 与埋点（硬约束 16）。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）；文件删除只走 v1.47 已有的 `TrashService.purge` 路径。
- 回收站数据链：沙箱 `trash/<vaultKey>` 按库隔离；`purgeAll` 与 `purge` 同走 `VaultAccess` 解析层，不按 `rootKind` 分叉（硬约束 14）。
- 图标与状态切换注意 [api_notes L-7 / Z2](../../harmonyos/api_notes.md)：按钮禁用 / 计数随状态刷新时不要用全局 @Builder 三元实参。
- 视觉 token 以 v2 原型 `:root` / `[data-theme="dark"]` 为准。
