# v1.32 需求文档 —— 视觉一致性收口

> 状态：🟢 32.1–32.13 原生本地实现全部完成（2026-11-06）；全仓 Node 871/871、签名 HAP 构建通过。API26 模拟器与 API24 / XT2 设备验收待用户手动完成，不阻止后续版本领取。详细进度见下方实施记录。
> 对应里程碑：独立优化。领取顺序以 [实施总清单](../实施总清单.md) 为准；32.8–32.12 为第二轮追加。
> 需求来源：[需求池 J 节「视觉一致性收口」](../../requirements_backlog.md#j-视觉与设计系统design-token)（2026-11-04 原型走查后用户确认合为一个版本按顺序修）。

## 1. 版本定位

v1.24 / v1.25 / v1.27 / v1.31 已重做导入库、分享、同步页与单屏更多菜单，但其余弹窗、专业模式格式栏、宽屏栏内菜单等仍是旧样式，放在一起割裂明显。本版只做视觉与交互一致性收口，不增删功能。

## 2. 完成判定

所有工具弹窗共用同一外壳（宽屏居中卡片、单屏底部半模态、圆形关闭、胶囊按钮且主操作突出）；简单 / 专业模式的格式栏都在编辑时停靠栏底；所有「…」菜单为图标行；新建弹窗、窄侧栏、Aa 面板、设置操作行的细节问题消除。原生与设备分别验收。

## 4. 明确不做

- 不增删任何功能或菜单项，不改弹窗内容与校验规则；不改设置页信息结构（v1.13）。
- 不调整图片查看器与 Aa 跟手面板（formatDialog）的外形。
- 不把快切改为全屏页面。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）。
- 单屏半模态沿用块属性面板 / 导入库的同一形态；原生弹窗组件与半模态接口以 API 24 SDK 核实为准。
- 视觉 token 以 v2 原型 `:root` / `[data-theme="dark"]` 为准；图标复用现有资源，缺失的按同一线稿规格补充。
