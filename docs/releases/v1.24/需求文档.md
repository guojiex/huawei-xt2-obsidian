# v1.24 需求文档 —— 导入库弹窗视觉重做

> 状态：⚪ 规划中；v2 原型已按本版重做，并在 headless Chrome 下完成单 / 双 / 三屏、浅 / 深色截图和功能链路核对；原生未实现、未验收。
> 对应里程碑：独立优化（首发界面打磨）。领取顺序以 [实施总清单](../实施总清单.md) 为准，版本号不代表领取顺序。
> 需求来源：[需求池 R-01](../../requirements_backlog.md#r-导入库弹窗视觉重做2026-11-03)（2026-11-03 用户反馈“导入库的 UI 设计太丑”）。
> 设计基线：[导入库弹窗设计](../../prototype/v2/导入库弹窗设计.md) · [v2 原型](../../prototype/v2/index.html)（知识库选择器 / 库管理 →「＋ 导入库」）。
> **范围更新（2026-11-03）**：本版只负责本地目录导入视觉重做；Git 来源切换与恢复入口已单独分配到 [v1.26](../v1.26/需求文档.md)。

## 1. 版本定位

重做 v1.5 已有“导入库”弹窗的视觉层级与状态表达：让用户一眼看懂“选一个目录 → 关联”这一步，并清楚看到选中、失败和可重试状态；单屏改为与块属性面板一致的底部半模态。语义、数据与服务不变。

## 2. 完成判定

在单屏、双屏、三屏及浅 / 深色下，导入弹窗按设计基线呈现四段结构（标题区、目录卡片、关联说明、底部操作）；目录卡片的未选择、已选择、授权失败三态及关联中、取消选择状态都有对应文案和下一步入口；键盘、读屏与触控都能完成选择与关联。原生实现与目标设备行为经独立验收，原型截图不代替原生或设备证据。

## 4. 明确不做

- **不改导入语义与服务**：授权关联、不复制、解除关联、私有数据边界沿用 [v1.5](../v1.5/需求文档.md)；不新增目录扫描、文件数统计、导入前预览或复制导入。
- **Git 来源恢复不属于 v1.24**：Git 分段、表单及恢复后的设计验收归 [v1.26](../v1.26/需求文档.md)；本版只负责本地目录导入视觉与交互。
- **不在弹窗内改库名**：改名仍在库管理中完成，弹窗不增加名称输入框。
- **不改库管理页、知识库选择器的入口位置与文案**（仍为「＋ 导入库」）。
- **不以原型或截图代替原生 / 设备证据**；不在模拟器上制造授权失败或强杀进程，失败态用单测或可控注入验证。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。目录选择与持久授权接口只按 [api_notes T1 / T2](../../harmonyos/api_notes.md#t-组外部目录选择与持久授权2026-10-31v15-前置核实) 已核实结论接入；本版不引入新的系统能力。
- 单屏半模态沿用块属性面板已定形态；ArkUI 半模态的具体接口与参数（如 `bindSheet` / `preferType`）以 API 24 SDK 与 `docs/harmonyos/api_notes.md` 核实为准，查不到就列入报告，**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）。
- 视觉 token 真源为 v2 原型 `:root` / `[data-theme="dark"]`，原生按既有映射（`brand` / `brand_bg` 等）同步；危险色浅底由 `--danger` 与 `--paper` 混合得到，原生若无对应资源需按映射规则新增，并在验收记录说明。
- 原生只改导入弹窗的布局、组件外观与界面接线，继续调用现有目录选择、授权、库注册服务，不修改模型、存储或协议（同 [v2 设计说明 §1](../../prototype/v2/设计说明.md#1-范围与约束)）。
