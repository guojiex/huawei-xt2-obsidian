# v0.3 需求文档 —— 能同步

> **2026-11-01 用户决策**：本版维持 **push-only**，不纳入手机 pull/checkout；远端前进或冲突继续交由 PC 解决。pull/checkout 的整库恢复方案不再是 v0.3 的待验或阻塞项。

> **2026-10-31 路线与进度更新**：优先 Native libgit2 的路线已接入 App 源码：clone、status、stage、commit、fetch、push；现有 Web 实现及历史验证保留。已有库操作仅改 `.git` 元数据与索引，不做工作区 checkout；在建立整库可恢复方案前不接 pull/checkout。API26 模拟器 `Git2Native` Hypium 9/9、真实 AssetStoreKit 合成令牌生命周期 Hypium 1/1；未安装验证生产 App 的完整同步 UI；API24 / XT2 和真实服务商 HTTPS 认证仍待验。开发入口见 [Native 优先实现提示词](实现提示词_Native优先.md)。

> 历史排期：Git 同步曾在外部依赖队列；2026-10-27 的 Native N-API 初版只验证独立模块、不接 App。该状态已由本次接入进度更新。

> **状态**：⚠️ Native 模块已编入主 App 与 `ohosTest` HAP；API26 模拟器 test HAP 验证 9/9。status/stage/commit/fetch/push 已接入同步页源码。按用户决策本版 push-only，pull/checkout 不纳入范围；API24 / XT2、生产 App UI 端到端和服务商 HTTPS 认证未验。具体边界见 §6。
> **对应里程碑**：M3.5 + M4
> **版本定位**：把本地库接到远端 Git 仓库上，并把形态适配彻底收口。

## 1. 版本定位

手机端"随手记必须能回写"是硬需求，所以同步不能留到 v2。
这一版把 v0.1 的库模型升级为「本地库 + Git 库并存」，并让形态切换在任何界面下都不丢东西。

⚠️ **当前代码接入不等于 v0.3 完整验收**。Native clone 和已有库的只读/元数据操作有隔离验证；首页未推送提交角标已落源码并通过源级回归和 unsigned HAP 构建，生产 App 的同步页面运行与角标 UI、API24 / XT2 以及全版本折叠/展开验收仍待完成，具体结果见 §6。

## 2. 完成判定

> 填入仓库地址与令牌后，能把远端仓库拉成 `vaults/<仓库名>` 并与本地库并存；
> 编辑后能 commit 并 push 到 `xt2` 分支；任意界面下折叠/展开都不丢笔记与光标。

## 3. 需求清单

### 3.1 导入 Git 仓库（M3.5）

> **2026-10-31 导入入口设计对齐**：入口统一命名「导入库」，在其中选择「Git 仓库」进入本节导入流程；同一弹窗的「本地目录」关联归 v1.5。入口与设计验收统一见 [v1.5 §3.1](../v1.5/需求文档.md#31-导入入口与设计验收2026-10-31)，视觉与交互以 [v2 设计说明 §3](../../prototype/v2/设计说明.md#3-知识库与文件导航) 为准。本节既有认证、克隆、安全存储及失败清理要求继续有效，原型演示不改变本版实现与验收状态。

**本轮受控写入例外**：新 clone 只落入本次创建的 `vaults/<id>__importing` 未登记目录。该目录不包含既有用户数据，因此其中 Git 元数据、文本、图片和其他二进制文件可通过普通二进制写入保留原字节。当前本机 API 26 SDK 中 `openSync`、`writeSync(ArrayBuffer)`、`closeSync` 的声明标注 `@since 9`，兼容 API 24 的声明依据成立；API 24 / XT2 运行行为仍须单独验收。普通写入没有 `AtomicFile` 回滚保证，失败可能留下半成品，只能清理本次导入目录。clone/checkout、待写队列 flush 和从磁盘重新读取后的 Git 状态校验通过后，才改名并登记。失败或登记持久化失败不得留下可用库；重启时依导入标记清理未完成导入。目录 `renameSync` 不作为已有文件原子覆盖保证。

已有库更新不适用该例外：本地 Markdown 保存继续使用 AtomicFile 字符串路径；Git 后端只可把可无损 UTF-8 往返的文本交给 AtomicFile 字符串写入，不能无损往返的字节在打开目标文件前拒绝。已有库二进制覆盖不在本次实现范围，失败保留旧内容的要求不变。

### 3.4 Native libgit2 N-API 模块（2026-10-27 用户授权；2026-10-31 接入 App）

模块导出 libgit2 版本/能力查询、仓库状态、异步 clone，以及异步 `stage`、`commit`、`fetch`、`push`。clone 仅接受绝对路径下的全新导入目标，不覆盖已有目录；HTTPS 默认使用鸿蒙预设 CA，`caFile` 是特殊环境可选覆盖。主 App 的 `GitNativeService` / `SyncPage` 已接线，保留现有 Web 桥接与打包产物。

已有库 stage 只更新 `.git/index`，commit 写 Git 对象及 `HEAD`，fetch 更新对象库和远端跟踪引用，push 只写远端 `xt2`；这些操作不调用 checkout、不写入或删除笔记工作区。libgit2 checkout 不提供多文件整体回滚保证，因此当前不提供 pull/checkout。API26 test HAP 验证不代表 API24 / XT2 真机运行或生产 App UI 验收。
