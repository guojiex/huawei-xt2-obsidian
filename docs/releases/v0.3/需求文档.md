# v0.3 需求文档 —— 能同步

> **状态**：🟡 开发中（clone 模拟器调试未通过，同步闭环未完成，见 §3.4 与 §6）
> **对应里程碑**：M3.5 + M4
> **版本定位**：把本地库接到远端 Git 仓库上，并把形态适配彻底收口。

## 1. 版本定位

手机端"随手记必须能回写"是硬需求，所以同步不能留到 v2。
这一版把 v0.1 的库模型升级为「本地库 + Git 库并存」，并让形态切换在任何界面下都不丢东西。

⚠️ **本版本当前先卡在模拟器 clone**；已有 Node、构建与 API 26 模拟器调试记录，但没有完整 clone 成功证据。XT2 全流程验收仍待完成，具体结果见 §6。

## 2. 完成判定

> 填入仓库地址与令牌后，能把远端仓库拉成 `vaults/<仓库名>` 并与本地库并存；
> 编辑后能 commit 并 push 到 `xt2` 分支；任意界面下折叠/展开都不丢笔记与光标。

→ 本版本的实际工作量 = **clone 与多库集成、令牌迁移、push 实现 + 全链路真机验证**，而不是从零写同步。

## 5. 技术约束与依赖

- 同步**只用**「JS 自定义 http client 转发到 `@ohos.net.http`」；`onInterceptRequest` 拦截 ❌ 已否决 —— `api_notes.md` **B4**
- packfile / 大文本走 **WebMessagePort + ArrayBuffer + 分块（4MB）**；`runJavaScript` 只走控制指令 —— `api_notes.md` **B7**
- git 容器**常驻**：`Stack` + `visibility(Hidden)`，不用 `NodeContainer` —— `api_notes.md` **B2**
- git 桥接**先主线程** —— `api_notes.md` **B3**
- 前台 clone/push 无需额外权限 —— `api_notes.md` **E3**
- 改完 `web/gitbridge/` **必须重新打包并把产物入库** —— `AGENTS.md` 已知坑
