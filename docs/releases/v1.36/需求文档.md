## 1. 版本定位

v0.8 / v1.37 能把知识库导出为 ZIP，但没有对应的导入，换机、重装或误重置后无法用这份备份恢复。本版补上「从 ZIP 新建知识库」，形成导出 → 导入闭环。

## 2. 完成判定

在导入库弹窗选择一个 ZIP，预览其中的笔记与图片数量后，新建一个知识库并写入内容；任何失败都不留下半成品库，不影响已有库。原生与设备分别验收。

## 4. 明确不做

- 不恢复应用设置、草稿、回收站、最近打开、同步配置或访问令牌（导出包本就不含）。
- 不做合并导入、按文件冲突选择、增量恢复或「全部知识库一次恢复」。
- 不导入为外部目录库或 Git 库；不支持 ZIP 以外的压缩格式与加密 ZIP。
- 不做自动备份、定时备份或云端备份。

## 5. 技术约束与依赖

**前置核实（走 `docs/harmonyos/` 提问流程，未核实前不落码 36.1、36.5、36.6）：**

1. API 24 可用的 ZIP 解压能力：能否逐条目读取名称与大小、逐条目解压到指定沙箱路径，以及在解压前检测路径越级与符号链接。
2. 系统文件选择器按扩展名 / 类型限定 `.zip` 的方式，以及选中文件的读取授权范围与时长。
3. 解压过程能否取消；空间不足时的错误形态。

**核实结论（2026-11-06，本机 SDK 声明核对，见 [api_notes Y1–Y4](../harmonyos/api_notes.md#y-组zip-导入解压2026-11-06v136-前置核实本机-sdk-声明核对) 与 [qa 存档](../harmonyos/qa/2026-11-06_ZIP导入解压能力_API24.md)）**：

1. ✅ 成立：`zlib.createZipSync` + `Zip.inflateInit2`（windowBits [-15,-1] Raw Deflate）+ `Zip.inflate` + `ZStream` 均 since 12 ≤ API 24。方案为**自绘解析**——`fs` 读字节 → 解析 EOCD / Central Directory → 解压前校验全部条目（`..` / 绝对路径 / 反斜杠 / 盘符 / 加密位 / symlink 模式位 / ZIP64 / 条目数与总大小上限）→ 逐条目 raw inflate 写入临时库目录。36.5 的「解压前检测」由我方校验满足，§5 末段「若 1 不成立则回炉」**不触发**。
2. ✅ `DocumentSelectOptions.fileSuffixFilters`（since 10）限定 `'描述|.zip'` + `maxSelectNumber: 1`；授权沿用 picker 临时 URI 既有结论（[T 组](../harmonyos/api_notes.md#t-组外部目录选择与持久授权2026-10-31v15-前置核实)），走「复制已授权 fd 到沙箱」链路，零新增权限。
3. ✅ 取消：自绘方案在条目间检查取消标志即可中断；空间不足：`fs` 写类抛 `13900025 No space left on device`，预检用 `statfs.getFreeSizeSync`（since 10）。
4. ⚠️ 未核实边界（实现期补）：`ZStream` 运行时字段更新语义与错误码形态（声明齐全未实测）；真实 Picker `.zip` 过滤视觉与取消行为。

**既有约束：**

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）。
- 文本写入走统一库访问层与 AtomicFile；库登记走 `VaultRegistry`；临时目录与清理规则与 v0.3 新 clone 一致。
- 文件名、路径与笔记内容不进日志或埋点。
