# v1.34 需求文档 —— 错误处理、恢复与可复制诊断

> 状态：⚪ 规划中，高优先级；初步静态盘点已记录，原生改造与验收未开始。
> 来源：[需求池：全应用错误处理与可复制诊断](../../requirements_backlog.md)（2026-11-04 用户提出）。领取顺序见[实施总清单](../实施总清单.md)。

## 1. 目标

错误发生后，用户应能知道哪一步失败、已保存到什么程度、可以如何继续；不能只弹一句“失败”然后把用户困在原地。无法立即修复的错误应提供足够的诊断信息，并能在设置中的诊断信息里查看和复制最近的错误记录。

本版本针对全应用错误处理做完整盘点和分类，优先处理保存与数据安全、笔记切换及恢复，再覆盖库和文件操作、编辑预览、导入 / Git 同步、分享和设置。错误确因未知时明确写“原因未确定”，不编造原因。

## 3. 需求与验收

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| 34.1 | 盘点所有面向用户的失败入口、后台静默失败、桥接超时及异常捕获；建立可追踪清单，记录触发条件、当前反馈、是否有数据风险、恢复方式和处理状态。 | 覆盖第 2 节各范围及其调用链；逐项标注已处理、已有合理处理或未完成及原因，不以搜索到的 toast 数量代替分支审计。 |
| 34.2 | 面向用户的失败反馈说明操作与失败阶段、已完成 / 未完成的部分、可采取的下一步；对未知原因明确说明。提示应可读、足够停留或可重新查看。 | 注入失败时，用户无需猜测是读取、保存、授权还是网络等阶段；取消、失败和实际成功分别表述，提示内容不冒充原因。 |
| 34.3 | 对阻断操作提供合理恢复路径：安全重试、返回 / 保留当前内容、重新授权、重载或其他适用操作；有数据丢失风险时说明后果并由用户选择。 | 保存、切换、草稿和导入失败不静默丢弃或覆盖内容；取消保留当前状态，重试只重做安全且明确的操作。 |
| 34.4 | 在现有“设置与关于 → 通用 → 诊断信息”增加最近错误记录：至少包含时间、操作 / 阶段、可安全展示的错误分类或代码、结果和可采取的下一步；提供用户主动复制，空记录、记录不可用与复制失败有说明。 | 在可控失败下查看和复制得到与界面一致的记录；最近记录有数量 / 大小上限与明确保留策略，重启后的保留行为写明并验证；不自动发送。 |
| 34.5 | 错误记录与复制输出采用安全白名单；不记录或复制笔记标题、文件名、路径、正文、字数、标签、令牌、凭据、远端 URL 等敏感内容，不直接拼接未经筛选的系统异常或网络响应。 | 用含敏感示例的错误和异常测试，验证页面、日志、持久化数据及剪贴板输出均不泄露；需要定位时保留安全的阶段、错误码及构建标识。 |
| 34.6 | 各范围提供可控失败与恢复回归，并核对诊断记录、复制及隐私；复用 v1.15 已有诊断与剪贴板能力，按 API24 核实新增平台接口。 | 至少覆盖保存 / 草稿、笔记切换、预览桥接、授权 / 文件操作、Git 导入与同步、分享、诊断复制 / 失败；分别记录自动测试、构建及设备证据。 |

## 4. 范围与约束

- 本次只定义需求和初步盘点；不因此宣称现有错误处理已修复，也不改变既有验收记录。
- 保留现有 AtomicFile、草稿与目标一致性保护；不能为让用户继续而静默覆盖笔记或丢弃未保存内容。
- 诊断记录是用户主动查看和复制的本地信息，不新增第三方 SDK、自动上传或笔记内容埋点。设备表现待独立验收，不作为开发前置。
- 原始异常可能携带路径、URL、令牌或正文；仅展示和记录经过白名单处理的分类 / 代码，不直接展示任意异常文本。
