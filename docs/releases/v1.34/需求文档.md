# v1.34 需求文档 —— 错误处理、恢复与可复制诊断

> 状态：🟡 开发中，高优先级；34.1 错误分支盘点已完成，原生改造与验收继续进行。
> 来源：[需求池：全应用错误处理与可复制诊断](../../requirements_backlog.md)（2026-11-04 用户提出）。领取顺序见[实施总清单](../实施总清单.md)。

## 1. 目标

错误发生后，用户应能知道哪一步失败、已保存到什么程度、可以如何继续；不能只弹一句“失败”然后把用户困在原地。无法立即修复的错误应提供足够的诊断信息，并能在设置中的诊断信息里查看和复制最近的错误记录。

本版本针对全应用错误处理做完整盘点和分类，优先处理保存与数据安全、笔记切换及恢复，再覆盖库和文件操作、编辑预览、导入 / Git 同步、分享和设置。错误确因未知时明确写“原因未确定”，不编造原因。

## 4. 范围与约束

- 本次只定义需求和初步盘点；不因此宣称现有错误处理已修复，也不改变既有验收记录。
- 保留现有 AtomicFile、草稿与目标一致性保护；不能为让用户继续而静默覆盖笔记或丢弃未保存内容。
- 诊断记录是用户主动查看和复制的本地信息，不新增第三方 SDK、自动上传或笔记内容埋点。设备表现待独立验收，不作为开发前置。
- 原始异常可能携带路径、URL、令牌或正文；仅展示和记录经过白名单处理的分类 / 代码，不直接展示任意异常文本。
