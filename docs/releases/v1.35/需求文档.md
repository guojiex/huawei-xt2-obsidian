# v1.35 需求文档 —— 跨库搜索

> 状态：🟡 原生本地实现完成（2026-11-06），模拟器与 API24 / XT2 设备验收待用户；v2 原型 35.1–35.4 与 35.6 / `searchScope` 演示齐备。
> 对应里程碑：首发后。领取顺序以 [实施总清单](../实施总清单.md) 为准（首发后队列第 1 位）。
> 需求来源：[需求池 B 节「跨库搜索」](../../requirements_backlog.md#b-笔记库级能力共同前提全库索引)（2026-11-04 原型走查登记，2026-11-05 分配）。
> 基础：[v0.4 快速切换与文件名搜索](../v0.4/需求文档.md)、[v1.1 当前库全文搜索](../v1.1/需求文档.md)、[v1.5 外部目录知识库](../v1.5/需求文档.md)。

## 1. 版本定位

快切与搜索目前只覆盖当前库（v0.4 / v1.1 的「切库不串数据」）。有多个库的用户记得笔记名却不记得放在哪个库，只能逐个切库再搜。本版在**不改变默认行为**的前提下，给搜索加一个显式的「全部库」范围。

## 2. 完成判定

搜索面板可在「当前库 / 全部库」之间切换；全部库结果标注所属库，点开时切换到该库并打开笔记；默认仍为当前库，最近打开仍按库隔离；不可读的库被跳过并说明。原生与设备分别验收。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 35.1 | **范围分段。** 快切 / 搜索面板顶部增加「当前库 / 全部库」分段（样式同 v1.25 范围分段）。每次打开面板默认「当前库」，不记忆上次范围。只有一个库时不显示分段。 | 单库用户界面与现状一致；多库用户默认结果与现状一致 |
| 35.2 | **搜索内容。** 「全部库」下文件名搜索覆盖所有已登记库；正文搜索沿用 v1.1 规则，逐库执行并合并结果。排序：当前库结果在前，其余按库在库管理中的顺序。 | 同名笔记在不同库分别列出，不合并 |
| 35.3 | **结果标注。** 「全部库」下每条结果在路径前显示所属库名（`--caption`、`--muted`），当前库标「当前」；按库分组，组标题为库名与命中数。 | 读屏朗读顺序为「库名，笔记名，路径」 |
| 35.4 | **打开即切库。** 点开其他库的结果：先按现有切库流程保存当前笔记、切换到目标库，再打开该笔记；切库失败时停留原库并提示原因，不打开。 | 打开后知识库选择器显示目标库；返回键不回到原库搜索结果 |
| 35.5 | **最近打开隔离不变。** 最近打开仍按库记录；从全部库结果打开的笔记只记入其所属库的最近列表。「全部库」下空查询不显示跨库最近列表。 | 切回原库后其最近列表不出现别的库的笔记 |
| 35.6 | **不可读的库。** 外部目录库授权失效、Git 库导入未完成等不可读的库在「全部库」中跳过，结果底部提示「已跳过 N 个暂不可读的库」，可展开查看库名；不弹授权。 | 不因单个库失败导致整个搜索失败 |
| 35.7 | **原型同步。** v2 原型 `#quickSearchDialog` 实现 35.1–35.4（演示库数据）。35.6 不可读库与复现参数 `searchScope` 暂未演示，原生实现时补原型。 | 保留既有元素 ID；原型不读取设备文件 |

## 4. 明确不做

- 不做跨库双链、跨库反链、跨库标签聚合或跨库移动 / 复制笔记。
- 不建立全局合并索引，不改各库数据隔离与 v1.5 授权模型；不在后台预先扫描所有库。
- 不记住范围偏好，不把「全部库」设为默认。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）。
- 所有读取经统一库访问层按库执行；外部目录库只使用已持久化的授权，失效时跳过（35.6），不触发重新授权。外部目录授权失效时的读取失败路径须在实现前按 `api_notes.md` 核实。
- 大库性能：逐库搜索需可取消（关闭面板或修改查询即取消未完成的库），避免旧查询结果覆盖新查询；性能预算在实现时用本机大库样例测量并记录，不预设数字。
- 笔记内容与查询词不进日志或埋点。
