# v1.77 需求文档 —— Git 同步页视觉重构：默认显示差异 + 卡片分组

> 状态：已实现（2026-11-16）。设计真源：[Git 同步页设计](../../prototype/v2/Git同步页设计.md)（§2 结构图、§2A 逐行差异、§5 组件表）；原型入口 `?ui=2&view=sync`。需求来源：用户 2026-11-16 看到 v1.76 全屏页的 XT2 真机截图后反馈「太丑了」——右栏在选文件前是一大片空白占位，左栏状态 / 文件 / 输入框平铺成一堆灰色条，底部主按钮灰色且没有原因说明。本版只改呈现，不改 Git 语义与 diff 数据链。

## 1. 版本定位

v1.76 把同步从浮窗改成了全屏页，但**全屏不等于好看**：真机上 40% 宽的左栏塞满无分组的灰条，60% 宽的右栏在用户点文件之前只有一条汉堡图标和一句「在左侧点选一个改动文件」，看起来像页面没加载出来；底部「提交并推送」因为提交者信息未填而置灰，用户不知道为什么。

本版把同步页当作一个真正的「代码审查」界面来重做：进入即看到差异、信息按卡片分组、主按钮禁用有解释。v1.75 的 native `getFileDiffs` 数据口径、push-only 与 v1.73 fast-forward pull 安全边界完全复用，不改。

需求池：Git 同步相关条目在 [§C 同步与数据](../../requirements_backlog.md#c-同步与数据)。

## 2. 完成判定

打开 Git 库的同步页 → 右栏**立即显示第一个改动文件的逐行差异**（不需要先点文件），左栏是「推送概览」和「本地改动 N 个文件」两张白卡，文件行选中态有品牌色左边轨，diff 卡头有 M/A/D 徽章与 `+N −M` 统计，行号列有独立底色 → 提交者名称 / 邮箱以带「必填」标签的输入框呈现，未填时主按钮旁写明原因 → 深色模式可读、单屏上下堆叠、返回 / 忙碌保护沿用 v1.76。原有推送 / 拉取 / 分支编辑 / 令牌重试流程全部不变。

## 4. 明确不做

- 不改变 push-only / 仅快进 pull 的安全边界，不做合并 / 冲突解决 UI。
- 不改 native `getFileDiffs`、类型声明、diff 数据口径（HEAD ↔ 工作区未提交改动）。
- 不把同步页改成独立 `@Entry` / router 路由（沿用 Index 内 `topView='gitsync'`）。
- 不自动填写或持久化提交者名称 / 邮箱；不新增权限；笔记正文（路径 / 内容）不进日志与埋点。
- 不改其它弹窗 / 页面的视觉（本版范围仅同步页）。

## 5. 技术约束与依赖

- 颜色 / 圆角 / 间距 / 字号只引用 `app.color.*`、`app.float.*` 或 `Tokens` 常量，不散写数值；原型改样式必须同步 `:root` 与原生资源真源。
- ArkTS 注意：`@Builder` 调用不能链式加修饰符，`CredentialEditor` 需外包一层 `Column` 才能加 padding；`ForEach` 的 key generator 保留 `change.path`；清单 `nestedScroll(SELF_FIRST)` 键盘避让逻辑不动。
- 自动选中在 `loadFileDiffs()` 末尾调用；`diffCache` 是普通 `Map`（不触发 V1 `@State`），仍靠 `diffVersion++` 驱动刷新，自动选中在缓存写完后再跑。
- 原型有两个 `<script>` 块，`restoreUrl` 在前者、`openGitSync` 在后者，任何跨块的直达调用都必须走 `window.__initialViewSync` 这类提前捕获的标记。
- 真机验收（API24 / XT2）由用户执行后回填 §6.2。
