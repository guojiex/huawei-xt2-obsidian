# v1.8 专注模式入口状态修复

状态：原型与原生实现完成；单栏无效入口与专注状态双栏入口保护已复验。2026-11-02 补充简单模式分栏入口，并按单双栏状态互斥显示入口，尚未重新验证；此前定向测试 94/94、全仓 Node 511/511、生成器检查与 unsigned arm64-v8a HAP 构建通过。模拟器、API24 / XT2 验收待做，未发布。与 v1.7 和其他版本需求正交，无功能依赖，可单独实施及验收，不阻塞其他版本。

## 1. 来源与范围

来源：[需求池「专注模式入口状态反馈」](../../requirements_backlog.md)。工作区的专注按钮目前容易被理解为全屏按钮；进入专注后应明确提供退出入口。该功能控制应用内专注布局，不改变系统窗口全屏状态。

## 2. 需求与验收

| 编号 | 要求 |
| --- | --- |
| 18.1 | 双屏、三屏的布局入口互斥：简单模式或专业模式的右侧参考栏未显示时显示分栏入口；专业模式下左右栏均有已打开笔记且右侧参考栏显示时显示专注入口，不再同时显示分栏入口。分栏入口打开 / 关闭右侧参考栏；专注入口临时隐藏导航与参考栏，并在退出时恢复进入前布局。专注状态下始终显示退出入口，即使窗口宽度变化到单屏布局。简单模式点击分栏入口后切换到专业模式并打开右侧参考栏。进入 / 退出分别显示向外展开 / 向内收起图标，并同步“进入专注模式” / “退出专注模式”名称与操作提示。 |
| 18.2 | 点击切换、返回或既有退出方式、会话恢复、导航触发退出和断点变化后，入口始终反映实际状态；不改变栏位和内容恢复语义。明暗主题、旋转及可用键盘 / 无障碍操作保持可辨识。 |
| 18.3 | v2 原型与原生 UI 一致；图标遵循既有 token 和已核实资源或自绘，禁止猜测系统资源名。分别记录自动测试、构建、模拟器及用户手动 API24 / XT2 验收，不以原型代替原生证据。 |
