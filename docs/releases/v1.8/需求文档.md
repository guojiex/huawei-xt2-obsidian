# v1.8 专注模式入口状态修复

状态：原型与原生实现完成，定向 / 全仓自动测试、生成器检查及 unsigned arm64-v8a HAP 构建通过；模拟器、API24 / XT2 验收待做，未发布。与 v1.7 和其他版本需求正交，无功能依赖，可单独实施及验收，不阻塞其他版本。

## 1. 来源与范围

来源：[需求池「专注模式入口状态反馈」](../../requirements_backlog.md)。工作区的专注按钮目前容易被理解为全屏按钮；进入专注后应明确提供退出入口。该功能控制应用内专注布局，不改变系统窗口全屏状态。

## 2. 需求与验收

| 编号 | 要求 |
| --- | --- |
| 18.1 | 双屏、三屏普通状态显示进入专注的向外展开图标；专注状态同一位置显示退出专注的向内收起图标。操作后图标、可访问名称和提示同步更新，明确为“进入专注模式” / “退出专注模式”。 |
| 18.2 | 点击切换、返回或既有退出方式、会话恢复、导航触发退出和断点变化后，入口始终反映实际状态；不改变既有单屏入口可见性、栏位和内容恢复语义。明暗主题、旋转及可用键盘 / 无障碍操作保持可辨识。 |
| 18.3 | v2 原型与原生 UI 一致；图标遵循既有 token 和已核实资源或自绘，禁止猜测系统资源名。分别记录自动测试、构建、模拟器及用户手动 API24 / XT2 验收，不以原型代替原生证据。 |

## 3. 不做

不引入系统全屏 API，不改保存、笔记内容或布局策略，不改包版本和发布状态。
