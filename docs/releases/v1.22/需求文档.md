# v1.22 需求文档 —— 分栏调节条交互增强

> 状态：🟡 开发中；22.1–22.4 原生本地实现与构建记录见下；22.5 原型已有交互复核，定向自动回归 5/5；真实浏览器目视受本地文件 URL 安全策略阻止，模拟器因 Mac 锁屏未验，API24 / XT2 由用户手动验收。22.4 已接受动态读屏文本作为替代，机器可读数值范围语义缺 API 依据并记为已知差异；版本仍未完成。
> 对应里程碑：独立优化。
> 需求来源：[需求池 Q-01](../../requirements_backlog.md)；设计基线：[分栏调节条设计](../../prototype/v2/分栏调节条设计.md)。

## 1. 版本定位

增强现有分栏调节条的可发现性、拖动反馈、恢复操作与无障碍状态，不改变既有分栏布局模型。

## 2. 完成判定

在支持的宽屏布局中，用户能通过触摸、鼠标或键盘发现并调整栏宽，可吸附或恢复默认、取消未完成拖动；读屏能获知当前比例、边界与状态（拖动中的视觉读数浮层已于 2026-11-07 按用户决定撤销）。原生能力与目标设备行为经独立验证。

## 3. 需求清单

| 编号 | 交付范围与验收要求 |
| --- | --- |
| 22.1 | **可见把手与轨线。** 静止时显示抓握把手和三个圆点提示；悬停 / 聚焦时显示全高轨线，拖动时把手放大并填充品牌色。粗指针热区不小于 36vp；把手与轨线不占布局、不改变栏宽计算。 |
| 22.2 | **边界与无障碍提示。** 拖动、键盘调整、恢复默认与取消**不弹任何视觉提示浮层**（2026-11-07 用户决定：撤销原「拖动中显示两侧比例和宽度」的读数气泡与「栏宽已保存」等反馈浮层——主流应用没有这种交互）；当前比例、栏宽、吸附与边界状态仅通过读屏文本说明，颜色不是唯一信息。 |
| 22.3 | **拖动、恢复与触摸。** 沿用既有栏宽范围与保存键；距离默认比例约 10vp 内吸附，原型支持 Alt 暂停吸附；Esc 取消并恢复拖动前比例，双击恢复默认。触摸以两次轻触恢复默认，不依赖 `dblclick`；减少动态效果偏好下不播放吸附动画。 |
| 22.4 | **键盘与读屏。** 左 / 右方向键按 16vp 步进，Shift 扩大至 64vp，Home / End 到最小 / 最大，Enter 恢复默认。分隔条继续提供 `aria-valuemin` / `aria-valuemax` / `aria-valuenow`，并补充当前比例及状态文本。（原生若无机器可读数值范围接口，以动态读屏文本替代，2026-11-05 决定）|
| 22.5 | **原型与设计同步。** v2 原型覆盖目录栏和正文 / 参考栏两种调节条；保持现有 token、布局边界、栏宽状态键及单屏 / 专注模式隐藏规则。设计说明链接到独立规格。自动检查、真实浏览器、模拟器和 API24 / XT2 证据分开记录。 |

## 4. 明确不做

- 不改变默认栏宽、每栏最小宽度、栏数量、折痕规则或既有栏宽持久化键。
- 不增加栏宽设置项；默认恢复继续复用现有设置入口。
- 不做拖动惯性、多段吸附、拖动预览缩略图或振动依赖。
- 不将浏览器原型结果作为 ArkUI / ArkWeb 手势、触觉、读屏接口或 XT2 设备验收证据。

## 5. 技术约束与依赖

- 首次分栏实现归 [v0.7 §7.22–7.23](../v0.7/需求文档.md)；本版只增强调节条，不回填旧版需求或扩大布局范围。
- 现行设计 token 以 [v2 设计说明](../../prototype/v2/设计说明.md) 和原型 `:root` / `[data-theme="dark"]` 为准。
- HarmonyOS API、手势、读屏和触觉行为必须查证 [API 笔记](../../harmonyos/api_notes.md)，未核实的接口不写入实现承诺。

### 6.4 22.4 键盘与读屏（2026-11-04）

- 两种分隔条均支持左右方向键按 16vp 调整、Shift 扩大为 64vp、Home / End 到既有边界、Enter 复用现有恢复默认操作；键盘调整与恢复共用既有保存及短暂反馈逻辑。读屏文本动态包含当前两侧比例、栏宽、状态和按键操作。
- HarmonyOS 依据：API 24 SDK 中 `onKeyEvent` since 15，相关 DPAD / Home / End / Enter 键值 since 9，`getModifierKeyState(['Shift'])` since 12，`accessibilityText(string)` since 12；详见 [API 笔记 L-11](../../harmonyos/api_notes.md#l-11-v07-分栏手势与单屏横向窗口识别api-24-sdk-声明)。
- 自动验证：`node --test tools/tests/test_split_handle.mjs`：7/7；`git diff --check` 通过。
- 构建：DevEco `hvigorw assembleHap` 成功，33 项任务（19 执行 / 14 up-to-date），构建用时 10 秒。该证据不代表键盘焦点或读屏设备验收。
- SDK 核查未发现可设置原生无障碍数值范围的 API；当前仅以 `accessibilityText` 播报动态值，不能声称等同机器可读的 `aria-valuemin` / `aria-valuemax` / `aria-valuenow`。
- ⏭ 历史跳过记录（2026-11-05 已解除）：22.4 原生机器可读数值范围语义 —— 当时本机 API 24 SDK 声明中未找到相关接口；现按下方决定接受动态读屏文本作为已知差异。
- 2026-11-05 产品决定：接受已实现的动态读屏文本作为原生替代，记为**已知差异**（读屏可播报比例与状态，但没有机器可读的最小 / 最大 / 当前值）；以后找到 API 24 依据再补，不阻塞本版。上一条跳过自本日解除。
- ⏭ 跳过：22.4 API24 / XT2 键盘与读屏验收 —— 本轮不连接或操作真机，自动测试与 HAP 构建不能证明实际焦点路由、按键步进及动态读屏文本的播报 —— 请用户在 API24 / XT2 用键盘及系统读屏检查两种分隔条的调整、边界、恢复和播报，并提供实测结果后解除。

22.5 本地原型交互已实现；真实浏览器、模拟器及 API24 / XT2 验收分别记录，原型验证不替代原生或设备验收。
