# v1.71 需求文档 —— 文件树拖拽移动与拖笔记进栏打开

> 状态：2026-11-16 原生实现完成（签名 HAP 构建通过、Node 测试通过）；API24 / XT2 真机验收待用户。

## 1. 版本定位

侧栏文件树补上两类拖拽交互，一次收口：

1. **树内拖拽移动**：长按拖笔记 /
   文件夹到目标文件夹行释放即完成移动，是左滑「移动」对话框之外的更快路径。此前需求池从未登记过此交互，本版立项（[需求池 §B 新增条目](../../requirements_backlog.md#b-笔记库级能力共同前提全库索引)）。
2. **拖笔记进正文栏打开**：补 [v0.9 9.4](../v0.9/需求文档.md)（L-02）「点击文件进入激活栏，拖到目标栏打开」的原生落地缺口。现状：只有
   Agent 引用树有拖放（`AgentWorkspace` 的 `allowDrop` / `onDrop`），主文件树行 `draggable` 仅 `referenceOnly`
   模式开启（FileTreeView.ets:1111），左右正文栏没有任何 drop 目标；v1.28 空态文案「从文件列表选一篇，或拖到这一栏打开」与
   v1.32 底部提示「左滑操作 · 拖图标到任一栏」都承诺了原生不存在的拖拽。

## 2. 完成判定

双屏 / 三屏下，从文件树长按拖起一篇笔记：

- 落在**文件夹行**上 = 该笔记移动到该文件夹（树刷新、新位置展开可见、当前打开路径 / 最近打开 / 草稿 / 全文索引 /
  双链引用与既有「移动」对话框结果完全一致）；
- 落在**左右任一正文栏**上 = 该栏打开这篇笔记（drop 前有落点高亮）。

文件夹拖到另一文件夹 = 整个子树移动；拖到自身 / 子孙行不响应。单屏（无第二栏）栏落点不适用，树内移动仍可用。Agent
引用侧栏与对话区拖放行为零回归。签名 HAP 构建通过；API24 / XT2 真机验收待用户。

## 4. 明确不做

- 不做跨库拖拽移动；不做拖到回收站区删除。
- 不做置顶 / 收藏的拖入、树内拖拽排序（置顶已有独立语义，见 v1.62）。
- 不做跨应用拖出 / 拖入（需求池另有条目，API 24 支持度待核实）。
- 不做拖拽批量多选移动。
- 不给拖拽移动加撤销（与既有「移动」对话框对齐，都没有）。
- 不新增权限、不改 token / 设计真源映射。

## 5. 技术约束与依赖

- **拖放 API 现网已用，无新增核实项**：`FileTreeView.onDragStart`（Agent 引用树，`application/x-yaoshi-note-ref`，payload 含
  vaultId + relPath，FileTreeView.ets:1112）与 `AgentWorkspace.allowDrop` / `onDrop`（AgentWorkspace.ets:
  843–846）；本版把同族能力接到主树与正文栏。MIME 沿用或新增由实现期定。
- **移动全链复用，不复制第二套逻辑**：`Index.doMovePath`（Index.ets:6817）已内建草稿迁移、FTS retarget、双链重写、recent-open
  retarget、reveal 与树刷新；`NoteService.movePath`（NoteService.ets:425）自带自身 / 子孙兜底与同后缀不覆盖。
- **主树 `draggable` 放开**：`draggable(this.referenceOnly && !n.isDir)` 改为主树可拖，落点侧过滤候选与 `movePath` 兜底双保险。
- **手势共存是实测项**：长按拖起与 `swipeAction` / 滚动的共存行为无官方记载（api_notes 未记载），列入验收实测，不凭模拟器结论外推到
  XT2。
- v2 原型同步把「拖行尾图标到目标栏」改为整行拖拽语义（或补整行拖拽），原型与原生交互一致。
- 颜色 / 圆角 / 间距 / 字号只引用现有 token。

### 2026-11-16 拖拽双失效修复（API26 模拟器实测定位 + 修复 + 复验通过）

**用户实测反馈**：树内拖拽移动、拖笔记进栏打开**双双失效**（v1.71 原生实现装机后）。
在 API26 arm64 模拟器（Mac 宿主）用 `uitest uiInput drag` 注入复现，两个独立根因：

- **根因一（匹配层，树 / 栏 / Agent 共因）**：拖拽 summary 恒归一为
  `ApplicationDefinedType` 桶键，`allowDrop('application/x-yaoshi-note-ref')` 私有串永不匹配，
  日志 `DragDropManager onDragEnd, target data is not allowed to fall into`。
- **根因二（栏独有）**：ArkWeb 原生接管 Web 区域拖放（落点 `TargetNode is Web`、chromium
  `allow_op = -1` 全拒），栏根容器 `onDrop` 收不到 Web 区域 drop。

**修复**（详见 api_notes **AH2 / AH3**）：

1. 三处 `NOTE_REF_MIME` 常量值统一改官方示例值 `'ApplicationDefinedType'`
   （`FileTreeView` / `Index` / `AgentWorkspace`），applicationDefinedType 与 allowDrop 共用；
   细分过滤下沉到事件回调（树 / 栏靠会话态 `dragSourcePath` / `treeDragPath` 空串守卫，
   Agent 靠 `rawData` JSON 的 `vaultId` 校验）。
2. 拖拽数据改 `ApplicationDefinedRecord`（`rawData` = TextEncoder(JSON)，类型层不再依赖
   `(type, value)` 形态）；Agent `readNoteRefText` instanceof 分派 + `decodeToString`，
   保留旧 `(type, value)` 回退（v1.58 会话兼容）。
3. 栏「拖拽会话护盾」：`@State treeDragActive`（onTreeDragStart 置 / onDragEnd 复位），
   左右栏容器 Stack **末位**条件挂载全尺寸透明 Column（allowDrop + onDragEnter/Leave/Drop
   → 既有 onPaneDrag*），把 Web 落点抢回来。

**复验（API26 模拟器，`uitest uiInput drag` 注入）**：✅ 全部通过——

- 树内移动：05_问卷 → 00_Inbox（toast「已移动到 00_Inbox/…」、树刷新缩进正确）→ 拖回
  01-规划（toast 确认回原路径 `20_Projects/AI方向、副业与自媒体探索/01-规划/…`，库已还原）。
- 栏落点：02-访谈日志 → 右栏 Web 区（2600,1200），右栏标题由 01-方向判断与初版建议.md
  切换为 02-访谈日志.md；日志 `TargetNode is Column`（护盾生效，不再是 Web）。
- 修复后日志 0 条 `not allowed to fall into`（修复前每次 drop 必现）。

**验证**：`test_tree_drag_move.mjs` 8 用例全过（含修复专项用例）；`devecocli build` 成功并装机。
