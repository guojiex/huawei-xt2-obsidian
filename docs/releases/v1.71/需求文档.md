# v1.71 需求文档 —— 文件树拖拽移动与拖笔记进栏打开

> 状态：2026-11-15 用户提出并确认范围（笔记 + 文件夹都做；「拖进栏打开」一并收口）。未落码。

## 1. 版本定位

侧栏文件树补上两类拖拽交互，一次收口：

1. **树内拖拽移动**：长按拖笔记 /
   文件夹到目标文件夹行释放即完成移动，是左滑「移动」对话框之外的更快路径。此前需求池从未登记过此交互，本版立项（[需求池 §B 新增条目](../../requirements_backlog.md#b-笔记库级能力共同前提全库索引)）。
2. **拖笔记进正文栏打开**：补 [v0.9 9.4](../v0.9/需求文档.md)（L-02）「点击文件进入激活栏，拖到目标栏打开」的原生落地缺口。现状：只有
   Agent 引用树有拖放（`AgentWorkspace` 的 `allowDrop` / `onDrop`），主文件树行 `draggable` 仅 `referenceOnly`
   模式开启（FileTreeView.ets:1111），左右正文栏没有任何 drop 目标；v1.28 空态文案「从文件列表选一篇，或拖到这一栏打开」与
   v1.32 底部提示「左滑操作 · 拖图标到任一栏」都承诺了原生不存在的拖拽。

## 2. 完成判定

双屏 / 三屏下，从文件树长按拖起一篇笔记：

- 落在**文件夹行**上 = 该笔记移动到该文件夹（树刷新、新位置展开可见、当前打开路径 / 最近打开 / 草稿 / 全文索引 /
  双链引用与既有「移动」对话框结果完全一致）；
- 落在**左右任一正文栏**上 = 该栏打开这篇笔记（drop 前有落点高亮）。

文件夹拖到另一文件夹 = 整个子树移动；拖到自身 / 子孙行不响应。单屏（无第二栏）栏落点不适用，树内移动仍可用。Agent
引用侧栏与对话区拖放行为零回归。签名 HAP 构建通过；API24 / XT2 真机验收待用户。

| 71.1 | **树内拖拽移动**    | 主文件树笔记行、文件夹行可长按拖起；文件夹行（展开 / 收起态均算）为移动落点，drop 前高亮反馈；释放调用既有 `Index.doMovePath` 全链（flushWorkspaceSaves → `NoteService.movePath` → recent-open / 当前栏 / 右栏 retarget → reveal → 刷新树）；落到树根部空白区 = 移到库根（对齐移动对话框「库根目录」语义） |

## 4. 明确不做

- 不做跨库拖拽移动；不做拖到回收站区删除。
- 不做置顶 / 收藏的拖入、树内拖拽排序（置顶已有独立语义，见 v1.62）。
- 不做跨应用拖出 / 拖入（需求池另有条目，API 24 支持度待核实）。
- 不做拖拽批量多选移动。
- 不给拖拽移动加撤销（与既有「移动」对话框对齐，都没有）。
- 不新增权限、不改 token / 设计真源映射。

## 5. 技术约束与依赖

- **拖放 API 现网已用，无新增核实项**：`FileTreeView.onDragStart`（Agent 引用树，`application/x-yaoshi-note-ref`，payload 含
  vaultId + relPath，FileTreeView.ets:1112）与 `AgentWorkspace.allowDrop` / `onDrop`（AgentWorkspace.ets:
  843–846）；本版把同族能力接到主树与正文栏。MIME 沿用或新增由实现期定。
- **移动全链复用，不复制第二套逻辑**：`Index.doMovePath`（Index.ets:6817）已内建草稿迁移、FTS retarget、双链重写、recent-open
  retarget、reveal 与树刷新；`NoteService.movePath`（NoteService.ets:425）自带自身 / 子孙兜底与同后缀不覆盖。
- **主树 `draggable` 放开**：`draggable(this.referenceOnly && !n.isDir)` 改为主树可拖，落点侧过滤候选与 `movePath` 兜底双保险。
- **手势共存是实测项**：长按拖起与 `swipeAction` / 滚动的共存行为无官方记载（api_notes 未记载），列入验收实测，不凭模拟器结论外推到
  XT2。
- v2 原型同步把「拖行尾图标到目标栏」改为整行拖拽语义（或补整行拖拽），原型与原生交互一致。
- 颜色 / 圆角 / 间距 / 字号只引用现有 token。
