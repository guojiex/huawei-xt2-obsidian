# v0.2 需求文档 —— 能写笔记

> **状态**：⚪ 规划中
> **对应里程碑**：M0.5 + M1 + M2 + M3
> **版本定位**：从"能看"到"能写"。文件树能浏览、编辑器中文流畅、预览能渲染、杀进程不丢内容。

## 1. 版本定位

这是**应用真正成立**的版本。v0.1 交付骨架，这一版往骨架里填内容：
左边能选笔记、中间能打字、右边能看渲染结果，且内容不会丢。

⚠️ 本版本的**头号风险是 M0.5 spike**（中文输入法）。它不是需求，是**前置关卡**——
结论决定编辑器走方案 A（CodeMirror 6）还是降级方案 B（TextArea）。

## 2. 完成判定

> 在真实目录下能浏览并打开笔记（目录可展开/折叠、状态按库分别记忆）；
> 输入中文流畅、撤销可用；杀进程重进内容还在；表格/代码块/图片等语法能正确渲染。

## 3. 需求清单

### 3.1 前置关卡：M0.5 WebView 编辑 spike（**不通过则后续需求全部重排**）

| # | 验证项 | 说明 |
| --- | --- | --- |
| 0.1 | **中文输入法** | ⚠️ **头号风险**。重点测拼音/语音/手写下的 composition 事件与光标跟随 |
| 0.2 | **CodeMirror 6 的 contenteditable vs textarea** | ⚠️ 官方建议优先 textarea，而 CM6 就是 contenteditable —— **两者必须对比实测** |
| 0.3 | 光标与滚动 | 输入/删除时光标位置正确、长文滚动正常 |
| 0.4 | 折叠 resize | 形态切换时 Web 组件 resize 不重载、不丢光标 |

> spike 结论必须**回写**到 `docs/harmonyos/api_notes.md`（❓ → ✅），实测值比官方答复更可信。

| # | 需求 | 来源 | 验收点 |

## 4. 明确不做

| 不做 | 原因 |
| --- | --- |
| Git 同步 | v0.3 |
| 全文搜索 / 双链 / 图谱 | 依赖索引层，属 v2 |
| 所见即所得 Live Preview | 需求池标后置，成本 L |
| 图片插入、附件、KaTeX、Mermaid | 后置（KaTeX/Mermaid 前端库现成，但不在 MVP） |
| 回收站 | 虽是左滑删除的兜底，但优先级低于本版本主线；若时间允许可并入 |
| 小艺智能体 / AI 编辑（F8） | ❌ 已定不进 MVP |
| 埋点 / 数据分析 | ❌ 需求池 H 节，整节后置 |

## 5. 技术约束与依赖

- **必须先有 v0.1 的骨架**（三栏容器 + 库模型），本版本不重写布局
- 编辑器方案 A/B 取决于 M0.5 spike 结论 —— `mvp_design.md` §3
- Web 组件宽高 **≤ 7680px 物理像素**（超过会白屏）—— `AGENTS.md` 硬约束 12
- 中文输入法结论 —— `api_notes.md` **B5 / B6**
- 原子写 —— `api_notes.md` **C1**
