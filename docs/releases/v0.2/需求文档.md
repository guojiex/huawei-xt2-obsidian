# v0.2 需求文档 —— 能写笔记

> **状态**：⚪ 规划中
> **对应里程碑**：M0.5 + M1 + M2 + M3
> **版本定位**：从"能看"到"能写"。文件树能浏览、编辑器中文流畅、预览能渲染、杀进程不丢内容。

## 1. 版本定位

这是**应用真正成立**的版本。v0.1 交付骨架，这一版往骨架里填内容：
左边能选笔记、中间能打字、右边能看渲染结果，且内容不会丢。

⚠️ 本版本的**头号风险是 M0.5 spike**（中文输入法）。它不是需求，是**前置关卡**——
结论决定编辑器走方案 A（CodeMirror 6）还是降级方案 B（TextArea）。

本版本还承接一项**回头活**：把 v0.1 的默认 ArkUI 界面改成 HarmonyOS Design 观感（3.5 视觉基线）。
v0.1 交付时界面是默认样式，与设计稿不一致；**用户已拍板：token 落地并入 v0.2，v0.1 不动**。

## 2. 完成判定

> 在真实目录下能浏览并打开笔记（目录可展开/折叠、状态按库分别记忆）；
> 输入中文流畅、撤销可用；杀进程重进内容还在；表格/代码块/图片等语法能正确渲染；
> **界面观感与设计稿一致**（色板/圆角/间距/字号走 token，深色模式不靠反色）。

## 3. 需求清单

## 4. 明确不做

| 不做 | 原因 |
| --- | --- |
| Git 同步 | v0.3 |
| 全文搜索 / 双链 / 图谱 | 依赖索引层，属 v2 |
| 所见即所得 Live Preview | 需求池标后置，成本 L |
| 图片插入、附件、KaTeX、Mermaid | 后置（KaTeX/Mermaid 前端库现成，但不在 MVP） |
| 回收站 | 虽是左滑删除的兜底，但优先级低于本版本主线；若时间允许可并入 |
| 小艺智能体 / AI 编辑（F8） | ❌ 已定不进 MVP |
| 深色模式**手动切换**开关 | 本版本只做 token 与跟随系统；手动切换（follow / light / dark 三态）后置 |
| `Hds*` 组件的完整替换 | 只在**确认可引入**时用；否则按同观感自绘，不为一个列表项引整套 UI Design Kit |
| 埋点 / 数据分析 | ❌ 需求池 H 节，整节后置 |
| **zip 导出 / 导入**（Q2） | ⏸ **2026-10-17 用户决定后置**：MVP 还没在真机上跑通过、没真实用户、真机上没有笔记存量 —— 此时导出是空功能。保留在需求池，**触发条件**见 `open_questions.md` Q2 |
| zip **导入** | 依赖导出那批打包能力，随导出一起后置 |

## 5. 技术约束与依赖

- **必须先有 v0.1 的骨架**（三栏容器 + 库模型），本版本不重写布局
- 编辑器方案 A/B 取决于 M0.5 spike 结论 —— `mvp_design.md` §3
- Web 组件宽高 **≤ 7680px 物理像素**（超过会白屏）—— `AGENTS.md` 硬约束 12
- 中文输入法结论 —— `api_notes.md` **B5 / B6**
- 原子写 —— `api_notes.md` **C1**
- 视觉基线 —— 需求池 **J 节**；token 真源 `docs/prototype/index.html`，已定决策见 `open_questions.md`「视觉基线」
- 版本号读取、UI Design Kit 可用性等鸿蒙结论 —— `api_notes.md` **H 组**（未核实项❓不进关键路径）
