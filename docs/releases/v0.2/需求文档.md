# v0.2 需求文档 —— 能写笔记

> **状态**：🔵 进行中（草稿恢复实现与本地 Hypium 单测已完成；§3.4 API 26 模拟器验收通过，XT2、M0.5 与其他未完成项仍待验）
> **对应里程碑**：M0.5 + M1 + M2 + M3
> **版本定位**：从"能看"到"能写"。文件树能浏览、编辑器中文流畅、预览能渲染、保存与恢复逻辑可验证。

## 1. 版本定位

这是**应用真正成立**的版本。v0.1 交付骨架，这一版往骨架里填内容：
左边能选笔记、中间能打字、右边能看渲染结果，且内容不会丢。

⚠️ 本版本的**头号风险是 M0.5 spike**（中文输入法）。它不是需求，是**前置关卡**——
结论决定编辑器走方案 A（CodeMirror 6）还是降级方案 B（TextArea）。

本版本还承接一项**回头活**：把 v0.1 的默认 ArkUI 界面改成 HarmonyOS Design 观感（3.5 视觉基线）。
v0.1 交付时界面是默认样式，与设计稿不一致；**用户已拍板：token 落地并入 v0.2，v0.1 不动**。

## 2. 完成判定

> **测试方式（2026-10-24 用户决定）**：不在模拟器上主动制造崩溃、强杀进程或写入中断。恢复与失败路径使用单测；Darwin 本地 Hypium 运行器缺少 `fileIo.readTextSync`、`listFileSync`，且不能验证真实 `AtomicFile`，因此草稿存储读写/清理/目录复制与正式保存失败采用 mock。单测覆盖逻辑，不代表真实进程中断或设备级原子性已验证；历史实测记录保留。

> 在真实目录下能浏览并打开笔记（目录可展开/折叠、状态按库分别记忆）；
> 输入中文流畅、撤销可用；保存后重新打开内容一致；恢复逻辑用单测验证；表格/代码块/图片等语法能正确渲染；
> **界面观感与设计稿一致**（色板/圆角/间距/字号走 token，深色模式不靠反色）。
