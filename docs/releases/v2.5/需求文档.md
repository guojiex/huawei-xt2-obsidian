# v2.5 需求文档 —— 文件树深层级缩进封顶

> 状态：开发中（2026-11-22 立项并当日落码）
> 对应里程碑：无（独立 UI 优化，文件列表体验族，承接 [v1.49](../历史版本归档.md#v149-需求文档) / [v1.62](../历史版本归档.md#v162-需求文档) 所在的侧栏文件树）

## 1. 版本定位

文件夹嵌套过深时，文件树行缩进按每级 24px/vp 线性增长，侵占笔记名的显示空间：原生侧名称被省略号截到极短（`FileTreeView` 每级一个 24vp 缩进格），原型侧行宽下限 `--tree-text-min + depth × --tree-indent` 随层级增长撑出横向滚动。本版把**视觉缩进封顶**：第 4 级起缩进不再增长，笔记名恢复可用宽度；原型与原生同版落地。

## 2. 完成判定

展开 5 层以上嵌套目录时：第 4 级及更深的行缩进停在 96px/vp（`min(depth, 4) × 24`）不再增长，笔记名在 240px 侧栏下保留省略号截断前的可用宽度；0–3 级行的缩进、引导线与既有交互零变化。

## 3. 需求清单

来源：[需求池 B 节「文件树深层级缩进封顶」](../../requirements_backlog.md)（2026-11-22 用户提出）。

| #    | 需求                                                         | 验收点                                                                                                                                                |
| ---- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 25.1 | **缩进封顶**（原型）                                         | `:root` 新增 `--tree-depth-cap:4`；`.tree-row` 内边距改 `calc(var(--s2) + min(var(--depth), var(--tree-depth-cap)) * var(--tree-indent))`；`.tree-children::before` 引导线位置同步 `min(var(--parent-depth), calc(var(--tree-depth-cap) - 1))`（封顶档合并为最深一条引导线） |
| 25.2 | **撤销随层级增长的行宽下限**（原型）                         | `.tree-row` / `.file-entry` 删除 `min-width:calc(var(--tree-text-min) + depth × indent)`：深层行不再撑出横向滚动，名称按既有 `text-overflow:ellipsis` 截断；`--tree-text-min` token 保留（`.pane-more-menu` 仍引用） |
| 25.3 | **原生同步**                                                 | `FileTreeView.levelsOf` 按 `Size.treeDepthCap` 封顶（缩进格与引导线列数不再随深层级增长）；`Tokens.ets` 新增 `treeDepthCap = 4`                                                       |
| 25.4 | **防线**                                                     | 新增源级契约测试 `test_tree_indent_cap.mjs`（原型 CSS 封顶表达式 + 原生 levelsOf 封顶 + token 配对）；`test_v2_token_sync.mjs` 数值映射补 `Size.treeDepthCap ↔ --tree-depth-cap`；mdeditor / mdpreview rawfile 产物随 `:root` 变更重打包并提交 |

## 4. 明确不做

- 不改章节（大纲）列表缩进：H1–H6 上限 5 层、每级 16px（`--s4`），不挤占名称空间，维持现状。
- 不改 24px/vp 每级缩进与引导线语义（[v0.2 1.5](../历史版本归档.md#v02-需求文档) 既定决策）。
- 不做深层级面包屑、行内横向滚动、可配置缩进档位——封顶后名称空间已够，不引入第二套层级表达。
- 不改 `FileTree.MAX_DEPTH = 8` 的扫描保护与目录 / 文件排序。
- 笔记名超长的省略号截断、`title` / aria-label 完整路径、左滑与拖拽交互均沿用现状，零改动。

## 5. 技术约束

- 设计真源：`docs/prototype/v2/index.html`（AGENTS.md 硬约束 17：间距 / 尺寸只引用 token）。
- 原型 `:root` token 块被 mdeditor / mdpreview 构建脚本内嵌，`--tree-depth-cap` 入 `:root` 后必须重打包两个 rawfile 产物（`test_v2_token_sync` 会校验产物未过期）。
- 原生侧不引入新 HarmonyOS API；`Math.min` 纯逻辑封顶。
