# v2.5 需求文档 —— 文件树深层级缩进封顶

> 状态：开发中（2026-11-22 立项并当日落码；2026-11-23 真机验收发现行尾开销缺陷，方案 A 闭环修订）
> 对应里程碑：无（独立 UI 优化，文件列表体验族，承接 [v1.49](../历史版本归档.md#v149-需求文档) / [v1.62](../历史版本归档.md#v162-需求文档) 所在的侧栏文件树）

## 1. 版本定位

文件夹嵌套过深时，文件树行缩进按每级 24px/vp 线性增长，侵占笔记名的显示空间：原生侧名称被省略号截到极短（`FileTreeView` 每级一个 24vp 缩进格），原型侧行宽下限 `--tree-text-min + depth × --tree-indent` 随层级增长撑出横向滚动。本版把**视觉缩进封顶**：第 4 级起缩进不再增长，笔记名恢复可用宽度；原型与原生同版落地。

## 2. 完成判定

展开 5 层以上嵌套目录时（2026-11-23 闭环修订）：第 **2** 级及更深的行缩进停在 48px/vp（`min(depth, 2) × 24`）不再增长；**窄侧栏（XT2 三栏 nav 200-248vp）下行尾不再有 48px 星标按钮**（收藏降为名字尾 12px 状态标记）、跨栏按钮隐藏（拖拽替代）——深层笔记名保留 ≥60px/vp 可用宽度；0–1 级行的缩进、引导线与既有交互零变化。

> 首轮判定（封顶 4 级 / 96px，「笔记名在 240px 侧栏下保留可用宽度」）经真机目视证伪：行尾星标按钮（v1.97）+ 跨栏按钮合计 ~96px 未计入预算，深层名字宽归零。修订见 §6。

## 4. 明确不做

- 不改章节（大纲）列表缩进：H1–H6 上限 5 层、每级 16px（`--s4`），不挤占名称空间，维持现状。
- 不改 24px/vp 每级缩进与引导线语义（[v0.2 1.5](../历史版本归档.md#v02-需求文档) 既定决策）。
- 不做深层级面包屑、行内横向滚动、可配置缩进档位——封顶后名称空间已够，不引入第二套层级表达。
- 不改 `FileTree.MAX_DEPTH = 8` 的扫描保护与目录 / 文件排序。
- 笔记名超长的省略号截断、`title` / aria-label 完整路径、左滑与拖拽交互均沿用现状，零改动。

## 5. 技术约束

- 设计真源：`docs/prototype/v2/index.html`（AGENTS.md 硬约束 17：间距 / 尺寸只引用 token）。
- 原型 `:root` token 块被 mdeditor / mdpreview 构建脚本内嵌，`--tree-depth-cap` 入 `:root` 后必须重打包两个 rawfile 产物（`test_v2_token_sync` 会校验产物未过期）。
- 原生侧不引入新 HarmonyOS API；`Math.min` 纯逻辑封顶。
