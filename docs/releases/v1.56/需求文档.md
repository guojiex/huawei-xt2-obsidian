# v1.56 需求文档 —— 接收系统分享（文本 / 链接存入笔记）

> 状态：本地实现完成（2026-11-12 落码，56.1–56.6），模拟器分享面板实测与 API24 / XT2 验收待用户。来源：需求池 D 节「系统分享：文本/链接存入笔记」（2026-10-31 登记，「建议纳入，成本低、场景真」）。

## 1. 背景

应用目前已能向外分享（v0.8 / v1.25 / v1.53）；本版补**接收方向**：用户在浏览器、备忘录、聊天应用里把一段文本或一个链接分享给曜石笔记，保存为库内新笔记。这是「剪藏 / 快速收集」场景的最小闭环。

接收侧机制（官方指南「应用内处理分享内容」+ 本机 SDK 声明核实，2026-11-12）：

- `module.json5` 的 `EntryAbility.skills` 追加 `actions: ["ohos.want.action.sendData"]` + `uris` 穷举支持接收的 UTD 类型，应用即出现在系统分享面板；
- `EntryAbility` 在 `onCreate`（冷启动）或 `onNewWant`（热启动）拿到 want，`systemShare.getSharedData(want)` 解析出 `SharedData.getRecords()`；
- 文本与链接内容在 `SharedRecord.content`，标题在 `SharedRecord.title`；`SharedData` 总量 ≤ 200KB（IPC 约束，来源侧受限，接收侧仍做防御）。

API 核实：`systemShare.getSharedData`（`@kit.ShareKit`，`@hms.collaboration.systemShare`）since 4.1.0(11) ≤ API 24，syscap `SystemCapability.Collaboration.SystemShare`，**无权限要求**；接收注册只改 skills，不动 `requestPermissions`。

## 2. 完成判定

从系统分享面板把**一段文本**和**一条链接**分别分享给 App，各在目标库产生一篇内容正确的新笔记（可先在保存确认层编辑标题与内容）；冷启动与热启动两路径均工作；零新增权限。

## 3. 需求清单

### 56.1 接收注册（module.json5）

- `EntryAbility.skills` 追加 `{ actions: ["ohos.want.action.sendData"], uris: [...] }`，保留既有 home skill 不动。
- UTD 穷举声明：`general.text`、`general.plain-text`、`general.hyperlink`。官方示例只声明 `general.text`，但「uris 需穷举支持的类型」且父类匹配子类记录的行为未实测——按穷举写，不赌层级匹配。
- `maxFileSupported` 缺省（本版不接收文件类分享）。
- `requestPermissions` 不动（零新增权限红线）。

### 56.2 EntryAbility 双路径解析

- `onCreate(want)` / `onNewWant(want)` 判 `want.action === 'ohos.want.action.sendData'` 后调 `systemShare.getSharedData(want)`：
  - 取**第一条** `utd` 为文本/链接的记录（多条 record 其余忽略，批量不做）；
  - 解析出 `{ utd, title, content }` 载荷；`content` 为空的记录视为无效，跳过；
  - 全部无效或解析抛错（1003703001）→ 不崩溃，进主界面 + toast「无法读取分享内容」。
- 冷启动：`onCreate` 时 UI 未建，载荷暂存在 Ability 层，`onWindowStageCreate` / 主页面就绪后转交；热启动：`onNewWant` 转发到已存在的主页面。转发机制（AppStorage / emitter）落码时定，不写入本档。
- 非 `sendData` want（正常桌面启动等）走现有路径，零行为变化。

### 56.3 保存分享确认层（UI）

- 新全屏对话框（UtilityDialogShell 模式，同 v1.53 分享预览弹窗），全形态复用，深浅色 token only。
- 元素：
  - **标题输入**：默认值规则——`record.title` 非空用之；否则链接取 URL 截 80 字符；否则文本取正文首行去空白截 30 字符；兜底「分享剪藏 yyyy-MM-dd HH:mm」；
  - **目标库行**：显示当前库名，点击弹库列表可切换（默认当前库）；无库可写时禁用保存并说明；
  - **内容预览**：多行可编辑（TextArea），默认模板——链接（`general.hyperlink`）：`[title](url)`，title 与 url 相同则直接 `url`；文本：`content` 原文；
  - 取消 / 保存按钮；标题为空时保存禁用。
- 无障碍：输入框 label、读屏文案、按钮语义完整（照既有弹窗惯例）。

### 56.4 落盘与打开

- 保存位置：**目标库根目录**（首期不做文件夹选择）。
- 文件名 = 标题 + `.md`，经现有唯一命名去重（同名加序号）。
- 写入走 NoteService 现有创建链路（新建唯一命名笔记；硬约束 10/15 语义：失败清理半成品，不留残文件）。
- 保存成功：toast「已保存到〈库〉/〈文件名〉」+ `revealPath` 打开该笔记 + 刷新文件树；确认层关闭。
- 保存失败：toast 直出真实异常 message（v1.53 53.8 决策），无半成品残留，确认层保留现场可重试。

### 56.5 红线

- **零新增权限**：`module.json5` 的 `requestPermissions` 不动。
- 笔记内容与标题**不进埋点**（硬约束 16）；本功能不新增任何埋点。
- 失败无半成品；目标路径出现残文件即删除。
- token only（颜色 / 圆角 / 间距 / 字号不散写）。

## 4. 明确不做（本版）

- 接收**文件类**分享（图片 / PDF / 任意文件 UTD）——涉及沙箱落盘与重名策略，另立版本。
- **追加到已有笔记**——需要笔记选择器，交互更重；本版只新建。
- 多 record 批量保存——只取第一条有效记录。
- HTML 记录 → Markdown 转换——不声明 `general.html`。
- 网页正文抓取（完整剪藏模式）——Obsidian Web Clipper 级别，成本 L，需求池另立。
- 保存到库内子文件夹——首期固定库根。
- 分享历史 / 自动归类 / 标签推断。

## 5. 技术约束与依赖

- API ≤ 24：`getSharedData` since 11 满足；syscap `SystemCapability.Collaboration.SystemShare`（XT2 自身向外分享已验证面板存在）。
- ✅ **构建 schema 实测（2026-11-12 落码踩到）**：`skills[].uris[]` 条目在 hvigor 的 module.json5 schema 里 `required: ["scheme"]`——只写 `utd` 构建直接失败（`propertyNames 'utd' must be valid` + `anyOf` 不匹配）。官方指南「应用内处理分享内容」的示例同样每个 uris 条目带 `"scheme": "file"`（预留字段，接收分享不生效），照抄即可。
- `SharedData` 总量 ≤ 200KB（IPC）：来源侧已受限；接收侧对空内容、超长标题做防御，正文不截断（200KB 文本整篇可存）。
- 双路径覆盖：`onCreate`（App 未运行被分享拉起）与 `onNewWant`（App 已在运行）。官方 FAQ 明确不能在 `onForeground` 取数。
- 转发机制已落码拍板：`AppStorage['incomingShare']`（JSON 载荷，`receivedAt` 时间戳做重复触发 nonce）；Index 侧 `@StorageProp + @Watch` 兜晚到、`aboutToAppear` 兜早到，消费后立刻清键。
- 写入遵循硬约束 10/15：新建唯一命名笔记直接写、失败清理半成品；不使用 `openSync(TRUNC)` 覆盖已有文件。
- ⚠️ 待实测（模拟器 + XT2）：分享面板中 App 的展示位置与图标；`general.text` 是否匹配子类型记录（已按穷举规避，实测后回填）；多来源（备忘录 / 浏览器 / 微信）实际 record 结构差异。

## 6. 验收记录

2026-11-12（Windows 本机，本地实现）：

- **56.1 落码**：`module.json5` `EntryAbility.skills` 追加 `sendData` + UTD 穷举（`general.text` / `general.plain-text` / `general.hyperlink`，每条带 `"scheme": "file"`，见 §5 schema 实测）；home skill 与 `requestPermissions` 不动（零新增权限）。
- **56.2 落码**：`EntryAbility` `onCreate` 挂钩 + 新增 `onNewWant` 同入口；`resolveSharedWant` 走 `systemShare.getSharedData` 取首条文本类有效记录，`AppStorage['incomingShare']` JSON 转发（`receivedAt` nonce）；无有效记录 / 抛错发 `errorPayload`（「无法读取分享内容」）不崩溃；hilog 只记记录数与错误码，不记标题 / 内容。
- **56.3 落码**：`SaveShareDialog`（UtilityDialogShell 模式）——标题输入 + 实时目标路径预览（重名加后缀提示、含 `/` 提示固定库根）、目标库内联切换（VaultItem 选中态）、内容 TextArea 可编辑、取消 / 保存（saving 中禁用、失败保留现场不关层）。
- **56.4 落码**：`Index` `@StorageProp + @Watch` 兜晚到、`aboutToAppear` 兜早到，消费后清键；`saveSharedNote` 走 `previewCreatePath` + `createNoteWithContent`，跨库先 `switchVault`（失败只 toast 不盲开），成功 revealPath + 刷新树 + toast。
- **新增 `ShareIngestService`**（纯逻辑、无 SDK 依赖）：载荷接口、UTD 判定、标题默认链（record.title → 链接 URL 截 80 → 文本首行截 30 → 「分享剪藏 + 时间」）、正文模板（链接 `[title](url)`、title==url 直出、文本原文）。
- **验证**：新增 `tools/tests/test_share_ingest.mjs` 20/20（esbuild+vm 单测 12 + 源级断言 8：skills 注册、权限白名单恰好 2 项、双路径接线、日志不泄漏内容、Index 消费链、库根 `/` 拒绝、冷启动兜底、确认层禁用 / 失败保留 / 成功关闭）；`arkts_check` 仅 2 项预存 `BuildProfile` 虚拟模块误报；`devecocli build` exitCode=0；全仓 Node 1228 测 14 失败，与干净 HEAD worktree 基线（1203 测 14 失败）逐项一致（均为既有 block_context_toolbar / split handle / Aa 菜单问题），**零新增回归**。
- ⏭ 模拟器分享面板实测（x86 可验）：备忘录 / 浏览器分享文本与链接 → 面板出现曜石笔记 → 保存确认层默认值 → 落盘打开；冷 / 热启动双路径；取消零写入。
- ⏭ 真机（API 24 / XT2）：同上 + 面板展示位置、`general.text` 子类型匹配实测、多来源 record 结构差异、200KB 上限表现。
