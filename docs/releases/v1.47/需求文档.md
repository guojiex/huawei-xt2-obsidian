# v1.47 需求文档 —— 回收站条目永久删除

> 状态：开发中（47.1/47.2/47.3 已落码，47.4 已落码待验收；待模拟器与 XT2 真机验收），2026-11-09 立项。来源：[需求池 B 节「回收站条目永久删除」](../../requirements_backlog.md)；47.1 来自 [W 组](../../requirements_backlog.md#w-图标全局-builder-按值实参冻结2026-11-09)背景所述当日修复；47.4 来自 [需求池 B 节「切换知识库恢复各库工作区会话」](../../requirements_backlog.md)（2026-11-09 用户提出，当日进版本）。

## 1. 目标与范围

回收站自 v0.2 落地以来只有「恢复」一个出口——删除的笔记无法在应用内彻底清除（只能删整库或设置里重置全部数据，见 v0.9 迁移验收清单与 v1.3 需求文档的既有记录）。本版本补上单条永久删除：

1. 回收站每条目提供「永久删除」入口（原型与原生 TrashView 一致）；
2. 点击后弹确认弹窗（危险色主操作），确认才真删——**不进撤销**，与文件删除（移入回收站 + 撤销）语义不同；
3. 删除后回收站列表、计数、空态与文件树联动刷新，toast 告知结果。

47.1 记录进入版本前已完成的同域修复：回收站折叠箭头图标不切换（全局 @Builder 按值实参冻结，四次同源踩坑中最新的一个，见 W 组背景）。

## 3. 明确不做

- 不做「清空回收站」批量入口与自动过期清理（需求池 B 节登记原文：「不做清空全部 / 批量 / 自动过期」）。
- 不做回收站弹窗向 UtilityDialogShell 的迁移——那是 [v1.32 32.1](../v1.32/需求文档.md) 的范围（回收站弹窗 2026-11-05 决定同样迁移，归属不变）。
- 永久删除不进撤销链：撤销只覆盖「移入回收站」的删除；确认弹窗即唯一保护。
- 存量图标冻结缺陷（GitSyncDialog 步骤图标、NoteDialogs 目录选中色等 10 处）不在本版本——留在 [需求池 W-01](../../requirements_backlog.md) 待分配批次。

## 4. 技术约束与依赖

- 图标实参写法约束见 [api_notes L-7 / Z2](../../harmonyos/api_notes.md)：全局 @Builder 多参按值传参不触发动态渲染；状态切换必须走 if/else 分支。防线测试 [`tools/tests/test_icon_builder_args.mjs`](../../../tools/tests/test_icon_builder_args.mjs) 拦截新增违规。
- 回收站数据链：`TrashService.list / restore`（沙箱 `trash/<vaultKey>`，按库隔离）；`purge` 与 `restore` 对称，走同一 `VaultAccess` 解析层，不按 `rootKind` 分叉（AGENTS.md 硬约束 14）。
- 埋点红线不变：文件名 / 路径 / 笔记内容不进 hilog 与埋点（AGENTS.md 硬约束 16）。
