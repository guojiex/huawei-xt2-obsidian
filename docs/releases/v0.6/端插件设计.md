# 小艺端插件：名称与描述

> 2026-10-26 设计稿。用于“Agent 对话”托管面板方案，覆盖本版既有六项笔记工具；六项工具的 0.1.0 版本现已在小艺平台保存为草稿，未发布、未接线或真机联调。以下设计名称已用于平台配置，实际参数见 §6。

## 1. 一个插件，六个工具

**插件名称：曜石笔记**

**插件描述：**

> 在用户授权的曜石笔记范围内，按文件名或库内路径查找笔记、读取正文、创建笔记、追加内容、按原文片段局部替换，以及撤销最近一次仍可撤销的笔记操作。适用于读书问答、整理讨论结论和修改笔记。讨论本身不会修改笔记；只有用户明确要求写入或撤销时才执行对应操作。无法访问未授权的笔记库或应用内部数据，不支持整篇删除、批量改写或 Git 同步。

插件按应用能力聚合；六项工具沿用现有工程标识，便于与本地服务对应。读书追问、总结、导读、讨论沉淀属于智能体任务与角色指令，不为每种表达增加一个插件或重复工具。

## 2. 工具名称与描述

以下“工具名称”为建议技术标识，“中文名称”用于展示或辅助说明；平台是否支持独立展示字段需核实。

| 工具名称 | 中文名称 | 工具描述（建议配置文案） |
| --- | --- | --- |
| `QueryNotes` | 查找笔记 | 当用户按文件名或路径寻找笔记，或目标不明确时，在当前授权范围内查找并返回候选笔记的名称与库内相对路径。本工具不读取正文，不执行全文语义搜索。多个候选无法唯一确定目标时，应先向用户澄清，不自行选一篇。 |
| `ReadNote` | 读取笔记 | 读取已明确且在授权范围内的笔记正文及当前内容版本，供回答问题、总结或后续修改使用。追加和局部修改前应先读取最新内容；笔记不存在、无权限或读取不完整时如实报告，不编造原文或已读取状态。 |
| `CreateNote` | 创建笔记 | 用户明确要求把内容保存为新笔记时，在授权库和允许的目录内创建 Markdown 笔记。已有同名文件不会被覆盖，返回实际创建路径。仅请求总结、讨论或给建议时不要调用；新建时不要求先读取不存在的目标笔记。 |
| `AppendNote` | 追加笔记内容 | 用户明确要求把指定内容补充到已有笔记末尾时，向已读取的目标笔记追加内容，保留原有正文。执行时校验内容版本；笔记已变化则拒绝本次写入，重新读取后再决定下一步。返回实际追加结果，不用于替换原文。 |
| `EditNote` | 局部替换笔记 | 用户明确要求修改已有笔记中的某一处内容时，以最新读取版本中的唯一、精确原文片段为锚点，替换为指定新内容。原文已变化、锚点不存在或出现多次时拒绝修改；重新读取或明确范围后再操作。不执行整篇覆盖或整篇删除。 |
| `UndoLastEdit` | 撤销最近一次笔记操作 | 用户明确要求撤销时，撤销当前授权范围内最近一次仍可撤销的创建、追加或局部替换。必须对应本地记录的实际操作，且目标没有后续变更；新建撤销仅允许移除该次创建且未被继续编辑的笔记。发生冲突或没有可撤销记录时返回原因，不撤销对话或其他操作。 |

`EditNote` 首期文案限定为现有局部替换契约，不借命名引入任意编辑命令。创建的撤销是严格绑定该次创建的恢复能力，不是通用删除工具。

## 3. 典型调用选择

| 用户表达 | 工具顺序 |
| --- | --- |
| “找一下阅读笔记” | QueryNotes；多个候选先澄清。仅限已有授权范围，不借查找扩大范围 |
| “这篇主要讲什么？” | ReadNote → 智能体总结，不写文件 |
| “把这轮结论记到这篇末尾” | ReadNote → AppendNote |
| “另存一篇读书小结” | CreateNote；若小结依赖笔记原文，先 ReadNote |
| “把这句话改成……” | ReadNote → EditNote |
| “撤销刚才的追加” | UndoLastEdit；不让模型自行生成反向替换冒充撤销 |

## 4. 必须由执行器保障的边界

- 授权绑定发起时的库/目标，不从模型参数或执行时的全局当前库扩大范围。首期按 [交互设计 §4](交互设计.md) 约束；QueryNotes 不自动拥有全库访问权，CreateNote 仅在授权库及允许目录内创建。
- 文件名/路径只是定位信息，不授予权限；隐藏内部数据和库外路径拒绝。精确参数及授权上下文绑定待正式协议核实，不把名称描述当作已实现的安全校验。
- 写入复用既有保存协调、版本校验、统一路径解析与 AtomicFile。工具描述提醒模型正确选用工具，不能代替执行器校验。
- 结果只依据真实执行：查找返回候选，读取返回正文及版本，写入返回实际路径/变更与本地操作标识，失败返回可操作原因。具体平台结果字段另行核实，不假设存在平台 requestId 或任意消息按钮。
- 端插件执行在应用中，不等于读取结果不会进入平台模型上下文；正文处理与用户告知按真实平台链路核实。

## 5. 本期不额外配置的插件

不增加通用文件系统、Shell、网页搜索、云盘、消息发送或 Git 插件。笔记读取与写入已能支持本期阅读、讨论和沉淀；将来有明确需求再分配版本。智能体名称沿用“曜石笔记助手”，与插件名称区分。

接口依据见 [api_notes F1 / F12–F13](../../harmonyos/api_notes.md)；本设计对应需求 §3-2–5、AG-12，不解除平台接入暂缓，也不修改 v0.7 本地 mock 工具实现。

| 工具 | 已保存输入参数 | result 对象内已保存输出字段 |
| --- | --- | --- |
| QueryNotes | vaultId、query（可选） | message、matchesJson |
| ReadNote | vaultId、path | content、contentHash、path、message |
| CreateNote | vaultId、path、text | path、contentHash、operationId、message |
| AppendNote | vaultId、path、baseHash、text | path、contentHash、operationId、message |
| EditNote | vaultId、path、baseHash、anchor、text | path、contentHash、operationId、message |
| UndoLastEdit | vaultId、operationId | path、operationId、message |

平台默认输出封套 code（Double）与 result（Object）保留。自定义结果字段使用 String、非必填，以便失败时只返回失败原因而不伪造正文或操作标识。matchesJson 是候选项 JSON 数组的字符串，每项包含 name 与 path，空列表为 []；不把它当成原生 Array 字段。baseHash 必须原样使用 ReadNote 的 contentHash，撤销 operationId 必须来自实际写入结果。

验证：刷新列表后六项工具及六个版本存在；逐项重新打开配置，核对描述、输入字段、隐私/必填/开启设置、后台执行与结果字段均已持久化。平台侧栏“工具（12）”计入六个工具名称及六个版本行，不是创建了十二个不同工具。

本记录只证明平台配置已保存。App 尚须实现正式端插件参数与结果映射、授权范围绑定、保存/冲突协调与真机调用；现有本地 mock 的运行接口不能据此宣称已接通。发布与 App 最低支持版本配置须待实际接线版本确定。

## 7. ListVaults 平台配置增量（2026-10-28）

用户授权在现有插件工具页配置 `ListVaults`（列出知识库）。已创建并保存工具版本 **0.1.0**，actionId 为 `969d2b4bc2e44173bc5ea8f713545366`，与既有工具版本保持一致，不把用户所说插件 v1 自动改写为工具 1.0.0。

- 描述：查询用户已授权访问的知识库，返回标识、名称、类型、是否当前库；不读正文，不扩大授权，后续工具使用返回的真实 vaultId。
- 执行：后台执行，不涉及端侧 App 页面操控；未新增权限、测试用户或 App 最小支持版本声明。
- 输入：无参数，不要求用户先提供尚未发现的 vaultId。
- 输出：保留平台 `code`（Double）与 `result`（Object）封套；result 下 `vaultsJson`、`message` 均为 String、非必填。vaultsJson 为数组 JSON 字符串，每项含 `vaultId`、`name`、`type`（local/git）、`isCurrent`（Boolean）；空列表为 `[]`。不返回沙箱绝对路径、远端凭据或正文。
- 验证：页面提示“保存成功”；刷新重新读取，工具名称/版本、描述、后台执行、无输入及两个输出字段均持久化。侧栏工具（14）计入七个工具名称和七个版本行。
- 平台插件当前显示“已上架”，这是本次读取到的现状；未点击升级、提交审核或发布，也未核实新增工具是否已包含在在线发布版本中。此前 §6 草稿状态为历史记录。

**本地实现进度（2026-10-28）**：已新增 `InsightIntentExecutorImpl` 后台执行 `ListVaults`，并在 `insight_intent.json` 注册 `ListVaults` / `0.1.0` 映射。执行器只返回 App 注册的 local/git 库 `vaultId`、`name`、`type`、`isCurrent`，不序列化注册表中的远端地址、认证用户名或私有标识；结果按平台 `code` / `result` 封套返回。API 26 SDK 构建成功，profile 已打入 HAP；未做 API 24 / XT2 或小艺平台真实调用。六项笔记操作工具尚未接入正式执行器；`CreateVault` 进展见 §8。发现列表不代替后续工具的目标授权校验。

## 8. CreateVault 平台配置增量（2026-10-29）

- 工具：`CreateVault`，版本 `0.1.0`；用户明确要求在现有“曜石笔记”插件添加该工具。Action ID：`7bf2ad1eee1546668eb94dedddef88ea`。
- 描述：用户要求新建本地知识库时，按名称创建空白库并返回实际 `vaultId`、名称和类型。名称按 App 既有清理规则处理；重名时追加 `-2`、`-3` 等后缀。创建后不切换当前库，不导入已有本地目录。
