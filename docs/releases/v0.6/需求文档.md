## 1. 版本定位

让小艺通过经核实的 HarmonyOS 入口操作当前授权的本地笔记库。先在 v0.5 样例练习笔记验收，再验证其他本地库；不把 Git 版本记录设为前置。

## 2. 完成判定

真正的小艺入口可调用笔记操作，能定位、读取、创建、追加和细粒度修改，返回准确结果；修改可保护当前编辑内容，失败不损坏文件。普通按钮或假回复不算接入完成。产品交互以本版交互设计为准：笔记页“Agent 对话”拉起平台托管对话面板，在小艺内聊天并通过端插件操作笔记；明确指令直接执行并返回真实结果，App 提供实际变更与一次撤销；不增加写入前确认弹窗。

## 3. 需求清单

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| 1 | 官方能力核实 | 先核实 API 24 的接入入口、意图声明、生命周期、参数/返回值及权限，证据归档到 harmonyos；未知关键接口不编造 |
| 2 | 定位与读取 | 用 vaultId + 库内相对路径唯一定位，复用文件名列表，不等待 v1.1 正文索引；不能访问库外、隐藏内部数据或其他未指定库 |
| 3 | 创建与追加 | 复用现有创建/保存服务；重名按现有规则返回实际路径，不覆盖旧笔记；UTF-8 正确 |
| 4 | 锚点编辑 | 先读后改，锚点必须唯一；原文已变化、锚点缺失/重复则拒绝，返回可操作信息 |
| 5 | 编辑保护与撤销 | App 内有未保存编辑时先协调保存或拒绝；写前保留一次本地前像，撤销时确认当前内容仍等于该次修改结果，避免覆盖后续编辑；不依赖 Git |
| 6 | 真实联调 | 样例练习中完成读→追加→锚点修改→撤销，sm/md/lg 与前后台生命周期分别记录；不声称 API 26 结果等于 XT2/API 24 |
| 7 | 操作交互设计 | 笔记页按钮→小艺托管面板聊天→端插件操作→返回笔记与撤销；覆盖不可用、拉起失败与关闭返回；见 [交互设计](交互设计.md)。本轮仅原型，不改变接入排期 |
| 8 | 库内读书对话 | 围绕发起时授权的库和笔记阅读与沉淀；App 校验工具目标范围，平台会话由小艺管理，不承诺映射为 App 本地会话；跨库联合对话不在首期 |

## 4. 明确不做

自动 commit/push、后台 Git、批量改写、整篇/整库删除、跨库全局检索、自动发送正文至自建第三方服务均不在首期。小艺平台自身能力与权限按实际文档核实，不猜测数据流或审核要求。

## 5. 技术约束

见 [API 笔记 F 组](../../harmonyos/api_notes.md)；F-C 的 Web/git 限制不再阻塞本地文件操作，但入口与生命周期仍必须核实。写入继续 AtomicFile、路径继续统一解析器，撤销前像放库外私有目录，不混入笔记与搜索。幂等/失败/并发冲突用单测验证，不做模拟器崩溃实验。
