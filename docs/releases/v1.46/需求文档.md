# v1.46 需求文档 —— 焦点与崩溃兜底加固

> 状态：开发中，2026-11-08 立项。来源：[需求池 T 组](../../requirements_backlog.md#t-焦点与崩溃兜底加固2026-11-08)。

## 1. 目标与范围

按 2026-11-08 官方答复（[qa 归档](../../harmonyos/qa/2026-11-08_焦点requestFocus错误码与全局兜底答复_API24.md)，结论见 [api_notes L-19 / L-20](../../harmonyos/api_notes.md)）加固两次 DFX JSCrash 暴露的系统性薄弱面：

1. `FocusRequest.safely` 兜底日志区分焦点错误码（T-01）；
2. `EntryAbility` 安装 `errorManager.setDefaultErrorHandler` 全局 JS_CRASH 兜底（T-02）；
3. 修复简单模式纯文本段落宿主的引擎焦点黑框（T-03，v1.18 18.4 遗留场景回流）；
4. `focusEmptyPane` 撤除 `setTimeout(0)` 时序猜测，按 L-20 官方推荐改事件驱动（T-04，2026-11-08 用户追加）。

不改变任何焦点目标选择与产品交互；22 处调用点继续全部经由 `common/FocusRequest.ets` 收口。T-03 仅抑制 ArkWeb 给聚焦 contenteditable 宿主画的默认焦点描边（CSS `outline: none`），光标、格式栏与编辑行为不变。T-04 仅改 `focusEmptyPane` 的请求时机（定时器猜测 → 预查询 + onAppear 事件），目标选择逻辑（`emptyPaneFocusId`）原样保留。

## 3. 明确不做

- 不在 `focusEmptyPane` 之外的 21 处调用点接入预查询 / onAppear 改造：预查询挡不住 150001/150002 与「查询后、请求前销毁」窗口，就地 try-catch 已足够（焦点是尽力而为的 UX 增强）；仅 `focusEmptyPane` 因定时器时序猜测被 2026-11-06 DFX JSCrash 实证过不可靠而改造为 46.5。
- 不把兜底日志接进 `hiAppEvent`、第三方上报或任何埋点通道。
- 不移除、不绕过调用侧 try-catch：全局兜底是崩溃后的观测与可控退出，不替代就地捕获（官方定位）。

## 4. 技术约束与依赖

- 错误码族、预查询能力与 `setDefaultErrorHandler` 结论见 [api_notes L-20](../../harmonyos/api_notes.md#l-20-✅-requestfocus-错误码族--节点预查询--errormanager-全局兜底官方答复--本机-sdk-复核2026-11-08)；本机 SDK 声明行号证据见 [qa 归档](../../harmonyos/qa/2026-11-08_焦点requestFocus错误码与全局兜底答复_API24.md)。
- `setDefaultErrorHandler` 仅主线程（子线程抛 16000205），安装位置必须是 `EntryAbility.onCreate`；handler 需保存返回的前序处理器用于链式调用。
- 历史：两次 JSCrash 见 [api_notes L-19](../../harmonyos/api_notes.md)；`FocusRequest.safely` 收口与隐私约束见 `common/FocusRequest.ets` 头注释。

### 2026-11-08 追加 46.5（T-04，用户指定：撤除 focusEmptyPane 的定时器时序猜测）

- **改动**（`pages/Index.ets`）：新增 `pendingEmptyPaneFocus` 待聚焦栏位字段；`focusEmptyPane` 改「`getAttachedFrameNodeById` 预查询（L-20 推荐的已挂载查询）→ 命中立即 `FocusRequest.safely`；未命中记 pending，预查询本身异常同样落 pending」；新增 `emptyPaneFocusId`（目标选择逻辑原样抽出，注释保留 2026-11-06 崩溃上下文）与 `consumeEmptyPaneFocus`（pending + 目标 id 双守卫，同栏兄弟行先挂树不抢焦点、无 pending 无操作）；reopen 行与 `EmptyPaneAction`（带 focusId 的动作）挂 `.onAppear` 消费 pending。`setTimeout(0)` 移除。
- **设计边界**：pending 仅由 `focusEmptyPane` 写入、被目标行 onAppear 消费后清零；空栏再次出现必经 `closePaneNote` → `focusEmptyPane` 重新置位，无陈旧 pending 抢焦点路径。预查询异常不向 `closePaneNote` 的 try 冒泡（避免误报「关闭失败」），落 pending 走事件补齐。
- **测试**：`test_pane_close.mjs` 重构焦点回归段并新增 4 条（未挂载 → pending → onAppear 补齐、兄弟行不抢、无 pending 无操作、150003 双路径不崩溃）+ 1 条源级事件驱动断言（方法体无 `setTimeout`、两处空栏行挂 onAppear）→ 15/15；`test_focus_keyboard_regression.mjs` 目标对齐断言窗口适配三方法结构 → 13/13。VM 沙箱不再注入 `setTimeout`，方法体重新引入定时器会直接 ReferenceError 拦截。
