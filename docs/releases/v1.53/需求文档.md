# v1.53 需求文档 —— 导出 PDF（分享面板）

> 状态：本地实现完成（2026-11-10）。来源：需求池「导出 PDF」条目（2026-10-31 用户提出）。
> API 核实结论见 [api_notes.md AD 组](../harmonyos/api_notes.md)。

## 1. 背景

笔记分享目前有长图 / Markdown·ZIP / 文本三路（25.x）；用户需要「导出 PDF」——适合打印与通用阅读的固定版式文档。API 24 核实结论：**HMS PDF Kit**（`@kit.PDFKit`，since 5.0.0(12)）可从零构建 PDF 且无权限要求；打印框架（`@ohos.print`）需新增 `ohos.permission.PRINT`（撞硬约束 13）且出口不受控，已否决（AD2）。

用户已拍板三个设计点（2026-11-10）：
1. **页面规格：A4 竖版**（595 × 842 pt 固定，非自适应宽页）；
2. **页面图像：逐页渲染**（块边界分页，不切断文字行 / 代码块；非长图直接切页）；
3. **输出去处：分享面板加 PDF 格式**（生成后走系统分享，与长图 / ZIP 同链路；不做保存到目录）。

## 2. 需求

### 53.1 PDF Kit 服务封装（NotePdfDocumentService）

- `import { pdfService } from '@kit.PDFKit'`；A4 常量 `595 × 842` pt；页数上限 `MAX_PAGES = 100`（超限提示改用 Markdown / ZIP）。
- `isSupported()`：`canIUse('SystemCapability.OfficeService.PDFService.Core')`（AD4：设备支持未核实，必须检测）。
- `exportFromPageImages(pageJpegs: string[], pdfPath: string)`：
  `new pdfService.PdfDocument()` → `createDocument(595, 842)` → 逐页 `insertBlankPage(i, 595, 842)` + `addImageObject(jpg, 0, 0, 595, 842)`（全幅贴页，渲染层已按 A4 比例留白）→ `saveDocument(pdfPath)` → `releaseDocument()`。
- 任一步返回 `false` / 抛错：清理半成品 PDF（存在即删）后抛带用户文案的错误；`releaseDocument()` 在 finally 兜底。

### 53.2 Web 侧 A4 逐页分页（mdpreview）

- 新纯函数模块 `web/mdpreview/src/pdfPagination.mjs`（不依赖 DOM，Node 可切片测试）：
  - `MAX_PDF_PAGES = 100`；
  - `computePdfPageTops(bounds, pageHeight)`：输入块边界数组（每项 `{ top, bottom }`，页面坐标），输出每页顶部偏移数组。算法：顺序贪心——块放得下当前页则继续；放不下且块高 ≤ 页高则新页从该块顶开始（**不切断行 / 块**）；单块自身超页高则按页高硬切兜底（块顶 == 当前页顶时同理）；页数超上限抛错；
  - `pdfBottomPadding(tops, pageHeight, scrollHeight)`：末页补白 = `max(0, 末页顶 + 页高 − scrollHeight)`，保证最后一页快照完整。
- `index.ts` 新增 `preparePdfPages(id, pageHeightVp)`：等 mermaid / 本地图片 / 双帧（与 `requestShareCaptureMetrics` 同等待）→ DOM 遍历收集 `#content` 顶层块边界（`getBoundingClientRect` 差值 + scrollTop，避免 offsetParent 歧义）→ 调纯函数算 tops → 设 `padding-bottom` 补白 → `scrollTop = 0` → 双帧 → 回传 `{ pageCount, pageTops }`（tops 序列化为 JSON 字符串，经现有 `onShareCaptureResult` 通道）。
- 水印与长图同源：`appendShareWatermark` 的 footer 在文档流内，自然作为末块参与分页。
- 复用现有 `setShareCaptureScrollTop` 逐页定位；页面快照即整页，无裁剪。

### 53.3 ArkTS 捕获链路（Index）

- 复用隐藏捕获层（`ShareImageCaptureLayer`，快照组件 id 不变），新增 **PDF 模式**分支：
  - 组件尺寸固定 A4 比例：宽 `700` vp、高 `700 × 842 / 595 ≈ 990.59` vp（不取整，保持精确比例；快照物理像素取整误差 ≤ 1 px，全幅贴页无感）；
  - 主题固定**浅色**（PDF 是文档，不做深色底；`themeOverride: 'light'`，不写入用户长图外观偏好）。
- `prepareNotePdfShare(vaultId, notePath, itemName)` 流程：
  syscap 检查 → 读编辑器内容 → 挂捕获层（PDF 模式）等 Web 就绪 → `requestShareCaptureMetrics`（等 mermaid / 图片）→ `appendShareWatermark` → `preparePdfPages(页高 vp)` 得 tops → 逐页：`setShareCaptureScrollTop` → `getComponentSnapshot` → 首页校验快照宽高比（偏差 > 1% 报错）→ JPEG 写盘（quality 92，复用 `NoteImageShareService.writeJpeg`，逐页 release，不同时持有全部 PixelMap）→ `NotePdfDocumentService.exportFromPageImages` 合成 → 打开文件预览分享。
- 会话与临时文件：复用 `NoteShareService` 会话目录（`sharePath`，24h 过期清理既有机制）；页 JPEG 与 PDF 都在会话目录内，失败时整目录清理。
- 取消语义与长图一致（`shareCaptureCancelled` / `cancelShareCaptureRequests`）。

### 53.4 分享面板接线

- 笔记作用域格式列表新增：`{ value: 'pdf', label: 'PDF 文档', detail: 'A4 竖版逐页排版，适合打印与通用阅读。', icon: 'doc' }`；**syscap 不支持时不显示该行**（优雅降级，不出不可用入口）。
- `prepareShare` 新增路由：`format === 'pdf' && scope === 'note'` → `prepareNotePdfShare`；生成完成走 `ShareFilePreviewDialog`（format `'PDF'`），分享 utd 用精确类型 `UniformDataType.PDF`（AD3；`openShareFilePreview` 加可选 utd 参数，默认 `FILE` 不影响 ZIP）。
- 生成期间与 ZIP 一致直接 await（无进度对话框）。

### 53.5 红线

- **零新增权限**（module.json5 不动；打印框架路线已因此否决）。
- 笔记内容不进埋点（v1.52 红线延伸到新链路）；分享内容红线照 25.x。
- 失败不留半成品：PDF / 页 JPEG 生成失败清理会话目录；`saveDocument` 前目标路径已存在（重试场景）先删。
- token only；水印与长图同源不新增文案。

### 53.6 修复：分享不再硬依赖隐藏编辑器 Web 就绪（XT2 真机反馈）

- **现象**：真机上笔记正常显示、点分享却持续报「编辑器尚未就绪，暂时无法分享」，长时间等待不自愈。
- **根因**：`openShareDialog` 守卫检查 `editorBridgeForPath(activeFilePath()).ready` —— 即**隐藏的 CodeMirror 编辑器 Web**；用户看到的笔记由预览 Web（mdpreview）渲染，两者独立。简单体验模式编辑器层 `Visibility.Hidden`，其 Web 加载失败 / 死亡对用户完全不可见（笔记照常显示、预览编辑照常落盘），分享却被永久堵死。
- **修复**：新 helper `noteMarkdownForShare(vaultId, path)` 统一取正文 —— 桥就绪走 `bridge.getContent()`（含编辑器内未保存改动）；未就绪用 `NoteService.tryReadNote` 读库文件兜底（编辑器未就绪即不存在其未保存改动，磁盘文件即权威内容；同 8735 行 ZIP 快照流「文件为权威」既有惯例）；读取失败显式报「未能读取笔记内容，暂时无法分享」。五条笔记分享链路（文本 / Markdown·ZIP / 长图 / PDF / 守卫）全部改走该 helper；`prepareNoteImageShare` 去掉 `editor` 形参。
- 守卫只剩「没打开笔记」一种拦截（toast 改「请先打开一篇笔记」，与 `openShareNoteDialog` 同文案）。
- 红线不变：笔记内容不进埋点；失败无半成品；零新增权限。

## 3. 明确不做（本版）

- 深色 PDF、自适应宽页、双档页面规格（拍板为固定 A4 竖版浅色）。
- 文字可选中 / 可复制的 PDF（需文本层注入，成本 L，且图片态已满足打印 / 阅读主场景）。
- 页眉 / 页脚 / 页码（`addTextObject` 后置，本版只做图片页）。
- 生成进度对话框（与 ZIP 一致直接 await）。
- 保存到用户目录（DocumentSavePicker，拍板走分享面板）。

## 4. 验收标准

1. 分享笔记面板出现「PDF 文档」格式行（syscap 支持时）；点击生成 A4 竖版 PDF 并打开文件预览，确认后走系统分享，接收方得到 `.pdf` 文件。
2. 多页笔记的分页不切断文字行 / 代码块 / 表格行（块边界分页）；超页高单块按页高硬切不崩溃。
3. 末页补白完整（快照不满页时无黑边 / 拉伸）；水印出现在文档尾部。
4. 失败路径：syscap 不支持 → 面板无 PDF 行；页数超 100 → 明确报错提示改用 Markdown / ZIP；生成失败 → 无半成品残留、可重试。
5. 契约测试：分页纯函数（空内容 / 单页 / 跨页块 / 超页高块硬切 / 上限 / 补白）；源级断言（分享面板 PDF 行、syscap 检测、prepareShare 路由、module.json5 零新增权限）。
6. `arkts_check` 零错误；签名 arm64-v8a HAP 构建成功。

### 53.10 修复：长笔记长图分享报「长图分段尺寸不足」＋ prepared 视口膨胀（2026-11-11 模拟器实测）

- **故障一（模拟器复现，16KB / 30 块长笔记）**：长图分享报「长图分段尺寸不足，无法覆盖全文」。
  **故障二（XT2 真机用户报告，机制未完全定案）**：长图 / PDF 出现「一页渲染两页且内容重复」。
- **根因（web 侧布局诊断插桩实证）**：补白写在 `#content` 的 `padding-bottom` 上，而
  `#content` 是 `box-sizing: border-box`——当补白（742px）+ 原 padT（24px）超过视口高
  （710px）时内容盒被钳到 0，**盒高下限 = padT + padB = 766 > 710**，`#content` clientHeight
  虚增至 766。链路：web 侧自校验用补白**前**的 vh=710（13490 = 19×710 恰好通过）→ 回包
  `prepared.vh = 766` → ArkTS 侧校验 `13490 < 19×766 = 14554` 失败 → 报「尺寸不足」。
  诊断数值（模拟器，视口 360×710，dpr 2.875）：initial `vh=710 padB=64 cH=710.261px`；
  prepared `vh=766 padB=742px cH=766px`（修复前）。**视口本身从未变化**（ih 恒 710），
  纯粹是 `#content` 溢出导致 clientHeight 虚增。
- **修复（长图与 PDF 两链路同修）**：补白载体从 `#content` 的 `padding-bottom` 改为
  `#content` 内**流内 spacer div**（id `share-capture-spacer`，`resetShareCaptureSpacer()`
  归零后重设，重试幂等）——spacer 不参与 `#content` 盒高计算，clientHeight 恒等于视口，
  两侧校验自然一致：
  - `renderer.mjs` `shareCaptureBottomPadding(sh, vh, pageCount)` 去掉 currentPadding 参数，
    返回 spacer 高度 `max(0, vh×pageCount − sh)`；
  - `pdfPagination.mjs` `pdfBottomPadding(tops, pageHeight, sh)` 同去参，
    返回 `max(0, 末页顶 + 页高 − sh) + 1`（+1px 舍入余量沿用 53.9）；
  - `index.ts` `prepareShareCapturePages` / `preparePdfPages` 改用 spacer，prepare 先 reset
    再量 metrics。**本条修订 §53.2 中「设 padding-bottom 补白」的表述**（冻结记录，以本条为准）。
  - 补白只保证 `scrollTop` 可达（maxScroll = (n−1)×vh），长图拼接用 initial.scrollHeight，
    **补白不进最终长图**，无空白尾页问题。
- **临时诊断插桩（XT2 验收后移除）**：web `shareCaptureDebugInfo()` 附布局诊断

- **测试**：`test_pdf_pagination.mjs` 补白断言改 spacer 语义（591/1/1、291/1、去第 4 参
  throws），28/28；全仓 `node --test` 1201 测 1187 过、14 失败均为多会话混树既有基线
