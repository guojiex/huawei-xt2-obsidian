# v1.26 需求文档 —— 恢复 Git 界面入口

> 状态：Git UI 与设计已恢复；定向自动测试和 arm64 HAP 构建通过；设备、真实 provider 与 v0.3 完整验收仍待补。来源：[需求池 C 节](../../requirements_backlog.md#c-同步与数据)；用户于 2026-11-03 决定恢复 v1.23 暂隐的 Git 入口。
> 版本号不代表领取顺序。Git 底层范围仍以 [v0.3](../v0.3/需求文档.md) 的 push-only 决策为准。

## 1. 版本定位

重新开放已实现的 Git 仓库导入、同步和远端链接分享 UI。复用 Native libgit2、凭据存储、库管理和分享服务，不重写 Git 协议或数据层。

## 2. 完成判定

用户可从“导入库”选择 Git 仓库，可在当前 Git 库打开同步页并看到本地待推送数量，可在 Git 库分享已配置远端的链接；本地库与外部目录库不出现 Git 专属入口。设计稿与原生 UI 一致。

恢复入口不代表 v0.3 的设备与真实服务商验收完成；两者仍分别记录。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 26.1 | 恢复导入来源选择 | “导入库”弹窗显示“本地目录 / Git 仓库”切换；Git 表单沿用现有地址、分支和 SyncPage 凭据流程，本地目录导入不变 |

## 4. 明确不做

- 不修改 Native libgit2、认证协议、令牌存储或 Git 库数据。
- 不实现 pull、checkout、合并、强推、提交历史 / 回滚或后台自动同步；沿用 v0.3 已定边界。
- 不改变本地目录导入语义、分享文件生成方式或 `INTERNET` 权限声明。
- 不以原型、自动测试或构建替代 v0.3 的生产 UI、真实 provider HTTPS、API24 / XT2 验收。

## 5. 技术约束与依赖

- Git 操作继续由 `GitNativeService` / Native libgit2 执行；推送目标为 `xt2`，仅允许快进，远端分叉交由 PC 处理。
- Git 凭据继续通过 `GitCredentialStore` 存入 AssetStoreKit `SECRET`；令牌不得写入路由参数、日志或普通偏好。
- 样式遵循 v2 原型 token；不新增 API、权限或网络后台行为。
- v0.3 的未完成设备及真实服务商验收见 [v0.3 §6](../v0.3/需求文档.md#6-验收记录)。

## 6. 验收记录

### 6.1 需求与范围

- 已从需求池分配 Git UI 恢复，范围限于现有入口与原型。
- v0.3 push-only 技术边界未改变。

### 6.2 实现与验证

- 原生恢复导入来源切换及 Git 专属入口；同步按钮、菜单项和待推送角标沿用既有 Git 状态读取与同步页，远端链接沿用既有分享服务。v2 设计说明、导入弹窗规格与 `index.html` 原型已同步；原型只演示 UI，不执行 Git 操作。
- Git 同步入口和导入弹窗定向自动测试 **15/15**；原型 Git 示意定向测试 **1/1**。原型整套测试 **82/86**，4 项失败涉及样例图片路径、frontmatter 标签（2 项）和源码区间映射，与本次改动无关。
- 使用 DevEco 自带 arm64 JBR 25.0.2 执行 `assembleHap`，**HAP 构建成功**（33 项任务，18 执行、15 up-to-date）。`python3 tools/generators/build_changelog.py --check` 与 `git diff --check` 通过。
- 未做模拟器目视或 API24 / XT2 设备验收；真实 provider HTTPS 与 v0.3 端到端验收仍未完成。自动测试和 HAP 构建不替代这些验收。
