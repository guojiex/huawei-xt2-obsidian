# v1.79 需求文档 —— 单屏 Git 同步页简化（不展示 diff）

> 状态：已实现（2026-11-16）。设计真源：[Git 同步页设计](../../prototype/v2/Git同步页设计.md)（§2 结构图、§2B 单屏、§5 组件表）；原型入口 `?ui=2&view=sync`（切到「单屏」预设）。需求来源：用户 2026-11-16 看单屏设计稿后反馈「单屏的时候你的设计稿非常奇怪」——v1.77 把左栏改成「推送概览 + 本地改动（3 文件 + 提交说明 + 提交者名称/邮箱）」两张卡后，单屏仍沿 v1.76 的「上 44% 清单 + 下 56% diff」两段式：44% 塞不下这些内容，文件列表与提交者字段被裁、上下两块各自滚动，用户在手机上既看不到文件也没法填提交者信息。用户拍板「单屏做简化版，不展示 diff 也行」。本版只改单屏形态；宽屏 / 双屏保留 v1.78 铺满 diff 全部行为，不改 Git 语义与 diff 数据链。

## 1. 版本定位

v1.76 定单屏为「上下堆叠」，v1.77 / v1.78 持续往左栏和右栏加内容，单屏的两段式布局却没跟着改——44% 的清单区放不下 v1.77 新增的提交字段，是本版要修的结构性缺陷。

本版按用户拍板做减法：**单屏不展示逐行差异**，把「推送概览 + 本地改动清单 + 提交说明 + 提交者字段 + 底部操作」收进**一个整页滚动流**，所有内容滚动可达、不裁切、不用在两块滚动区之间切换。逐行 diff 是宽屏 / 双屏能力（v1.75 native `getFileDiffs` + v1.78 铺满查看器），单屏只做「核对文件名与增删统计后提交推送」的轻量流程。推送 / 拉取 / 分支编辑 / 令牌重试与全部安全边界沿用既有版本，不改。

## 2. 完成判定

单屏打开同步页 → 只有一个从上到下滚动的页面：推送概览卡 → 本地改动 N 个文件（M/A/D 标记 + `+N −M` 统计，**无展开箭头、点按不展开**）→ 提交说明 → 提交者名称 / 邮箱（必填）→ 底部操作栏 → 滚动能完整看到并提交 → 没有右栏 diff、没有下方割裂滚动区、没有"点文件在右侧核对正文"文案。宽屏 / 双屏：右栏 diff 贴边铺满（v1.78）与全部交互不变。

## 4. 明确不做

- 不改 diff 数据口径、native `getFileDiffs`、两份 `Index.d.ts`、`GitNativeService`；单屏只是不渲染 diff，`diffCache` 与 `+N −M` 统计仍加载。
- 不改宽屏 / 双屏的 v1.78 铺满查看器、手风琴单开、自动选中、右栏滚动。
- 不改 push-only / 仅快进 pull / 分支编辑 / 令牌重试流程与隐私边界（路径 / 正文不进日志）。
- 不改其它页面 / 弹窗视觉；不做单屏的 diff 下钻入口（用户明确「不展示 diff 也行」）。

## 5. 技术约束与依赖

- 原生 `singleScreen` 是 `@Prop boolean`，布局分支稳定，不会在页面内动态切换；原型用全局 `phone`（`viewport==='phone'`），窗口尺寸变化时 `ResizeObserver → applyViewportGeometry` 会更新并重渲染，源码对单屏分支用 `typeof phone!=='undefined'&&phone` 防御。
- `@Builder` 调用不能链式加修饰符；单屏分支移除 `this.DiffPane()` 后外层 `Column` 只剩一个 `Scroll`，需保留 `layoutWeight(1)` 撑满。
- 单屏内层清单不滚动，故 `BarState.Off` + `nestedScroll(PARENT_FIRST)`；宽屏维持 `SELF_FIRST` 键盘避让，不动。
- 颜色 / 间距只引用 token；原型改样式后同步截图。
- 真机验收（API24 / XT2）由用户执行后回填 §6.2。
