# v1.29 需求文档 —— 单屏点按笔记区收起文件列表

> 状态：⚪ 规划中；v2 原型已实现，headless Chrome 功能与截图核对通过；原生未实现、未验收。
> 对应里程碑：独立优化。领取顺序以 [实施总清单](../实施总清单.md) 为准。
> 需求来源：[需求池 P-02](../../requirements_backlog.md#p-单屏工作区体验优化2026-11-01)（2026-11-04 用户提出）。2026-11-04 在用户提供的最新 docs 上重新合入。
> 相关：[v0.10](../v0.10/需求文档.md) 文件导航推入与正文联动动画；[v1.6](../v1.6/需求文档.md) 单屏切库后保持导航打开（本版不改其语义）。

## 1. 版本定位

单屏展开文件 / 章节列表时，正文被推到右侧仍露出一部分。用户点按这部分笔记，应当收起列表回到笔记，而不是没有反应。

## 2. 完成判定

单屏导航展开时，点按右侧露出的笔记区域即收起导航；这一下只用于收起，不在正文中放光标、不触发链接或选中文字。宽屏（双屏 / 三屏）行为不变。原生与设备分别验收。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 29.1 | **点按笔记区收起。** 仅在单屏（`isSingleScreenLayout()` 为真）且导航展开时生效：被推开的工作区整块（含顶栏露出部分）作为收起区，点按 / 轻触后收起导航，等同点击导航内关闭按钮。 | 收起后回到原激活栏、原滚动位置与编辑 / 预览状态 |
| 29.2 | **首次点按只收起。** 这一下被收起动作消费：不把焦点或光标放进编辑器、不打开链接或图片查看器、不开始选区、不触发格式浮条；收起完成后再点按才正常作用于正文。 | 收起过程中正文内容与选区不变 |
| 29.3 | **可见提示。** 导航展开时，在露出的笔记区覆盖一层淡遮罩（`--scrim` 约 45% 不透明度），与导航推入动画同步淡入淡出（`--nav-duration` / `--nav-curve`）；减少动态效果时直接显示 / 隐藏。收起后遮罩**立即**不再拦截点按，只保留淡出视觉。 | 收起动画尚未结束时点按正文不被遮罩吞掉 |
| 29.4 | **焦点与无障碍。** 遮罩不进入 Tab 顺序、对读屏隐藏；键盘与读屏继续使用导航关闭按钮、Esc 与系统返回收起。点按收起后焦点回到顶栏汉堡按钮。 | 读屏不朗读遮罩；Tab 顺序不变 |
| 29.5 | **不影响既有规则。** 不改变：点选文件后收起并打开笔记；v1.6 单屏切库后保持导航打开；导航左右滑动 / 推入动画（v0.10）；宽屏导航收起规则。 | v1.6 / v0.10 既有回归不受影响 |
| 29.6 | **原型同步。** v2 原型以 `#navScrim` 实现 29.1–29.4。 | 原型不作为原生或设备验收 |

## 4. 明确不做

- 不新增导航内的左滑收起手势（另行登记）；不改变导航宽度与推入距离。
- 不把遮罩用于宽屏布局。
- 不在收起时自动保存或切换笔记（导航展开本身不改变正文状态）。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）。
- 原生需在 ArkUI 正文容器之上加可点按遮罩并消费该次手势，避免事件穿透到 ArkWeb 编辑器 / 预览；手势与命中测试接口以 API 24 SDK 与 `docs/harmonyos/api_notes.md` 核实为准。
- 复用 v0.10 导航开合状态与动画参数，不新增第二套开合状态。

## 6. 验收记录

### 6.1 原型（2026-11-04）

- 已改：`docs/prototype/v2/index.html` —— `#noteWorkspace` 内新增 `#navScrim`（`aria-hidden`，单屏 `nav-open` 时显示），点按调用既有 `closeNav` 收起并把焦点还给 `#menu`；`pointerdown` 阻止默认行为，避免穿透到正文；关闭态 `pointer-events:none`。
