# v1.88 需求文档 —— 双栏空态点击笔记不再两栏同开

> 状态：已实现（2026-11-19）。需求来源：用户 2026-11-19 反馈「双栏空态，点击一个笔记之后，两个栏都同时打开这个笔记」。根因：`Index.readAndPush`（左栏打开链路）遗留「右栏为空且未被显式置空（`rightPaneIntentionallyEmpty === false`）时，把左栏正在打开的笔记自动镜像到右栏」的初始化分支——早期右栏是跟随左栏的 reference 镜像栏；[v1.28](../v1.28/需求文档.md) 引入 `rightPaneIntentionallyEmpty` 只覆盖「用户显式关闭过右栏笔记」一种退出路径，双栏空态经其它路径进入（全新 / 空工作区、只关过左栏笔记、旧会话缺标记）时 flag 仍为 false，首次点击即两栏同开。会话恢复链路（`applyWorkspaceSession` 等）全部以 `initializeRight=false` 调用 `readAndPush`，从不经过该分支，不受影响。

## 1. 版本定位

修复交互缺陷：左栏打开笔记只进激活栏，不再自动复制到空右栏。对齐设计真源（原型 `selectNote`：文件名点击在激活栏打开）与 [v1.28 28.4](../v1.28/需求文档.md)「空栏可先点选为活动目标；点选只改变目标栏，不自动复制另一栏当前笔记；随后从文件列表选的笔记在已选空栏打开」。

## 2. 完成判定

双栏布局、右栏为空（无论是否两栏皆空）时，从文件列表点击笔记 → 仅激活栏打开该笔记，另一栏保持空态；右栏要打开笔记仍走行尾按钮、拖拽落点或先点选空栏再从文件列表选择。两栏已是同一篇时，左栏重新打开该篇的右栏基线同步不变。

## 4. 明确不做

- 不改 `setActivePane` 切换激活栏时「右栏空 + 左栏有笔记」的跟随加载（`toggleActivePane` 等切换路径的既有行为；空栏点选走 `setActivePane(pane, true)`（`preserveEmpty`），有 `test_empty_pane_target_selection` 防线，不受本版影响）。
- 不改会话恢复链路（恢复全部传 `initializeRight=false`，本就无镜像；v1.28「旧会话缺标记时按默认行为兼容」的兼容面即恢复链路本身，语义不变）。
- 不改 `rightPaneIntentionallyEmpty` 标志的其余读写（关闭右栏笔记、`setActivePane` 门控、工作区会话存取）。
- 不改原型 `index.html` 与设计文档（原型 `selectNote` 本无镜像，本版是原生向设计真源对齐，方向单向）。
- 不改「另一栏打开」的正向入口（行尾按钮、拖拽到栏落点、先点选空栏再选择）。
- 不做模拟器 / 真机验收（用户自行验收，实测结果照实回填）。

## 5. 技术约束与依赖

- 设计真源：`docs/prototype/v2/index.html` 的 `selectNote`（`activePane==='right' ? reference=id : current=id`，文件名点击仅在激活栏打开）；[设计说明](../../prototype/v2/设计说明.md)「文件名点击在激活栏打开；宽屏行尾按钮用于在另一栏打开」。
- [v1.28 28.4 / 28.6](../v1.28/需求文档.md) 语义不回退：空栏点选只改变目标栏；空栏状态进工作区会话。

### 实现说明

- 方案 A 落地为「直接删除分支」而非加恢复期门控：会话恢复链路全部传 `initializeRight=false`（`applyWorkspaceSession` 等处），镜像分支删除后无人依赖，门控会变成死代码。
- `initializeRight` 参数与 `rightPaneIntentionallyEmpty` 标志的其余语义（关闭右栏、`setActivePane` 门控、会话存取）不动。
- 测试 harness 沿用 esbuild + vm 抽源执行模式（参考 `test_workspace_open_request_guard.mjs`）。
