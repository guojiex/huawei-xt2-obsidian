# v1.66 需求文档 —— 完整应用数据导出 / 导入（应用级备份与恢复）

> 状态：⚪ 规划中（2026-11-14 立项，未落码）
> 需求来源：[需求池「本地 zip 导出 / 导入」](../../requirements_backlog.md)的「完整应用备份」后置部分（`open_questions.md` Q2，2026-11-14 用户拍板分配本版）；「系统备份（Backup Extension）」条目只做评估结论，不落码。
> 前置能力：v0.8 知识库 ZIP 导出、[v1.36](../v1.36/需求文档.md) ZIP 导入（安全校验 + 解压）、[v1.49](../v1.49/需求文档.md) 导入恢复 mtime、[v1.37](../v1.37/需求文档.md) 设置页导出入口。

## 1. 版本定位

把「整个 App 的数据」做成一个可带走、可恢复的备份文件：设置页一键导出全部库与应用偏好为单个备份 ZIP，换机或重置后选择该文件全量恢复。此前只有逐库导出（v0.8 / v1.37）与 ZIP 建库（v1.36），没有应用级备份——换机要逐库操作且丢置顶、排序、收藏、外观等偏好。

## 2. 完成判定

API26 模拟器：设置页「导出应用备份」生成单个备份文件，包含全部沙箱库（含回收站、草稿、附件、`.git`）、库注册信息与应用偏好，且不含 Git 凭据与缓存；随后「从备份恢复」该文件，库列表、笔记内容、置顶 / 收藏 / 排序 / 外观偏好与导出前一致（统计按 mtime 重算一致）；恢复前有明确的全量替换警告与二次确认；全程不新增任何权限。API24 / XT2 由用户手动验收。

## 4. 明确不做

- **不做合并式 / 增量恢复**：同名库融合、按时间增量合并均不做——全量替换语义清晰、可测试；合并是另一个需求，需要时回需求池。
- **不做云端备份 / 自动备份**：只做用户手动导出导入；定时自动备份、WebDAV / 云端上传均留池。
- **不导出凭据**：Git 令牌等敏感值只存 AssetStoreKit（硬约束 11），备份不含、恢复后需重新登录绑定。
- **不打包外部目录库内容**：外部库数据不在沙箱，备份只带注册信息；这是外部库形态的固有边界。
- **不落盘统计数据**：统计始终实时重算（既有口径），备份不含统计、恢复不迁移统计。
- **不做 Backup Extension 落码**（66.4 只出评估结论）。
- **不改既有逐库导出 / ZIP 建库**：v0.8 / v1.36 / v1.37 行为不变，应用备份是并列的新入口。

## 5. 技术约束与依赖

- 环境：ArkTS · API 24 · Stage 模型；只用 API ≤ 24 接口（AGENTS.md 硬约束 2）。
- **零新增权限**：沙箱内读写不需要权限（硬约束 13）；备份文件写入 / 读取走既有 Picker / 保存面板链路（v1.36 `ZipImportDevice`、v0.8 导出保存）。
- 路径只由 `context.filesDir` 等 Context 属性拼出（硬约束 14）；外部库访问一律走 `VaultRegistry.accessFor(vaultId)`。
- 恢复替换的完整性：整体替换前先解包校验，校验通过才动现有数据；对既有笔记文件的改写遵循既有写入安全策略（硬约束 10 / 15），失败保持原状。
- mtime 恢复复用 [api_notes Y5](../../harmonyos/api_notes.md)（`fs.utimes`，API 11+，限沙箱路径）。
- 安全上限复用 v1.36 口径（条目 / 体积 / 单文件 / 解压比率），备份导入不得放宽。
- 备份文件版本号向前兼容策略：恢复时遇到更高版本号备份明确拒绝并提示升级 App，不猜格式。
