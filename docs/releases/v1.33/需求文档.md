# v1.33 需求文档 —— 单指关节双击截图

> 状态：❌ **应用侧无法实现，结论关闭（2026-11-10）**——API 24 无任何生产可用的指关节识别 API（官方追问 + 本机 SDK 复核），指关节双击截图为系统级能力，应用零代码零权限收口；XT2 设备行为归用户实测，不影响本结论。依据见 [api_notes O5](../../harmonyos/api_notes.md#o5-指关节双击截图用户转贴答复公开帮助文档与本机-sdk-核对2026-11-05)。
> 来源：[需求池：单指关节双击页面截图](../../requirements_backlog.md)（2026-11-04 用户提出）。排期见[实施总清单](../实施总清单.md)。

## 1. 目标

在应用内使用单指关节双击，截取当前页面。暂按当前可见页面理解，截图范围和保存 / 分享方式以核实后的系统行为为准；不将其扩展为笔记全文长图。

## 2. 需求与验收

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| 33.1 | 核实 API 24 / XT2 上单指关节双击是否由系统统一识别并触发截图，应用能否接收该手势以及调用对应截图能力；记录 SDK / 官方依据，不编造接口或把推断当结论。 | 能说明适用版本、系统配置、手势归属及截图路径；无法确认时记录未知。 |
| 33.2 | 按已核实的系统能力，让应用内当前页面支持单指关节双击截图；若系统已提供该能力，检查应用是否妨碍系统手势，避免重复触发。 | 单次双击产生一次当前页面截图；普通手指触控、正文编辑及滚动不受影响。 |
| 33.3 | 覆盖单屏和展开形态、简单 / 专业模式以及截图成功与失败的适用行为；复用系统既有的截图反馈和存储方式。 | 分别记录可执行的自动检查、模拟器及 API24 / XT2 的验证结果；未验证项如实保留。 |

## 3. 边界

- 不实现全文长图、自动分享、上传或新增截图编辑功能；既有分享能力仍按其版本需求执行。
- 不新增未经核实的系统接口或权限，不干扰已有手势与笔记数据。
- 真机验收与开发并行，不作为开始实现的前提；本需求不改变当前其他版本的验收事实。

## 5. 结论（2026-11-10 关闭）

**本需求无法由应用实现，版本以「应用零改动」关闭。**

- 33.1 ✅ 已核实：API 24 无生产可用的指关节识别/监听 API；指关节双击截图属系统级能力，系统层识别消费、不透传应用。
- 33.2 ❌ 无法实现：应用既收不到该手势，也无从配合或妨碍；应用不新增任何手势识别、截图入口或权限。
- 33.3 归用户：XT2 上系统开关状态（设置 → 辅助功能 → 快捷启动及手势 → 截屏）、应用前台 / ArkWeb 焦点场景触发、折叠形态表现由用户在 API24 / XT2 实测；若系统已开启该手势则需求天然满足，若系统不支持则需求作废——两种结果都不产生应用侧代码。
- 后续如出现指关节类公开 API（或升级 API 26+ 后相关能力开放），重新开版评估，不复活本版。
