# v1.40 需求文档 —— Markdown 真源与 RDB 搜索索引双写

> 状态：规划中，2026-11-07 用户授权先设计；尚未实现、构建或设备验收。
> 对应里程碑：共享搜索基础设施，承接 v1.1、v1.35 与 v1.16 的正文搜索。
> 需求来源：[需求池 B / E](../../requirements_backlog.md#b-笔记库级能力共同前提全库索引)；用户决定见 [已定决策](../../open_questions.md)。设计详见 [设计说明](设计说明.md)。本次只交付设计，不调整当前实现领取顺序。

## 1. 版本定位

Markdown 文件继续作为笔记唯一真源，原生 RDB 持久保存可重建的搜索正文副本与全文索引。首次构建后跨重启、切库复用；文件成功保存后增量更新索引，搜索缓存失败不影响笔记保存结果。

这是单向派生的“双写”，不是两套可互相覆盖的真源，也不承诺文件系统与 RDB 的跨存储原子事务。接受原生分词搜索与现有字符子串搜索的差异。

## 2. 完成判定

在隔离库中证明首次建索引、重启复用、增量更新、后台对账、失败补偿和按库隔离均符合设计；已保存的 Markdown 不因数据库失败被回滚或覆盖；数据库与笔记发生不一致时最终以文件为准。自动测试、构建、模拟器及 API24 / XT2 分别留证，不以设计文档代表实现或验收。

## 3. 需求清单

| 编号 | 需求 | 验收点 |
| --- | --- | --- |
| 40.1 | Markdown 真源、RDB 派生正文和全文索引；数据库位于 App 私有的系统管理数据库目录，不进入知识库 | 编辑、预览、Git、导出继续读取 Markdown；删掉索引仍能打开、编辑笔记；不从 RDB 正文反写原文件 |
| 40.2 | 原生分词搜索替换现有内存正文索引；App 当前库 / 跨库与小艺正文搜索共用 | 搜索规则按设计明确验证，不要求旧结果集合相同；文件名搜索及 `QueryNotes` 的既有路径语义保持；不保留并行的内存全文引擎 |
| 40.3 | 按稳定 `vaultKey` 隔离索引并复用持久数据 | 同名文件跨库不串结果；切库不删除旧库索引；重启正常打开已有数据库，不再次清空、全量插入或全库重新分词 |
| 40.4 | 文件成功提交后增量更新，数据库失败不改写文件保存结论 | 文件失败不发布新索引；文件成功而索引失败仍报告文件保存成功；待处理任务重读当前文件后重试，不重放旧正文 |
| 40.5 | 新建、保存、改名、移动、回收站、恢复、删除、库导入及删除均接入 | 逐项验证成功、文件失败、RDB 失败和任务重复；旧异步任务不得覆盖新索引或清除新待处理任务 |
| 40.6 | 首次完整构建与重启后台对账；明确不完整与权限状态 | 重启复用索引可先返回经过权限和源文件检查的缓存结果，并表达索引更新中；每库每进程首次使用分批做正文哈希对账，只重索引变化文件；目录遍历不完整时不误删未见条目 |
| 40.7 | 数据库不可用、损坏、schema / 分词配置变化可恢复 | 失败不伪装成零条结果；索引可独立重建，不动 Markdown、草稿和撤销数据；恢复后对账能覆盖文件成功、索引未写及删除未同步的断点 |
| 40.8 | 更新共享搜索调用契约及统一访问层的必要能力 | 元信息通过 `VaultAccess` 获取，遍历须能表明上限截断 / 失败；调用方区分完整结果、缓存结果、正在构建与失败，不借用输出预算 `truncated` 表达索引陈旧 |
| 40.9 | 隐私、清理和性能验证 | 明确允许本地搜索正文副本；不分享、Git 同步或上报数据库；授权失效不通过缓存绕过访问限制；删除库 / 重置清理索引；测量首次构建、正常重开、对账、增量更新、内存与磁盘占用 |

## 4. 明确不做

- 不把 RDB 改为笔记真源，不迁移编辑、草稿、Git、附件或双链到数据库。
- 不新增内存索引快照、sidecar、云搜索、向量检索、自定义 Native 分词器或多引擎自动回退。
- 不保持旧全文子串命中集合，不承诺中文单字命中；高级 FTS 查询语法不在本版开放。
- 不新增搜索设置或独立搜索页面，状态反馈复用现有加载、结果和错误通路。
- 不接入小艺平台，不开放多文件批量修改或 `UndoBatch`；这些仍按 v1.16 的确认与恢复门槛处理。
- 不承诺对外部应用修改的实时通知、文件与数据库的全局原子提交或绝对实时结果。

## 5. 技术约束与依赖

- ArkTS / Stage，兼容 API24；原生数据库与中文全文检索依据只见 [api_notes AC 组](../../harmonyos/api_notes.md#ac-组rdb-全文索引2026-11-07-官方文档与-sdk-声明核对)。接口声明可用不代表 XT2 已验证。
- 文件访问沿用 `VaultRegistry.accessFor(vaultId)`，库身份沿用 [库身份与安全边界](../../engineering/库身份与安全边界.md)；不以显示名称隔离数据。
- 已有文件保存继续遵守 [api_notes C1](../../harmonyos/api_notes.md) 与外部访问层边界；RDB 事务只包数据库操作。
- 本版批准在 App 私有数据库持久保存搜索正文，替代旧搜索方案“不持久化正文副本”的设计选择；历史验收记录保留原状，不据此修改在线隐私政策。
