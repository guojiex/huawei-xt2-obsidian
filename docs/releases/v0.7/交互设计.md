## 1. 核心场景：读书笔记的来回讨论

只读参考用户库中的阅读日记、书籍索引和“问题导读掌握循环”的组织方式：读前设问 → 阅读后的个人回答 → 诊断与追问 → 下一轮讨论 → 沉淀概念或行动笔记。不复制私人正文、对话、个人经历或文件名到公开样例。

公开演示使用原创 `sample_vault/notes/40_阅读/读书对话练习.md`，不是实际书籍摘录。界面保留多轮消息与引用来源；本轮不把提问、诊断做成固定向导，用户可以自由对话。

入口：在原型版本标注选择 v0.7 → 查看该版 UI，进入独立“小艺对话”页。笔记页顶栏也有同版“Agent”入口；返回回到笔记页，再进入可继续当前对话。

## 3. 对话、知识库与引用

- 每段对话固定属于一个知识库。顶栏切库后切换到该库自己的对话列表、草稿与引用，不把原对话迁移到另一个库。
- 新对话初始不附带笔记；拖入/点击后形成可移除的引用卡片，显示文件名。文件列表与消息引用展示完整相对路径以区分同名笔记。
- 发送时读取明确引用的笔记内容，消息保留本轮引用的内容快照；后续追问可以沿用本段对话的引用。原型保留这些快照，但不调用模型。真实平台传递方式与范围告知须待能力核实，不能承诺全部内容只在端侧处理。
- 拖入只添加引用，不移动文件；拒绝跨库或外部文件拖入。引用失效不猜目标，要求重新选择；多个引用先逐个显示，写入目标必须明确。
- 第一版不支持跨库联合检索/对话；该意愿留在需求池，不提前做跨库权限与索引。
- 原型对话历史、草稿和写入仅在浏览器内存，刷新恢复；真实对话存储、平台上下文与持久化契约仍待接入阶段确定，不假装原型已持久化。

## 4. 写入直接执行，结果内撤销

对话本身不默认改笔记。用户明确要求创建/追加/替换，或点击“追加到引用笔记 / 存为新笔记”后直接执行，不再弹修改预览确认框。多篇同名或目标含糊时先澄清对象，澄清不是重复确认已明确的写入指令。

消息内显示：操作结果、完整目标路径、修改前后内容、“查看笔记”“撤销这次操作”。新建重名沿用不覆盖策略并显示实际名称。撤销只覆盖最近一次操作；文件有后续编辑、其他写入或目标变化时拒绝覆盖。失败保留原文、对话和输入，不返回假成功。

原型可点击体验追加、新建及一次撤销；每张写入结果独立显示，只有最近一次可实际撤销。锚点替换的真实工具仍按需求 §3 约束实施，本次不提供假模型自动定位效果。未保存编辑或引用后内容变化均拒绝过期写入，提示重新引用；连续操作先核对最新原文。

## 10. 正文中的行内笔记引用（2026-10-25）

引用不再只有整条消息的附件语义。用户先定位输入框光标，再点击文件行或拖入笔记，即在该位置插入可编辑的 `[[库内相对路径]]`。可以写“先参考 [[A.md]] 解释这一点，再参考 [[B.md]] 比较分歧”，也可在同一消息重复引用 A。发送后每处标记在原位置成为可点击的引用，文字先后顺序与换行保留。

消息内部保存有序 parts：text / note_ref（sourceId、path），另存去重后的引用内容快照。不同句子中的引用不能被重新排序为整条消息附件；重复引用只复用来源内容，不能删除其正文出现位置。App 内部结构不等于平台已支持的消息格式，真实接入时按正式协议适配并保持顺序。

输入中直接删除/剪贴引用标记会同步更新本轮引用；无效或已改名引用阻止发送并保留草稿，不静默绑定到其他文件。过去消息的引用保留原有上下文语义。存在多篇引用但写入目标不明确时拒绝固定写入场景，不擅自改第一篇；结果卡明确标注“追加到首篇引用”的按钮是独立、明确的操作。

本轮专项自动化共 27/27，新增光标插入、A/B/A 有序消息、删除/无效引用和多目标写入保护。输入区仍是 textarea 标记编辑，发送后行内按钮展示；浏览器真实视觉、光标/拖拽和设备交互仍待验，不能据此标记原生 App 已完成。

### 对话管理交互（2026-10-25）

双击列表中的对话名称或顶部当前标题弹出重命名框；列表支持 F2 键盘替代，拒绝空名并保留草稿。单击选择时不重建列表行，保证后续双击能触发。移除单独的铅笔按钮；行尾归档图标在悬停/键盘聚焦时显示，触摸设备常显。归档从最近列表移除，保留消息与草稿；归档当前对话后选择其他未归档对话，全部归档时进入空白新对话。

右上角配置 → Agent → 对话管理默认显示已归档，可筛选全部对话；逐项显示所属知识库，可恢复归档或确认删除。删除仅移除对话，不删除或回滚已写入的笔记；最后一段对话删除后进入新对话，不重新播种历史样例。原型数据仍仅在本页内存；不代表 App 持久化已交付。

参考：[OpenAI 官方 Codex 对话整理说明](https://developers.openai.com/blog/mastering-codex-remote-for-engineering#8-keep-a-clean-chat-list) 支持归档保留记录的语义；双击弹窗与设置内删除的位置按用户本轮要求设计，并非声称官方各端均使用相同手势。

2026-10-25 对话管理样例：设计稿在三个本地库各预置一段已归档对话（原创消息与草稿），首次直接打开设置 Agent 即可看到；恢复或删除后，本页内不会重新补回样例。刷新仍恢复初始演示数据，不影响 App 安装样例或用户笔记。
