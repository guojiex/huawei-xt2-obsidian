# v0.7 需求文档 —— 本地 Agent 对话工作区与 mock

> 状态：🟡 优先设计与原型实施；App 原生页面/持久化尚未实现，不把原型当装机交付。来源：需求池 G 节，2026-10-25 用户要求提高优先级，先固定回复 mock，后接小艺。
> 领取顺序：先处理本地构建阻塞与 v0.5 必要收口，随后领取本版，排在 v1.0–v1.3 前。无须等待小艺能力开通、Git clone 或后台资格。

## 1. 范围与完成判定

在 App 中提供库内 Agent 对话工作区，先使用明确标记的确定性 mock；工具是真实受控本地操作，mock 仅替代模型/平台回复。原型阶段仅操作浏览器内存样例，不冒称 App 文件写入。真实小艺接入由 v0.6 承担。

## 3. 不做

不调用小艺、其他模型或外部 MCP；不加自建服务器。后台持续运行、系统通知和平台授权待 v0.6 核实；本版显示不可用状态，不伪造授权或通知。跨库对话、全库 RAG、任意脚本/Skill 安装、批量或整篇删除、自动 Git 提交均不在本期。

## 4. 实施依据

[交互设计](交互设计.md) · [Agent 运行设计](Agent_运行设计.md) · [实现提示词](实现提示词.md)。API ≤24，所有原生工具写入走已有服务和 AtomicFile，路径只用统一解析器；不记录笔记内容至埋点。失败恢复用单测，不做模拟器崩溃/强杀/写入中断实验，不重置用户现有数据。
