### 2.1c 编辑与预览滚动跟随（2026-10-27 新增，原型已接线，待视觉及原生验收）

| 编号 | 需求 | 完成判定 |
| --- | --- | --- |
| 7.27 | 编辑区滚动带动预览跟随 | 来源：需求池 A「编辑区滚动带动预览跟随」。编辑与预览同时可见且展示同一篇笔记时，用户滑动编辑区，预览尽量显示相同源码段落；首期单向、可关闭，具体规则与验收见下。原型已接入默认开启且可保存的“跟随编辑”开关、源码行/预览块映射、单向跟随与手动预览暂停；原生 App 尚未实现，原型浏览器视觉与实际滚动手感仍待验收 |

**交互与范围**：

- 预览栏头提供“跟随编辑”开关，默认开启，保存为应用级偏好。关闭后两边独立滚动，立即停止待执行的同步；再次开启时按编辑区当前阅读位置对齐。
- 只有编辑/预览同屏时执行跟随，包括三屏展开、双屏收起目录等实际双栏布局；单屏或双屏仅切换编辑/预览时暂停，不修改用户各自的阅读位置。重新恢复同屏且开关开启后，待布局稳定再对齐。
- 以编辑区视口顶部可见的源码行/段落为阅读锚点，映射到预览块并按块内相对位置尽量对齐；首尾可达边界钳制。不可只把全文滚动百分比作为完成依据。空行归到最近的有效块；重复标题/相同文本按源码位置区分。图片、表格、代码、公式和图表高度不同，不承诺逐像素一致。
- 用户可直接滚动预览，编辑区不反向移动；松手后预览保持该处，不立即被旧同步任务拉回。下一次用户主动滚动编辑区再恢复跟随。程序化滚动不触发新的同步循环，不因光标闪烁、保存回调或后台重渲染抢回预览。
- 编辑导致重渲染、图片/公式/图表异步完成、分栏拖动及旋转后，更新映射；仍处于跟随状态时重新定位最近有效锚点，手动浏览状态则保护预览阅读位置。切笔记、库或关闭同屏布局时取消旧任务，旧笔记的异步结果不能滚动新笔记。
- 不改 Markdown 正文来存锚点；桥接只传本次笔记/渲染标识、源码位置与块内比例等必要定位信息，不在滚动事件中反复传全文，不写入正文/路径埋点。位置跨 Web 传递的 API、生命周期及 API ≤24 能力，落码前按项目知识库与实际 SDK 核实，不在需求中编造接口。
