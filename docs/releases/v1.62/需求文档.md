# v1.62 需求文档 —— 置顶区独立分组（置顶语义变更）

> 状态：原生实现完成（2026-11-13），验收证据见 §6。⏭ HAP 构建受环境策略阻断待重跑；模拟器与 API24 / XT2 目视验收待用户。
> 来源：[需求池 · Pin 置顶（文件列表 / 卡片 / 双栏）](../../requirements_backlog.md) 追加：2026-11-13 用户实测反馈 v1.50「同层最前」语义不可感知，拍板变更为置顶区独立分组。
> 本版**修改 v1.50 已交付的置顶语义**（50.1），入口与数据通道全部沿用，零迁移。

## 1. 背景

v1.50 把置顶实现为「同层最前」的显式排序权重（[v1.50 §50.1](../v1.50/需求文档.md)）。2026-11-13 API26 模拟器实测确认该链路功能正常（点击触发、状态切换、持久化、重排均通过），但语义有硬伤：

- **笔记已是所在目录第一个时，置顶后无任何可见变化**——用户原话「他已经是本目录最前面一个那你置顶了个屁」；
- 置顶笔记位于折叠文件夹时，侧栏完全看不到置顶效果；
- 行尾 12vp 小 pin 标记过弱，不构成有效反馈。

用户拍板：**置顶改为「置顶区」独立分组**——置顶笔记固定显示在侧栏文件树最顶部的「置顶」分区，跨目录可达，无论它在哪个文件夹、是否已是本层第一，置顶后立即产生可见的位置变化。

## 2. 完成判定

任意笔记（含已是所在目录第一个的、位于折叠文件夹内的）置顶后，侧栏顶部「置顶」分区**立即出现该笔记行**并可点击打开；取消置顶后该行消失；目录树内不再有同层置顶重排（恢复 v1.49 纯排序）；既有 `pinned_<vaultId>` 数据无需迁移、重启保持。

## 3. 需求清单

### 62.1 置顶区（侧栏「文件」页签内、目录树之上）

- **位置与显隐**：计数头之下、目录树之上；仅当前库至少有一篇置顶时显示；按库隔离；折叠状态按库记忆。
- **区头 = 分区标签**（沿用 [v1.54 §54.1](../v1.54/需求文档.md) 收藏区第三稿的分区标签形态与交互）：「置顶」+ 篇数，caption 字号、字重 500、字距 0.08em、muted 色，无图标；折叠箭头在区头右端，指针设备仅悬停 / 键盘焦点 / 已收起时显示，触屏常显；点区头任意处展开 / 收起。
- **目录树上方加同款分区标签「全部笔记」**（仅置顶区可见时出现）：侧栏读作「置顶 / 全部笔记」两个分区；收藏区原生落地后（v1.54 仍为设计稿）三个分区共用此标签模式。
- **行形态与收藏行同款**（首字色块 + 标题 + 所在文件夹）：
  - 首字色块：24vp 圆角方块，内为标题首字（拉丁字母大写），文字色与 14% 底色取自 callout 色板，**按所在文件夹哈希取色**（同文件夹同色形成视觉分组）；
  - 标题：small 字号、主文字色、超长 ellipsis；
  - 所在文件夹：行尾 caption、muted 色，只显示最近一级（根目录显示「根目录」），最多占行宽 40%；完整路径进悬停提示与读屏（「打开置顶的笔记：X，位于 Y」）；
  - 行高 40vp（粗指针 48vp），行间距 2vp。
- **当前笔记**：仅标题变品牌色 + 字重 500，不加底色（底色高亮留给目录树，避免同一篇笔记两处同时高亮）。
- **置顶区排序**：最近置顶在前（`pinned_<vaultId>` 数组逆序渲染，数组顺序即置顶先后，不存时间戳、不改数据结构）。
- **树中原位置保留**：置顶笔记仍留在目录树原位（置顶是顶部快捷置顶，不改变目录组织），树内行尾 pin 标记沿用 v1.50。
- 行点击在当前栏打开该笔记；**不自动展开目录树**到该笔记位置（置顶区本身即快捷入口；树内选中高亮照常切换）。
- 置顶笔记位于折叠文件夹：照常显示在置顶区（本版核心价值——不用展开就能打开）。
- 列表超高：区内滚动，上限约 5.5 行，细滚动条，不推挤目录树。

### 62.2 语义变更：废弃「同层最前」排序权重（替代 v1.50 §50.1）

- **树内排序恢复 v1.49 纯规则**：目录前文件后、同组按模式（name 字典序 / mtime 降序）、父先于子 DFS 不变式；`FileTree.resort` 不再把置顶笔记排到本层最前，两种排序模式下均不受置顶影响。
- 置顶的**唯一可见效果 = 出现在置顶区**（外加树内行尾 pin 标记）。
- 沿用不变：50.2 入口（文件行左滑操作条「置顶 / 已置顶」+ 键盘菜单「置顶 / 取消置顶」）、50.3 数据（PinStore · `file_tree_state` preferences 的 `pinned_<vaultId>` 键）、50.4 陈旧口径（改名 / 移动后旧路径留存无副作用，不自动清理）。
- LazyForEach 行键含置顶态的规则保留（切换置顶后树行 pin 标记正确刷新，faqs-arkui-219 同坑）。

### 62.3 置顶区取消置顶入口

- **触屏**：置顶区行左滑展开「取消置顶」，**滑到底松手 = 取消置顶**（提示文案「· 松手取消置顶」）——**不沿用文件树的三档删除语义**，在置顶区滑一下不该把笔记删进回收站（与 v1.54 收藏行同口径）。
- **指针设备**：行悬停 / 键盘焦点时，行尾文件夹名原位换成「取消置顶」图标按钮（pin 图标，muted 色，悬停主文字色），点击即取消、无确认。
- 树内入口（左滑 / 键盘菜单）切换置顶时，置顶区即时增删行。
- toast 反馈：「已置顶：X」/「已取消置顶：X」——v1.50 无 toast，本版补上（用户抱怨的核心就是反馈不可见）。

### 62.4 数据与生命周期

- 数据沿用 v1.50 `pinned_<vaultId>`，**零迁移**——旧数据直接以新语义渲染。
- 折叠状态新键：`file_tree_state` preferences 增 `pinSectionOpen_<vaultId>`（布尔，按库记忆，默认展开——置顶是主动行为，有置顶就该看到）。
- 删除（进回收站）：置顶区**隐藏**该行，置顶关系保留；恢复后自动回到置顶区。
- 永久删除：从置顶列表移出。
- 重命名 / 移动：置顶区标题与文件夹标注跟随树数据，置顶关系不丢。
- 陈旧条目（路径已不存在）：无副作用、不自动清理（50.4 口径）。

### 62.5 红线

- 置顶的标题 / 路径 / 篇数**禁止进埋点**（H 节「笔记内容禁止进埋点」红线延伸）。
- 零新增权限；颜色 / 圆角 / 间距 / 字号只引用 token（硬约束 17）。

## 4. 明确不做（本版）

- **置顶笔记从目录树中移除**（微信式「提到列表最前」）——评估后不做：树是库目录的映射，置顶笔记从树里消失会让按目录找笔记的用户困惑；树内保留 + 行尾 pin 标记 + 顶部置顶区。
- 置顶区手动拖动排序——回需求池（置顶超过约 10 条后有价值，届时与「按文件夹分组」一起考虑，与 v1.54 收藏同口径）。
- 跨库置顶聚合、置顶区内搜索、置顶笔记分组。
- 收藏区原生落码——v1.54 仍为设计稿，本版不顺带做；置顶区按 v1.54 §54.1 既有设计语言实现，收藏落地时**共用分区标签与行组件**，不写两套。
- 再出一版原型设计稿——分区标签 / 首字色块 / 行形态均复用 v1.54 已定且经用户走查的设计，不重复出稿；用户要求原型先行时再补。（2026-11-13 用户要求原型先行，已补——见 §6 验收记录「原型 v1.62 化」。）
- referenceOnly（Agent 引用侧栏）：不显示置顶区（保持纯树，与 v1.50 口径一致）；「章节」页签不加置顶区。
- 卡片 / 双栏视图接入：两类视图尚不存在，落地时各自接入。

## 5. 技术约束与依赖

- 本版只改**渲染与排序语义**，入口与数据不动：
  - `FileTree.resort` 去掉 `pinned` 参数（`model/FileTree.ets`），`compareSiblings` 移除置顶分支；`test_file_pin.mjs` 的 8 项 resort 契约全部重写为置顶区契约，`test_file_list_sort.mjs` 适配新签名；
  - `FileTreeView` 渲染分两段：置顶区（分区标签 + 行列表）与目录树（「全部笔记」标签 + 既有 TreeList），数据同源于一次 `FileTree.scan`；
  - 置顶区行是独立列表段，LazyForEach 键独立空间（如 `pin-<relPath>`）；树行键沿用 v1.50 规则。
- 视觉规格对齐 [v1.54 §54.1 第三稿](../v1.54/需求文档.md)：分区标签样式、首字色块（callout 色板按文件夹哈希）、行高 40/48vp、行尾文件夹 40% 上限、**行尾图标列对齐规则**（`--touch` 宽按钮、右侧留 `--s1`，与树行尾图标同列）。
- 置顶区行左滑用独立手势（滑到底 = 取消置顶），不复用树行 `swipeAction` 的 `onAction` 删除回调。
- 目录行无置顶入口、referenceOnly 无置顶区（防线断言沿用并扩展）。
- 涉及文件预估：`FileTreeView.ets`（置顶区渲染 + 取消置顶手势）、`FileTree.ets`（resort 收窄）、`tools/tests/test_file_pin.mjs` / `test_file_list_sort.mjs`（契约重写）。

### 实现取舍（需求内部冲突以 §5 / 62.2 为准）

1. 行高统一取粗指针档 48vp（`Size.touch`），细指针 40vp 未在原生做设备类型分支（目标设备 XT2 为触屏）；区头折叠箭头常显（原生未核实指针类型 API，触屏可发现性优先），未按「指针设备仅悬停 / 焦点 / 收起时显示」降噪。
2. §62.4「重命名 / 移动后置顶关系不丢」与 §62.2「沿用 50.4 陈旧口径」及 §5「入口与数据不动」冲突，按后者执行：旧路径留存在偏好但不显示，用户对新路径重新置顶即可；若要路径跟随需另立版本。
3. §4 明确不再出原型设计稿，`docs/prototype/v2/index.html` 仍为 v1.50「同层最前」演示语义 —— 原生与原型在此项上按需求有意不同步。（2026-11-13 被「改设计稿」用户指令推翻，原型已同步 v1.62 语义并补出置顶 + 收藏同框布局，见 §6 验收记录；本条留档。）
