# v1.0 需求文档 —— 首个可日用版本

> **状态**：⚪ 规划中；按本地编辑与 v0.5 样例范围验收；小艺不作前置；Git v0.3 后置（2026-10-25 调整）
> **对应里程碑**：M5

## 1. 版本定位

收口三折叠本地 Markdown 编辑、共享样例体验，完成 MVP 的性能、恢复和视觉验收。

## 2. 完成判定

按 [`mvp_design.md` §8](../../mvp_design.md) 的完整清单在 XT2 真机验收；暗色、长文、空库和离线场景可正常使用，恢复与失败处理单测通过，未通过项不得以“代码已写”替代。

## 3. 需求清单

| # | 需求 | 来源 | 验收点 |
| --- | --- | --- | --- |
| 1 | 深色模式 | 需求池 D「深色模式」 | 跟随系统时，ArkUI、编辑 Web 和预览 Web 颜色一致，正文、代码块可读 |
| 2 | 大文档与大目录性能 | 需求池 E「大文档优化」「大目录懒加载」 | 用 [`mvp_design.md` §8](../../mvp_design.md) 的 100KB 文档和 1000 篇目录指标真机测量；未达标时只优化测出的瓶颈 |
| 3 | WebView 首次打开体验 | 需求池 E「WebView 预加载」 | 测量首次打开编辑器与预览的等待时间；首帧有可识别的加载状态，内容最终正确显示 |
| 4 | 空状态与恢复路径 | 需求池 E「草稿与崩溃恢复」、需求池 B「回收站」 | 空库可直接创建首篇笔记；草稿恢复按 v0.2 执行单测，误删恢复验证正常回收站流程 |
| 5 | 全链路回归与发布 | [`mvp_design.md` §8](../../mvp_design.md) | 单屏、双屏、三屏下完成建库、写笔记、预览、保存、共享样例；小艺待能力开通后在 v0.6 验收，Git 相关回归留在 v0.3 |
| 6 | 三屏分栏宽度拖拽调节 | 需求池 D「分栏宽度拖拽调节」 | 三屏展开态两条分隔条（目录\|编辑、编辑\|预览）可拖动实时改宽；松手时距折痕 16vp 内吸附；每栏最小约 190vp（18%）；跨折痕不拦截、折痕标红警示；双击把手与设置页「恢复等分栏宽」均恢复等分并清除持久化；重启 / 切形态后宽度保持；md / sm 无可拖动分隔条（维持等分）。交互与取舍以原型 `docs/prototype/index.html` 为准（2026-10-25），把手选中态用品牌 token（硬约束 17） |

## 4. 明确不做

- 全文搜索、双链、插件、Git 同步：MVP 边界见 [`mvp_design.md` §1](../../mvp_design.md)。
- zip 导出：仍按 [`open_questions.md` Q2](../../open_questions.md) 的触发条件重新评估，不因进入 v1.0 自动纳入。
- 后台自动同步：沿用前台同步决策。

## 5. 技术约束与依赖

> **测试方式（2026-10-23 用户决定）**：不在模拟器上主动制造崩溃、强杀进程或写入中断。恢复与失败处理使用单测，通过可控时钟、存储失败注入和重新创建服务实例验证；模拟器仅验证正常编辑、保存、切换和重新打开。单测不代表真实进程中断或设备级原子性已验证；历史实测记录保留。

依赖已实现本地功能及 v0.5 的验收结果；v0.6 小艺待用户开通能力后独立推进，Git v0.3 不作本地范围发布的前置；涉及 HarmonyOS 行为时以 [`api_notes.md`](../../harmonyos/api_notes.md) 为准。v1.0 发布动作按 [`releases/README.md`](../README.md) R9 执行。
