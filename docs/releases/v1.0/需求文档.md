# v1.0 需求文档 —— 首个可日用版本

> **状态**：⚪ 规划中；v0.1–v0.4 全部通过验收后进入发布阶段
> **对应里程碑**：M5

## 1. 版本定位

收口三折叠本地 Markdown 编辑与 Git 回写体验，完成 MVP 的性能、恢复和视觉验收。

## 2. 完成判定

按 [`mvp_design.md` §8](../../mvp_design.md) 的完整清单在 XT2 真机验收；暗色、长文、空库、离线和进程中断场景可正常使用，未通过项不得以“代码已写”替代。

## 3. 需求清单

| # | 需求 | 来源 | 验收点 |
| --- | --- | --- | --- |
| 1 | 深色模式 | 需求池 D「深色模式」 | 跟随系统时，ArkUI、编辑 Web 和预览 Web 颜色一致，正文、代码块可读 |
| 2 | 大文档与大目录性能 | 需求池 E「大文档优化」「大目录懒加载」 | 用 [`mvp_design.md` §8](../../mvp_design.md) 的 100KB 文档和 1000 篇目录指标真机测量；未达标时只优化测出的瓶颈 |
| 3 | WebView 首次打开体验 | 需求池 E「WebView 预加载」 | 测量首次打开编辑器与预览的等待时间；首帧有可识别的加载状态，内容最终正确显示 |
| 4 | 空状态与恢复路径 | 需求池 E「草稿与崩溃恢复」、需求池 B「回收站」 | 空库可直接创建首篇笔记；异常退出与误删恢复分别按 v0.2 的原有承诺验收 |
| 5 | 全链路回归与发布 | [`mvp_design.md` §8](../../mvp_design.md) | 单屏、双屏、三屏下完成建库、写笔记、预览、保存、Git 导入与回写；同步失败时本地内容保持完整 |

## 4. 明确不做

- 全文搜索、双链、插件、AI 编辑：MVP 边界见 [`mvp_design.md` §1](../../mvp_design.md)。
- zip 导出：仍按 [`open_questions.md` Q2](../../open_questions.md) 的触发条件重新评估，不因进入 v1.0 自动纳入。
- 后台自动同步：沿用前台同步决策。

## 5. 技术约束与依赖

依赖 v0.1–v0.4 的验收结果；涉及 HarmonyOS 行为时以 [`api_notes.md`](../../harmonyos/api_notes.md) 为准。v1.0 发布动作按 [`releases/README.md`](../README.md) R9 执行。

## 6. 验收记录

> 发布后填写：逐项真机实测值、失败项、修复和发布版本号。
