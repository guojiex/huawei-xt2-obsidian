<summary>历史选型备注（首次实现已前移）</summary>

> **落码选型备注（2026-10-25 官方组件调研，本机 API 24 SDK 实证 + 用户拍板）**：**展开态用官方、收起态用自绘**。
> ① **展开态（目录｜编辑）**：`Navigation` 分栏模式 `enableDragBar(true)`（@since 14，默认 false）+ `divider({ color, startMargin, endMargin })`（@since 23，默认色 `#33000000`）+ `navBarWidth` / `navBarWidthRange` / `minContentWidth`。这就是微信 / 华为备忘录同款按钮。编辑｜预览放 content 区内部固定等分。**自觉放弃折痕吸附**——官方 dragBar 无吸附能力，这是选官方的代价；折痕标红保留（自绘覆盖层，pointer-events:none）。
> ② **收起态（编辑｜预览）**：**不用 Navigation Split**——官方文档明示 `hideNavBar=true` + Split = 单栏，收起态要么整页单栏、要么把编辑器塞进 NavBar 槽位（UI 树两形态、状态跨挂载保持、NavDestination 路由栈全部受扰），滥用代价远超收益；`RowSplit`（@since 7）分割线初始化后固定（编程重置不响应）且无任何样式属性，`SplitContainer` 不在 API 24 SDK，`FoldSplitContainer` 已由 A2-bis 否决。故**自绘 overlay 把手**：PanGesture + `@State` 百分比 + preferences 持久化，行为全栈（吸附 / 钳制 / 双击重置 / 设置页重置）。
> ③ **持久化**：目录宽与收起态编辑宽两份独立状态（原型 localStorage 演示键 `xt2-proto-split`，App 侧进 preferences）；URL hash **不带**栏宽（临时手感，不分享）。
> ④ **重置**：双击把手与设置页「恢复等分栏宽」共用同一 `resetSplit`（两个值都回等分、都清持久化）。

</details>

### 2026-10-31 布局优化增量（需求 7）

- **决策**：用户审阅**自适应布局审计文档**（该文件从未入库，本仓库与本机路径 `layout-optimization/adaptive-layout-optimization.md` 均已核查不存在）后拍板，只采纳结构性必然有收益、无回归风险的两项；审计其余项经核实不做（理由见下）。本决定对这两项取代此前「未取得数据前不做无依据性能优化」的立场；[`mvp_design.md` §8](../../mvp_design.md) 的 1000 篇 / 100KB XT2 实测仍待验，本记录不替代。
- **代码**：`FileTreeView.ets` 新增 `TreeRowDataSource implements IDataSource`——文件树每次变化都是整树重扫，故只走 `onDataReloaded` 整体通知、不做按索引增量（规避 LazyForEach 增删不同步的经典错误，faqs-arkui-1355）；`ForEach` → `LazyForEach`，键值逻辑（展开 / 选中态进键，faqs-arkui-219 踩坑）逐字保留；`List` 增加 `.cachedCount(10)`。`NoteDialogs.ets` 新建 / 移动两处目录选择器 `.height(160)` → `.constraintSize({ maxHeight: 160 })`（本 SDK 无独立 `.maxHeight()` 属性）：目录项少时收缩不留白，超过 160 仍内部滚动，上限不变。
- **验证**：`devecocli check arkts` 两文件 0 错误（85 条告警为全仓既有基线）；`tools/tests/test_file_tree_keyboard.mjs` 8/8；`tools` 全量 `node --test` 236 用例改动前后同为 216 过 / 20 败——stash 改动复跑基线确认 20 败为本机（Windows）既有，与本次无关；签名 HAP 构建 `BUILD SUCCESSFUL`。构建前首次在本 Windows 机器执行 `native/git2_napi/build.sh` 预构建（libgit2 v1.9.7 + mbedtls v3.6.7 + napi 交叉编译成功），该编译证据属 v0.3 Native 路线，不证明设备运行。
- **审计其余项不做及理由**：List 默认已有 Spring 回弹（官方 FAQ faqs-arkui-113），补 `edgeEffect(Spring)` 为无效功；Scroll 默认 `EdgeEffect.None`（官方文档），加回弹是交互手感决策非缺陷，未采纳；`displayPriority` 属设计决策，「七能力填空」不构成需求；NoteDialogs 场景 LazyForEach 无效（Scroll 不支持懒加载，官方文档）；RelativeContainer 扁平化与固定宽高收益不成立且与三折叠断点自适应冲突；QuickSwitcher 等其余 ForEach 列表条目少或结果有上限，改造收益不成立。
- **待验**：大目录懒加载与目录选择器收缩的 API26 / API24 / XT2 设备行为；§8 性能指标实测不变。
