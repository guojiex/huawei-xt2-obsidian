# v1.49 需求文档 —— 文件列表按时间排序

> 状态：本地实现完成（2026-11-09），待模拟器 / XT2 目视验收。来源：[需求池 · 文件列表按时间排序](../../requirements_backlog.md)（用户授权「全都做，按顺序」，本版承接该条）；同日紧随 v1.48 收口后领取。
>
> 范围裁定（立项时定，写进本版不回滚）：
> - **创建时间本版不做**。理由：两类库的现有 stat 链路（沙箱 `fileIo.Stat` 与外部 Native `statByFd`）都只稳定提供 `mtime`；POSIX `ctime` 是 inode 变更时间而非创建时间，且外部 Native 侧不返回它——硬约束 14 要求沙箱 / 外部同序，单侧能拿到的字段不能进统一排序口径。需求池该条按「名称 / 修改时间」两档部分交付，创建时间待文件系统能力核实后另立。
> - 排序只作用于**侧栏文件树**（`FileTreeView`）；快速切换（QuickSwitcher）、跨库搜索、小艺工具的列表顺序不变（它们是检索 UI，名称序是翻页稳定的前提）。

## 1. 需求

### 49.1 排序模式与语义

文件树新增两档排序，可切换：

| 模式 | 语义 |
| --- | --- |
| 按名称（默认，现状） | 每层目录内：目录在前、文件在后，同组字典序升序 |
| 按修改时间 | 每层目录内：目录在前、文件在后；同组内按文件 mtime **降序**（新的在前），mtime 相同按名称升序稳定；目录用自身 mtime |

不变式：父目录永远在子项之前（扁平化 DFS 结构不破）；目录 / 文件分组先后与现状一致（视觉模型不换）。

### 49.2 切换入口

侧栏目录头（「N 篇笔记」行）新增排序按钮（sort 图标 + bindPopup 菜单，与库切换菜单同款弹层模式）：两个选项「按名称排序」「按修改时间排序」，当前项尾部对勾；读屏带「当前按 X 排序」。Agent 引用侧栏（`referenceOnly`）不显示入口，但树沿用已持久化的排序。

### 49.3 偏好持久化

排序偏好为 **App 级单一偏好**（不分库），存 preferences（`file_tree_state` 库内新增 `sort_mode` 键），默认 `name`；坏值回退 `name`。切库、重启后保持。

### 49.4 实现边界

- 排序在 `FileTree.scan` 之后对**可见行**做纯逻辑重排（stat 只打可见节点，折叠子树不消耗）；沙箱 / 外部库共用同一重排代码，不按 `rootKind` 分叉（硬约束 14）。
- stat 拿不到（文件消失 / 授权抖动）按最旧处理，排序不崩、不抛。
- 外部库每个 stat 一次根 fd 开关，大库全展开时开销待真机实测记录，不阻塞本版。

## 2. 不做

- 创建时间排序（见上，能力受限，不做不承诺）。
- 排序方向切换（升 / 降序反转）、每库独立偏好、目录文件混排——需求池未提，不擅自加。
- 快速切换 / 搜索 / 小艺工具的排序变化。

## 3. 完成判定

契约测试（纯逻辑重排：名称等价、mtime 降序、平局稳定、父先于子、stat 失败兜底、折叠不消耗）+ 入口 / 持久化源级断言全绿；`arkts_check` 零新增错误；签名 HAP 构建成功；模拟器 / XT2 目视（菜单样式、切换即生效、重启保持）待用户验收。

## 4. 验收记录
