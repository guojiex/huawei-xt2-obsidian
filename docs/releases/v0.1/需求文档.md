# v0.1 需求文档 —— 三形态骨架 + 多库

> **状态**：🟡 开发中（当前版本）
> **对应里程碑**：M0 + M0.2
> **版本定位**：装到 XT2 上能跑起来，三种形态下布局都正确，能建库、切库。

## 1. 版本定位

第一个"能装机能看"的版本。**此时还不能写笔记** —— 这一版只交付三件事：
形态骨架正确、库模型成立、状态不丢。

它是后面所有版本的地基：v0.2 往骨架里填编辑能力，v0.3 往库上接 Git。

## 2. 完成判定

> 在 XT2 上单屏 / 双屏 / 三屏展开三档各转一圈，布局按断点正确切换且无控件溢出；
> 折叠展开后当前所在库不变；能新建本地库、改名、删库、切库，重进应用后库列表还在。

## 3. 需求清单

### 3.1 形态与布局（M0）

| # | 需求 | 来源 | 验收点 |
| --- | --- | --- | --- |
| 1.1 | 三档断点系统：sm / md / lg | `mvp_design.md` §2 | 用 `window.on('windowSizeChange')` + `px2vp()` 计算，**不用 `getFoldDisplayMode()` 做形态分支** |
| 1.2 | 三栏骨架**自绘** | 已定决策 | 单屏单栏 + 抽屉；双屏态各 **50%**；三屏展开态各 **1/3**。`FoldSplitContainer` ❌ 已否决 |
| 1.3 | 栏宽规则 | 已定决策 | **一栏 = 一整块物理屏，栏边界压折痕**；不是"先定栏宽再躲折痕" |
| 1.4 | 折痕处理 | `api_notes.md` A2 | 本版本**只做标注**（打印 `getCurrentFoldCreaseRegion()`），**不参与计算**；真机校准后写成常量表替换等分 |
| 1.5 | 形态切换状态保持 | 需求池 D 节 | 折叠/展开切换时当前库与当前选中项不丢（UIAbility 不重建，见 `api_notes.md` A4） |
| 1.6 | 三屏态 FoldStatus 打印 | 真机清单 | 真机上打印实际返回值建映射表（官方未记载三折叠返回什么） |

### 3.2 库模型（M0.2）

| # | 需求 | 来源 | 验收点 |
| --- | --- | --- | --- |
| 2.1 | 首次启动自动建 `vaults/local` | F0 | 不配任何远端也能进应用，本地库是默认入口 |
| 2.2 | 库注册表持久化 | `mvp_design.md` §4.5 | 库列表存在注册表里，重进还在；库 = `vaults/` 下一个目录 |
| 2.3 | 新建本地库 | F7 | 名字走消毒规则（过滤 `/ \ : * ? " < > |` 与控制字符，去前导点，去首尾空白；空名拒绝；重名加 `-2`） |
| 2.4 | 库改名 | F7 | 显示名 = 目录名，**改名即改目录名**；Git 库改名不影响远端 |
| 2.5 | 删除本地库 | F7 | ⚠️ **不可逆**，确认弹窗必须写明；弹窗里"建议先导出备份"这句在 zip 导出（Q2）落地前**先不要写**（别承诺没实现的东西） |
| 2.6 | 多库切换 | 需求池 B 节 | 切库后文件树/编辑器上下文归零是允许的（本版本还没有文件树） |

## 4. 明确不做

| 不做 | 原因 |

## 5. 技术约束与依赖

- 三折叠恒为 `phone`，`deviceTypes` 保持 `["phone","tablet","2in1"]` —— `api_notes.md` **A5**
- 三栏自绘、`FoldSplitContainer` 否决、栏宽规则 —— 见 `open_questions.md` 已定决策总表
- 断点机制实现要点 —— `api_notes.md` **A3**
- 沙箱读写无需权限，路径只能由 `context.filesDir` 等 Context 属性拼出 —— `AGENTS.md` 硬约束 14
- ⚠️ 所有标 ⚠️/❓ 的鸿蒙结论，**真机验证前不许写进关键路径** —— `docs/harmonyos/README.md` 铁律 5
