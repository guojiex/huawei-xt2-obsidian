# 〇、最重要的两条铁律（违反直接返工）

1. **禁止凭记忆编造 HarmonyOS API 名 / 参数 / 返回值。**
   鸿蒙很多行为官方文档没写清楚，凭通用 Android/iOS 经验猜几乎必错。本项目已经因为「照着记忆里或不确定的 API 写代码」踩过坑。
   - 写任何一个 API 之前，先在 DevEco Studio 用代码补全 / 悬浮提示确认它**真实存在且签名一致**；
   - 或在本仓库 `docs/harmonyos/api_notes.md` 里找到对应条目；
   - **两者都找不到 → 停下来，在最终报告里列出「需要确认的 API」，不要用猜测的实现蒙混过去。**
2. **严格只用 API ≤ 24 的接口。** 本项目 `compatibleSdkVersion` 是 `6.1.1(24)`，即 **API 24**。
   如果你发现某个更方便的接口是 API 25/26 才有的（例：`fileIo.listFileExt` 的 `fileFilter` 参数），**必须降级到 ≤24 的等价写法**，并在报告里注明。

# 三、本次要实现什么（v0.1 = M0 + M0.2）

**版本定位**：第一个「能装机能看」的版本。**此时还不能写笔记。** 只交付三件事：形态骨架正确、库模型成立、状态不丢。

## A. 形态与布局（自绘，不许用官方分栏组件）

1. **三档断点系统** sm / md / lg
   - 必须用 `window.on('windowSizeChange')` + `px2vp()` 计算
   - **禁止用 `display.getFoldDisplayMode()` 做形态分支**（官方说明它不返回全部形态值）
   - 断点阈值写在 `docs/mvp_design.md` §2，以那里为准
2. **三栏骨架自绘**
   - 单屏（sm）：单栏 + 抽屉式侧栏
   - 双屏（md）：**两栏各 50%**
   - 三屏展开（lg）：**三栏各 1/3**
   - ⚠️ **`FoldSplitContainer` 已被否决，禁止使用**（它的"三分栏"不是三列横排、比例只有几个预设值、面向双折叠悬停态）。具体理由见 `docs/harmonyos/api_notes.md` A2-bis
3. **栏宽规则**：**一栏 = 一整块物理屏，栏边界压折痕**。不是"先定栏宽再躲折痕"——顺序反了
4. **折痕只做标注，不参与计算**
   - 本版本仅在合适位置打印 `display.getCurrentFoldCreaseRegion()` 的返回值用于将来校准
   - **不要把它的返回值写进布局算式**
   - ⚠️ 已知该接口**只返回单个 Rect**，而三折叠有两条铰链，官方未记载三折叠返回什么 —— 所以本版本按等分实现，等真机拿到数据再换成常量表
5. **形态切换不丢状态**：折叠/展开时当前所在库、当前选中项都不能丢（UIAbility 在折叠切换时**不重建**，但你仍要保证状态存放在合适的地方）
6. **三屏态 FoldStatus 打印**：在真机上打印实际的 `FoldStatus` 返回值。
   ⚠️ **不要把猜测的映射关系硬编码**。写一个留 TODO 的打印/日志点，由真机测试者回填。
7. **目录栏可整体收起**（md / lg 两档都要）
   - 收起入口：侧栏右上角「收起 «」；唤回：顶栏汉堡按钮
   - **双屏收起** → 腾出的那栏给预览，变成「编辑 | 预览」各占一整块屏（这样**不跨折痕**）
   - **三屏收起** → 编辑区扩到 2/3，**会跨第一条折痕**。这是物理限制，不是 bug；原型里那条折痕标红并提示「被内容横跨」，照做

## B. 库模型（多库本地存储）

1. 首次启动自动创建默认本地库 `vaults/local` —— 不配任何远端也要能进应用
2. **库注册表持久化**：库列表存在注册表里，正常退出后重进还在。库 = `vaults/` 下的一个目录
3. **新建本地库**：名字走消毒规则（过滤 `/ \ : * ? " < > |` 与控制字符 → 去前导点 → 去首尾空白 → 空名拒绝 → 重名自动加 `-2`）
4. **库改名**：显示名 = 目录名，**改名即改目录名**
5. **删除本地库**：⚠️ **不可逆**，确认弹窗必须写明这一点。
   ⚠️ 弹窗里**不要写"建议先导出备份"** —— zip 导出功能还没实现，别承诺不存在的东西
6. **多库切换**：切库后上下文归零是允许的（本版本还没有文件树）

## C. 工程配套

1. **路径解析器**：库内相对路径 → 绝对路径**只有一层实现**，将来 UI 和端侧意图执行器共用。
   ⚠️ 路径**只能**由 `context.filesDir` 等 Context 属性拼出，**禁止硬编码沙箱目录字符串**
2. 中文文件名统一用**下划线**，不用空格与连字符

# 六、完成判定（验收标准）

> 在 XT2 上单屏 / 双屏 / 三屏展开三档各转一圈，布局按断点正确切换且无控件溢出；
> 折叠展开后当前所在库不变；能新建本地库、改名、删库、切库，重进应用后库列表还在。

另外必须满足：**代码能通过命令行编译**。用本仓库自带的脚本：

```powershell
.\tools\build.ps1          # 已内置 JAVA_HOME → DevEco 自带 jbr，不要手动设
```

看到 **BUILD SUCCESSFUL** 才算完成。编译失败不许交付。

# 七、交付要求

1. **每个非显而易见的设计决策，在代码里留一行简短注释说明理由**——尤其所有涉及上述硬约束的地方（为什么自绘、为什么不用某 API）
2. **所有不确定项显式列出**，不要悄悄用猜测实现覆盖：
   - 需要真机才能确定的值 → 写 `// TODO(真机校准): …` 并给合理默认值
   - 需要查证的 API → 在报告里列出
3. 更新 `docs/releases/v0.1/需求文档.md` 的「验收记录」小节（能离线自查的部分）
4. **不要修改 `docs/harmonyos/api_notes.md` 的既有结论** —— 它是单一真源。
   如果你在真机上验证出与文档不同的行为，**在报告里说明**，由我来更新文档
5. commit 信息用中文，格式：`feat(v0.1): <简述>`；一个逻辑改动一个 commit
