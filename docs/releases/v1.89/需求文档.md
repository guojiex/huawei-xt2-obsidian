# v1.89 需求文档 —— 无库只读打开单个 Markdown 文件（注册为系统 .md 打开方式）

> 状态：规划中（2026-11-19 立项）。需求来源：用户 2026-11-19 提出「增加一个新版本：不需要笔记库也能打开一个 markdown 文件，只渲染预览不编辑；注册成系统支持的可以打开 md 文件的应用」。
> 归属需求池 D 节「鸿蒙系统能力与设备特性」，与 v1.56「接收系统分享（文本 / 链接）」同族——本版补的是**文件打开入口**（`viewData` + `FileOpen`），v1.56 是分享面板入口（`sendData`），两者机制不同、互不覆盖。

## 1. 版本定位

把曜石笔记注册为系统里能打开 `.md` 文件的应用：用户在文件管理器或其它应用里点开一个 Markdown 文件、选择「用曜石笔记打开」，App 直接进入**只读预览**该文件的界面。不依赖任何已建笔记库、不入库、不可编辑、不写回源文件。核心是「把一个 .md 当文档看一眼」的最轻路径。

## 2. 完成判定

系统文件选择器 / 文件管理器把一个 `.md` 文件以 `ohos.want.action.viewData` 拉起本应用，冷启动（`onCreate`）与热启动（`onNewWant`）两条路径都能进入只读预览页，正文渲染正确、顶部显示来源文件名；全程不创建 / 不读取笔记库、无编辑入口、不修改源文件；`uris` / `skills` 声明使应用出现在系统「打开方式」列表；零新增权限。

## 3. 需求清单

### 89.1 注册为系统 md 打开方式（module.json5）

- `EntryAbility.skills` 追加一个 skill：`actions: ["ohos.want.action.viewData"]`，`uris` 含 `{ scheme: "file", type: <md 类型>, linkFeature: "FileOpen" }`。保留既有 home skill 与 v1.56 的 `sendData` skill 不动。
- **官方依据**：HarmonyOS「拉起文件处理类应用（startAbility）」指南给出 `viewData` + `scheme:"file"` + `type` + `linkFeature:"FileOpen"` 的声明范式（见 §5 链接）。`linkFeature: "FileOpen"` 大小写敏感、必填。
- **md 类型取值（已核实，2026-11-19）**：本机 SDK `udmf_meta.h:711` 明确定义 `#define UDMF_META_MARKDOWN "general.markdown"` @since 12（≤ API24）——系统存在 markdown 专用 UTD `general.markdown`，直接用于 `type`，**不用赌 `text/markdown` / `general.plain-text`**。本机 `modulecheck/module.json` schema 已核实 `skills[].uris[]` 字段集为 `scheme`（必填）/ `host` / `port` / `path*` / `type` / `utd` / `maxFileSupported` / `linkFeature`，官方范式 `type: "general.markdown"` + `linkFeature: "FileOpen"` + `scheme: "file"` 属合法声明。⚠️ 仓内旧结论「177 项 UTD 无 markdown」来自 ArkTS 侧 `uniformTypeDescriptor.d.ts` 枚举，native `udmf_meta.h` 的 `general.markdown` 未列入该枚举——两者来源不同，本版按 native 宏 + 官方 UTD 文档采用 `general.markdown`；构建期 schema 通过即落码，真机「打开方式」关联仍待验。结论补进 api_notes AF 组。
- `requestPermissions` 不动（零新增权限红线）——文件打开走临时授权 URI（见 89.3），不申请 `READ_MEDIA` 等权限。

### 89.2 冷 / 热启动 want 解析（EntryAbility）

- `onCreate(want)` / `onNewWant(want)` 判 `want.action === 'ohos.want.action.viewData'` 且 `want.uri` 非空 → 进入本版只读打开链路；非该 action 的 want（桌面启动、v1.56 `sendData`、调试直达）一律走现有路径，零行为变化。
- 从 `want.uri` 取待打开文件的 URI；文件名从 URI 末段解析（URL decode，失败兜底「未命名」）。
- 载荷经 `AppStorage` 传给只读预览页（沿用 v1.56 的时间戳 nonce 机制兜冷启动早到 / 晚到），页面就绪与载荷就绪两头都覆盖。
- 与 v1.56 `handleSharedWant` 并列新增分支，不改其既有逻辑（普通分享仍存库、本版只读预览不入库）。

### 89.3 读取临时授权文件内容（设备层，零落盘）

- 文件 URI 是**临时授权**（api_notes AF4）：授权随应用退出 / 重启失效，接收方不能长期操作宿主文件。本版只读一次、当次渲染，不走「拷进沙箱长期持有」路径。
- 用文件 IO 按 SDK 声明核实的方式打开 URI（`fileIo.open(uri, READ_ONLY)`，API ≤ 24）→ 读为字符串 → 交给 Web 预览 → 关闭 fd。路径不硬编码、不把 URI 当路径拼（硬约束 14）。
- 读取失败（URI 无效 / 授权失效 / 非文本文件）不崩溃：进只读预览页并显示可读错误态「无法读取该文件内容」，保留源文件路径信息只用于定位、不进日志正文（硬约束 16）。
- 大小上限：设一个防御性上限（如 2 MB，落码定具体值并写注释），超限显示「文件过大，仅预览前 N KB」或整篇拒绝并说明；避免超大文件一次编码进 Web 桥。

### 89.4 无库只读预览页（新独立页面）

- 新增一个独立 `@Entry` 页面（如 `pages/MarkdownFileOpenPage`），注册进 `main_pages`，由 EntryAbility 在 89.2 分支里 `loadContent` 到该页；**正常桌面启动仍进 `pages/Index`**，两条路径互不干扰。
- 复用 v1.74 的只读预览组件 `TrashPreviewWeb`（`PreviewWebView.ets`）：`markdown` 字符串入、只读 `setContent`、`setPreviewZoomControlsVisible(false)`、主题随 `appTheme`、外链走系统 `viewData` 不留在 Web 内加载。图片附件解析不在本版（该组件不注册 `__arkts` 代理）。
- 页面结构：顶部标题栏显示来源文件名 + 返回 / 关闭入口；正文区为只读预览（复用组件）。深浅色 token only（硬约束 17），`overScrollMode(ALWAYS)`（v1.86 口径）。
- **只读语义**：不提供编辑、保存、下载、入库、`另存到库` 等任何写入口；预览组件不 `setEditable(true)`；退出即结束，不留状态、不改源文件。

### 89.5 红线与回归

- 零新增权限；文件内容 / 文件名 / 路径不进埋点与日志正文（硬约束 16）；颜色 / 字号 / 间距只引用 token（硬约束 17）；不修改源文件（全程 `READ_ONLY`）。
- 回归：新增定向 Node 源级 / 行为测试覆盖 89.1（skills 声明字段）、89.2（action 判定与冷 / 热分支）、89.3（URI 读取与失败兜底）、89.4（只读页无写入口）；受影响套件、`arkts_check` 零错误，签名 HAP 构建通过；按版本要求做可安全执行的检查。
- 不写「API24 / XT2 待用户」类待验条目（2026-11-18 用户决定）；真机「打开方式」列表出现与只读渲染由用户自行验收，实测结果照实回填 §6。

## 4. 明确不做

- **不建库 / 不入库 / 不读写任何笔记库**：本版是独立的「看一个 .md」路径，不注册库、不写 VaultRegistry、不动工作区会话（对齐「不需要笔记库」）。
- **不编辑、不保存、不回写源文件**：只读预览，文件本身任何情况下不被修改（区别于 v1.56 把分享内容另存为新笔记）。
- 不做 md 之外的文件类型（`.txt` / PDF / 图片等）——本版只关联 `.md`，类型穷举以 §5 核实结果为准。
- 不注册 `sendData`（分享面板入口）——那是 v1.56 的范围；本版只加 `viewData` + `FileOpen`。
- 不做多文件批量打开（`maxFileSupported` 的取值按核实结果定，默认单文件）。
- 不解析 md 内相对路径图片（复用 `TrashPreviewWeb` 的既定边界，图片显示占位）。
- 不改 `Index.ets` 工作区、启动页 / 屏保、设置页、Git、搜索、小艺等既有功能；工作树中这些文件若带并行会话未提交改动，一律不碰。
- 不改对外版本字段（`app.json5` / `changelog.json` 由并行会话持有，发布动作另行处理）。
- 不做埋点；不做模拟器 / 真机验收（用户自行验收、结果回填）。

### 6.1 源码与实现
- **89.1**：`module.json5` 追加独立 `MarkdownViewAbility`（`exported: true`）+ `skills`：`ohos.want.action.viewData` +
  `{ scheme: "file", type: "general.markdown", linkFeature: "FileOpen" }`；EntryAbility 的 home / `sendData` skill 零改动。
- **89.2**：`MarkdownViewAbility` 冷启动（`onCreate` 缓存 want → `onWindowStageCreate` 读文件后 `loadContent`）/ 热启动（`onNewWant` 重解析）双路径，

- **89.3**：`MarkdownOpenService`（纯逻辑：action 判定 / 文件名 URL decode / 2MB 上限 / UTF-8 安全截断 / 载荷序列化的错误兜底）+
  `MarkdownOpenDevice`（动态 import：`fileIo.openSync(uri, READ_ONLY)` → `statSync` 判上限 → `readSync` → `TextDecoder` → `closeSync`，当次读取零落盘、零新增权限）。
