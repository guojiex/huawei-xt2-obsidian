# v1.94 需求文档 —— PDF 导出改用 ArkWeb 官方引擎（createPdf，矢量 PDF + 印刷级分页）

> 状态：**立项**（2026-11-20）。需求来源：用户拍板「拍一个版本，直接改成官方 print 引擎」，
> 并追问「长图能用官方的吗」。
> 归属分享域；本版**只改 PDF 导出链路**（捕获 → 预览 → 落盘），长图路径零改动。
>
> ⚠️ **术语澄清**：用户口语里的「官方 print 引擎」有两个候选实现，本版选定的是
> `WebviewController.createPdf()`，**不是** `createWebPrintDocumentAdapter()`。
> 理由见 §3.1。

## 1. 版本定位

### 1.1 现状（问题）

PDF 导出是「**自研分页 + 逐页截图 + 位图合成**」：

- web 侧自研分页（`web/mdpreview/src/pdfPagination.mjs`）：按**块级贪心**装填——标题组
  （标题 + 紧随正文）合并为一个单元放不下就整组下移；小块（≤30% 页高）放不下整块下移；
  大块（>30%）跨页硬切填满本页。后果是**页尾留白 2.3%~18.1% 随机分布**（2026-11-20 真机
  实测 20 页中 8 页留白），用户观感为「有些页结尾空白很多，有些页没啥空白」。
- 端侧逐页滚动 + `getComponentSnapshot` 截图（63 页时 ~10s，v1.93 后 20 页 ~3.4s），
  每页存 JPEG（`quality: 92`），再由 PDF Kit 把 JPEG 贴进 A4 页。
- 产物是**位图 PDF**：不可搜索、不可选中、放大模糊、体积随页数线性膨胀。

### 1.2 目标

用 **ArkWeb 官方 PDF 引擎**（Chromium print 管线）一次生成**矢量 PDF**：

- 分页由 Chromium 的 CSS Fragmentation 实现：行级断页、`orphans`/`widows`、
  `break-inside: avoid`、`break-after: avoid` 全部原生可用 → **页尾留白降到 2 行量级**，
  与 Chrome 打印 / Prince / Typora 等印刷型工具同档；
- 矢量输出：文字可选中可搜索、任意放大清晰、体积显著小于位图版；
- 性能：一次调用替代 N 次滚动截图，预期比 v1.93 的 3.4s 更快。

### 1.3 长图：**不能用官方引擎**（已答复用户）

`createPdf` / print 管线产出的是**按纸张分页的 PDF**，没有「超长单张图」这种输出形态。
Chromium 自定义纸型有尺寸上限（业界常规 200in ≈ 5080mm），而长图需要 61:1 ~ 100:1 的
极端比例；且长图路径现受 **96 MiB 单图预算**约束（正是长图生成失败的根因，见 v1.90）。

**决策**：长图**保留现有截图拼贴路径**，零改动。长图与 PDF 是两种产物形态，官方引擎
不覆盖长图。

## 2. 完成判定

真机 XT2，同一篇 63 页笔记（窄窗基线），导出 PDF：

1. **产物是矢量**：PDF 内含文本对象（`/Font` + 可提取文本），非整页 JPEG 图像；
   文件体积显著小于位图版。
2. **分页是印刷级**：页尾留白降到行级（≤ 几行），不再出现「页尾空 18%」；
   无「标题孤悬页尾」、无「代码块被切一半」等块级分页缺陷。
3. **内容完整**：末页到笔记结尾不缺、页间不重复；图片、表格、代码块、KaTeX 公式、
   Mermaid 图、水印全部正常渲染。
4. **预览可用**：导出前的分页预览仍可用（PDF Kit 渲染页 → 现有缩略图弹窗）。
5. **性能不劣化**：总时长优于 v1.93 的 ≈3.4s；明显劣化则记录并决策。

### 2.1 判定失败时的回退

若 Chromium print 管线在 ArkWeb 上不可用、或 print 媒体下布局无法收敛（spike 失败），
**整版回需求池**，恢复 v1.93 位图链路，不做半吊子改造。

## 3. 技术方案

### 3.1 引擎选型：`createPdf` 而非 print 适配器

| 维度 | `WebviewController.createPdf()` ✅ 选定 | `createWebPrintDocumentAdapter()` + `print.print()` ❌ |
|---|---|---|
| 产物落点 | **应用沙箱内**，返回 `Uint8Array` 字节流 | 系统打印框架 / 用户选择的位置，**拿不到沙箱文件** |
| 是否拉起 UI | **不拉起**，纯 API 调用 | **拉起系统打印预览页**（全新交互形态） |
| 权限 | 仅 `INTERNET`（取网络文档用；本地 rawfile 不需要） | 需 `ohos.permission.PRINT` |
| 适配分享链路 | **直接可分享**（写入沙箱 → 走现有 `shareFile`） | 不适配：产物不在沙箱，分享链路拿不到 |
| 官方定位 | 文档明写「保存前端页面为 PDF，**用于分享或存储**」 | 文档定位是「打印前端页面」 |

官方文档：`developer.huawei.com/consumer/cn/doc/harmonyos-guides/web-createpdf`。
SDK 核对：本地 API 26 SDK `hms/ets/api/@ohos.web.webview.d.ts` —
`createPdf(configuration: PdfConfiguration): Promise<PdfData>`（`@since 14`，
本工程 `compatibleSdkVersion 24` 可用），`PdfData.pdfArrayBuffer(): Uint8Array`。

### 3.2 尺寸与重排：宽度由纸型决定，不再由捕获层 vp 决定

`PdfConfiguration.width/height` 单位是**英寸**。A4 = 8.27 × 11.69 in
= **793.92 × 1122.52 CSS px**（96 CSS px/in）。

关键含义：**Chromium 按纸宽重新布局整个文档**，我们指定捕获层 700vp / 991vp 的旧口径
不再决定排版。捕获层只需能渲染出完整内容流，纸宽由 `PdfConfiguration` 决定。

`PdfConfiguration` 字段（SDK 全量核对，无遗漏）：

| 字段 | 类型 | 说明 | 本版取值 |
|---|---|---|---|
| `width` | number | 页宽（inch），推荐 A4 = 8.27 | 8.27 |
| `height` | number | 页高（inch），推荐 A4 = 11.69 | 11.69 |
| `marginTop/Bottom/Left/Right` | number | 页边距（inch），范围 [0, 半页高/宽)，越界按 0 处理 | 0 |
| `scale` | number? | 缩放倍数，[0.0, 2.0]，默认 1.0 | 1.0（不缩放） |
| `shouldPrintBackground` | boolean? | 是否打印背景色/背景图，默认 false | **true**（代码块底色、表格线、callout 底色需要） |

**无页眉/页脚/页码选项**——SDK 未提供，本版不提供页码（明确不做，见 §4）。

### 3.3 web 侧 print 媒体适配（必须改，否则布局不成立）

当前 CSS（`web/mdpreview/build.mjs` 内联）：

```css
html, body { margin: 0; padding: 0; height: 100%; background: var(--paper); }
body { display: flex; flex-direction: column; overflow: hidden; }
#content { flex: 1 1 auto; min-height: 0; overflow-y: auto; ... }
```

这是**视口应用布局**：`body` 高度锁 100%、`overflow: hidden`，`#content` 内部滚动。
print 媒体下必须解除，否则 Chromium 认为可视高度只有一页，内容被截断。

需新增 `@media print` 规则块：

- `html, body { height: auto; overflow: visible; }`；
- `#content { flex: none; overflow: visible; height: auto; }`——让内容自然流成整篇；
- `#content` 的 `padding` 在 print 下改为按纸宽的内边距（当前 `var(--s6) var(--s10) var(--s16)`
  是视口口径，纸宽 794px 下需重新取值）；
- 分页控制：`h1~h6 { break-after: avoid; }`、`pre/table/img/.callout { break-inside: avoid; }`、
  `p, li { orphans: 2; widows: 2; }`；
- 水印：现 `position: fixed` + `display:none` 的末页徽标机制（`shareWatermark.mjs`
  `prepareShareWatermarkForPdfCapture`）在 print 媒体下会**每页重复且默认隐藏** →
  print 媒体下改为**流内静态页脚**（`position: static; display: block;`），语义为
  「每页末尾的水印」还是「整篇末尾一次」由 print 规则决定（初版取整篇末尾一次，
  与长图一致；如需每页水印则用 `position: fixed` + `display: block`）。
- 深色模式：捕获层 PDF 模式本就强制 `themeOverride: 'light'`（现有行为），无需额外处理。

**改 CSS 意味着必须重建 mdpreview rawfile**（`web/mdpreview` → `npm run build` →
`entry/src/main/resources/rawfile/mdpreview/index.html`）。这是本版唯一需要动构建产物
的地方，需在提交中说明产物来源。

### 3.4 端侧改造点

| 环节 | 现状 | 本版 |
|---|---|---|
| 捕获层 | `PreviewWebView` 私有 `controller` | **暴露 controller**（`PreviewWebView` 增加对外可取句柄），`ShareFlowPanel` 拿到后调 `createPdf` |
| 分页准备 | `preparePdfPages` / `pdfPagination.mjs` / `setShareCaptureScrollTop` | **不再调用**（保留代码不删，见 §4） |
| 逐页截图 | `captureSegmentVerified` 循环 + JPEG 落盘 | **不再调用**（长图路径仍在用） |
| PDF 合成 | `NotePdfDocumentService.exportFromPageImages` → `NotePdfExportDevice` | **不再调用**；改为 `createPdf` 字节流 → 沙箱文件 |
| 预览 | 逐页 JPEG → `SharePdfPreviewDialog` | 改为：PDF 生成后用 **PDF Kit `PdfPage.render()`** 渲染各页为位图 → 同一弹窗 |
| 分享 | `shareFile(pdfPath, ...)` | 不变（产物已在沙箱） |

**PDF Kit 渲染能力已核对**（`hms/ets/api/@hms.officeservice.pdfservice.d.ts`）：
`PdfPage.render(...)` 支持 `PixelOptions` 控制渲染尺寸——可用于生成预览缩略图。

### 3.5 水印与元信息的取舍

- 现水印是「末页右下角徽标」（`position: fixed`）。print 媒体下 fixed 元素在 Chromium
  print 里**每页重复**（或被裁切），必须显式处理，不能放任。
- 本版初版取「整篇末尾一次水印」（`position: static`），与长图链路一致。

### 3.6 与现有打点的关系

`ShareDbg` / `pdfgeo` 打点针对旧的「逐页截图」链路，新链路不再有 `seg=` / `pdfgeo` 逐页
数据。**旧打点保留**（长图链路仍在用 `seg=`；`pdfgeo` 段随 PDF 链路改造失效），
在 §6 收尾时统一清理。

## 4. 明确不做

- **长图路径零改动**：用户可选宽度（`'wide'` = 720vp）、96 MiB 预算、`MAX_PAGES`、
  scale 1.0、`captureSegmentVerified` 重试机制全部保持。长图**不迁移到官方引擎**（§1.3）。
- **不删旧代码**：`pdfPagination.mjs`、`preparePdfPages`、`exportFromPageImages`、
  `SharePdfPreviewDialog` 保留在仓库，新链路不调用即可——本版不做大扫除，避免把
  「改造」与「清理」两件事混在一个提交里（长图与降级路径可能仍需要）。
- **不做 print 适配器路线**：不引入 `ohos.permission.PRINT`，不拉起系统打印 UI，
  不新增「打印 / 另存为 PDF」入口。
- **不提供页码 / 页眉页脚**：`PdfConfiguration` 无此能力，不自造。
- **不引入第三方 PDF 库**（jsPDF / pdfmake 等）：官方引擎已满足需求。
- **不动 Markdown / ZIP / 文本分享链路**。
- **不做 PDF 内跳转目录 / 书签**：超出本版范围。
- 零新增埋点零上报（硬约束 16）；诊断打点只记数字不记笔记内容。

## 5. 风险与约束

| 风险 | 说明 | 应对 |
|---|---|---|
| **print 媒体行为无官方明文** | SDK 只说「推荐用 `@media print` 优化布局」，没说 print 媒体下 `body{height:100%}` 会怎样 | 94.1 spike 优先验证；失败即回池（§2.1） |
| **打印媒体与视口媒体渲染差异** | Chromium print 会重排，可能与用户在屏幕上看到的不同 | 预览弹窗用 PDF Kit 渲染真实 PDF 页 → 用户看到的预览就是最终产物 |
| **内容在 print 下被截断** | 若 `#content` 的滚动容器未解除，Chromium 只渲染第一屏 | spike 判据必须包含「末页有笔记结尾内容」 |
| **中文断行 / 标点避头尾** | Chromium 有 CJK line-break 规则，行为可能与预期不同 | 真机肉眼验收，异常则加 `@media print` 规则微调 |
| **KaTeX / Mermaid 在 print 下重排** | 依赖 `matchMedia('print')` 的库可能换布局 | 肉眼看公式 / 图表是否变形 |
| **rawfile 重建** | 改 CSS 必须重建 mdpreview 产物 | 按现有构建链（`npm run build`）更新，不手改产物 |
| **性能可能不必然更快** | 一次 printToPDF 对超长文档可能耗时不短 | §2 判据⑤实测；劣化则记录并决策，不默认回退 |

## 6. 需求清单

### 94.1 spike（先行，出结论才继续）

用最小改动验证三件事，缺一即回池：

1. **可控出字节**：`createPdf` 在捕获层（被父级不透明工作区完全遮住的 Web）能成功返回
   `PdfData`，字节流非空，PDF 头合法（`%PDF-`）；
2. **print 媒体生效**：print 下 `body`/`#content` 的高度与 overflow 约束被解除，内容
   展开成整篇（判据：PDF 页数 ≫ 1，且末页含笔记结尾内容）；
3. **矢量输出**：产物含文本对象而非整页位图。

### 94.2 web 侧 print 媒体适配

`web/mdpreview/build.mjs` 的 CSS 加 `@media print` 块（§3.3 全量条目）：
解除视口高度/滚动约束、print 下的内边距、分页控制规则（`break-after` /
`break-inside` / `orphans` / `widows`）、水印在 print 下的形态。

### 94.3 端侧接入 `createPdf`

- `PreviewWebView` 暴露 `WebviewController` 句柄；
- `ShareFlowPanel` 的 PDF 分支改为：挂捕获层 → 等内容就绪 → `createPdf(A4 配置)` →
  字节流写入沙箱 `.pdf`；
- 旧的 `preparePdfPages` / 逐页截图 / `exportFromPageImages` 调用点从 PDF 分支移除
  （长图分支不动）。

### 94.4 预览改造

- 用 PDF Kit 打开生成的 PDF，逐页 `render()` 为位图喂给现有 `SharePdfPreviewDialog`；
- 预览的页数 / 缩略图与最终 PDF 一致（预览即产物）。

### 94.5 防线测试

- `tools/tests/` 新增源级断言：锁定 `createPdf` 调用点、`PdfConfiguration` 取值
  （8.27 / 11.69 / `shouldPrintBackground: true`）、`@media print` 关键规则存在、
  PDF 分支不再调用 `preparePdfPages` / `exportFromPageImages`、长图分支仍在调用。
- 既有分享族测试零回退。
