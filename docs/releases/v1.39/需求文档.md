# v1.39 需求文档 —— 分栏最小宽度按栏角色与系统字号

> 状态：⚪ 规划中；设计已定（2026-11-07），v2 原型与原生均未实现，未验收。
> 对应里程碑：独立优化。领取顺序以 [实施总清单](../实施总清单.md) 为准；建议在 [v1.38 三栏正文 / 参考分栏可拖](../v1.38/需求文档.md) 之后领取（同改 `splitRange` / 原生栏宽约束，先后做可避免冲突）。
> 需求来源：[需求池 Q-03 / Q-04](../../requirements_backlog.md#q-分栏调节条交互增强2026-11-03)（2026-11-07 用户提出「单栏最小宽度是不是应该根据机型或屏幕宽度决定」，经讨论确认改为按栏角色 + 系统字号，两项都做）；设计基线：[分栏调节条设计 §4](../../prototype/v2/分栏调节条设计.md#4-显示范围与比例)。

## 1. 版本定位

现在每个可见栏统一至少 240vp（[v0.7 交互设计「分栏最小宽度」](../v0.7/交互设计.md)，设计起点、非平台规定）。两个问题：

- **一刀切**：目录栏主要放文件名，正文 / 参考栏放正文内容，所需宽度不同，统一 240vp 让目录拖不窄。
- **不随系统字号变**：布局用 vp，只受「显示大小」影响；系统「字体大小」只放大 fp 文字（[API 笔记 AA5](../../harmonyos/api_notes.md)）。用户调大字号后，240vp 一行放不下几个字。

本版把最小宽度改为**按栏角色取基准、再乘系统字号系数**。

**明确不按机型、不按窗口宽度比例**：布局只看窗口宽度断点、不按设备形态分支（[API 笔记 A3](../../harmonyos/api_notes.md)）；按窗口比例取下限已在 v0.7 前试过（单屏横屏左栏可被压到约 172vp），改成绝对下限正是为解决该问题。vp 已按像素密度换算，同一 vp 值在不同屏幕上的观感一致。

## 2. 完成判定

目录栏可拖到 200vp（标准字号）；正文 / 参考栏仍不小于 240vp；系统字号放大后各栏下限按 39.2 同步变大并实时生效；在 sm / md / lg 目标窗口与 1.45 倍字号下各布局仍能放下全部可见栏。原型、原生与设备分别验收。

## 3. 需求清单

| 编号 | 需求 | 验收点 |
| --- | --- | --- |
| 39.1 | **按栏角色取基准下限。** 目录栏 200vp；正文栏 240vp；参考栏 240vp。数值为设计起点（非平台规定），以 39.6 截图走查为准，可在本版内微调并同步本文档。 | 标准字号下目录最窄 200vp 时，三级目录文件名仍可见至少 4 个汉字，图标、展开箭头、新建按钮不重叠；正文 / 参考最窄仍为 240vp |
| 39.2 | **跟随系统字号。** 实际下限 = 基准 × `k`，`k = clamp(fontSizeScale, 1, 1.45)`，结果向上取整到整数 vp。字号缩小（< 1）时不缩小下限；字号超过 1.45（含关怀模式与应用 `fontSizeMaxScale` 1.75）时下限不再加大，由文字换行承接。参考值：1.15 → 230 / 276；1.3 → 260 / 312；1.45 → 290 / 348（目录 / 正文与参考）。 | 标准 → 特大切换后下限按上表变化；1.75 时与 1.45 相同 |
| 39.3 | **实时生效与保存值。** 系统字号变化时（前台）立即按新下限重新应用布局，无需重启。下限变化只在布局时钳制，**不改写已保存的栏宽比例**；字号恢复后回到原比例。 | 三栏调好比例后切到特大再切回标准，比例与切换前一致；重开应用后保持 |
| 39.4 | **目标窗口可行性。** 1.45 倍上限按目标窗口反推：lg 三栏 290 + 348 + 348 = 986 ≤ 1107vp；md 双栏（目录收起）348 × 2 = 696 ≤ 709vp；md 目录 + 正文 290 + 348 = 638 ≤ 709vp；单屏横屏 780vp 目录 + 正文 638 ≤ 780vp。窗口小于可见栏下限之和时沿用既有窄窗口退让（[API 笔记 L-11](../../harmonyos/api_notes.md#l-11-v07-分栏手势与单屏横向窗口识别api-24-sdk-声明)），本版不新增自动收栏。 | 上述四种窗口在 1.0 与 1.45 下均能放下全部可见栏，且默认比例不足下限时被钳制到下限 |
| 39.5 | **调节条范围与读屏同步。** 两处调节条（目录 \| 正文、v1.38 的正文 \| 参考）的范围改用各栏的下限：目录最小值为目录下限，最大值须保留右侧各栏下限；三栏时还须按当前正文 / 参考比例收紧最大值，保证比例不变且每栏均满足下限。正文 / 参考调节条范围为 [正文下限, 可用区域 − 参考下限]。读屏边界文案按栏说明（如「已到最小宽度（目录至少 200 vp）」），不弹视觉浮层（v1.22 22.2 已撤销）。 | 拖到边界时读屏文案中的数值与当前字号下的下限一致；三栏非均分比例下拖动目录时比例不变且每栏满足下限 |
| 39.6 | **v2 原型同步。** `--pane-min` 拆为 `--pane-min-nav: 200px` 与 `--pane-min-content: 240px`；设计控制区新增「系统字号」演示下拉（1.0 / 1.15 / 1.3 / 1.45 / 1.75），只用于模拟 `k`、同时放大原型正文字号，不随 URL 持久化（可用 `?fontScale=` 截图复现）。扩展分栏定向测试覆盖 39.1–39.5；补截图（标准 / 特大 × 三屏 / 双屏）。 | 定向测试通过；截图含目录 200vp 与特大字号三栏；浏览器原型不作为原生或设备证据 |

## 4. 明确不做

- **不按机型、设备形态或折叠状态取值**，不建设备常量表；**不按窗口宽度比例取下限**（理由见 §1）。
- 不改默认比例（目录 1/3、正文 / 参考 1/2）与折痕规则；原生 MD 目录默认 0.38 的待决项（需求池 Q 节）不在本版处理。
- 不新增栏宽设置项或存储键；不提供用户自定义最小宽度。
- 不做「放不下就自动减少栏数」的自动收栏；窄窗口沿用既有退让，另需时回需求池。
- 不跟随「显示大小」另行换算（vp 本身已随 density 变化，见 AA5）。
- 不做 Agent 页分栏（v0.7 Agent 专属部分已延期）。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）；字号相关接口只用 [API 笔记 AA 组](../../harmonyos/api_notes.md) 已核实内容。
- 依赖 [v1.10 4.3](../v1.10/需求文档.md) 已配置的 `fontSizeScale: followSystem` 与 `fontSizeMaxScale: 1.75`；本版不改该配置。
- 栏宽模型、持久化与旋转钳制来自 [v0.7 §7.22–7.23](../v0.7/需求文档.md)；本版只替换「每栏 240vp」这一个常量为 39.1 / 39.2 的计算结果。
- 与 [v1.38](../v1.38/需求文档.md) 的关系：v1.38 文中的「240vp」「2 × 240vp」「480vp」在本版落地后按 39.5 的各栏下限计算；两版可分开验收。
- 目标窗口读数（sm 约 380、md 约 709、lg 约 1107vp）以 [API 笔记 A3](../../harmonyos/api_notes.md) 与 [v0.7 验收记录](../v0.7/需求文档.md) 为准。
- 系统字号只能手动或 UI 自动化拖设置滑条验证，命令行无法修改（AA4）；模拟器重启会把字号复位为标准。
