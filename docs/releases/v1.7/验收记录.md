## 17.6 模式切换与工作区目标保护（2026-11-01）

### 实现

- 模式切换遇到打开笔记请求仍在处理中时不执行保存或更改模式；保存期间如果库、左右笔记路径或打开请求代次变化，则保留当前模式并反馈。
- 左右编辑区的异步刷新默认捕获当前请求代次；旧刷新在读盘、桥接下发、编辑能力刷新或章节刷新任一等待后变旧时，不提交旧目标状态。
- 保存前校验编辑区的库 / 笔记目标与最近一次已提交加载目标一致。编辑器文本偏离已保存基线但没有对应脏状态时拒绝写盘；保存完成后若目标已变化，不覆盖新笔记的基线和脏状态。
- CodeMirror 的变更通知仍采用 300ms 防抖；每条 change 消息携带排程时的文档代次。切笔记开始时，原生桥立即使旧代次失效；新内容下发采用新代次，已过桥但迟到的旧通知会被拒绝。打开失败会恢复最近成功载入文档的代次，使原文档后续编辑通知仍可用。程序化替换前取消尚未发送的旧通知作为第二层保护。
- 保存、AtomicFile、笔记格式和用户数据迁移路径未改变；新增的保护避免把上篇笔记的桥接内容写到新选中的路径。

## 17.7 草稿恢复、自动保存与附件失败保护（2026-11-01）

### 实现

- 左右编辑器的自动 / 主动保存均先将修改快照写入应用私有恢复草稿，再经现有 `NoteService.saveNote → VaultAccess.writeAtomic` 更新正式 Markdown。正式写入成功后，只清除内容与已保存文本匹配的草稿；读盘、草稿写入或正式写入失败时保留编辑器脏状态，正式写入失败时恢复草稿保留。保存过程在草稿异步写入后再次核对打开请求代次，旧目标不能继续写入 Vault。
- 打开笔记时左右栏按库 ID 与相对笔记路径恢复草稿；只有正式内容仍逐字匹配草稿基线才恢复。草稿冲突、损坏或不可读时保留草稿并展示正式笔记，不静默覆盖或删除；模式偏好和工作区会话仍不包含笔记正文。
- 草稿使用 `VaultRegistry` 的应用私有路径，按稳定 `vaultKey` 隔离；正式笔记与图片仍统一走 `VaultAccess`，上层未按库类型分叉，也未使用 Picker URI 拼路径。
- 核查既有图片导入链路：附件使用笔记目录下的相对 `attachments/` 路径，经 `VaultAccess.writeNewBinary` 完成复制、大小与逐字节校验后才向编辑器插入 Markdown；目标冲突或复制失败不返回引用，已有同名附件不覆盖。本项没有改变图片复制接口或路径策略。
