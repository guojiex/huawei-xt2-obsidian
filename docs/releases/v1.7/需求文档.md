# v1.7 需求文档 —— 简单模式与专业模式

> 状态：已排期，原生未开始（2026-11-01）。
> 对应里程碑：M8.4。
> 来源：需求池 A「轻量编辑模式（预览页直接编辑）」。
> 优先级：当前新增功能队列首位；v1.6 已有本地实现与模拟器证据，下一项新增功能先领取本版，再继续 v0.9–v0.11、v1.5 / v1.4 等原有剩余队列。旧版待验和发布记录保留；不等待外部目录测试夹具、受限权限申请或 API24 / XT2 验收才开工。

## 1. 版本定位

默认提供能直接在排版正文内书写和设置格式的简单模式；需要 Markdown 源码、编辑 / 预览切换和双栏对照的用户主动选择专业模式。两种模式使用同一份 Markdown 笔记及保存链路。

设计入口：[v2 设计说明](../../prototype/v2/设计说明.md#简单模式与专业模式2026-11-01)。此前 v0.9 9.16 仅承接原型探索，本版承接原生产品实现，不把浏览器原型视为已经交付。

## 2. 完成判定

首次安装及未选择模式的已有用户默认进入简单模式，能在排版正文中完成基础输入、格式编辑、自动保存和重新打开；主动切换到专业模式后能继续编辑同一篇 Markdown，并使用既有源码 / 预览与双栏能力。模式切换和布局变化不丢修改，不破坏未编辑语法；偏好重开有效。代码、自动验证、构建、模拟器及用户真机验收按各自证据分别记录，发布另行执行。

## 3. 需求清单

| 编号 | 来源 | 交付范围与验收要求 |
| --- | --- | --- |
| 17.1 | 需求池 A「轻量编辑模式」；默认模式决定 | 应用级模式为简单 / 专业，默认简单；新安装、升级后没有显式模式偏好、偏好值无效时均采用简单。只有用户主动选择才持久化专业模式；旧会话的编辑 / 预览标志不推定为用户选择了专业模式。模式偏好跨切库和重开生效，读取失败安全回退，写入失败如实反馈，不声称已记住。 |
| 17.2 | 同上；入口设计决定 | 「设置 → 通用 → 编辑模式」使用带图标、说明和选中状态的两项单选列表，整行可点、键盘可选；单屏 / 双屏 / 三屏均在工作区右上角「…」菜单直接列出简单 / 专业两项，选中项高亮并打勾，选择立即生效，不进子菜单或设置页；简单模式下仍可打开该菜单。设置与关于同样收进该工作区更多菜单，所有断点移除独立顶栏设置按钮；退出设置时焦点回到更多按钮。栏内更多只放笔记级操作。正文不常驻模式下拉框；简单模式隐藏源码 / 预览分段按钮、双栏与空工具行，专业模式保留既有操作。所有主题、断点及旋转布局使用同一入口层级和 v2 token。 |
| 17.3 | 同上；预览内输入 | 简单模式呈现排版正文并可直接定位光标、选择文字和输入，支持空笔记、新增段落、换行、删除、段落拆分 / 合并、纯文本粘贴及撤销 / 重做。中文输入法组合期间不抢光标、不反复重建正文、不提前保存半段组合文本；跨块选择不得误改其他段落。格式工具对当前选区 / 插入位置生效，关闭面板可回到选区。正文、草稿和保存结果来自同一编辑状态。 |
| 17.4 | 同上；正文内格式编辑 | 基础格式覆盖正文、H1–H6、粗体、斜体、无序 / 有序列表、待办和引用；复用现有图片插入链路，在完成附件落库后插入并显示图片。基础格式可应用和取消，待办可修改状态，插入后看到排版结果。链接与代码块等复杂内容保留显示和原文；本版不承诺在简单模式中完整编辑所有 Markdown 扩展，不能把复杂块静默转成普通文字。复杂块的编辑限制与专业模式入口须在相关内容附近清楚说明，不能每次输入弹出提示。 |
| 17.5 | 同上；Markdown 完整性 | 同一篇 Markdown 是唯一正文真源，不保存独立富文本副本。修改映射到目标源码区间，未触及区间逐字保留；不能把整篇预览 HTML 反向转换后覆盖文件。属性、表格、围栏代码、图片 / 链接目标、双链、公式、Mermaid、callout 和未知语法均保留；暂不支持编辑的复杂块只读保护，跨块删除 / 粘贴不得绕过保护。转换或解析失败时保留原文与可恢复编辑，不清空或用降级文本替换笔记。 |
| 17.6 | 同上；模式及工作区状态 | 切换模式前处理组合输入与待保存内容，失败时保留当前模式和编辑状态并反馈。切换本身不重写正文；始终保留用户当前正在编辑的笔记，不能因恢复旧双栏快照跳回另一篇笔记。进入简单模式仅呈现一个正文编辑区；回专业模式恢复适用的栏位 / 布局和阅读位置，当前笔记保持激活；旧栏笔记已删除、移走或失去访问权时逐栏安全回退。切库、切笔记、旋转、会话恢复和异步桥接回调均防止旧内容覆盖新目标。 |
| 17.7 | 同上；保存与交付 | 接入既有自动保存、草稿恢复、保存反馈及 VaultAccess；沙箱库先完成闭环，外部库走同一适配层，不按 rootKind 在上层分叉。已有笔记更新遵守 AtomicFile 保护，失败保留旧内容与待恢复修改。保存成功提示以实际成功回调为准；模式偏好 / 会话不写入笔记正文。分别验证两种模式的编辑、保存、重开、只读 / 权限失败和旧专业模式回归，内容不得进入埋点或日志。 |

## 4. 明确不做

- 不新增独立富文本文件格式、云端协作、插件系统、Markdown lint 或新的 Markdown 方言。
- 不承诺所有复杂语法均可所见即所得编辑；支持范围按 17.4–17.5，复杂块必须可保留和安全转到专业模式处理。
- 不借此重写文件、附件、Git 或外部授权服务，不申请新权限；不等待真实 Git / 外部目录设备链路才能验证沙箱编辑。
- 不改包版本、签名、tag 或发布状态；不把原型完成、构建成功或 API26 模拟器证据当作 API24 / XT2 通过。
- 不恢复已撤下的本地 Agent View 或 v1 旧设计稿。

## 5. 技术约束与依赖

- 必须先审查现有编辑器、预览器、桥接、保存 / 草稿和会话恢复，形成可验证的块映射与编辑方案再实现；不能直接把原型 contenteditable 代码当作生产编辑器。
- 复用 v0.9 既有 UI、v0.7 栏位状态、v1.3 图片及 v1.5 已有 VaultAccess；只依赖实际所需接口，旧版本整版验收和发布不是本版前置。
- API24、中文输入风险、原子保存和图片源授权以 [api_notes](../../harmonyos/api_notes.md) 的 C1 / Q1 及编辑器相关条目为准；其他 HarmonyOS API 必须从 SDK 和官方资料核实，禁止编造 Hds 组件或 symbol。
- 需求与入口决定只链接 [决策记录](../../open_questions.md) 和 [v2 设计说明](../../prototype/v2/设计说明.md#编辑模式入口修订与参考2026-11-01)；本版不新增平台行为结论。

## 6. 实施顺序与验收记录

1. 编辑器方案与最小闭环：沙箱空笔记 / 普通段落输入，源码区间映射、中文组合、自动保存与重开；验证失败保护后再扩格式。
2. 17.1–17.2 模式偏好和设置入口；17.3–17.5 基础编辑、格式与复杂块保护。
3. 17.6–17.7 双模式切换、会话 / 切库、附件、失败恢复与旧专业模式回归。
4. 自动检查与 HAP 构建、可用模拟器正常交互、用户手动 API24 / XT2 验收、发布分别收口。
