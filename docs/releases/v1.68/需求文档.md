# v1.68 需求文档 —— Git 导入在同一弹窗内完成

> 状态：用户于 2026-11-15 指定按[导入库弹窗设计 §7](../../prototype/v2/导入库弹窗设计.md#7-git-导入在同一弹窗内完成2026-11-15)实施。原生实现记录见 §6；本文件不代表设备验收或发布完成。

## 1. 版本定位

收掉 Git 导入表单后的重复确认页：用户在「导入库」弹窗填写远端信息与凭据后直接启动导入；克隆进度、失败原因和重试留在同一个弹窗。继续复用 v0.3 Native libgit2 clone、VaultRegistry 恢复标记与 GitCredentialStore。

## 2. 完成判定

导入不再导航到重复 Git 表单；弹窗预览目标库名并在原位展示真实进度。导入中无法切换来源或关闭；失败保留输入并允许重试；成功只登记一个通过状态校验的新 Git 库并切换到该库。令牌不进路由、日志或普通偏好，弹窗关闭后清空。本地目录 / ZIP 导入和既有 Git 同步窗口保持原行为。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 68.1 | 同一弹窗承载 Git 配置和导入 | 仓库地址、分支、令牌及服务商用户名仅填写一次；显示按正式 ID 生成规则推导的目标库名；提交后不跳转到重复表单或要求第二次确认 |
| 68.2 | 同窗真实进度和关闭保护 | 使用 Native clone 回调与实际校验 / 登记步骤更新阶段；不显示伪造百分比；忙碌期间字段、来源、取消、关闭、遮罩、Esc、系统返回均不可改变当前导入 |
| 68.3 | 原位失败和重试 | 显示可操作建议与脱敏底层错误；认证失败将焦点交还凭据输入，网络等失败聚焦重试；失败保留原表单且不留下可用半成品库，清理失败保留恢复标记供启动恢复 |
| 68.4 | 导入成功及凭据边界 | Native clone 返回隔离目录且磁盘仓库状态 / 分支验证通过后才发布、登记和切库；成功关闭弹窗并提示；令牌仅在成功后进入 AssetStoreKit `SECRET`，关闭弹窗清空输入 |

## 4. 明确不做

- 不改 Native libgit2、远端认证协议、Git 凭据存储格式、push-only 同步边界或仓库写入策略。
- 不改本地目录关联、ZIP 导入、Git 同步弹窗、Git 库分享或库管理语义。
- 不新增权限、网络后台任务、成功确认页或进度百分比估算。
- 不以原型 / 源码级证据替代 API24 / XT2 或真实 provider HTTPS 验收。

## 5. 技术约束与依赖

- 继续遵循 [v0.3 §3.1 与 §6](../v0.3/需求文档.md)：唯一新建目标 `vaults/<id>__importing`、先写恢复标记、clone 后重新读取状态校验、无覆盖发布、登记失败清理、清理失败保留恢复标记。
- 继续遵循 [v1.26 §3.5](../v1.26/需求文档.md)：令牌只放 AssetStoreKit `SECRET`，不进入路由参数、日志或普通偏好。
- 忙碌遮罩 / 返回阻止使用已核实 API24 可用的 `CustomDialogControllerOptions.onWillDismiss`（[api_notes I5](../../harmonyos/api_notes.md#i5-customdialogcontrolleroptionsonwilldismiss--sdk-声明可用于-api-24运行时待验)）；API24 / XT2 运行时仍单独验收。
- 颜色、圆角、间距、字号只引用现有 v2 token；不新增系统符号或 API。

- 2026-11-15：原生源码实现完成；验证状态见 §6.2。

### 6.2 实现与验证（2026-11-15）

- **源码已实现**：`GitImportService` 统一执行隔离目录 clone、真实 Native 进度、磁盘状态 / 分支校验、正式目录发布、注册、令牌安全存储与失败清理；`ImportVaultDialog` 显示目标库名、真实阶段、脱敏失败原因与重试，忙碌期间禁用字段 / 来源 / 关闭操作，失败按认证或其他故障定位焦点。导入完成后复用 `switchVault`，失败时沿用现有切库回滚保护。
- **入口调整**：导入弹窗直接调用服务，不再交接草稿或导航到 SyncPage；`pages/SyncPage` 已从 `main_pages.json` 移除。已有库的 Git 同步仍从独立 `GitSyncDialog` 打开；本地目录和 ZIP 导入回调未改。
- **凭据与恢复边界**：令牌仅作为内存参数交给 Native clone，写入仍走 `GitCredentialStore`；失败细节按令牌脱敏后显示 / 写入本地 hilog；导入标记、无覆盖目标、克隆后仓库校验和启动恢复清理沿用 `VaultRegistry`。
- **自动化测试**：本轮未运行测试；现有导入弹窗契约用例仍以旧 SyncPage 交接为断言，需要后续与新入口同步。
- **构建与设备**：未执行 HAP 构建或真实 Git 操作；API26 模拟器、API24 / XT2 与真实 provider HTTPS 未验收。源码实现不代表这些证据通过。
