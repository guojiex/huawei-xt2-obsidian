## 1. 版本定位

v0.3 已实现「暂存 → 提交 → fetch → 仅快进 push 到 `xt2`」，但 v2 设计稿里同步入口点开只有一行示意提示，同步页本身从未设计；推送分支也写死为 `xt2`。本版重做同步页，并允许**每个库配置推送分支**：默认推到 App 固定分支 `xt2`，用户在电脑上把它合并到主线并解决冲突；手机端仍不做合并。

## 2. 完成判定

当前 Git 库打开同步页后，用户能看到远端、推送分支、待推送提交与本地改动；可修改提交说明与推送分支；推送过程分步可见，成功、远端已前进、令牌失效、网络失败、无改动都有明确文案与下一步入口。不同库的推送分支互不影响，改分支后待推送数按新分支重新计算。原生与设备分别验收。

## 3. 需求清单

| # | 需求 | 验收点 |
| --- | --- | --- |
| 27.1 | **同步页外壳。** 与导入库 / 分享面板共用外壳：宽屏居中卡片（520vp，顶部锚定），单屏底部半模态；图标标题「同步到 Git」，摘要「库名 · 推送到 <分支>」。推送进行中不能关闭（关闭按钮、遮罩、Esc / 系统返回均无效）。 | 仅当前库为 Git 库时可从顶栏同步按钮（带待推送角标）或单屏更多菜单进入；关闭后焦点回到入口 |
| 27.2 | **状态卡。** 三行：远端（主机 / 路径，「HTTPS · 令牌已保存在本机」，不显示令牌）；推送分支（分支名 + 「默认分支 / 自定义分支；在电脑上合并到 <跟踪分支>」+「更改」）；待推送（「N 个已提交 · M 个未提交改动」+ 上次推送时间）。 | 数值只读本地 Git 状态，打开同步页不触发网络 |
| 27.3 | **可配置推送分支。** 「更改」就地展开编辑区：分支名输入框（等宽字体）、说明、「恢复默认 xt2」、「保存」。默认分支为 **`xt2`**（沿用 v0.3，已导入库无需迁移）。按 Git 引用名规则校验：非空、≤ 100 字符；不含空格与 `~ ^ : ? * [ \`；不含 `..`、`@{`、`//`；不以 `/ . -` 开头、不以 `/ .` 或 `.lock` 结尾；不是 `HEAD`。非法时输入框标红、说明改为原因、保存禁用。Enter 保存，Esc 取消并把焦点还给「更改」。 | 只影响当前库；保存后摘要与状态卡即时更新；令牌不变 |
| 27.4 | **推到跟踪分支的提示。** 输入值等于克隆时跟踪的分支（如 `main`）时不禁止，但说明改为警示色：「推送会直接更新远端 main，仍只允许快进；建议使用单独分支，在电脑上合并」。 | 推送规则仍为仅快进、不强推 |
| 27.5 | **分支持久化与计数。** 推送分支按库保存在库注册表 / 库元数据（与 `vaultId` 绑定），不写进令牌、URL 或日志；改名库时随库迁移，删除库时一并清除。待推送数相对本地 `origin/<推送分支>` 跟踪引用计算；该引用缺失时显示未知，联网确认远端无此分支后才可按首次推送处理。 | 两个 Git 库分别设置不同分支，互不影响；重启后保留 |
| 27.6 | **本地改动与提交说明。** 有未提交改动时列出文件（M 修改 / A 新增 / D 删除，色块 + 字母 + 读屏名称），最多约 4.5 行后内部滚动；提交说明默认「更新 N 个文件（曜石笔记）」，用户可改，空白时回退默认。无未提交改动但有已提交待推送时显示「将推送 N 个已提交的更新」；两者都没有时说明本地没有待推送内容、远端状态需联网确认，并禁用主操作。 | 主操作文案：有改动「提交并推送」，否则「推送」 |
| 27.7 | **分步过程。** 推送时显示步骤列表：暂存改动 → 提交 → 检查远端 <分支> → 推送（无改动时只显示后两步），当前步旋转指示、完成步实心；主按钮显示「正在推送…」并禁用，取消禁用。 | 步骤与 Native `stage → commit → fetch → push` 一一对应；减少动态效果时不旋转 |
| 27.8 | **结果态。** 成功：「已推送到 <分支>」，说明「在电脑上把 <分支> 合并到 <跟踪分支>」，按钮「完成」；**远端已前进**（非快进被拒）：本次未推送、本地提交保留，提供「改推到其他分支」直接打开分支编辑；**令牌无效或无写权限**（401 / 403）：提供「更换令牌」，沿用同步页凭据流程；**网络失败**：本地提交保留，可重试。失败态主按钮为「重试」。 | 失败均不丢本地提交、不强推、不报告虚假成功 |
| 27.9 | **原型同步。** v2 原型以页面内演示数据实现 27.1–27.8，底部演示脚注提供「远端已前进 / 令牌失效 / 网络失败 / 无改动」演示入口；不执行 Git、不访问远端、不读取令牌。 | 原型不作为原生或设备验收 |

## 4. 明确不做

- **不做 pull、checkout、合并、变基、冲突解决界面、强推、提交历史 / 回滚、后台或定时自动同步**：沿用 v0.3 与已定决策，冲突一律在电脑上处理。
- **不做按提交选择文件**（部分暂存）与多远端选择；一次推送提交全部改动到当前库唯一远端。
- **不改导入表单**：克隆分支与令牌收集归 [v1.26 26.1 / 26.5](../v1.26/需求文档.md)；本版不在导入时询问推送分支（导入后默认 `xt2`，可在同步页改）。
- 不更改令牌存储位置（AssetStoreKit `SECRET`）与认证方式（GitHub `Bearer`、Gitee `Basic`）。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**，查不到就列入报告（`AGENTS.md` 硬约束 18）。
- **会改动 Native 接口参数**：v0.3 的 `GitNativeService` / Native libgit2 目标分支固定为 `xt2`，本版需把推送目标与待推送计数的比较分支改为参数（默认 `xt2`）。不改认证、fetch / push 协议与「仅快进、非快进拒绝」规则；其余 Native 行为不变。
- 分支名校验以 Git 引用名规则为准，原生与原型使用同一组规则并有单测覆盖；以上列举不是完整规则，实现时需核对完整引用名约束。
- 打开页面只读本地跟踪引用，不能据此证明远端实时状态；无本地跟踪引用时应显示状态未知，首次创建远端分支前需联网核实，不能仅凭本地引用缺失断言远端不存在或计算全部提交。
- 凭据继续经 `GitCredentialStore` 存 AssetStoreKit `SECRET`；推送分支属普通库元数据，不与令牌同存。
- 已定决策「固定推送到 `xt2`」随本版修订为「默认 `xt2`，可按库配置」，见 [已定决策](../../open_questions.md)。
