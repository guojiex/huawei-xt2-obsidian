# v1.58 需求文档 —— 写作统计面板重设计（入口与形态）

> 状态：⚪ 规划中；v2 原型设计稿已完成（2026-11-13），原生未改，未验收。
> 对应里程碑：独立优化。领取顺序以 [实施总清单](../实施总清单.md) 为准。
> 需求来源：2026-11-13 用户走查反馈「这个界面怎么会写在管理库一起的列表页」——[v1.51](../v1.51/需求文档.md) 设计稿与 [v1.52](../v1.52/需求文档.md) 原生把「统计与成就」放进了库切换下拉菜单（与「导入库」「管理库」并列），页面也套用库管理页的全屏外壳。本版只改**入口位置与页面形态**；指标口径仍以 v1.51 §2 为准，v1.52 的统计服务（`VaultStatsService`）不动。

## 1. 问题

1. **入口放错地方**：库下拉菜单是「切换 / 管理知识库」的地方，统计是「我的写作情况」，两件事放在同一组蓝色动作里，用户会以为它是库的设置项，也很难被发现（要先点开库卡片）。
2. **页面像库管理**：全屏替换内容区、顶栏「← 返回笔记」、限宽 760 的列表排版，与库管理页一模一样；一个看一眼就走的统计被做成了需要「进去—出来」的二级页面。
3. **热力图版式错误**：原型把 12 周排成 12 行 × 7 列并拉满宽度，格子变成直径约 80px 的大圆，一屏只能看到 3 周。
4. **没有重点**：四张数字卡同权重，最能激励写作的「连续写作」和「下一个成就」没有被突出。

## 2. 完成判定

库下拉菜单不再出现统计入口；侧栏底部常驻连写条、单屏「更多」菜单有「写作统计」；点按打开独立的「写作统计」面板（宽屏居中弹窗、单屏半模态），关闭回到原处；面板以连写为主视觉，热力图为 7 行 × 12 列小方格，成就有「下一个」进度。原型、原生与设备分别验收。

## 4. 明确不做

- 不改统计口径、徽章集与扫描方式（v1.51 §2 / v1.52 52.1）。
- 不做跨库汇总、年度报告、分享统计图、目标设定（如每日字数目标）与提醒推送。
- 连写条不做动画庆祝（达成徽章时不弹窗、不撒花），避免打扰写作。
- 统计值、成就不进埋点、不写 hilog（v1.52 52.4 红线不变）。

## 5. 技术约束与依赖

- 环境事实：HarmonyOS API 24 / ArkTS；包名 `com.jxg.huaweiobsidian`；目标设备 XT2。**禁止凭记忆编造 HarmonyOS API**（`AGENTS.md` 硬约束 18）；弹窗与半模态只复用仓库内已有实现。
- 侧栏连写条在每次侧栏渲染时只读缓存值；进面板时按 v1.52「进页重算」刷新，结果回写给连写条。冷启动首次扫描放在空闲时机，不进入首帧关键路径（[启动页设计](../../prototype/v2/启动页设计.md) 不允许新增等待）。
- 视觉 token 以 v2 原型 `:root` / `[data-theme="dark"]` 为准；暖色只用既有 `--cb-warn`，不新增颜色 token。
