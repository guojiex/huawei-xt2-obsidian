## 3. 版本边界

- **App vX.Y**：面向用户的应用交付范围，包含 UI、平台接线和设备验收；包版本仍由 AppScope 与发布规则管理。
- **Agent vX.Y**：执行语义、Provider/工具契约、上下文与持久化行为的版本承诺；可以被多个后续 App 版本复用。
- **提示词/Skill revision**：特定模板内容的版本。仅调整模板不必升级 Agent 次版本，仍须固定模板与案例回归。
- **schemaVersion**：某种配置/对话/运行数据结构的迁移版本，不等于 Agent 或 App 版本。

相同 Agent 契约下的修复/模板调整记补丁或模板 revision；新增能力升级次版本；破坏既有工具/消息/恢复契约时单独记录兼容与迁移策略。将来实际发布才建立 `agent/vX.Y.Z` 标签；本轮不打 tag、不改包版本、不标记已发布。

## 4. 开发与验收规则

需求先进入本目录需求清单，再分配 Agent 版本。App 页面需求仍由 App 需求池分配；两边通过编号引用，不复制成两份独立承诺。一个提交可以同时完成两边，但验收分别记录。

App v0.7 必须同时满足自身 UI/集成要求和 Agent v0.1 的必需出口；不能用“Agent 单测通过”替代 HAP、文件落盘与三形态交互，也不能用“原型能点”替代运行时工程能力。Agent v0.2 的新增范围不能无声回塞到 v0.7。

当前执行器仍与 App 在同一仓库，**独立版本管理不意味着现在拆 npm/ohpm 包、单独服务、CI 发布系统或多仓库**。需要这些机制时再立项。
