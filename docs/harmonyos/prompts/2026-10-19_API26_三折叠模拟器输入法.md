# API 26 三折叠模拟器输入法核实提示词

> 用途：粘贴到 HarmonyOS 官方 AI 助手 / DevEco 内的 AI 问答，核实当前三折叠模拟器的输入法配置与 ArkWeb 唤起行为。
>
> **当前设备实测环境**：DevEco Studio 26.0.0.851；`Huawei_TripleFold` 模拟器；HarmonyOS `7.0.0.107(SP8DEVC00E999R4P11)`；系统 API 26；ABI `arm64-v8a`。
> **应用环境**：`compatibleSdkVersion 6.1.1(24)`、`targetSdkVersion 26.0.0`、Stage + ArkTS；编辑页面是 ArkWeb 加载 rawfile HTML，A 档为 CodeMirror 6 (`contenteditable`)，B 档为同一页面的 HTML `textarea`。目标真机为华为 Mate XT2。

## 复制区开始

我在开发华为 Mate XT2 三折叠本地 Markdown 笔记应用，想核实 **DevEco 的 Huawei_TripleFold 模拟器如何正确使用系统输入法，以及 ArkWeb 内输入控件的差异**。

### 环境和已观察到的现象

- DevEco Studio 26.0.0.851；`compatibleSdkVersion: 6.1.1(24)`；`targetSdkVersion: 26.0.0`；Stage + ArkTS。
- 当前运行设备不是 API 24 x86 模拟器，而是 `Huawei_TripleFold`、HarmonyOS `7.0.0.107(SP8DEVC00E999R4P11)`、API 26、`arm64-v8a`。请只根据这个环境回答，不把 API 24 x86 的限制直接套用到这里。
- `bm dump -n com.huawei.hmos.inputmethod` 能看到预装的 `com.huawei.hmos.inputmethod`（版本 `1.2.6.463`）。
- 同一 ArkWeb 页面中，点击 B 档 HTML `textarea` 后会弹出华为系统软键盘；键盘可切到中文拼音，按键后能看到拼音组合串与中文候选词。没有出现首次使用授权页；语音输入和手写输入尚未测试。
- 初次点击 A 档 CodeMirror 6 `contenteditable` 没有弹出软键盘。先在 B 档唤起系统键盘后切回 A，再点击编辑区，键盘可用；用屏幕按键输入拼音 `nihao`，显示“你好”候选，点选后 CodeMirror 正确插入 `你好`，收到 `input data="你好" inputType=insertText isComposing=false` 并触发文档变更。
- `uitest uiInput inputText` 也能向 A/B 注入普通文本，但这类注入本身不能证明真实 IME composition 正常。真实拼音组合与候选已通过键盘屏幕按键观察到；首轮 A 未唤起、B 初始化后 A 可用的差异仍需解释。
- 三种模拟器形态 `single` / `double` / `triple` 均可切换。当前需要判断模拟器能可靠验证哪些输入法行为，哪些必须留给 XT2 真机。

### 请逐项回答

1. **如何确认并配置模拟器的系统输入法？** 请给出此版本模拟器中核实默认输入法、启用华为输入法、查看/选择中文拼音的准确设置路径。若需通过命令操作，请给出该版本确实支持的命令及参数；不要猜 `ime` 或 `settings` 命令。
2. **为什么 CodeMirror `contenteditable` 初次点击没有唤起软键盘，而在 HTML `textarea` 先唤起系统键盘后，切回 CodeMirror 又能正常输入？** 这是否是首次 IME 初始化/焦点时序问题，还是 ArkWeb 的已知差异？请给出 API 24 兼容的、官方支持的检查与处理步骤。
3. ArkWeb 的 `WebOptions`、键盘避让或键盘控制能力中，哪些设置可能影响 `contenteditable` 的键盘唤起？请核实准确 API 名、导入路径、方法/属性签名、最低 API 版本，并附官方文档链接。特别请明确 `keyboardAvoidMode`、`onInterceptKeyboardAttach`、`WebKeyboardController` 是否适用于上述 API 24 兼容应用；若某项不适用或无法确认，请直说。
4. **如何在 DevEco 模拟器里可靠地重复这次真实拼音验证？** 请区分：点击屏幕软键盘的拼音按键、`uitest uiInput inputText`、外接键盘输入各会产生什么类型的输入；哪些能验证 `compositionstart/update/end`、候选词、光标定位，哪些只是普通文本注入。请给出可复现的验证步骤和能判别键盘未 attach、composition 未送达、普通文本已提交的日志/事件证据。
5. 本模拟器上适合完成哪些 M0.5 项目（中文拼音、光标、500 行滚动、resize），哪些必须在 Mate XT2 真机上判定？请将“模拟器可复现的限制”和“设备专属问题”分开说明。

### 回答格式与约束

对每一项按 **结论 → 可复现步骤 → 准确 API / 命令与版本 → 官方文档链接 → 证据强度** 回答。

1. 明确区分 API 24（应用兼容版本）、API 26（模拟器运行系统）与 XT2 真机系统版本；不要把某一环境的结果外推到另一环境。
2. 不确定时直接写“不确定 / 官方未记载”，不要编造 HarmonyOS 接口名、命令、参数或行为。
3. 说明结论来自官方文档、SDK 声明、模拟器实测还是推断；不要把推断说成已实测。
4. 不需要改造项目或建议大范围重写，只回答如何核实当前模拟器输入法和 ArkWeb `contenteditable` 唤起键盘的问题。
