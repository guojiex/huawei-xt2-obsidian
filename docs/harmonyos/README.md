# 鸿蒙知识库（HarmonyOS 问答与结论）

> 这里是**本工程与鸿蒙官方 Agent 之间所有技术问答的唯一存放处**，也是所有「HarmonyOS 行为结论」的**单一真源**。
> 无论哪个 Agent / 哪次会话来开发这个仓库，**先读这里，再动手**。

## 为什么要有这个文件夹

鸿蒙的很多行为（折叠态返回值、Web 组件通道、原子写语义）**文档没写、只能靠问官方或真机实测**。
这类知识有三个特点：① 问一次很贵；② 问错了（对方编造接口名）代价极大；③ 隔几轮会话就忘。

所以定死一条规矩：**所有与鸿蒙的问答，一律落在这个目录，不许散落在聊天记录里。**

## 五条铁律

### 1. `api_notes.md` 是唯一真源，别处只准链接，不准复制

`docs/mvp_design.md`、`docs/open_questions.md`、代码注释里**只能写「详见 `docs/harmonyos/api_notes.md` A2」**，
不允许把结论文本复制过去。理由：结论会被推翻，抄一份就漏改一处。

### 2. 提问前先查，问过的不重复问

提问前**必须**先读 `api_notes.md` 与本文件底部的索引表。若问题已问过，只有三种情况值得再问：

- 官方答的是 ⚠️ 推断 / ❓ 不确定，而它**卡住了当前工作**；
- **API 版本变了**（升级 `compatibleSdkVersion` 后旧结论全部待复核）；
- 需要**追问细节**（原答太笼统）。

### 3. 每次提问都要留下 prompt 原文

从 `prompts/` 里最近一份复制改名，保留头部的**本机版本信息**和末尾的**防编造约束**（约束比问题本身更重要）。
命名：`prompts/YYYY-MM-DD_主题_APIxx.md`。

### 4. 不删旧结论，只标记推翻

被后续问答或真机实测推翻的结论，**保留原文加删除线**，写成：
`~~旧结论~~ → ❌ 已推翻（YYYY-MM-DD）：<原因>；新结论见 <位置>`。
理由：防止下一个 Agent 又走回同一条死路（我们已经在 `FoldSplitContainer` 上踩过一次）。

### 5. 置信度标记（落码前必看）

| 标记 | 含义 | 能不能直接落码 |
| --- | --- | --- |
| ✅ | 官方接口/文档明确记载 | 可以 |
| ⚠️ | 对方基于文档机制**推断** | **真机验证后**才能进关键路径 |
| ❓ | 官方文档未记载（对方诚实说"不确定"） | **不许押宝**，只做 spike 验证或绕开 |
| ⏸ | 方案暂缓（缺未验证的前提） | 等前提验证 |
| ❌ | 已推翻 | 禁止沿用 |

> 总原则：**凡标 ⚠️ / ❓ 的，真机验证前不许写进关键路径。**

## 工作流

### A. 要问一个新问题

1. 查 `api_notes.md` 和下方索引表 → 确认没问过（见铁律 2）
2. 从 `prompts/` 最新一份复制 → 改名 `prompts/YYYY-MM-DD_主题_APIxx.md` → 改问题
3. 粘给鸿蒙官方 Agent / DevEco AI
4. 拿到回答后走 B

### B. 拿到官方回答

1. **先存档**：`qa/YYYY-MM-DD_主题_APIxx.md`，逐条记「问了什么 → 官方怎么答 → 标记」。逐字原文能留就留，留不下就写要点清单并注明。
2. **再提炼**：把结论写进 `api_notes.md` 对应主题组，**每条必须带置信度标记**（✅/⚠️/❓）。
3. **更新索引**：在本文件底部索引表加一行。
4. **回填影响面**：结论推翻了既有设计，同步改 `docs/mvp_design.md` / 代码，并在 `api_notes.md` 的落地上表里记一笔。

### C. 真机验证之后

把验证结果**回写到 `api_notes.md`**：⚠️/❓ → ✅，并把**实测值**（如三屏态真实 `FoldStatus`、真实折痕 Rect）直接写进文档。
实测值比官方答复更可信，是知识库里价值最高的部分。
