### 2. 应用能否接收或识别“指关节双击”事件？

**结论：不能（未记载任何指关节识别能力）。**

- ArkTS 侧触摸事件（`TouchEvent`）可区分的输入来源为触摸屏、鼠标、触控笔、键盘等物理设备类型，公开事件模型中没有“指关节”这一来源类型，无法确认。
- Native 侧 `OH_ArkUI_UIInputEvent_GetSourceType()` 返回的也是“产生输入事件的真实物理设备，如触摸屏、鼠标”这类来源类型，输入工具仅区分手指、触控笔等，同样没有指关节<rsub ref="G.2.3">3</rsub>。
- **分发与仲裁**：指关节截屏手势在系统输入层被识别并消费，不会作为普通触摸事件分发给应用窗口。ArkUI 手势仲裁机制（命中测试收集、统一管理、互斥/并行手势）只作用于应用内已绑定的手势<rsub ref="H.1.5">4</rsub>，系统手势不在其仲裁范围内。NDK 手势拦截回调中虽可区分“是否系统手势”并建议对系统手势放行（返回 CONTINUE）<rsub ref="H.1.10">5</rsub>，但该回调针对的是长按等可透传的系统手势，指关节截屏事件本身不会到达应用，ArkUI/ArkWeb 的编辑、滚动等交互理论上不会影响它——此句为基于资料的推断，Mate XT2 实机行为无法确认。

### 3. 应用如何确保不妨碍系统手势？如何避免双截图？

- 系统手势在系统层处理，应用收不到该事件，正常情况下**不存在“应用拦截导致系统截屏失效”**的路径，应用无需做任何额外处理（基于资料的推断）。
- **双截图问题**：由于应用无法感知指关节双击事件，应用自行截图的触发源（按钮点击、应用内手势等）与系统截屏手势天然是两个独立入口，不会因为一次指关节双击同时触发两张截图。需要避免的是产品逻辑层面的重复：不要在应用内再提供与系统手势重叠的“指关节”类交互入口，也不要在 `onScreenshot` 类回调（API 24 未提供此类回调，未记载）中再做二次保存。

最小示例（组件截图 + 全屏截图 + 权限申请 + 保存相册的核心流程）：

```typescript
import { componentSnapshot, screenshot, window } from '@kit.ArkUI';
import { abilityAccessCtrl, common, Permissions } from '@kit.AbilityKit';
import { image } from '@kit.ImageKit';
import { BusinessError } from '@kit.BasicServicesKit';

@Entry
@Component
struct SnapshotDemo {
  @State pixmap: image.PixelMap | undefined = undefined;

  // 方式一：组件截图（无需权限），截取 id 为 'root' 的组件
  takeComponentSnapshot(): void {
    try {
      this.pixmap = this.getUIContext().getComponentSnapshot()
        .getSync('root', { scale: 1, waitUntilRenderFinished: true });
    } catch (err) {
      console.error(`getSync failed: ${(err as BusinessError).message}`);
    }
  }

  // 方式二：全屏截图（API 21 起手机可用，需 CUSTOM_SCREEN_CAPTURE 权限）
  async takeFullScreenShot(): Promise<void> {
    const hostContext = this.getUIContext().getHostContext() as common.UIAbilityContext;
    const atManager = abilityAccessCtrl.createAtManager();
    const result = await atManager.requestPermissionsFromUser(hostContext,
      ['ohos.permission.CUSTOM_SCREEN_CAPTURE' as Permissions]);
    if (result.authResults.length === 0 || result.authResults[0] !== 0) {
      console.error('permission denied');
      return;
    }
    try {
      const pixelMap = await screenshot.capture({ displayId: 0 }); // 主屏
      this.pixmap = pixelMap;
    } catch (err) {
      console.error(`capture failed: ${(err as BusinessError).message}`);
    }
  }

  build() {
    Column() {
      Image(this.pixmap).width(200).height(200)
      Button('组件截图').onClick(() => this.takeComponentSnapshot())
      Button('全屏截图').onClick(() => {
        this.takeFullScreenShot();
      })
    }
    .id('root')
    .width('100%')
    .height('100%')
  }
}
```

注意：`PixelMap` 使用完毕后必须调用 `release()` 释放内存，否则可能内存泄漏<rsub ref="G.1.1">7</rsub>。保存到相册时，将 PixelMap 先编码写入应用沙盒文件，再通过 `SaveButton` 或 `showAssetsCreationDialog` 写入媒体库<rsub ref="H.2.1">14</rsub>。
