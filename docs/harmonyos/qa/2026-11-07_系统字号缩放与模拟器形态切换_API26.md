# 系统字号缩放与模拟器形态切换（API 26 模拟器环境）

> 2026-11-07 向官方文档 Agent 的问答，背景：[v1.10 基础无障碍](../../releases/v1.10/需求文档.md) 系统字号适配与形态矩阵验证。
> 环境已随提问注明：Windows x86_64 宿主 DevEco Studio 自带 API 26 模拟器（HarmonyOS 7.0.0，SP8DEVC00E999R4P11，型号 emulator，屏幕 3184×2232）；被测应用 ArkTS Stage 模型，compatibleSdkVersion 6.1.1(24)。
> 提问时已随附本机核实事实：设置内「字体大小」滑条「标准」档在布局树里值为 2.000000；`settings list system/global` 无任何 font/fontSize/scale 键。
> 问题共 7 项：命令行改系统字号是否存在 / 滑条档位与 fontScale 映射 / 应用侧读取缩放系数的 API / 字号变化是否实时生效 / Text maxFontScale-minFontScale 语义 / 字号缩放与显示大小是否独立维度 / 模拟器折叠形态切换命令。防编造约束：查不到答「未记载」，不许猜接口名。

## 1. 命令行修改系统字体大小：❓ 未记载

- 官方 hdc 工具说明与模拟器命令行说明均未记载 `hdc shell settings put ...` / `param set ...` 改系统字体大小的方式；与本机 `settings list system/global` 无相关键的核实一致。
- 官方记载的自动化路径只有：模拟器命令行（仅折叠形态切换、屏幕配置等场景化命令，不含字体大小）；应用侧 `setFontSizeScale`（只影响**本应用**字体，设置后不再跟随系统，不能替代系统字号放大的适配验证）。
- 结论：**系统字号放大验证仍需手动（或 UI 自动化）操作设置界面滑条**。

## 2. 滑条档位与 fontScale 映射：❓ 档位表未记载

- 「标准」档 = fontScale 1.0（滑条布局值 2.000000 是设置界面的 UI 档位索引，不是缩放系数）。
- 适老化适配指南建议：应用若需适应系统字体大小变化，最大应调整至 **1.75 倍**，部分组件可调整至 2 倍，即 `fontSizeMaxScale` 建议配置为 1.75。
- 精确档位表需在设备上逐档拖滑条后读 `Configuration.fontSizeScale` 实测建立。

## 3. 应用侧获取字号缩放系数：✅ 三条记载路径

| API | 模块 | 起始版本 | 说明 |
| --- | --- | --- | --- |
| `Configuration.fontSizeScale` | `@ohos.app.ability.Configuration`（Ability Kit） | API 10 | `context.config` 读取当前字体缩放系数 |
| `ApplicationContext.onSystemConfigurationUpdated` 的 `onFontSizeScaleUpdated` 回调 | `@ohos.app.ability.systemConfiguration`（Ability Kit） | API 24 | 注册后系统字号变化回调新值；`offSystemConfigurationUpdated` 注销 |
| `UIContext.getMaxFontScale()` | `@ohos.arkui.UIContext`（ArkUI） | API 13 | 读当前 UI 上下文**最大**字体倍率（受 configuration 标签 `fontSizeMaxScale` 约束） |

## 4. 字号变化是否实时生效：✅ 实时，但有配置前提（关键）

- **应用字体大小默认不跟随系统变化**。必须在 `AppScope/resources/base/profile/configuration.json` 配置 `"fontSizeScale": "followSystem"`，并在 `AppScope/app.json5` 用 `"configuration": "$profile:configuration"` 引用，应用内 fp 字号才会跟随系统字号缩放。
- 配置 followSystem 后，系统字号变化时前台应用实时收到配置更新回调（UIAbility `onConfigurationUpdate`，或 API 24 起 `onFontSizeScaleUpdated`），UI 自动重排，无需重启。
- 若调用 `setFontSizeScale` 自定义字体大小，则不再跟随系统，也不再触发系统字号变化订阅。

## 5. Text maxFontScale / minFontScale 语义：⚠️ 版本记载有出入，语义一致

- 官方回答称 Text/Button/Search 等组件的 `maxFontScale` / `minFontScale` 是 **API 18 起**；但本机 SDK（DevEco 26.0，API 26 镜像）`ets/component/text.d.ts` 对两者的声明注释均为 `@since 12`。**两处均 ≤ 工程兼容上限 API 24，不影响可用性；编译以本机 d.ts 为准，档位差异已记录，不视为冲突。**
- `maxFontScale(scale)`：范围 [1, +∞)，小于 1 按 1 处理；限制系统缩放使文本放大时的上限。
- `minFontScale(scale)`：范围 [0, 1]；限制系统缩放使文本缩小时的下限。
- 二者只约束「系统字号缩放」维度，不改显式 `fontSize` 基准（实际渲染字号 = fontSize × 被钳制后的系统缩放系数）；不设置时默认不钳制（前提仍是配置了 followSystem）。

## 6. 字号缩放与显示大小缩放：✅ 两个独立维度

- 字体大小（fontSizeScale）作用于 fp 单位文本字号；显示大小是与像素单位无关的缩放系数，影响 vp 与 px 换算（density）。
- 窗口侧 `window.getWindowDensityInfo()`（API 15 起）返回 `WindowDensityInfo`，`systemDensity` 为系统显示大小缩放系数，范围 0.5–4.0。
- 即 vp 布局受显示大小影响，fp 字号受字体大小影响，两个滑条各自独立取值。

## 7. 模拟器折叠形态切换命令：✅ 存在（宿主侧 CLI，非 hdc shell）

- 模拟器命令行：`Emulator -instance {模拟器名称} -foldedState {折叠开合状态}`。
- 文档记载的支持状态：双折叠设备、Pura X Max 为 `open | half-open | close`；阔折叠设备（Pura X Max 除外）为 `open | close`；折叠 2in1 设备为 `open | vertical-open | half-open | close`。
- **三折叠设备**在该命令下的具体取值未记载（三折叠存在 F/M/G 三种形态，展开态对应 `FoldStatus.FOLD_STATUS_EXPANDED_WITH_SECOND_EXPANDED`，与双折叠判定逻辑不同）——需在本机三折叠模拟器上以 `open / half-open / close` 实测各值对应形态后固化，作为形态矩阵自动化的参数集。

## 8. 官方给出的适配验证流程

配置 followSystem → 启动应用 → 手动拖系统字体大小滑条 → 应用实时重排 → 逐档截图检查截断/遮挡/溢出 → `Emulator -foldedState` 切换折叠形态 → 重复字号 × 形态组合矩阵。若需「档位 → 系数」映射表，应用内读 `context.config.fontSizeScale` 配合逐档拖动实测建立。
