## 问

鸿蒙官方组件库有没有现成的「关系图谱 / 力导向图」组件（类似 Obsidian Graph View）？
没有的话，用哪些官方能力自绘？各自适用场景与性能边界如何？

## 答（AI 转述，要点）

- **无现成图谱组件**，需自绘。
- 官方可选能力：Canvas / CanvasRenderingContext2D（首选 2D 绘制）、XComponent（高性能自绘 Surface）、
  NodeContainer + NodeController / RenderNode（节点树管理）、OffscreenCanvas（离屏渲染）。
- 实现思路：节点数据（位置 / 速度）+ 边数据 + 力导向模拟（斥力 / 引力迭代）+ Canvas 每帧重绘；
  `onTouch` 触点与节点坐标做距离判断实现点击选中 / 拖拽。
- 性能：节点数百以上 → 力模拟放 taskpool / OffscreenCanvas 避免阻塞主线程；Canvas 宽高超 8000px 性能下降 → 改 RenderNode。
- 生态替代：三方组件库（hm chart 等，基于 ECharts）可省自绘。

## 本机 SDK 复核结论（真源见 api_notes AP1–AP4）

- ✅ Canvas / CanvasRenderingContext2D：`@since 8`，本仓 v1.63 启动页噪点已落地，2D 绘制接口 API ≤ 24。
- ✅ XComponent `@since 8`、RenderNode `@since 11`、OffscreenCanvas `@since 12`、NodeContainer `@since 8`：均 ≤ API 24，可用。
- ⚠️ OffscreenCanvas「独立线程离屏渲染」完整链路（OffscreenCanvasRenderingContext2D + worker 转移 + transferToImageBitmap）未逐条坐实。
- ❓ 「Canvas 8000px 上限、官方推荐改 RenderNode」为 AI 转述，官方文档未坐实；与硬约束 12（Web 组件 7680px）是两个不同对象。

## 方向收口

首选 **Canvas + 力导向**；性能升级备选 XComponent / RenderNode / OffscreenCanvas（AP3 先核实）；
原生实现前做「力导向 + onTouch 命中」spike（沿用 v1.94 / v0.2 spike 先例），通过后再开原生版。
