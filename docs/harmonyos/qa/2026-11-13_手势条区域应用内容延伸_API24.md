# 手势条区域应用内容延伸 / 沉浸式规范（2026-11-13，API24）

> 背景：AE1 曾据 hidumper/uitest 实测断言「底部 80px 是系统手势条专属区，应用内容按规范不应使用」。用户质疑：其他应用没有这条底部空带。就 5 问求证官方，答复**推翻了「不应使用」的推断**——官方 UX 标准恰恰要求可滚动内容显示在导航条下方。答复为官方 Agent 文档型回答（用户转交，见下方逐条），关键声明已用本机 API 26 SDK 复核。

## 问了什么（可复现粒度）

环境：DevEco Studio 6.0，compileSdkVersion API 24（`compatibleSdkVersion 6.1.1(24)`）；调试设备 API 26 x86_64 模拟器（Huawei TripleFold 3184×2232，density 2.4x），目标真机 Mate XT2 三折叠（API 24）。Stage 模型 ArkTS 应用。

已实测事实（`hidumper -s WindowManagerService -a '-a'`）：应用主窗口全屏 `[0,0,3184,2232]`（未调 `setWindowLayoutFullScreen`）；系统手势条窗口 `SCBGestureNavBar [0,2152,3184,80]`（ZOrd 2200）浮其上；应用当前把交互内容布局限制在 `[0,2152]`，底部 80px 只画页面底色；视觉上出现约 26vp 纯色条，而系统应用和其他三方应用内容看起来铺满到底、没有这条空带。

1. 手势指示条（小白条）所在约 26vp 区域是系统独占、应用内容不得进入，还是允许内容渲染到小白条下方？官方推荐做法是什么？
2. 备忘录、文件管理等系统应用的可滚动列表是否滚到小白条下方直到物理下沿？内容是渲染在 `SCBGestureNavBar` 系统窗口之下透出来的吗？
3. 若要让列表滚到物理下沿：用哪个 avoidArea 枚举拿手势条高度？window 需要什么状态？
4. 手势指示条颜色/深浅能否由应用侧控制（深色内容下指示条看不清）？有没有对应 API？
5. 三折叠不同展开形态下该区域高度是否一致？是否只能用 windowSizeChange + px2vp 断点机制适配？

末尾防编造约束：查不到直接答「未记载」，不猜接口名/枚举值，引用 API 时给出引入版本。

## 官方逐条答复

### 1. 是否系统独占

不是系统独占。沉浸式布局下应用可用布局区域延伸到整个窗口，系统 UI（状态栏、导航区域）浮在应用内容之上，应用内容可以渲染到小白条下方。官方通用应用 UX 体验标准明确要求：**应用内可滚动内容需要能显示在导航条下方**；底部固定控件、悬浮按钮等向上抬高避让导航条，避免误触，并为导航条提供沉浸背景。推荐做法：**可滚动内容铺满到屏幕物理下沿（小白条浮在内容之上），仅对固定交互控件做底部避让**。

### 2. 系统应用列表是否滚到小白条下方

是。即官方 UX 标准要求的形态——可滚动内容显示在导航条下方，滚动到底时避免导航条遮挡导致最底部功能不可用。实现即沉浸式布局：窗口内容延伸至整个窗口，`SCBGestureNavBar` 系统窗口浮在应用内容之上透出。

### 3. 避让区域类型与窗口状态

- 枚举：`window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR`，`getWindowAvoidArea(type)` 取 `avoidArea.bottomRect.height`（单位 px，需 px2vp）。
- 窗口状态：`setWindowLayoutFullScreen(true)`（API 9+）或 `setImmersiveModeEnabledState(true)`（API 12+，效果一致）。本应用主窗口已实测全屏，沉浸式已生效，可直接取避让区。
- 建议注册 `on('avoidAreaChange')` 在导航条显隐、折叠展开时动态更新。

### 4. 指示条颜色控制

可以。`setWindowSystemBarProperties`（API 9+）设置 `SystemBarProperties`：`navigationBarColor`（背景色）、`navigationBarContentColor`（小白条颜色，API 8 起支持）。注意：分屏、自由悬浮窗、自由多窗模式下不立即生效，仅全屏主窗口生效，2in1 设备不生效。

### 5. 三折叠各形态高度

不同展开形态下高度是否一致：**未记载**。官方推荐适配方式不是 windowSizeChange + px2vp 推算，而是监听 `on('avoidAreaChange')`——折叠/展开、导航栏显隐时系统回调给出对应 `AvoidArea`（含 `bottomRect.height`），无需按窗口尺寸推算；高度单位 px，布局时 px2vp。

官方附注：

- `AvoidArea.visible` 无实际含义，官方明确建议避免使用。
- 避让区矩形以窗口左上角为原点，底部导航区表示为 `bottomRect (0, H-h2, W, h2)`。
- 全局悬浮窗、模态窗等系统窗口获取避让区需先 `setSystemAvoidAreaEnabled(true)`（API 18+）；主窗口无需。
- 沉浸式全屏场景（游戏/全屏视频）导航条可自动隐藏，底部上滑恢复。
- 三折叠各形态高度**不要硬编码 26vp**，以 `avoidAreaChange` 回调实测值为准。

## 结论与落地

- ❌→✅ **推翻 AE1 的「应用内容按规范不应使用」**：官方 UX 标准要求可滚动内容显示在导航条（小白条）下方、铺满到物理下沿，仅固定交互控件避让。用户观察「其他应用没有底部空带」正确——它们的内容滚到了小白条下面。
- 本应用现状（交互内容布局止于 `[0,2152]`，底部 26vp 只剩底色）**不符合官方 UX 标准**，属可修的产品问题，不是系统独占限制。
- 落地路径（待版本需求承接）：`avoidAreaChange` / `getWindowAvoidArea(TYPE_NAVIGATION_INDICATOR)` 取高度 → 可滚动列表视口铺满到底 → 固定控件（新建按钮、底部工具栏、编辑器工具条等）加底部避让 → 深色内容下 `setWindowSystemBarProperties` 调 `navigationBarContentColor` 保对比度。改动范围必须整页统一（工作区 + 次级页面），呼应 AE1 回退复盘。
- ⚠️ 三折叠各形态高度数值未记载，不得硬编码 26vp（模拟器 80px ≈ 26vp 仅为 x86_64 API26 观测值）。
- ⚠️ `setWindowSystemBarProperties` 分屏/悬浮窗/多窗/2in1 不生效，XT2 全屏主窗口预期可用、待实测。
- ⏭ 待真机回归：XT2 / API24 各展开形态 `avoidAreaChange` 回调值。
- 结论提炼进 [api_notes AE1 更正 + AE2](../api_notes.md)。
