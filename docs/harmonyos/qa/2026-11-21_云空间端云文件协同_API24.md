# 华为云空间同步 = Core File Kit 端云文件协同（API 24 前置核实，2026-11-21）

> 背景：需求池 C 节「华为云空间同步」（`open_questions.md` Q8 并列候选）标注「API 24 待核实，走 `docs/harmonyos/` 提问流程」。本轮就路线 1（华为云空间）向官方 Agent 发起核实提问，答复为官方 Agent 文档型回答（用户转交，要点见下方）。关键声明已用**本机 API26 SDK d.ts**（`@ohos.file.cloudSync.d.ts`、`application/Context.d.ts`、toolchains `modulecheck/app.json`）、**本机文档库**（`devecocli docs`《端云文件协同适配指导》《端云文件协同概述》）逐条复核，全部坐实或有明确标记。

## 问了什么（可复现粒度）

环境：DevEco Studio 26.0.0.851，`compatibleSdkVersion 6.1.1(24)`（API 24），`targetSdkVersion 26.0.0`；华为 Mate XT2 三折叠真机（系统 API 26）；Windows x86_64 模拟器（API 26）。场景限定：本地 Markdown 笔记应用，笔记库 = `.md` 文件 + 附件图片的目录树（未来可能上千文件、单文件最大几 MB）；**不要端云一体化建表方案**，只要「文件/目录在云空间的读写与同步」。

提问（8 问）：

1. 三方应用接入华为云空间做文件同步的官方路径是什么？哪个 Kit / API（确切 Kit 名、模块名、@since 版本）？
2. 上述能力在 API 24（6.1.1(24)）是否可用？最低起始版本？
3. 授权与目录模型：应用专属云空间目录还是用户任意目录？用户怎么授权？需要什么权限？是否需 AGC 开通服务、有无上架审核前置？
4. 文件读写语义：云空间目录里 create / write / rename / delete 的行为？「本地缓存 + 自动双向同步」还是显式上传下载？断网时读写行为？
5. 多设备冲突：两台设备同时修改同一文件时平台怎么处理？有无冲突回调、保留策略、版本历史接口？
6. 同步状态：能否查询/订阅单文件或目录的上传下载进度与同步状态？`@ohos.file.cloudSync` 适用此场景还是仅适用应用沙箱数据？
7. 用户未开云空间 / 空间不足时的行为与错误码？应用能否检测用户是否开通云空间？
8. 文件数量、单文件大小、同步频率有无限制？

末尾防编造约束：每问若无明确记载直接答「未记载 / 不确定」，不猜接口名、Kit 名或版本号；给接口必须给来源。

## 官方逐条答复（要点）

### 1. 官方路径 = Core File Kit「端云文件协同」，不是 Drive Kit

- Drive Kit（云空间服务）目前面向 Android / Web 平台应用接入；HarmonyOS 应用侧官方文件同步方案是**端云文件协同**。
- Kit：Core File Kit；模块 `@ohos.file.cloudSync`（`import { cloudSync } from '@kit.CoreFileKit'`），首批接口 API 10 起。
- 核心对象：`cloudSync.FileSync`（同步状态管理与触发）、`cloudSync.CloudFileCache`（缓存/释放缓存）、`fileIo`（基本文件操作，含 `setxattrSync`/`getxattrSync` 扩展属性同步）。
- 沙箱路径：`/data/storage/el2/cloud`，经 `context.cloudFileDir` 获取。

### 2. API 24 可用性：可用

- 指南要求开发环境 SDK API 21 Release 及以上 → API 24 满足。
- 设备侧约束：调试设备系统 HarmonyOS 6.0.0.115 及以上，云空间版本 6.0.0.300 及以上。
- 例外：缓存大小查询与清理（`getCachedTotalSize`、`cleanAllFileCache`）要求 SDK API 26.0.0 Release 及以上，API 24 不可用。

### 3. 授权与目录模型：应用专属目录，无额外权限

- 应用访问的是**应用专属的云空间同步目录**（沙箱内 `/data/storage/el2/cloud`），不是用户云空间任意目录。
- 接入：① `AppScope/app.json5` 配 `"cloudFileSyncEnabled": true`；② 用户登录华为账号后，在**设置 → 云空间**找到该应用的同步开关并打开。
- 需要声明的权限：文档未记载需要额外权限。AGC 开通服务、上架审核前置：文档未记载。

### 4. 读写语义：本地缓存 + 系统自动双向同步

- 基本文件接口在 `/data/storage/el2/cloud` 下读写、重命名、拷贝、建目录；写入完成/目录创建成功后端云协同服务**自动触发同步上云**，无需显式上传。
- 下行：云上新增文件时元数据自动下行，此时文件 Location=2（本地仅元数据），需 `CloudFileCache.start(uri)` 按需缓存到本地才能读内容。
- Location 三态：1=仅本地（未上云）、2=仅云端（本地仅元数据）、3=本地+云端各一份。
- 断网：本地读写不受影响，同步延迟；`FileSync` 订阅状态，网络异常错误 `NETWORK_UNAVAILABLE`。

### 5. 多设备冲突：未记载

- 端云文件协同文档**未记载**双端同改一文件的冲突策略、冲突回调、保留策略或版本历史接口。
- `22400007`（"指定用于替换原始文件的历史版本文件不存在"）属云空间历史版本相关能力，指南未提供对应开放接口说明，对三方应用可用性无法确认，以 SDK d.ts 为准。

### 6. 同步状态：`@ohos.file.cloudSync` 就是本场景配套接口

- `FileSync.on/off('progress')`：同步过程事件，`SyncProgress` 含 `state`（SyncState，STOPPED=5 等）与 `error`（ErrorType，网络/电量/温度）。
- `FileSync.start()/stop()`：主动触发/停止；**`start()` 仅支持有限并发，调用频率过高会导致整机异常**。
- `CloudFileCache.on('progress')`：单文件缓存（下载）进度，`DownloadProgress` 含 `processed` 与 `error`；`CloudFileCache.start(uri)` 最大并发不超过 10，超过建议 `startBatch`。

### 7. 未开云空间 / 空间不足

- `22400001` 云端状态未 ready（未启用云/应用云同步开关未开）；`22400002` 网络不可用；云端空间不足→上行失败、云端无该文件记录；非充电电量低于 10% 完成当前批上行后停止。
- 检测用户是否开通云空间：无专门接口，靠 `FileSync` progress 的 `ErrorType` 间接判断。

### 8. 数量与大小限制：未记载

- 文件数量、单文件大小未记载。频率约束同第 6 条（`FileSync.start` 有限并发、`CloudFileCache.start` ≤10）。
- 官方提供了端云文件协同示例工程可参考。

## 对本工程的影响

1. **需求池 C 节「华为云空间同步」技术路线定型为端云文件协同**：笔记库整体放 `context.cloudFileDir`（`/data/storage/el2/cloud`），目录树 + `fileIo` 的形态与现有沙箱库同构，`VaultAccess` 抽象可平滑加一个 cloud 根实现，上层不按 `rootKind` 分叉的原则（硬约束 14）不受影响。
2. **API 24 可用，真机门槛满足**：XT2（系统 API 26）≥ HarmonyOS 6.0.0.115；云空间版本 6.0.0.300 需装机时确认。零新增权限，不触发硬约束 13 例外；`app.json5` 加 `cloudFileSyncEnabled: true` 是一次性开关（注意：这是全局开关，加之前评估对 git 同步库、外部库是否产生意外行为）。
3. **必须由版本需求承接的差异点**（与 git 路线的本质差异）：
   - 无版本历史语义、冲突策略未记载（❓）→ 产品需自防（如写入前 `FileSync.start` 拉齐、库级提示「多端勿同时编辑」），不能押宝平台合并；
   - Location=2 的附件需 `CloudFileCache.start` 按需缓存后才能读（图片附件可借此省本地空间，但打开附件的链路要处理「缓存中/失败」态）；
   - `FileSync.start` 有限并发（不可高频触发）、`startBatch` 单批 ≤400 URI（千级文件库首次全量下行要分批）；
   - `getCachedTotalSize`/`cleanAllFileCache` 是 API 26 接口，API 24 上的「空间管理」功能要么砍掉要么门禁。
4. **仍未解决，进入排期前必须补**：AGC 开通/审核前置 ❓、文件数量/单文件大小限制 ❓、冲突实测 ⏸（双机同改一文件，观察平台行为）、云空间版本装机确认。
5. 与既有决策不冲突：git（libgit2）与本地目录候选保留；本结论只把「华为云空间」候选的可行性问题从 ❓ 收敛为 ✅（能力存在、API 24 可用）+ 遗留 ❓（冲突与前置）。
