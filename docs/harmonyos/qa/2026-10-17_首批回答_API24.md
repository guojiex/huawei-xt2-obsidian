## A 组：三折叠形态与折痕

| # | 问了什么 | 官方怎么答 | 标记 |

| A1 | 获取当前折叠形态的准确接口 | `display.isFoldable()` / `display.getFoldStatus()` / `display.on('foldStatusChange')` / `display.on('foldAngleChange', cb<Array<number>>)`，从 `@kit.ArkUI` 导入。三折叠返回**两个**角度 | ✅ 接口 / ❓ 三屏态返回值 |
| A2 | 折痕区域接口、三折叠返回几段 | `display.getCurrentFoldCreaseRegion(): display.Rect` —— **只返回单个 Rect**，三折叠有两条铰链，会返回哪段**未记载** | ✅ 接口 / ❓ 三折叠行为 |

| A3 | 三档断点用 `windowSizeChange` + `px2vp()` 是否推荐 | **是，官方推荐**；并明确建议不要用 `getFoldDisplayMode()` 做形态分支 | ✅ |
| A4 | 折叠切换时 UIAbility 会不会重建 | **不会**。尺寸变化走事件通知；`module.json5` 里不存在类似 `configChanges` 的配置项，无需配置 | ✅ |
| A5 | 三折叠全展开算 tablet 还是 2in1 | **始终是 `phone`**，`deviceTypes: ["phone","tablet","2in1"]` 合适 | ✅ |

## B 组：Web 组件

| # | 问了什么 | 官方怎么答 | 标记 |
| --- | --- | --- | --- |
| B1 | `runJavaScript()` 脚本长度上限 | **官方未记载**。官方大数据通道是 `createWebMessagePort()` + `postMessage`（支持 string / ArrayBuffer） | ❓ 上限 / ✅ 替代方案 |
| B2 | 1×1 像素 / hidden 的 Web 组件里 JS 是否执行 | 组件在树上、JS 环境保留；**不推荐 1×1**。官方方案是 `NodeController` + `NodeContainer` 动态挂载（离线 Web 组件） | ⚠️ |
| B3 | Web 内 Worker 能否访问 `javaScriptProxy` 注入对象 | **不能**。注入是注入到 `window`，Worker 无 window。→ 桥接**不放 Worker** | ⚠️ |
| B4 | rawfile 页面 origin 与 CORS | `resource://rawfile/` 协议，ArkWeb **禁止 file/resource 协议跨域**，页面内 fetch 被拦。官方**首选拦截**（`onInterceptRequest`）而非转发 | ✅ |
| B4-延伸 | 拦截方案的致命前提 | `git-receive-pack`（push）是 POST + 大二进制，`WebResourceRequest` **能否拿到 POST body 官方答复未覆盖** → 拦截方案暂缓 | ❓ **待追问（B-1）** |
| B5 | 尺寸变化会不会重载页面 | **不会**，`onPageEnd` 只在加载完成触发。注意：异步渲染下 Web 宽高**不得超 7680px 物理像素**，超了白屏 | ✅ |
| B6 | Web 内中文输入法支持 | 文档未记载系统性问题，**必须真机实测**（contenteditable / textarea） | ❓ |
