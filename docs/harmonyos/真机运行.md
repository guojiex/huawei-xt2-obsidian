## 0. 一句话结论

**先签名，再安装。** 未签名 HAP 真机装不上（`entry-default-unsigned.hap` 只够做编译校验）。

**当前状态（2026-10-17）**：自动签名**已做过一次**，材料在 `C:\Users\<用户名>\.ohos\config\` 下；
但签名配置段含密码明文，**已从 `build-profile.json5` 剥离**（见 §6），
所以仓库里的 `signingConfigs` 看起来是空的 —— 构建前把它拷回来即可：

```powershell
Copy-Item .local\build-profile.signed.json5 build-profile.json5 -Force
.\tools\build.ps1        # 产物变为 entry-default-signed.hap
```

## 1. 一次性准备（手机端）

1. **开开发者模式**：设置 → 关于本机 → 连点「HarmonyOS 版本」**7 次**（会要求输锁屏密码）
2. **开 USB 调试**：设置 → 系统与更新 → 开发人员选项 → 打开「USB 调试」
3. 用**能传数据**的数据线连电脑（很多充电线不通数据，是最常见的"设备列表空白"原因）
4. 手机上弹「允许 USB 调试」→ 允许（勾上"始终允许"省事）

Windows 侧一般免驱；设备管理器里如果出现带感叹号的未知设备，装华为手机助手补驱动。

## 2. 签名（只做一次）

DevEco Studio 打开工程 → `File > Project Structure > Project > Signing Configs`：

- 勾选 **`Automatically generate signature`**
  （API 8/9 的老工程才需要同时勾 `Support HarmonyOS`；本工程是 **API 24**，不用勾）
- 未登录会提示 **`Sign In`** → 用华为开发者账号登录（需实名过的开发者账号）
- 回到 IDE 点 OK，自动签名完成 → `build-profile.json5` 会被写回签名配置

> 🕐 **官方明确的前提：本机系统时间要与北京时间（UTC+8）一致**，不一致会直接签名失败。

签名后再跑一次构建，产物会从 `-unsigned.hap` 变成 **`entry-default-signed.hap`**
（命令行：`.\tools\build.ps1`；也可以在 DevEco 里直接点运行，它会自己构建+签名+安装）。

> 🔒 自动签名写回 `build-profile.json5` 后，**立刻跑一次 `.\tools\signing.ps1 -Import`**：
> 它会把凭据抽到 `.local/local-signing.json`（已 gitignore）并还原 `build-profile.json5` 为干净版。
> 之后**直接 `.\tools\build.ps1` 就是签名构建**——签名由工程级 `hvigorfile.ts` 注入，
> 不需要也不应该再往 `build-profile.json5` 里塞凭据（机制见 `api_notes.md` I4）。

> ⚠️ **换电脑、换手机、换账号后签名会失效**（报错 `signature verification failed` 一类），
> 重新登录账号、重新做一次自动签名即可。

## 3. 三种安装方式

### 方式 A：DevEco 点运行（最省事，第一次推荐）

右上角设备列表选中你的真机 → 点绿色三角 **Run ▶**。
IDE 会依次做：构建 → 签名 → 安装 → 拉起应用。后续改动增量编译，很快。

### 方式 B：命令行（本仓库脚本）

```powershell
.\tools\build.ps1          # 构建（签名配置好后产物为 signed）
.\tools\install.ps1 -List  # 看设备连上没有
.\tools\install.ps1 -Run   # 安装并拉起
.\tools\install.ps1 -Reinstall  # 覆盖安装，保留应用数据
```

脚本会自动定位 DevEco 自带的 `hdc`，**只找到未签名产物时会拦下来并提示去签名**，
不会把时间浪费在设备端的签名报错上。

### 方式 C：手打 hdc

```powershell
$DEV = 'C:\Program Files\Huawei\DevEco Studio'
$hdc = "$DEV\sdk\default\openharmony\toolchains\hdc.exe"

& $hdc list targets
& $hdc install entry\build\default\outputs\default\entry-default-signed.hap
& $hdc shell aa start -a EntryAbility -b com.jxg.huaweiobsidian   # 拉起
& $hdc shell bm uninstall -n com.jxg.huaweiobsidian               # 卸载
```

## 5. 坑（踩过或官方点名的）

| 现象 | 原因 / 处置 |
| --- | --- |
| `hdc list targets` 为空 | 没开 USB 调试 / 线只能充电 / 没点"允许 USB 调试" / 驱动 |
| 安装报签名校验失败 | 产物未签名或用旧签名 → 重做自动签名 |
| 自动签名失败 | **本机时间与北京时间不一致**（官方点名的前提） |
| 装完桌面找不到图标 | debug 包常见 → 用 `install.ps1 -Run` 直接拉起 |
| 报"系统版本与应用不匹配" | 手机系统版本低于工程 `compatibleSdkVersion`（本工程 **6.1.1(24)**），升级手机系统或降工程版本 |
| 改了存储结构后数据没变 | 覆盖安装会**保留数据**，需要卸干净再装（`bm uninstall`） |

## 6. ⚠️ 开源仓库的凭据风险（MIT 公开仓库，别把私钥推上去）—— 已经踩过一次

**2026-10-17**：首次自动签名后，`build-profile.json5` 被写回了 `keyPassword` / `storePassword` **明文**
外加 `C:\Users\<用户名>\...` 绝对路径，差点进 commit（已剥离，`git log` 历史确认未污染）。

**规矩（AGENTS.md 硬约束 19）**：入库的 `build-profile.json5` **永久**是 `"signingConfigs": []`。

### ✅ 已解决（2026-10-17）：凭据搬出 `build-profile.json5`

签名改由**工程级 `hvigorfile.ts`** 注入，凭据只存在于 `.local/local-signing.json`：

```typescript
// 根 hvigorfile.ts（节选）
config: {
  ohos: {
    overrides: { signingConfig: { type: 'HarmonyOS', material: { ... } } }
  }
}
```

- 机制与 SDK 证据见 `docs/harmonyos/api_notes.md` **I4**
  （`config.ohos.overrides.signingConfig`，`mergeSigningConfig()` 里 overrides 优先级更高）
- ⚠️ 运行时 schema **只接受 `material` / `type` 两个字段**，写 `name` 会构建失败
  （别被 `.d.ts` 里的 `RequiredNamed { name: string }` 骗了）
- 没有 `.local/local-signing.json` 时不注入，构建照样成功，产物是 `-unsigned.hap`

日常流程：

```powershell
.\tools\signing.ps1 -InstallHook   # 首次：装 pre-commit，凭据被 git add 直接拒提交
.\tools\signing.ps1 -Import        # DevEco 自动签名后跑一次：抽凭据 + 还原干净版
.\tools\signing.ps1 -Status        # 看三态
.\tools\build.ps1                  # 直接签名构建 → entry-default-signed.hap
```

提交前自检：

```bash
git diff build-profile.json5     # 必须是空（现在应当永远为空）
```

### ❓ 顺带回答：那为什么不直接 ignore 掉 `build-profile.json5`？

三个原因，其中一个有实测：

1. **`hvigor` 找不到它就崩**（实测报错）：
   `hvigor ERROR: 00304035 Not Found — Cannot find project build file build-profile.json5`
2. **它装的是要共享的工程配置**：`products` / `modules` / `targetSdkVersion` / `compatibleSdkVersion` /
   `buildModeSet` / `strictMode`。签名段只是其中一小块，为藏一块丢整份不划算——别人 clone 下来无法构建。
3. **加 ignore 也拦不住**：文件已 tracked，`.gitignore` 对已跟踪文件无效，
   得 `git rm --cached` 才生效，效果等于从仓库删掉。

> 另：`ignore` ≠ 删除。被忽略的文件一直躺在磁盘上，随时能拷回来（这是旧方案的做法）。

### 其他

- 签名材料（`.p12` / `.cer` / `.p7b`）可能落在工程目录内 → `.gitignore` 已按扩展名忽略它们。
- 已经误提交的，改密码 + 重新签名，并当作泄露处理（`git log` 里删不掉历史）。
