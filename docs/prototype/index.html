设计稿说明（这几条是决策，看效果时一起判断）

  
    
    
  • 视觉基线（本轮改动）：整套 draft 按 HarmonyOS Design 重做，不再是随手调的数值 ——
      色板用语义色（品牌 #007DFF + 成功/警告/危险 + 三级文本灰），深色模式另有一套 token；
      圆角按控件场景取（图标 8 / 列表项·输入框 12 / 卡片·弹窗 16 / 按钮·菜单 20 / SnackBar 18 / 徽标全圆）；
      间距走 4vp 栅格（4/8/12/16/20/24/32/48）；
      字号阶梯 11/12/14/16/18/20/24，正文 16fp + 行高 1.65；
      字体鸿蒙黑体 HarmonyOS Sans（浏览器里逐级回退到系统黑体）。
      列表项按 HdsListItem 的观感做：主文本 16fp、副文本 12fp、行高 56vp、选中态主色 12% 底。
    • 
    
  • 这些数值是 token，不是散写的魔法数：落地到 ArkTS 时映射成 app.color.* / app.float.* 资源或一组常量，
      组件里只引用 token —— 否则深色模式和以后换主色都会变成全局搜替换。
    • 
    
  • 落地版本：v0.2（2026-10-17 拍板）。v0.1 界面不动 —— 它已编译通过，骨架不为一层皮重开。
      需求登记在 requirements_backlog.md J 节，验收点在 docs/releases/v0.2/需求文档.md §3.5；
      落码前须核实 J-1（Hds* 组件可引入性）/ J-2（Symbol 引用方式）/ J-3（字体是否需显式指定），见
      docs/harmonyos/api_notes.md I 组；核实前用自绘兜底，禁止凭记忆编组件名或资源 id。
      本文件的 :root 与 [data-theme="dark"] 是 token 真源，ArkTS 侧改值时两边同步。
    • 
    
  • 目录层级靠三样东西说清，不只靠缩进：
    
      ① 每级 24vp 缩进（早先手写 32/48/64/80，级差 16vp 太窄，父子看起来一样深）；
    
      ② 竖向引导线：每级一条，跨行连续——缩进只给"位置"，线才给"归属"，这是最省宽度的层级信号；
    
      ③ 目录与文件分色分工：目录=主色文件夹图标 + 500 字重（结构），文件=中性文档图标 + 400 字重（内容）。
    
      子文件比父目录固定深一级；折叠后子项整体消失，线也跟着断，不会剩半截悬空。
    • 
    
  • 次级页面一定有返回：库管理 / 导入仓库 / 设置都是平级面板，不是层级导航 ——
      进任何一页，顶栏左上角的汉堡都换成返回箭头，一点回笔记视图；顶栏右侧图标按用途收敛
      （导入页不再挂「同步」，设置页不再挂齿轮）。页面标题只出现在顶栏，内容区不重复一个大标题。
      平级面板的理由：这三页都是「配完就回」的一次性任务，做成层级会让返回路径变成猜谜。
    
      ⚠️ 系统返回键 / 侧滑返回的拦截**待核实**（视图是条件渲染不是路由），但顶栏返回按钮是硬要求，不依赖它。
    • 
    
  • 多库模型：vaults/ 下每个子目录是一个独立库。local 只是默认库的名字，本地库可以再新建任意个；每个 Git 仓库导入后也成为一个目录，各自独立同步。切换库只换目录，互不影响。
    • 
    
  • 名称即目录名：改名会连 vaults/ 下的目录一起改，不做「显示名」与「目录名」分离 —— 否则导出到电脑时目录名对不上，还得查映射表。输入时实时预览目标路径，重名自动加后缀，非法字符（/ \ : * ? " < > |）直接过滤掉。
    • 
    
  • Git 库改名不影响远端：改的只是手机上的文件夹名，remote 与分支不动，同步照常。弹窗里必须写明这一句，否则用户会以为改了远端仓库名而不敢改。
    • 
    
  • 删除语义不同：本地库删除 = 目录连内容一起删，**不可恢复**（zip 导出还没做，删了就是真没了）；Git 库「移除本地副本」只删手机上的目录，远端仓库不动，可以重新导入。
    • 
    
  • 栏宽按等分，但等分 ≠ 折痕（真机实测推翻了早先假设）：双屏两栏各 50%、三屏三栏各 1/3。
    
      ⚠️ 早先写的是「边界正好落在铰链上、没有任何一栏横跨折痕」——真机数据证明这是错的：
      XT2 三块物理屏是 379 / 330 / 352（合计 1061）—— ⚠️ 这是由实测窗口宽反推的（1061−709=352、709−379=330），
      不是系统折痕接口直读的值：`getCurrentFoldCreaseRegion()` 的 `creaseRects` 至今没做过真机采集（api_notes A2 ❓、清单 D3 未做）。
      折痕在 379 与 709；
      而等分点是 354.5（双屏）/ 353.7、707.3（三屏）→ 第一处差 25vp。
      后果：只要某栏右边界越过 379，它就横跨第一条折痕 —— 双屏的右栏、三屏的中栏与右栏都横跨。
    
      v0.2 决策（用户拍板）：维持等分、不做动态分栏、不做机型校准表 ——「按官方折痕差不多就行，不用搞太精细」。
      折痕值只用于标注，不参与分栏计算。橙色虚线 = 折痕真实位置，标红 = 该栏被内容横跨。
    • 
    
  • 侧栏因此偏宽：实测下双屏侧栏 354vp（709/2）、三屏侧栏 354vp（1061/3），比文件树需要的 240vp 宽。既然不做动态分栏，就把多出来的宽度用起来 —— 宽屏时每条笔记多显示一行「修改时间 · 字数」，后续还能放摘要或最近打开列表。
    • 
    
  • 目录栏可以整体收起（双屏 / 三屏都可以）：收起点侧栏右上角的「收起 «」，唤回点顶栏左上角的汉堡 ☰（toggle，v0.1 首轮修的就是它）。收起后双屏变「编辑 | 预览」、三屏编辑区扩到 2/3。
    
      ⚠️ 早先说「双屏收起仍然不跨折痕」也是错的 —— 等分边界 354.5 与折痕 379 不重合，双屏的右栏（收起后是预览栏）同样横跨折痕。
      这是物理约束，不是布局没调好：折痕位置硬件固定，要真正不跨折痕就得按 379/330/352 分栏（即动态分栏，已决策不做）。
    • 
    
  • 折痕位置已按真机反推：设计稿里双屏折痕在 53.45%（379/709）、三屏在 35.72%（379/1061）与 66.82%（709/1061），
      —— 与早先「折痕 = 等分点」的假设解耦，两个位置现在是分开画的两件事：等分是布局，折痕是硬件。
    • 
    
  • 单屏态（外屏 380vp）用分段控件在「编辑 / 预览」之间切换：只有一块屏，容不下两栏，编辑与预览互相让位。
    
      开关放在内容区顶部右侧（pane-head 右端）而不是顶栏右上角 —— 顶栏在 380vp 下已经挂了汉堡 / 同步 / 设置三个图标，
      再挤一个 48vp 热区会打架；而且「编辑 / 预览」是内容区的模式，跟文件名并排放才读得懂。
    
      两个 pane 的 pane-head 各挂一个同样的分段控件：切到预览后开关还留在原处，不会跟着编辑区一起消失（这是最容易踩的坑）。
      切到预览时收起软键盘——真机上键盘会挡掉半屏。
    
      ⚠️ 双屏 / 三屏不显示这个开关：两栏 / 三栏同时可见，没有切换的必要。
    • 
    
  • 左滑是跟手的三档手感，不是三个摆设按钮：向左拖（鼠标拖或触摸滑都一样）时行会跟着手指走 ——
    
      ① 拖一半松手 → 吸附露出图标操作条（重命名 / 移动 / 删除，都是 44px 图标，不挤文件名）；
    
      ② 一路滑到底 → 整条变红、只剩「🗑 松手删除」，松手直接删除，底部弹 5 秒「撤销」条兜底；
    
      ③ 文件夹没有第三档：滑到底只会回弹并提示「文件夹不能直接删除」——误删一个目录就是整个子树没了。
    
      越过操作条后拖动带阻尼（越滑越沉），防止手一抖就删掉。同一时刻只允许一行滑开，拖动超过 6px 就不算点击（避免误打开文件）。
    • 
    
  • 目录树可展开 / 折叠：点目录行（或左侧箭头）切换，折叠只影响显示，不动文件；正在编辑的文件即使被折叠也不会关闭。子文件缩进比父目录深一级，▾ = 展开、▸ = 折叠，文件夹图标开口 / 闭合同步变化。展开状态按库分别记忆（切库回来还是原来的样子）。
    • 
    
  • 新建（笔记 / 文件夹）有两级入口，共用一个对话框：
    
      ① 目录树头部「＋」（挨着「目录」标题 / 收起按钮）—— 在 vault 根目录新建（笔记或文件夹由对话框类型切换决定），不继承上次目录；
    
      ② 目录行尾的「＋」（只有目录行有，悬停才明显）—— 直接预填那个文件夹，一步到位。
    
      ⚠️ 侧栏底部的「新建笔记」按钮已移除（2026-10-18 用户拍板）：它和目录行「＋」在「在某个文件夹里建」上完全重复，唯一功能是根目录创建，已由头部「＋」接管。各级入口一致、不重复也不漏根目录场景。
    
      对话框里目录可改：点目录行展开全库目录列表（不受树折叠状态影响，折叠目录里的嵌套目录也列得出来），「根目录」恒为第一项 —— 要建在库根目录就显式选它。
    
      名字可以带 /（如 工程/流式系统/第一篇），缺少的目录会连名字一起建出来；非法字符（\ : * ? " < > |）直接过滤；重名自动加后缀；确认前实时预览目标路径。
    
      ⚠️ 末段不能为空，名称不能以 / 结尾（「只要目录/」会被拒绝：hint 警示 + 确认禁用 + 创建时再拦一道）。这条边界 2026-10-18 对齐：App 侧 normalizeRelPath 本就抛错，原型原先把末尾 / 当没输入、静默建成 只要目录.md，两端体验分裂。
    
      📁 建文件夹靠对话框里的「笔记 / 文件夹」切换（2026-10-18 用户拍板方案 A —— 原话「设计稿里面我要怎么新建文件夹？？？」：此前只能靠笔记名带 / 隐式建目录，建不了空文件夹）：切到「文件夹」后选父目录、填名字（同样可带 / 建多层），确认即建空目录，重名自动加后缀；下次创建仍由所点入口决定默认目录。
    
      🗑 删除同步配套：目录行尾原先只有 rename / move、没有删除按钮（建了文件夹却删不掉），本版补上；确认文案按「空文件夹 / 连里面 N 篇笔记一起删 / 单文件」三种形态给，Git 库照旧加远端警告；doDeleteNote 按 nodeRange 整棵子树移除并扣减文件计数。
      ⚠️ 设计稿原先没定义这个流程：最早的版本底部只有一个没绑行为的占位「新建」按钮，目录级新建入口、对话框形态均为实现期自补设计（2026-10-18 用户拍板：目录选择器 + 头部「＋」根目录入口，移除底部按钮）。
    • 
    
  • 「设置与关于」从顶栏齿轮进入（库管理页底部也有入口）：这里放版本号、一行开源/仓库信息、更新日志，以及当前形态 / 断点 / 库目录的诊断信息——真机校准时要对着这些值看日志。包名行已删（2026-10-21 拍板：那是开发期对 hdc 日志/签名用的诊断值，用户不需要；要查去工程配置或 hdc）。开源信息压成关于组底部一行小字（应用 MIT + 打包 isomorphic-git / CodeMirror 等 MIT 组件，保留最低成本版权声明）。更新日志只列用户可感知的变更，最新在上。版本号由应用包信息读出，不在代码里写死常量（写死必然与 app.json5 漂移）。后续版本才有的设置项在底部灰显占位。
    • 
    
  • 三栏常驻是 XT2 的主场：文件树 / 编辑 / 预览同屏，编辑时右侧实时渲染 —— 这是方案 A（CodeMirror + Web）想换来的东西，编辑区里的语法着色就是对标高亮效果。
    • 
    
  • 编辑区着色为示意：真实效果取决于 M0.5 的 WebView spike（中文输入法、光标、滚动、折叠 resize 四项）。spike 不过就降级 TextArea，着色消失。
    • 
    
  • 图片限高与完整查看：预览图片先按可视预览区的 60% 高度等比缩放，不裁剪；点击图片或按回车可看完整长图，关闭或 Esc 回到原笔记。60% 是原型起点，App 渲染器尚未同步实现。
    • 
    
  • 单屏顶栏沿用现状：紧凑单行标题和 48px 热区搜索图标，不新增常驻搜索框或单独缩小字号。
    • 
    
  • 按版本看交互：v0.4 是当前库文件名快切与最近打开；v1.1 增加当前库正文搜索。设计稿用内存样本演示，增量索引仍须按需求文档在真机实现。
    • 
    
  • [[双链]] 是 v1.2 示意：当前原型可演示跳转、未创建目标和反链；自动补全、同名消歧与重命名更新引用仍按 v1.2 需求验收。#标签 只是着色样本，未分配版本功能。
    • 
    
  • 搜索与双链只在当前库内生效：切库后重新显示该库结果；跨库检索仍留在需求池。
