设计稿说明（这几条是决策，看效果时一起判断）

  
    
    
  • 多库模型：vaults/ 下每个子目录是一个独立库。本地笔记随应用创建、开箱即用、可删除；每个 Git 仓库导入后成为一个目录，各自独立同步。切换库只换目录，互不影响。
    • 
    
  • 删除语义不同：本地库删除 = 目录连内容一起删，不可恢复（建议先导出）；Git 库「移除本地副本」只删手机上的目录，远端仓库不动，可以重新导入。
    • 
    
  • 栏宽 = 一整块物理屏，边界压在折痕上：双屏态两栏各 50%（左列表 / 右笔记），三屏态三栏各 1/3 —— 边界正好落在铰链上，所以没有任何一栏的内容会横跨折痕。合起态单栏 + 抽屉。橙色虚线是折痕标注，不是 UI。规则本身比具体数值重要：先定"一栏占一屏"，宽度是算出来的，不是拍出来的。
    • 
    
  • 侧栏因此偏宽：双屏态下侧栏有 330vp、三屏态 373vp，比文件树需要的 240vp 宽。既然不能收窄（收窄就会跨折痕），就把多出来的宽度用起来 —— 宽屏时每条笔记多显示一行「修改时间 · 字数」，后续还能放摘要或最近打开列表。
    • 
    
  • 折痕位置目前按等分假设：设计稿把双屏折痕放在 50%、三屏放在 1/3 与 2/3。真机上应该用系统折叠状态接口拿实际折痕区域再校准，不能写死百分比。
    • 
    
  • 三栏常驻是 XT2 的主场：文件树 / 编辑 / 预览同屏，编辑时右侧实时渲染 —— 这是方案 A（CodeMirror + Web）想换来的东西，编辑区里的语法着色就是对标高亮效果。
    • 
    
  • 编辑区着色为示意：真实效果取决于 M0.5 的 WebView spike（中文输入法、光标、滚动、折叠 resize 四项）。spike 不过就降级 TextArea，着色消失。
    • 
    
  • 搜索标了 v2：全文搜索依赖全库索引，MVP 不做；MVP 只做文件名检索。
    • 
    
  • [[双链]] 与 #标签 只是渲染示意：两者都依赖索引层，属需求池 B 组，MVP 后置。
    • 
    
  • 跨库检索不做：搜索与双链都只在当前库内生效（本就属 v2），切库后要重新搜。
    • 
    
  • 导入目前只有克隆：pull / commit / push 未实现，所以手机上改了还推不回去；PAT 当前明文存 preferences，正式版必须迁关键资产存储服务。
