# Git 同步页设计（v1.27 · v1.73 · v1.75 · v1.76 · v1.77 · v1.78 · v1.79）

> 现行设计规格，服务 [v1.27 推送](../../releases/v1.27/需求文档.md)、[v1.73 手动拉取](../../releases/v1.73/需求文档.md)、[v1.75 逐行差异](../../releases/v1.75/需求文档.md)、[v1.76 全屏页](../../releases/v1.76/需求文档.md)、[v1.77 视觉重构](../../releases/v1.77/需求文档.md)、[v1.78 右栏铺满](../../releases/v1.78/需求文档.md)与 [v1.79 单屏简化](../../releases/v1.79/需求文档.md)。原型入口：[v2 原型](index.html) → 打开演示开关「Git 库示意」→ 顶栏同步按钮（单屏：更多菜单 →「同步到 Git」），或用 `?ui=2&view=sync` 直达；底部演示脚注「查看结果 → 内容差异」直接展开一例。
> 同步语义（push-only、仅快进、手机不合并）见 [v0.3 §3.2](../../releases/v0.3/需求文档.md)；拉取语义（拒绝合并、仅快进）见 [v1.73 需求](../../releases/v1.73/需求文档.md)。v1.76 起同步是**占满内容区的独立全屏页**（与「设置与关于」同级），不再是浮窗 / 半模态，也不再与导入、分享共用弹窗外壳。

## 1. 思路

手机只负责「把改动安全地推上去」和「把远端更新安全地拉下来」，合并与冲突留给电脑：默认推到 App 固定分支 `xt2`，用户在电脑上把 `xt2` 合并进主线。高级用户可以按库改推送分支（例如每台设备一个分支）。

拉取沿用同一安全边界：只在**工作区干净且本地没有未推送提交**时把远端跟踪分支快进到本地（fast-forward），任何本地领先一律拒绝——手机上不做合并提交、变基或冲突解决。

## 2. 结构

全屏页占满应用内容区，工作区 / 侧栏隐藏（与设置页同范式）；顶部为返回栏，主体左右分栏，底部为操作栏。v1.77 起左栏信息按「推送概览 / 本地改动」两张卡分组，右栏**默认选中首个有差异的文件**，进入页面即看到逐行差异而不是空白占位。下图是**宽屏 / 双屏**形态（右栏铺满 diff 见 v1.78）；**单屏形态完全不同**——不展示 diff、整页单一滚动流，见 §2B：

```
┌───────────────────────────────────────────────────────────────┐
│ ‹  同步到 Git                                                  │  返回栏 settings-header
│    库名 · 推送到 xt2                                           │
├──────────────────────┬────────────────────────────────────────┤
│ ┌ 推送概览 ─────────┐ │ 逐行差异   当前工作区 ↔ 上次提交        │  标题贴顶（带底部分隔线）
│ │ 远端 github.com/… │ ├────────────────────────────────────────┤
│ │ 分支 xt2 [更改]   │ │ [M] 00_开始/快速上手.md  +2−1          │  文件头固定（不随滚动）
│ │ 待推送 2 已提交   │ │ 修改：上次提交 → 当前工作区             │
│ └────────────────────┘ ├────────────────────────────────────────┤
│ ┌ 本地改动 3 个文件 ┐ │ 1  1 │ # 快速上手                      │
│ │ ▍[M] 快速上手 +2−1│ │ -   - │ - 右侧是参考栏                  │

├──────────────────────┴────────────────────────────────────────┤
```

## 2A. 内容级 diff（全屏页右栏）

同步页的「本地改动」清单回答「哪些文件变了」，逐行差异回答「每个文件具体改了什么」。用户在推送前就能逐文件核对写入远端的正文，避免误提交敏感或错误内容。v1.76 起差异不再挤在浮窗内就地展开，而是占用**整页右半栏**，与左侧清单并排，长文档能看得更完整。v1.78 起右栏**整栏铺满**：diff 不再是一张浮在灰底上、四周留边、下方空白的卡片，而是贴左右边缘、占满标题行到底部操作栏高度的代码查看器（详见下方「右栏铺满」与 §5 对应行）。

- **入口与口径**：左侧清单每个改动文件是整行按钮（`sync-file-toggle`），点按在**右侧专设的 `sync-detail` 栏**显示该文件的行级 diff；再次点按收起，同一时刻只有一个文件选中（手风琴）。选中行高亮（`selected`）。口径固定为**当前工作区 vs 上次提交**，只覆盖未提交改动，与清单一一对应；已提交待推送的提交、远端跟踪分支的净变化都不在此视图内。推送分支、提交说明、拉取等其它区域不受影响。
- **默认选中（v1.77）**：进入同步页即自动选中**第一个有 diff 的改动文件**——原型 `openGitSync` 从 `gitSyncChanges` 找首个有 `gitSyncFileDiff` 的路径写入 `openFile`，原生 `autoSelectFirstDiff()` 在 `loadFileDiffs()` 回填缓存后设置 `expandedDiffPath` / `activeFileDiff`。右栏直接进入代码查看状态，不再出现「半屏空白 + 一句提示」像没加载的样子。手动点选其它文件仍是手风琴单开，再点当前文件可收起。
- **占位引导**：只有两种情况显示——用户主动收起当前文件，或本地没有未提交改动（「暂无逐行差异可看」）。切换选中会重渲染右栏，占位卡随之消失 / 出现；提交说明与提交者字段是左栏独立控件，不受影响、草稿不丢。
- **三态行**：M 显示「修改：上次提交 → 当前工作区」；A 显示「新文件（本次新增）」，全部为新增行；D 显示「本次删除」，全部为删除行。文件行行尾给出 `+N −M` 增删统计，diff 头给出文件路径与总差异行数。
- **diff 排版**：unified 单栏，每行四列——旧行号、新行号、`−`/`+`/空格标记、正文。删除/新增/未改动分别整行着红/绿/中性底；未改动行两侧行号都有值，删除行只有旧号、新增行只有新号。等宽字体、长行换行；两个行号列用 `--nav` 底形成独立的「代码栏」，正文落在白 / 淡红 / 淡绿底上。
- **右栏铺满（v1.78）**：右栏容器 `.sync-detail` 是 flex 列、`padding:0`、`--paper` 底、`overflow:hidden`；标题行贴顶并带底部分隔线；`.sync-file-diff` 去边框 / 圆角 / 阴影 / 外边距，`flex:1;min-height:0` 从标题行一直铺到底部操作栏，文件头固定、`.sync-diff-lines` `flex:1` 占满剩余高度并内部滚动，空态占位卡同样 `flex:1`。不再有灰边、浮卡阴影与卡片下方空白。原生 `DiffPane()` 去 padding、`DiffPanel()` 去 `borderRadius` / `bg_secondary` / 上下 padding 改 `bg_page`，`layoutWeight(1)` 保留占满剩余高度。
- **数据边界（原型）**：`gitSyncFileDiff` 存三个演示文件的前后文本，未提交改动清单本身仍来自 `gitSyncChanges`；`gitSyncUnifiedDiff` 复用 [编辑冲突对比](index.html) 的 `mismatchDiffRows`（LCS）算法产出增删/上下文行；`gitSyncDiffPaneHtml` 负责右栏渲染。原型不读取本地文件、不执行 Git、不访问远端，diff 文本随刷新恢复；底部「内容差异」演示按钮展开第一例。`openFile` 是唯一控制选中状态的字段，打开同步页即清空。
- **视觉 token**：红底 `--diff-del-bg` + 文字 `--danger`，绿底 `--diff-add-bg` + 文字 `--green`，行号 `--muted`；沿用 §5 通用 token，不散写颜色值。

## 2B. 单屏形态（v1.79 简化版，不展示 diff）

手机竖屏空间不足以同时容下清单和 diff：v1.77 左栏已有「推送概览 + 本地改动（文件 + 提交说明 + 提交者字段）」两张卡，v1.76 定的「上 44% 清单 + 下 56% diff」两段式在 44% 里塞不下这些内容，导致文件列表与提交者字段被裁、两块各自滚动。用户拍板单屏做减法——**不展示逐行差异**，整页只保留一个滚动流：

```
┌───────────────────────────┐
│ ‹  同步到 Git             │  返回栏
│    本地笔记 · 推送到 xt2   │
├───────────────────────────┤
│ ┌ 推送概览 ─────────────┐ │  ↑
│ │ 远端 / 分支 / 待推送   │ │  │
│ └───────────────────────┘ │  │
│ ┌ 本地改动 3 个文件 ────┐ │  │ 单一滚动流
│ │ [M] 快速上手    +2−1  │ │  │（整页一个 Scroll）
│ │ [A] 周会…       +8−0  │ │  │
│ │ [D] 购物清单    +0−5  │ │  │
│ │ 提交说明              │ │  │
│ │ 提交者名称 · 必填      │ │  │
│ │ 提交者邮箱 · 必填      │ │  ↓
│ └───────────────────────┘ │
├───────────────────────────┤
│ 提示 + (取消)(提交并推送) │  页脚（固定）
└───────────────────────────┘
```

- **无 diff**：单屏隐藏右栏 `.sync-detail`（原型 `display:none`）、原生 `build()` 单屏分支不渲染 `DiffPane()`。文件行是纯信息行：无展开箭头、点按不切换、`aria-expanded` / `aria-controls` 不输出；读屏只读「修改/新增/删除 + 路径 + 增删统计」。`+N −M` 统计仍显示（native diff 数据仍加载），但不提供逐行下钻。
- **整页滚动**：原型 phone 下 `.sync-side` 取消 `max-height:44%`、改 `flex:1;min-height:0`；原生单屏清单 `Scroll` 不设固定高度、`BarState.Off`、`nestedScroll(PARENT_FIRST)` 把手势交给整页外层。所有字段滚动可达、不裁切。
- **文案**：两处「点文件在右侧核对正文 / 点左侧文件可在右侧核对正文」在单屏改为「上报的本地改动」，避免指向不存在的右栏。
- **不变**：宽屏 / 双屏仍是 §2 的左右分栏 + v1.78 铺满 diff；推送 / 拉取 / 分支编辑 / 令牌重试与安全边界完全沿用。

## 3. 推送分支编辑

- 「更改」展开 `--nav` 底编辑区：标签「推送到分支」、等宽字体输入框、说明、「恢复默认 xt2」与「保存」。
- 说明三种状态：
  - 普通：「远端没有该分支时，首次推送会创建它。只影响当前库，令牌不变。」
  - 非法（`--danger`，输入框标红，保存禁用）：给出具体原因。
  - 等于跟踪分支（`--danger` 文字，可保存）：「推送会直接更新远端 main，仍只允许快进；建议使用单独分支，在电脑上合并。」
- 校验规则：非空、≤ 100 字符；不含空格与 `~ ^ : ? * [ \`；不含 `..`、`@{`、`//`；不以 `/ . -` 开头；不以 `/ .` 或 `.lock` 结尾；不是 `HEAD`。
- 键盘：Enter 保存，Esc 收起并把焦点还给「更改」；保存后 toast「当前库将推送到 <分支>」。

## 4. 状态与结果

### 4.1 推送（v1.27）

| 状态 | 主体 | 主按钮 | 次按钮 |
| --- | --- | --- | --- |
| 有改动 | 状态卡 + 改动清单 + 提交说明 | 提交并推送 | 取消 |
| 仅有已提交 | 状态卡 + 「将推送 N 个已提交的更新」 | 推送 | 取消 |
| 无改动 | 状态卡 + 「本地没有待推送的内容；远端状态以联网检查为准」 | 推送（禁用） | 取消 |
| 推送中 | 步骤：拉取远端状态 → 暂存 → 提交 → 推送 | 正在推送…（禁用） | 取消（禁用），不可关闭 |
| 成功 | 绿色结果卡：已推送到 <分支>；在电脑上合并到 <跟踪分支> | （隐藏） | 完成 |
| 远端已前进 | 红色结果卡 + 「改推到其他分支」 | 重试 | 关闭 |
| 令牌失效 401 / 403 | 红色结果卡 + 「更换令牌」 | 重试 | 关闭 |
| 网络失败 | 红色结果卡，本地提交已保留 | 重试 | 关闭 |

### 4.2 手动拉取（v1.73）

「拉取」是**正文内的文字链接**（「拉取远端更新」，与「更改」「更换令牌」同款），位于状态消息 / 落后提示之后；仅在无未提交改动、不在忙碌或编辑令牌时出现，页脚始终只有取消 / 关闭 + 主按钮两个按钮。拉取目标始终是跟踪分支（`main`），与推送分支无关。

| 状态 | 主体 | 主按钮 | 拉取链接 |
| --- | --- | --- | --- |
| 就绪（远端已前进 N） | 状态卡 + 红色提示「远端 <跟踪分支> 已前进 N 个提交；推送会被拒绝，请在电脑上处理。」 | 推送 / 提交并推送 | 拉取 |
| 拉取中 | 步骤列表 + 「正在拉取 main…」（`aria-live`） | 正在拉取…（禁用） | （隐藏，禁用） |
| 快进成功 | 绿色结果卡「已拉取远端更新」+ 「本地已快进合并远端 <跟踪分支> 的新提交。」 | （隐藏） | （隐藏） |
| 已是最新 | 回到就绪态 + 蓝色提示「远端 <跟踪分支> 没有新提交，本地已是最新。」 | 推送 / 提交并推送 | 拉取 |
| 本地未提交 | 红色结果卡「本地有未提交更改」+ 按钮式提示「拉取未开始。请先提交并推送本地改动，再拉取远端更新。」 | 重试拉取 | （隐藏） |
| 本地未推送（拒绝合并） | 红色结果卡「本地有未推送提交」+ 「为避免合并冲突，拉取已取消。请先推送到远端，或在电脑上处理后再拉取。」 | 重试拉取 | （隐藏） |
| 令牌失效 | 红色结果卡「拉取远端更新时认证失败」+ 「令牌可能已失效或缺少读取权限；本地库内容未变。输入新令牌后重试拉取。」 | 验证并重试拉取 | （隐藏） |
| 网络失败 | 红色结果卡「拉取远端更新失败」+ 「本地库内容未变；检查网络后可重试拉取。」 | 重试拉取 | （隐藏） |

- 成功后次按钮为「完成」并触发工作区刷新；其余结果为「关闭」。
- 认证失败点主按钮就地展开令牌编辑（复用 AB-01 的更换令牌区），保存后自动重试拉取。
- 拉取中不可关闭弹窗；「stale 拒绝合并」结果卡保留「在电脑上处理」链接，仅推送场景的「远端已前进」结果提供「改推到其他分支」。

结果卡用 `role=status`；失败文案都写明本地库内容未变 / 本次未推送、本地提交已保留。

## 5. 组件规格

| 元素 | 规格 |
| --- | --- |
| 外壳 | 全屏独立页：`section.settings-page.sync-page` 占满内容区；打开时 window 加 `sync-open` 隐藏侧栏 / 工作区 / 分栏控件；顶栏 `settings-header`（返回箭头 + 标题 + 库名摘要）；单屏左右栏改上下堆叠（清单上、diff 下，清单最高 44%）。不再使用浮窗 / 半模态。v1.77：页面画布用 `--nav`，所有内容落在白卡上，不再把文字直接铺在灰底。 |
| 分组卡片（v1.77） | `.sync-block`：`--paper` 底 + `--line` 描边 + `--r` 圆角，卡间距 `--s4`；`.sync-block-head` 高 `--s12`，标题 `--small`/600，右侧摘要 `--caption` `--muted`；左栏分「推送概览」与「本地改动 N 个文件」两张卡，原生对应两张 `bg_card` 白卡（圆角 `Radius.card`）。 |
| 状态行 | 行最小高 `--s12 + --s1`，行间细线；左列标签 `--small` `--muted` 宽 `--s16`（不换行）；值 `--small` / 600，副文 `--caption`。 |
| 改动标记 | `--s5` 方块、`--s1` 圆角、等宽字母：M `--blue-soft`/`--blue`，A `--green` 16%，D `--danger` 12% |

## 6. 无障碍

- 全屏页打开时焦点在主按钮；返回 / 关闭后回到顶栏同步按钮（单屏为更多菜单按钮）。Esc 关闭（忙碌时不可关），焦点管理同设置页。
- 改动标记有读屏名称（修改 / 新增 / 删除）；步骤列表 `aria-live=polite`；分支输入用 `aria-invalid` 与 `aria-describedby` 关联说明。
- 颜色不是唯一信息：改动标记有字母，结果卡有标题与图标；选中态除底色外还有品牌色左边轨。
- 逐行 diff：文件行按钮带 `aria-expanded` 与 `aria-controls`（指向右栏对应 `role=region` + 文件名标签的 diff 卡）；每个增删行附视觉隐藏的「删除行 / 新增行 / 未改动」读屏前缀（`vh`），标记列 `aria-hidden` 避免朗读符号；默认选中的文件其 `aria-expanded=true`，读屏进入页面即可读到已展开的差异卡；手风琴切换保留焦点在当前按钮，提交说明 / 提交者草稿不因切换文件而丢失。
- 主按钮禁用不是静默状态：页脚 `role=status` 文字说明缺什么（提交者名称 / 邮箱），读屏可播报。

## 7. 原型备注

- `#gitSyncDialog`（全屏 `section`）；脚本 `gitSyncState`（含 `openFile`、`authorName`、`authorEmail`）、`validateGitBranch`、`renderGitSync`、`runGitSync`、`runGitPull`；逐行差异相关 `gitSyncFileDiff`、`gitSyncUnifiedDiff`（复用 `mismatchDiffRows`）、`gitSyncFileItemHtml`、`gitSyncDiffPaneHtml`、`gitSyncFileId`；`openGitSync`/`closeGitSync` 通过 window 的 `sync-open` class 与页面 `hidden` 切换全屏页。底部演示脚注提供推送 4 个 + 拉取 6 个结果演示入口，另有「内容差异」入口（`data-sync-demo="diff"`）直接展开第一例。
