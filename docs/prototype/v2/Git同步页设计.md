# Git 同步页设计（v1.27）

> 现行设计规格，服务 [v1.27 需求](../../releases/v1.27/需求文档.md)。原型入口：[v2 原型](index.html) → 打开演示开关「Git 库示意」→ 顶栏同步按钮（单屏：更多菜单 →「同步到 Git」）。
> 同步语义（push-only、仅快进、手机不合并）见 [v0.3 §3.2](../../releases/v0.3/需求文档.md)；外壳与 [导入库弹窗设计](导入库弹窗设计.md)、[分享面板设计](分享面板设计.md) 共用。

## 1. 思路

手机只负责「把改动安全地推上去」，合并与冲突留给电脑：默认推到 App 固定分支 `xt2`，用户在电脑上把 `xt2` 合并进主线。高级用户可以按库改推送分支（例如每台设备一个分支）。

## 2. 结构

```
┌──────────────────────────────────────────┐
│ [⟳] 同步到 Git                       (×) │  标题：库名 · 推送到 xt2
├──────────────────────────────────────────┤
│ ┌──────────────────────────────────────┐ │
│ │ 远端      github.com/me/notes         │ │  状态卡 sync-card
│ │           HTTPS · 令牌已保存在本机    │ │
│ │ 推送分支  xt2                  [更改] │ │  → 就地展开编辑区
│ │           默认分支；在电脑上合并到 main│ │
│ │ 待推送    2 个已提交 · 3 个未提交改动 │ │
│ │           上次推送：今天 09:12         │ │
│ └──────────────────────────────────────┘ │
│ 本地改动                   推送时一并提交 │
│  [M] 00_开始/快速上手.md                  │  sync-changes
│  [A] 10_写作/会议记录/周会 11-03.md       │
│  [D] 购物清单.md                          │
│ 提交说明                                  │
│ ┌ 更新 3 个文件（曜石笔记） ────────────┐ │
├──────────────────────────────────────────┤
│                    ( 取消 ) (提交并推送)  │
└──────────────────────────────────────────┘
```

## 3. 推送分支编辑

- 「更改」展开 `--nav` 底编辑区：标签「推送到分支」、等宽字体输入框、说明、「恢复默认 xt2」与「保存」。
- 说明三种状态：
  - 普通：「远端没有该分支时，首次推送会创建它。只影响当前库，令牌不变。」
  - 非法（`--danger`，输入框标红，保存禁用）：给出具体原因。
  - 等于跟踪分支（`--danger` 文字，可保存）：「推送会直接更新远端 main，仍只允许快进；建议使用单独分支，在电脑上合并。」
- 校验规则：非空、≤ 100 字符；不含空格与 `~ ^ : ? * [ \`；不含 `..`、`@{`、`//`；不以 `/ . -` 开头；不以 `/ .` 或 `.lock` 结尾；不是 `HEAD`。
- 键盘：Enter 保存，Esc 收起并把焦点还给「更改」；保存后 toast「当前库将推送到 <分支>」。

## 4. 状态与结果

| 状态 | 主体 | 主按钮 | 次按钮 |
| --- | --- | --- | --- |
| 有改动 | 状态卡 + 改动清单 + 提交说明 | 提交并推送 | 取消 |
| 仅有已提交 | 状态卡 + 「将推送 N 个已提交的更新」 | 推送 | 取消 |
| 无改动 | 状态卡 + 「本地没有待推送的内容；远端状态以联网检查为准」 | 推送（禁用） | 取消 |
| 推送中 | 步骤：暂存 → 提交 → 检查远端 → 推送 | 正在推送…（禁用） | 取消（禁用），不可关闭 |
| 成功 | 绿色结果卡：已推送到 <分支>；在电脑上合并到 <跟踪分支> | （隐藏） | 完成 |
| 远端已前进 | 红色结果卡 + 「改推到其他分支」 | 重试 | 关闭 |
| 令牌失效 401 / 403 | 红色结果卡 + 「更换令牌」 | 重试 | 关闭 |
| 网络失败 | 红色结果卡，本地提交已保留 | 重试 | 关闭 |

结果卡用 `role=status`；失败文案都写明「本次未推送、本地提交已保留」。

## 5. 组件规格

| 元素 | 规格 |
| --- | --- |
| 外壳 | `--share-width`（520）居中、距顶 `min(10vh, 96px)`；单屏底部半模态 |
| 状态卡 | `--line` 描边、`--r` 圆角；行最小高 `--s12 + --s1`，行间细线；左列标签 `--small` `--muted` 宽 `--s16 + --s2`；值 `--small` / 600，副文 `--caption` |
| 改动标记 | `--s5` 方块、`--s1` 圆角、等宽字母：M `--blue-soft`/`--blue`，A `--green` 16%，D `--danger` 12% |
| 改动清单 | 行高 `--s10`，最多约 4.5 行后内部滚动 |
| 步骤 | `--nav` 底卡；圆点 `--s4`：未开始描边、进行中品牌色旋转、完成 `--green` 实心 |
| 结果卡 | 成功 `--green` 12% 底，失败 `--danger` 9% 底；图标 `--s6`；操作为文字按钮 |

## 6. 无障碍

- 打开时焦点在主按钮；关闭后回到顶栏同步按钮（单屏为更多菜单按钮）。
- 改动标记有读屏名称（修改 / 新增 / 删除）；步骤列表 `aria-live=polite`；分支输入用 `aria-invalid` 与 `aria-describedby` 关联说明。
- 颜色不是唯一信息：改动标记有字母，结果卡有标题与图标。

## 7. 原型备注

- `#gitSyncDialog`；脚本 `gitSyncState`、`validateGitBranch`、`renderGitSync`、`runGitSync`；底部演示脚注提供四个结果演示入口。
- 演示数据（远端、改动、时间）写在脚本内，仅演示；不执行 Git、不访问远端、不读取令牌，刷新恢复。
