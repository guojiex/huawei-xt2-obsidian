# Git 同步页设计（v1.27 · v1.73 · 逐行差异）

> 现行设计规格，服务 [v1.27 需求](../../releases/v1.27/需求文档.md)与 [v1.73 手动拉取](../../releases/v1.73/需求文档.md)。原型入口：[v2 原型](index.html) → 打开演示开关「Git 库示意」→ 顶栏同步按钮（单屏：更多菜单 →「同步到 Git」）；底部演示脚注「查看结果 → 内容差异」直接展开一例。
> 同步语义（push-only、仅快进、手机不合并）见 [v0.3 §3.2](../../releases/v0.3/需求文档.md)；拉取语义（拒绝合并、仅快进）见 [v1.73 需求](../../releases/v1.73/需求文档.md)。外壳与 [导入库弹窗设计](导入库弹窗设计.md)、[分享面板设计](分享面板设计.md) 共用。

## 1. 思路

手机只负责「把改动安全地推上去」和「把远端更新安全地拉下来」，合并与冲突留给电脑：默认推到 App 固定分支 `xt2`，用户在电脑上把 `xt2` 合并进主线。高级用户可以按库改推送分支（例如每台设备一个分支）。

拉取沿用同一安全边界：只在**工作区干净且本地没有未推送提交**时把远端跟踪分支快进到本地（fast-forward），任何本地领先一律拒绝——手机上不做合并提交、变基或冲突解决。

## 2. 结构

```
┌──────────────────────────────────────────┐
│ [⟳] 同步到 Git                       (×) │  标题：库名 · 推送到 xt2
├──────────────────────────────────────────┤
│ ┌──────────────────────────────────────┐ │
│ │ 远端      github.com/me/notes         │ │  状态卡 sync-card
│ │           HTTPS · 令牌已保存在本机    │ │
│ │ 推送分支  xt2                  [更改] │ │  → 就地展开编辑区
│ │           默认分支；在电脑上合并到 main│ │
│ │ 待推送    2 个已提交 · 3 个未提交改动 │ │
│ │           上次推送：今天 09:12         │ │
│ └──────────────────────────────────────┘ │
│ 本地改动                   推送时一并提交 │
│  [M] 00_开始/快速上手.md                  │  sync-changes
│  [A] 10_写作/会议记录/周会 11-03.md       │
```

## 2A. 内容级 diff（就地展开）

同步页的「本地改动」清单回答「哪些文件变了」，逐行差异回答「每个文件具体改了什么」。用户在推送前就能逐文件核对写入远端的正文，避免误提交敏感或错误内容。

- **入口与口径**：清单里每个改动文件都是整行按钮（`sync-file-toggle`），点按就地展开该文件的行级 diff；再次点按收起，同一时刻只有一个文件展开（手风琴）。口径固定为**当前工作区 vs 上次提交**，只覆盖未提交改动，与清单一一对应；已提交待推送的提交、远端跟踪分支的净变化都不在此视图内。推送分支、提交说明、拉取等其它区域不受影响。
- **三态行**：M 显示「修改：上次提交 → 当前工作区」；A 显示「新文件（本次新增）」，全部为新增行；D 显示「本次删除」，全部为删除行。文件行行尾给出 `+N −M` 增删统计，diff 头给出总差异行数。
- **diff 排版**：unified 单栏，每行四列——旧行号、新行号、`−`/`+`/空格标记、正文。删除/新增/未改动分别整行着红/绿/中性底；未改动行两侧行号都有值，删除行只有旧号、新增行只有新号。等宽字体、长行换行、容器内部滚动（`max-height` 引用 `--s16`），不撑高弹窗、不与提交说明抢占空间。
- **数据边界（原型）**：`gitSyncFileDiff` 存三个演示文件的前后文本，未提交改动清单本身仍来自 `gitSyncChanges`；`gitSyncUnifiedDiff` 复用 [编辑冲突对比](index.html) 的 `mismatchDiffRows`（LCS）算法产出增删/上下文行。原型不读取本地文件、不执行 Git、不访问远端，diff 文本随刷新恢复；底部「内容差异」演示按钮展开第一例。`openFile` 是唯一控制展开状态的字段，打开同步页即清空；切换展开只改 DOM 的 `hidden` 与 `aria-expanded`，不整段重渲染，提交说明草稿不丢。
- **视觉 token**：红底 `--diff-del-bg` + 文字 `--danger`，绿底 `--diff-add-bg` + 文字 `--green`，行号 `--muted`；沿用 §5 通用 token，不散写颜色值。

## 3. 推送分支编辑

- 「更改」展开 `--nav` 底编辑区：标签「推送到分支」、等宽字体输入框、说明、「恢复默认 xt2」与「保存」。
- 说明三种状态：
  - 普通：「远端没有该分支时，首次推送会创建它。只影响当前库，令牌不变。」
  - 非法（`--danger`，输入框标红，保存禁用）：给出具体原因。
  - 等于跟踪分支（`--danger` 文字，可保存）：「推送会直接更新远端 main，仍只允许快进；建议使用单独分支，在电脑上合并。」
- 校验规则：非空、≤ 100 字符；不含空格与 `~ ^ : ? * [ \`；不含 `..`、`@{`、`//`；不以 `/ . -` 开头；不以 `/ .` 或 `.lock` 结尾；不是 `HEAD`。
- 键盘：Enter 保存，Esc 收起并把焦点还给「更改」；保存后 toast「当前库将推送到 <分支>」。

## 4. 状态与结果

### 4.1 推送（v1.27）

| 状态 | 主体 | 主按钮 | 次按钮 |
| --- | --- | --- | --- |
| 有改动 | 状态卡 + 改动清单 + 提交说明 | 提交并推送 | 取消 |
| 仅有已提交 | 状态卡 + 「将推送 N 个已提交的更新」 | 推送 | 取消 |
| 无改动 | 状态卡 + 「本地没有待推送的内容；远端状态以联网检查为准」 | 推送（禁用） | 取消 |
| 推送中 | 步骤：拉取远端状态 → 暂存 → 提交 → 推送 | 正在推送…（禁用） | 取消（禁用），不可关闭 |
| 成功 | 绿色结果卡：已推送到 <分支>；在电脑上合并到 <跟踪分支> | （隐藏） | 完成 |
| 远端已前进 | 红色结果卡 + 「改推到其他分支」 | 重试 | 关闭 |
| 令牌失效 401 / 403 | 红色结果卡 + 「更换令牌」 | 重试 | 关闭 |
| 网络失败 | 红色结果卡，本地提交已保留 | 重试 | 关闭 |

### 4.2 手动拉取（v1.73）

「拉取」是**正文内的文字链接**（「拉取远端更新」，与「更改」「更换令牌」同款），位于状态消息 / 落后提示之后；仅在无未提交改动、不在忙碌或编辑令牌时出现，页脚始终只有取消 / 关闭 + 主按钮两个按钮。拉取目标始终是跟踪分支（`main`），与推送分支无关。

| 状态 | 主体 | 主按钮 | 拉取链接 |
| --- | --- | --- | --- |
| 就绪（远端已前进 N） | 状态卡 + 红色提示「远端 <跟踪分支> 已前进 N 个提交；推送会被拒绝，请在电脑上处理。」 | 推送 / 提交并推送 | 拉取 |
| 拉取中 | 步骤列表 + 「正在拉取 main…」（`aria-live`） | 正在拉取…（禁用） | （隐藏，禁用） |
| 快进成功 | 绿色结果卡「已拉取远端更新」+ 「本地已快进合并远端 <跟踪分支> 的新提交。」 | （隐藏） | （隐藏） |
| 已是最新 | 回到就绪态 + 蓝色提示「远端 <跟踪分支> 没有新提交，本地已是最新。」 | 推送 / 提交并推送 | 拉取 |
| 本地未提交 | 红色结果卡「本地有未提交更改」+ 按钮式提示「拉取未开始。请先提交并推送本地改动，再拉取远端更新。」 | 重试拉取 | （隐藏） |
| 本地未推送（拒绝合并） | 红色结果卡「本地有未推送提交」+ 「为避免合并冲突，拉取已取消。请先推送到远端，或在电脑上处理后再拉取。」 | 重试拉取 | （隐藏） |
| 令牌失效 | 红色结果卡「拉取远端更新时认证失败」+ 「令牌可能已失效或缺少读取权限；本地库内容未变。输入新令牌后重试拉取。」 | 验证并重试拉取 | （隐藏） |
| 网络失败 | 红色结果卡「拉取远端更新失败」+ 「本地库内容未变；检查网络后可重试拉取。」 | 重试拉取 | （隐藏） |

- 成功后次按钮为「完成」并触发工作区刷新；其余结果为「关闭」。
- 认证失败点主按钮就地展开令牌编辑（复用 AB-01 的更换令牌区），保存后自动重试拉取。
- 拉取中不可关闭弹窗；「stale 拒绝合并」结果卡保留「在电脑上处理」链接，仅推送场景的「远端已前进」结果提供「改推到其他分支」。

结果卡用 `role=status`；失败文案都写明本地库内容未变 / 本次未推送、本地提交已保留。

| 落后提示 | `.sync-behind`：`--danger` 9% 底、`--danger` 文字；已是最新提示 `.sync-status-msg`：`--blue-soft` 底；均 `--small`、圆角 `--r` |

## 6. 无障碍

- 打开时焦点在主按钮；关闭后回到顶栏同步按钮（单屏为更多菜单按钮）。
- 改动标记有读屏名称（修改 / 新增 / 删除）；步骤列表 `aria-live=polite`；分支输入用 `aria-invalid` 与 `aria-describedby` 关联说明。
- 颜色不是唯一信息：改动标记有字母，结果卡有标题与图标。
- 逐行 diff：文件行按钮带 `aria-expanded` 与 `aria-controls`，展开区 `role=region` + 文件名标签；每个增删行附视觉隐藏的「删除行 / 新增行 / 未改动」读屏前缀（`vh`），标记列 `aria-hidden` 避免朗读符号；手风琴切换保留焦点在当前按钮，提交说明草稿不因展开而丢失。
