# 版本历史设计（v2.2）

> 现行设计规格，服务 [v2.2 设计稿](../../releases/v2.2/需求文档.md)。原型入口：[v2 原型](index.html) → 任一笔记的「⋯」菜单（单屏更多菜单「当前笔记」组 / 桌面左右栏）→「版本历史」；或 `?ui=2&panel=history` 直达（跟随左栏当前笔记）。
> 本文只讲 UI 设计与留档口径；端侧存储与写入语义以需求文档 §2.2.4 为准。

## 1. 思路

版本历史回答一个问题：**「这篇笔记之前的某个样子是什么，能不能回去」**。它不是 Git：没有提交者、分支、diff，只有「按次保存留档的快照列表」。因此 UI 只做三件事：

1. **之前有哪些版本**——列表：来源 + 时间 + 字数，最新在前；
2. **某个版本长什么样**——只读预览，看完再决定；
3. **怎么回去**——恢复；恢复前自动把「现在」也留档，回去的路永远有回程票。

与既有保护的关系：回收站管「删」、草稿快照管「崩」（v1.7 保存链路，正式保存成功即清理）、Git 管「同步历史」（无手机端 UI）；版本历史管「改」——四者互补，不互相替代。

## 2. 结构

两个 `utility-dialog` 弹窗（与回收站 / 回收站只读预览同范式，不新造容器语言）：

```
┌─────────────────────────────────────────────┐   ┌─────────────────────────────────────────────┐
│  版本历史                              × │   │  预览历史版本                          × │
│  「快速上手」 · 最多保留 20 个版本           │   │  恢复前留档 · 5 分钟前                      │
│ ┌─────────────────────────────────────────┐ │   │ ┌─────────────────────────────────────────┐ │
│ │ [自动]      5 分钟前   1234 字      ↩ │ │   │ │ # 快速上手                               │ │
│ │ [手动保存]  昨天       1230 字      ↩ │ │   │ │ ……（只读渲染，不可编辑）                  │ │
│ │ [恢复前留档] 2 天前    1218 字       ↩ │ │   │ │                                         │ │
│ └─────────────────────────────────────────┘ │   │ └─────────────────────────────────────────┘ │
│             [ 保存当前版本 ]                 │   │    [ 删除此版本 ]  [ 恢复此版本 ]           │
│  按保存留档；恢复前会自动保存当前内容……       │   │  预览只读；恢复前会自动留档当前内容。        │
└─────────────────────────────────────────────┘   └─────────────────────────────────────────────┘
```

- **入口**：三个笔记级「⋯」菜单各加「版本历史」，布点与文案沿用 [v1.54](../../releases/历史版本归档.md#v154-需求文档) 收藏切换先例——单屏更多菜单「当前笔记」组（图标 + 标签，跟随激活栏）、桌面左 / 右栏「⋯」菜单（纯文字行，跟随各自栏内笔记）；无笔记时入口禁用。
- **列表行**：来源标签 + 相对时间 + 字数（内容与当前一致时标注「与当前一致」）；行主体点击进预览；行尾「恢复」图标直接恢复。空态「还没有历史版本」；首次打开自动 seed 三条演示版本。
- **预览**：复用回收站只读预览（[v1.74](../../releases/历史版本归档.md#v174-需求文档)）的滚动区与渲染链：`renderMarkdown` 渲染、不可编辑、关闭后列表状态不变；底部「删除此版本」（危险色文字按钮，直接删、不二次确认——版本不是笔记）与「恢复此版本」（主按钮）。

## 3. 三类来源

来源标签是列表里唯一的「分类学」，颜色只复用既有语义色：

| 来源 | 标签文案 | 语义 | 颜色 |
| --- | --- | --- | --- |
| `manual` | 手动保存 | 用户点「保存当前版本」显式留档 | 品牌蓝（`--blue` on `--blue-soft`） |
| `auto` | 自动保存 | 自动保存成功后留档（同一笔记两次自动留档间隔 ≥ 10 分钟，口径起点） | muted（`--outer` 底 + `--muted` 字） |
| `preRestore` | 恢复前留档 | 恢复旧版本前自动保存的「当时内容」 | danger 系（`--diff-del-bg` 底 + `--danger` 字） |

恢复的完整语义：**先把当前内容留一份 `preRestore`，再写入目标版本内容**。列表随即刷新，新留档出现在最前——恢复错了随时再恢复回来，不存在单行道。

## 4. 交互与数据边界（原型）

- **演示数据**：首次打开某笔记的版本历史时 seed 三条演示版本（自动 / 手动 / 恢复前留档各一，正文为当前内容的变体）；此后「保存当前版本」「恢复」「删除此版本」均真实作用于内存中的演示数组。刷新即重置，不进 localStorage、不进 URL 正文参数。
- **上限淘汰**：每篇最多 20 份，超出按最旧淘汰（`HISTORY_LIMIT` 常量）；三类一视同仁。
- **永久删除联动**：回收站单条永久删除 / 清空（共用 `purgeOne`）时，该笔记的版本历史一并清除；移入回收站与从回收站恢复不动历史。
- **URL 直达**：`?ui=2&panel=history`（跟随左栏当前笔记；无笔记时回落不打开）；`stateUrl` 的 panel 链加 `history`，`restoreUrl` 对应复位。
- **不做的事**：不 diff、不备注、不设置项、不清空全部；原型不写任何文件。

## 5. 视觉 token

- 弹窗沿用 `utility-dialog` / `utility-head` / `search-note`；预览滚动区复用 `trash-preview-scroll` / `trash-preview-body`。
- 来源标签：`manual` = `--blue-soft` 底 + `--blue` 字；`auto` = `--outer` 底 + `--muted` 字；`preRestore` = `--diff-del-bg` 底 + `--danger` 字。
- 行内时间 / 字数用 `--caption` / `--small`；间距 `--s1`–`--s3`；圆角 `--small-r` / `--pill`。组件内不散写数值。
