# 需求池（Roadmap Backlog）

> 用途：罗列这款应用**将来能实现**的需求点，供挑选 MVP 范围。此处不做排期，只标价值、成本与依赖。
> 成本量级：S ≈ 1–3 天，M ≈ 1 周，L ≈ 2 周以上。
> 「MVP 建议」只是我的判断，最终以你的取舍为准。

> 📌 **本表是「需求池」，不是「要做清单」**。
> 需求被选中后**分配进某个版本**，落在 `docs/releases/vX.Y/需求文档.md`；
> **本表不标注"分到了哪个版本"** —— 版本归属只在版本目录里记一次，避免两处不一致。
> 新需求先回这里登记，再决定进当前版本还是下一个。规则见 `docs/releases/README.md`。

> **关于「后台自动同步」**（已登记，暂不实现）：
> 前台 clone/push **不需要任何额外权限**；只有「退到后台还在传」才需要申请 `KEEP_BACKGROUND_RUNNING` + `DATA_TRANSFER` 两个长时任务权限，多一套权限申请与审核成本。
> MVP 的替代做法：clone/push 走前台 + 进度条，期间不切走；配合「未推送改动角标」提醒用户回来点一次同步。
> **重开评估的时机**：前台链路在真机上跑稳之后，若实测「大库 clone 要等太久、用户忍不住切走」再考虑。

> **关于「分栏宽度拖拽」**（2026-10-25 登记，用户需求原型：微信的分栏正中间有个按钮，拖动它改分栏宽度）：
> **范围（用户拍板）**：**lg 展开态**目录栏宽可拖；**lg 收起态**编辑 / 预览宽可拖；**md / sm 一律维持等分**（用户明确 2 屏不需要）。
> 设计取舍已在原型 `docs/prototype/index.html` 落地（浏览器打开即可试），ArkTS 实现可直接照做：
> 1. **展开态（目录 | 编辑）**：用 **Navigation Split 官方 dragBar**（`enableDragBar(true)` + `divider` 定制，微信 / 备忘录同款）——连续拖拽实时改宽，范围约 [233vp, 488vp]；**编辑 / 预览在 content 区固定等分，中间无把手**（用户拍板「预览和编辑不需要在中间再动态分栏」）。
> 2. **收起态（编辑 | 预览）**：自绘 overlay 把手（14vp 热区 + 4vp 圆钮，视觉同官方：1vp 细线 + 中央圆钮），**松手时距折痕 1.5%（≈16vp）内弱吸附**到 66.82%—— 既满足「拖动改宽」，又不破坏「栏边界压折痕」原则。
> 3. 拖到**跨折痕**的位置不拦截：折痕线标红警示（沿用原型已有 `drawHinges` 机制），用户主动选择即接受。
> 4. **每栏最小 18%**（≈190vp）：目录树 / 编辑区再窄也能用。
> 5. **重置两个入口**（2026-10-25 用户拍板）：① 双击把手恢复等分；② **设置页「恢复等分栏宽」按钮**（布局组，附「当前栏宽」实时文案）。
> 6. **持久化**（2026-10-25 用户拍板）：目录宽与收起态编辑宽**两份独立状态**，重启 / 切形态后保持（原型用 localStorage 演示，App 侧进 preferences 存储）；重置同时清除。

### 向外分享约定（2026-10-25）

- **范围**：2026-10-25 后续扩展为单篇笔记、指定文件夹（含子目录）与整个知识库；不跨库、不递归收集链接到范围外的其他笔记。
- **文件分享**：没有本地图片时发送 `.md`；引用本地图片时发送 ZIP，包含当前笔记与其引用的本地图片，包内使用有效的相对图片路径，解压后可查看。仅收集当前库内被引用的图片，不打包无关文件；网络图片保留链接，不自动下载。
- **文件夹 / 知识库**：文件夹 ZIP 包含范围内笔记与其引用的当前库内图片；知识库 ZIP 保留内容及附件目录结构。排除 `.git`、回收站、草稿、缓存、凭据和应用内部数据；内容分享不包含 ZIP 导入或备份恢复。
- **Git 入口**：“分享笔记”提供当前笔记的图片、文件及远端笔记网页链接；“分享文件夹”可选 ZIP 或远端文件夹链接；“分享知识库”可选 ZIP 或仓库首页链接（用户明确确认），ZIP 来自当前本地内容。本地库只提供图片 / 文件选项，不提供远端链接。
- **远端链接边界**：笔记链接对应远端版本，不包含尚未推送的本地修改；私有仓库仍需接收人有访问权限。设计需提示这些限制；远端笔记不存在时不提供该笔记链接，仍可分享图片或文件。
- **排期**：基础分享已进入版本计划，归属与顺序见 [版本索引](releases/README.md)；社媒分享仍按上表低优先级后置。本段为需求约定，不代表系统分享或远端链接适配已实现、已验证。

### ⚠️ 三条必须先解决的工程约束（不是需求，是前置条件）

1. **历史 git 出路冲突 —— 当前只约束「自动 commit」，一次撤销不依赖 Git**
   官方方案假设有**原生 ArkTS git**，我们的 git 是 isomorphic-git **跑在 ArkWeb 页面里**；
   而后台意图执行的生命周期是 `onCreate → onExecute`，**不建 window → Web 组件可能不存在 → commit 无处调用**。
   三条出路见 `api_notes.md` F6：**A 入队延迟提交（推荐）/ B 执行时拉起不可见 Web / C 放弃 git 改文件级备份**。
   → **2026-10-25 调整**：首期小艺操作不依赖 Git；本冲突只阻塞自动 commit，不再阻塞本地操作。见 v0.6 需求文档。

2. **写文件必须走 `AtomicFile`**
   官方示例用 `openSync(READ_WRITE | TRUNC)` 覆盖写，写一半崩 = 文件半截。
   这违反我们既有的原子写硬约束，**意图执行器里也必须换成 `AtomicFile`**。

3. **`noteId` 必须能唯一定位「库 + 库内相对路径」**
   示例假设单库单层（`filesDir/notes/<id>.md`），我们是**多库 + 多级目录**。
   候选：① `<库id>::<相对路径>` 编码成一个参数；② 拆成 `vaultId` + `path` 两个参数（更不易填错，但需补 `ListVaults` 意图）。

### 顺带的免费准备（现在就该做，成本为零）

- **anchor 出现多次时必须拒绝执行** —— 官方没提，但这是防错改的必要闸门，执行器侧必做。
- **笔记路径统一由一层「库内路径 → 绝对路径」的解析器产出**，别让意图执行器和 UI 各拼一遍字符串。
- 意图参数的 `description` 会**被大模型用来理解怎么填参**，写意图时字段说明要写得像给人看的说明书。

### 前置结论（已核实，不用再查）

- 鸿蒙**原生支持**三类埋点，无需第三方 SDK：曝光 `onVisibleAreaApproximateChange`(17+)、点击 `UIObserver.on('willClick')`(12+)、页面 `navDestinationSwitch`(12+) —— **API 24 全部可用**。
- 链路：`hiAppEvent.write` 落盘 → `addWatcher` 累积触发 → `takeNext()` 批量取 → 自建 http 上报。
- **全局无侵入**方案（组件只声明 `.id()` / `.customProperty()`，Ability 层统一监听）最匹配我们的文件树，业务代码零侵入。

### 🔴 三条硬约束（做埋点时不可违反）

1. **笔记内容一律不得进入埋点。**
   可采集：行为坐标（目录层级、当前形态、按钮点击、同步成败与耗时）。
   **禁止**：笔记标题、文件名、路径、正文、字数、标签。
   → 这是个人知识库，不是内容社区；采集用户内容会显著抬高隐私合规成本与上架审核风险。

2. **曝光去重按「会话内」定义指标。**
   官方示例的去重 `Set` 是**内存态**，进程重启即失效；跨会话去重要额外持久化。
   → 推荐先把指标定义为「单会话内曝光」，避免数据口径自欺。

3. **上报非实时、失败即丢，绝不阻塞主链路。**
   `triggerCondition` 本就是累积触发；**不做重试队列**，避免埋点上报与 git 同步抢带宽。采集与上报全走旁路，异常吞掉。

### ⚠️ 能力限制（影响指标口径）

官方明确：可见区域计算**不支持兄弟组件遮挡、窗口遮挡、组件旋转**，只算自身节点相对祖先直至窗口边界的裁切比。
→ **三折叠形态切换瞬间的曝光比值准确性无保证**，相关埋点只当趋势看，别当精确数据用。
