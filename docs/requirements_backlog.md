> 用途：罗列这款应用**将来能实现**的需求点，供挑选 MVP 范围。此处不做排期，只标价值、成本与依赖。
> 成本量级：S ≈ 1–3 天，M ≈ 1 周，L ≈ 2 周以上。
> 「MVP 建议」只是我的判断，最终以你的取舍为准。

## C. 同步与数据

| 需求点 | 价值 | 成本 | 依赖 | MVP 建议 |
| --- | --- | --- | --- | --- |
| GitHub 单向拉取（zipball 导入） | 高 | S | 网络 + 解压 | ✗ 已放弃，改动会被覆盖 |
| GitHub 双向同步（isomorphic-git） | 高 | M–L | Web 组件 + fs 桥接 | ✓ **已纳入 MVP** |
| Git Data API 轻量双向（无本地历史） | 高 | M | HTTP + sha 乐观锁 | ✗ 未选，完整 git 语义更值 |
| libgit2 Native 双向 | 高 | L | NDK 编译 | ✗ 后置，库不大用不上 |
| 冲突策略：推 `xt2` 分支，PC 端合并 | 高 | M | 同步方案 | ✓ **已纳入 MVP**，手机上不做合并 |
| 冲突副本（远端版本另存新文件） | 中 | S | 无 | ✗ 未选，会污染库且推不上去 |
| WebDAV 同步（坚果云等） | 中高 | M | WebDAV 客户端 | 后置 |
| 本地 zip 导出 / 导入 | 中 | S | 压缩 + FilePicker | 建议纳入，沙箱存储的保命通道 |
| 系统备份（Backup Extension） | 中 | S | 工程已生成该能力 | 建议纳入 |
| 提交历史查看 / 单文件回滚 | 中 | M | 本地 git 历史 | 后置，isomorphic-git 已具备能力 |
| **后台自动同步**（切到后台仍继续传输） | 中高 | M | 长时任务 + 两个权限 | ✗ **先不做**（2026-10-17 定），v2 再评估 |
| 同步冲突提醒 / 未推送改动角标 | 中 | S | 本地 git 状态 | 建议纳入，替代后台同步的低配方案 |
| 局域网/华为云盘同步 | 低中 | L | 各家 SDK | 后置 |

> **关于「后台自动同步」**（已登记，暂不实现）：
> 前台 clone/push **不需要任何额外权限**；只有「退到后台还在传」才需要申请 `KEEP_BACKGROUND_RUNNING` + `DATA_TRANSFER` 两个长时任务权限，多一套权限申请与审核成本。
> MVP 的替代做法：clone/push 走前台 + 进度条，期间不切走；配合「未推送改动角标」提醒用户回来点一次同步。
> **重开评估的时机**：前台链路在真机上跑稳之后，若实测「大库 clone 要等太久、用户忍不住切走」再考虑。

## 附：我的 MVP 边界建议

GitHub 双向同步（见 C 节）已单独确认纳入 MVP，不在这个清单里。除此之外，我建议从上面再补这 5 条进 MVP：

1. **编辑/预览双栏实时联动**（三屏展开态的核心价值，不然三栏只是摆设）
2. **快速切换（文件名模糊搜索）**（成本 S，体验提升巨大，且不依赖索引层）
3. **最近打开 + 回收站**（都是 S 成本，一个是效率一个是安全网）
4. **系统分享存入笔记**（S 成本，鸿蒙生态下的真实高频场景）
5. **深色模式 + WebView 预加载**（体验底线）

其余一律后置。特别是双链和图谱——它们看起来是 Obsidian 的灵魂，但依赖完整索引层，硬塞进 MVP 会把工期拖成两倍。
