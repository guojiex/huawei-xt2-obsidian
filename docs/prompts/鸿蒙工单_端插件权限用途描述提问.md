## 答复核对结论（2026-11-15 收到，页面标注「内容由 AI 生成，仅供参考」）

**可直接照做**（与官方《端插件权限管控》一致，已回填 `api_notes.md` F19 / 提示词文档 §1）：

1. 报错层级确认：平台在调用端插件前的配置校验拦截，指令未下发到应用 —— 所以没有授权弹窗、端侧无 `onExecute` 记录。
2. 入口确认：**智能体编排页 → 权限配置**
   ；只有添加带权限的端插件后才出现，工作流同理，追加权限用「添加权限」按钮。之前找不到，最可能是没添加带权限的端插件，与开发模式 /
   账号类型无关。
3. 每个权限项单独填用途描述 → 调试台单工具验证 → 重新提交上架审核 → 手机端用户授权。完成前写入用例记「阻塞」。
4. 驳回意见：智能体列表「不通过」标签悬浮，或编排页「版本记录」图标。
5. 端侧判断：在 `onExecute` / 后台回调入口加日志，无打印即上游拦截；调试台单工具测试可区分权限拦截与端插件注册问题。

**已收敛（第二轮答复 + 官方文档独立印证）**：

- ✅ 「意图框架仅支持预置垂域意图」**不适用于端插件路径**。最硬证据是官方《插件工具对应在端侧文件配置》示例本身就用自定义
  `intentName`（`CallPhone` / `LoadCalendarEventCard` / `Travel` / `SearchWeather` / `ServiceExtensionIntent`）且 `domain`
  全为 `""`；Intents Kit 的预置意图约束只面向系统推荐场景（且仅企业开发者）。**本工程 11 项自定义名合法、`0.1.0`
  与空 `domain` 也合法，不改 `insight_intent.json`、不改 F15 / F17。** 详见 `api_notes.md` F20。
- ✅ 平台创建工具名可用下划线，但端侧校验更严（`^[A-Z][a-zA-Z0-9]+$`，大驼峰、无下划线）—— 创建平台工具一律用大驼峰。本地 11
  项已实跑核对全部符合，见 F21 核对表。

**仍须在平台确认 / 未采信为结论**：

- ⚠️ 「备忘录写入」权限项绑定到哪个插件：确认 Agent 用的是本工程 `CreateNote` 还是系统「备忘录-CreateNote」；若走系统备忘录，笔记不进知识库，T3
  判据不成立。
- ⚠️ 11 个平台工具名、`intentVersion`、执行类型是否与端侧逐项一致（**8 项旧工具的平台版本号从未登记**），见下方核对清单与

- ⚠️ `1000101101` 已升级为「社区强线索」（debug 签名 / AGC 未上架解析导致意图未注册），但仍非官方明文，须 XT2 实测。**其修复路径（AGC
  上架 / release 指定设备发布）在本项目不可执行** —— 个人开发者、应用未上架、无发布证书与 AGC 发布环境，见 `api_notes.md`

- ⚠️ 「草稿/未上架状态不允许外部正常调用」「鸿蒙 7 智能体权限细粒度开关」「调试态填完即可执行」，均**未取得官方明文**，仅作线索。
