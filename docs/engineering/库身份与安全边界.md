# 库身份与安全边界

本页是 2026-11-02 对当前源码的静态核对和待验收清单，不是安全测试报告，也不改变已发布版本的承诺。涉及平台行为仍以 [鸿蒙 API 记录](../harmonyos/api_notes.md) 为准；版本状态及设备证据分别见 [实施总清单](../releases/实施总清单.md) 和各版验收记录。

## 1. 库身份与状态键

`vaultKey` 是注册表里的稳定内部身份，库改名不变；`vaultId` 是当前调用标识，沙箱库也是目录名，外部库改名只改应用内名称。**两种键当前并存，不能笼统写成“所有状态都按 key”或“改名迁移全部成功”。**

| 状态 | 当前键 / 存储 | 改名和验证边界 |
| --- | --- | --- |
| 注册表与当前库 | Preferences `vault_registry`，记录 `id` 和 `vaultKey`；当前库按 id | Registry 改名时更新 id，保留 key；旧注册项缺 key 时生成，持久化和中断恢复需另验。 |
| 回收站、恢复草稿 | 沙箱 `trash/<vaultKey>`、`drafts/<vaultKey>` | 稳定 key 无需随名称搬目录；旧 `.trash` 复制策略见 §3。 |
| Agent 对话和操作记录 | 解析器按 `vaultKey` 定位 | 落盘、删除与恢复的具体状态按对应版本验收，不能单凭路径推断跨进程完整性。 |
| Git 令牌 | Asset Store `vault:<vaultId>:token`，秘密值放 SECRET | `Index` 在改名后调用迁移；失败提示重新填写，不代表改名整体回滚。旧版 Preferences 明文 token 在同步页尝试删除，并非先迁入安全存储；清理失败不阻塞页面，升级与失败重试仍须验收。 |
| 文件树展开 / 最近打开 | Preferences `expand_<vaultId>` / `recent_<vaultId>` | 当前仍按 id；改名后的迁移与重启恢复须单独核验，不能宣称已完整迁移。 |
| 工作区会话及搜索缓存 | 涉及当前库 id、笔记路径或进程内 id | 改名后重定位和持久化失败须结合实际调用链及重启场景验收；不能用草稿的 key 隔离代替。 |

来源：[VaultRegistry](../../entry/src/main/ets/model/VaultRegistry.ets)、[GitCredentialStore](../../entry/src/main/ets/git/GitCredentialStore.ets)、[FileTree](../../entry/src/main/ets/model/FileTree.ets)、[RecentOpenStore](../../entry/src/main/ets/model/RecentOpenStore.ets)、[Index 改名调用](../../entry/src/main/ets/pages/Index.ets)、[SyncPage](../../entry/src/main/ets/pages/SyncPage.ets)。改名涉及目录、Preferences、Asset Store 等多个步骤；单文件 AtomicFile 不能使这些操作成为事务。当前测试方式不主动在模拟器制造崩溃，失败注入和服务重建的测试不能等同真实断电或进程中断证据。

## 2. Web 预览威胁模型与待验收项

**威胁**：Git 仓库或外部目录可能含攻击者控制的 Markdown、HTML、图片链接和图表内容。若不可信内容在持有原生代理的页面中执行脚本，可能滥用代理暴露的能力或影响编辑内容；网络资源还可能泄露访问行为。具体攻击可达性和影响范围尚需验证，不能直接认定可以读取 Git 令牌或任意写库。

**源码事实**：当前 [预览渲染链](../../web/mdpreview/src/sourceMapping.mjs) 使用 `marked.lexer()` / `marked.parser()`，[渲染器](../../web/mdpreview/src/renderer.mjs) 也提供 `marked.parse()`；应用自己的预览源码中未找到 DOMPurify 清洗调用；[预览页面](../../web/mdpreview/src/index.ts) 将渲染结果放入 `innerHTML`。Mermaid 配置 `securityLevel: 'strict'`，不等于整个 Markdown 已消毒。[PreviewWebView](../../entry/src/main/ets/components/PreviewWebView.ets) 明确注册 `readAsset`、编辑内容回调、双链点击及其他方法；没有在该组件看到直接暴露 Git 令牌的方法。预览与 [Git 备选桥](../../entry/src/main/ets/git/GitBridgeView.ets) 是不同组件，不能把两者能力混为一谈。外部图片的 http / https、data 和 blob 来源在预览脚本中被跳过本地路径转换，不等于已被禁用或经过安全审计。

**发布前需确定并验证**：

1. 盘点原始 HTML、事件属性、危险协议、SVG / MathML、Mermaid 及编辑模式的完整渲染链；制定适合实际功能的消毒允许列表和回归样本，不能只写“使用 DOMPurify”。
2. 盘点每个 WebView 的代理方法、参数、可达资源和调用时机；验证路径约束、来源 / 导航限制及调用方鉴别能否在 API24 实现。不要仅依赖 Base64 或前端校验。
3. 明确外链打开、远程图片、数据 URI、本地附件以及网络 / 文件访问策略，核对 API24 能力与默认值；如果限制会影响本地资源或 Markdown 兼容，记录权衡。
4. 测试恶意 Markdown、错误协议、路径穿越、跳转和远程资源请求，并检查是否能触发桥接及编辑内容变化；分别记录源码、自动测试、模拟器和 API24 / XT2 证据。安全策略尚未实现或验收，不能把本节当作保护已生效。

## 3. 旧回收站与分享同步

v1.5 新回收站及草稿位于库外沙箱；首次打开回收站时，旧库内 `.trash` 的 Markdown 复制、逐项校验并保留源目录，非 Markdown 也保留原处，详见 [v1.5 §6.6](../releases/v1.5/需求文档.md#66-旧-trash-复制校验与保留2026-11-01-用户决定)。复制成功不代表原目录或其远端历史被清理。

[v0.3](../releases/v0.3/需求文档.md) 记录 Native stage 排除根 `.trash` 的测试，并保留已跟踪内容；这不能删除已有 Git 提交或远端内容，也不能推出其他 Git 客户端和嵌套目录均有保护。`.gitignore` 不会移除已跟踪文件，自动改写用户仓库也会带来额外影响，因此不在文档审查中修改用户 `.gitignore` 或删除源目录。分享需求要求排除回收站，旧根目录、附件、已跟踪内容和实际接收文件仍须独立验收；在验收前不能承诺不会泄露。
