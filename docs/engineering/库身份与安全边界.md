# 库身份与安全边界

本页是 2026-11-02 对当前源码的静态核对和待验收清单，不是安全测试报告，也不改变已发布版本的承诺。涉及平台行为仍以 [鸿蒙 API 记录](../harmonyos/api_notes.md) 为准；版本状态及设备证据分别见 [实施总清单](../releases/实施总清单.md) 和各版验收记录。

## 1. 库身份与状态键

`vaultKey` 是注册表里的稳定内部身份，库改名不变；`vaultId` 是当前调用标识，沙箱库也是目录名，外部库改名只改应用内名称。**两种键当前并存，不能笼统写成“所有状态都按 key”或“改名迁移全部成功”。**

| 状态 | 当前键 / 存储 | 改名和验证边界 |
| --- | --- | --- |
| 注册表与当前库 | Preferences `vault_registry`，记录 `id` 和 `vaultKey`；当前库按 id | Registry 改名时更新 id，保留 key；旧注册项缺 key 时生成，持久化和中断恢复需另验。 |
| 回收站、恢复草稿 | 沙箱 `trash/<vaultKey>`、`drafts/<vaultKey>` | 稳定 key 无需随名称搬目录；旧 `.trash` 复制策略见 §3。 |
| Agent 对话和操作记录 | 解析器按 `vaultKey` 定位 | 落盘、删除与恢复的具体状态按对应版本验收，不能单凭路径推断跨进程完整性。 |
| Git 令牌 | Asset Store `vault:<vaultId>:token`，秘密值放 SECRET | `Index` 在改名后调用迁移；失败提示重新填写，不代表改名整体回滚。旧版 Preferences 明文 token 在同步页尝试删除，并非先迁入安全存储；清理失败不阻塞页面，升级与失败重试仍须验收。 |
| 文件树展开 / 最近打开 | Preferences `expand_<vaultId>` / `recent_<vaultId>` | 当前仍按 id；改名后的迁移与重启恢复须单独核验，不能宣称已完整迁移。 |
| 工作区会话及搜索缓存 | 涉及当前库 id、笔记路径或进程内 id | 改名后重定位和持久化失败须结合实际调用链及重启场景验收；不能用草稿的 key 隔离代替。 |

来源：[VaultRegistry](../../entry/src/main/ets/model/VaultRegistry.ets)、[GitCredentialStore](../../entry/src/main/ets/git/GitCredentialStore.ets)、[FileTree](../../entry/src/main/ets/model/FileTree.ets)、[RecentOpenStore](../../entry/src/main/ets/model/RecentOpenStore.ets)、[Index 改名调用](../../entry/src/main/ets/pages/Index.ets)、[SyncPage](../../entry/src/main/ets/pages/SyncPage.ets)。改名涉及目录、Preferences、Asset Store 等多个步骤；单文件 AtomicFile 不能使这些操作成为事务。建议后续设计尽力回滚与启动时对账，但目前没有证据表明现有实现已具备完整对账或崩溃恢复。当前测试方式不主动在模拟器制造崩溃，失败注入和服务重建的测试不能等同真实断电或进程中断证据。

## 2. Web 预览实现备注

预览桥接应只暴露所需方法，不提供任意路径读写或令牌读取；Markdown 渲染前应消毒（如 DOMPurify），具体兼容性随实现验证。当前 [预览渲染链](../../web/mdpreview/src/sourceMapping.mjs) 使用 marked 生成 HTML 并由 [页面](../../web/mdpreview/src/index.ts) 插入 `innerHTML`，在应用预览源码中未找到 DOMPurify 清洗调用；[PreviewWebView](../../entry/src/main/ets/components/PreviewWebView.ets) 已注册图片读取和编辑内容等代理，因此不能把上述建议写成已落实。

## 3. 旧回收站与分享同步

v1.5 新回收站及草稿位于库外沙箱；首次打开回收站时，旧库内 `.trash` 的 Markdown 复制、逐项校验并保留源目录，非 Markdown 也保留原处，详见 [v1.5 §6.6](../releases/v1.5/需求文档.md#66-旧-trash-复制校验与保留2026-11-01-用户决定)。复制成功不代表原目录或其远端历史被清理。

[v0.3](../releases/v0.3/需求文档.md) 记录 Native stage 排除根 `.trash` 的测试，并保留已跟踪内容；这不能删除已有 Git 提交或远端内容，也不能推出其他 Git 客户端和嵌套目录均有保护。`.gitignore` 不会移除已跟踪文件，自动改写用户仓库也会带来额外影响，因此不在文档审查中修改用户 `.gitignore` 或删除源目录。建议先在用户确认并评估现有规则后，将根 `.trash/` 加入 Git 排除规则，并独立确认 ZIP 排除，再推进迁移；`.gitignore` 对已跟踪文件和已有历史无效。分享需求要求排除回收站，旧根目录、附件、已跟踪内容和实际接收文件仍须独立验收；在验收前不能承诺不会泄露。
