# 应用内部存储架构（已确认方案）

> 2026-10-25 起草 · **2026-10-26 用户已确认下述修订方案，持久化与删除联动尚未实现/验收**。
> 本次仅更新决策与需求，不创建运行目录、不迁移旧数据、不替换现有存储实现；文件名保留以兼容已有链接。
> 现状依据当前工作区源码（含未提交/未跟踪的草稿和凭据实现），不是设备沙箱实测；规划部分单独标注。路径规则沿用 [AGENTS.md](../../AGENTS.md)，Agent 行为见 [运行设计](../releases/v0.7/Agent_运行设计.md)。

## 1. 已确认结论

1. **用户笔记与 App 自身数据分开。** `filesDir/vaults/` 只放知识库内容及已有库内元数据；应用配置、Agent 对话、运行记录和撤销前像都在库外。
2. **内部存储与配置导出分开设计。** 通用偏好沿用 Preferences，不强制新增 `app.json`；Agent 配置首期采用独立 Preferences store `agent_settings`，以带版本的单个 JSON 字符串保存系统提示词、Skill 改写及工具开关。配置导入/导出未来单独立项，不因可迁移需求改变内部存储。
3. **不为目录统一立即重写旧 Preferences。** 当前 Preferences store（含新增分栏偏好） 原位保留，职责明确，不复制一份到 JSON。令牌仍只进入 Asset Store。
4. **永久数据与缓存分开。** 对话、未完成操作账和撤销前像不可当缓存删除；分享图片/ZIP、可重建索引放 `cacheDir`。
5. **库名称不作为 Agent 历史的永久身份。** 为库增加稳定 `vaultKey`，目录名称/现有 vaultId 变更时不搬整段对话。这需要注册表增量迁移，已确认方向，尚未实施。
6. **内容分享不等于整 App 备份。** 分享笔记/库时不带 App 配置、聊天、草稿、回收站、Git 凭据或运行记录。

## 2. 当前代码实际存在哪里

这里的 `filesDir` 来自 Context，不能替换成硬编码的设备绝对路径。Preferences 和 Asset Store 的物理文件位置由系统管理；下面列的是逻辑 store / key，不臆造 `.xml` 文件名。

### 2.1 当前文件目录

```text
<Context.filesDir>/
├── vaults/
│   ├── local/                         默认本地知识库；首次创建时写入共享样例
│   │   ├── *.md / 子目录 / 配图
│   │   └── .trash/                    当前回收站：镜像库内相对路径
│   ├── <vaultId>/                     其他本地库或 Git 库
│   │   ├── .git/                      Git 库自身仓库数据（同步仍暂缓）
│   │   └── .trash/
│   └── <vaultId>__importing/           Git clone 导入中的临时目录
├── drafts/                            当前工作区草稿实现，位于库外
│   └── <vaultId>/<笔记相对路径>.draft
└── drafts.recovery                    异常保留文件：仅当 drafts 根误成普通文件时使用
```

- 草稿记录字段为 `version / baseText / content`，不是 Markdown 正文文件；当前保存采用 AtomicFile。
- `drafts.recovery` 不是每篇笔记的备份，也不是“清缓存”可删的目录。
- `.trash` 目前位于库内，保留这一现状；不能因为文件树隐藏它就认为 Git/分享已经排除了它。同步排除和 ZIP 排除仍需各自验收。
- `__importing` 是现有导入实现的位置，本稿不先挪它。残留目录是否可清理须先核对任务与注册表，不能只凭后缀删除。

## 3. 已确认目标目录（待实施）

保留 `vaults/`、`drafts/` 和现有 Preferences，新增 App 自有命名空间，避免把配置和 Agent 内容混进知识库。

```text
<Context.filesDir>/
├── vaults/                            用户知识库；沿用现有结构与解析器
│   └── <vaultId>/
│       ├── <用户自定目录与 Markdown>
│       ├── <用户附件目录>/             沿用原库路径；不强制改成某个 Assets 名称
│       ├── .trash/                    保留现有回收站位置
│       └── .git/                      仅 Git 库存在
├── drafts/                            沿用当前草稿镜像结构
├── drafts.recovery                    已有异常保留文件，存在时人工/恢复流程处理
└── app/                               新增：不属于任何知识库的 App 私有数据
    ├── agent/
    │   └── vaults/
    │       └── <vaultKey>/             稳定内部库身份，不使用显示名称
    │           └── conversations/
    │               └── <conversationId>/
    │                   ├── conversation.json   消息、来源、输入草稿、会话 Skill 等
    │                   └── runs/
    │                       └── <runId>/
    │                           ├── state.json  状态、配置快照、上下文清单与工具执行账
    │                           └── operations/
    │                               └── <operationId>.json
    │                                          写前原文、目标与版本、预期结果 hash、操作状态
    └── migrations/
        └── state.json                只在确实执行增量迁移时建立；不放笔记副本

<Context.cacheDir>/
├── exports/<exportJobId>/             分享临时图片、Markdown 副本、ZIP 与配图
└── indexes/<vaultKey>/                将来可重建的搜索/反链索引，未实施前不建空目录

系统管理的独立存储：
├── Preferences：vault_registry / file_tree_state / recent_open_state / pane_layout（保留）；agent_settings（待新增）
└── Asset Store：令牌等秘密值（不可改放上述 JSON 或导出 ZIP）

应用包内只读资源（随版本更新，不是用户数据目录）：
└── 共享样例 / 内置系统提示词 / 内置 Skills / mock 场景 / changelog 数据
```

说明：上树展示的是**业务归属**，不是给系统 Preferences/Asset Store 重新造目录。`cacheDir` 的业务可读分享 URI 和接收 App 读取生命周期，需在 v0.8 按官方文件分享机制单独核实；目录草案不等于已经可跨 App 读取。

首期不引入 `app.db`、通用 blob 对象库、每条消息单独文件或任意插件目录。每段对话先保存为一个有版本的 JSON；如后续真实数据证明整段重写开销不可接受，再提出数据库迁移，不提前建设两套真源。

## 4. App 配置到底放哪里

| 类别 | 建议位置 | 内容与责任 |
| --- | --- | --- |
| 通用设置 | Preferences | 保留现有偏好，不强制新增 app.json，不再次复制库注册表、笔记、Agent 消息 |
| Agent 设置 | Preferences `agent_settings` → `settings_json`（待实现） | 作为单个带版本配置对象读写，系统提示词与 Skill 改写一并保存；系统持久化接口负责底层存储，App 仍负责校验、版本兼容与写入协调 |
| 内置提示词与 Skills | 应用包只读资源 | 源码真源 `agent/prompts/reading_coach.md`、`agent/skills/builtin.json`；已生成浏览器原型和原生 AgentDefaults；内置资源与用户覆盖分离 |
| 内置 mock 场景 | 应用包只读资源 | 源码真源 `agent/mock/scenarios.json`，用户配置页不编辑可执行场景脚本 |
| 密钥/访问令牌 | Asset Store | 不允许用户把 API key 当作普通设置字段；自定义提示词同样不应填写密钥 |
| 当前库与库注册表 | 既有 Preferences | 暂不迁移，不在另一份配置中重复维护 currentVaultId |
| 目录展开/最近打开 | 既有 Preferences | 属于可清理的体验状态；迁移到新命名空间需单独立项，不随本稿变更 |

Preferences `settings_json` 的配置对象结构（不是导出格式承诺）：

```json
{
  "schemaVersion": 1,
  "configRevision": 1,
  "systemPrompt": {
    "mode": "builtin",
    "baseRevision": "包内提示词版本",
    "customText": ""
  },
  "defaultSkillId": "reading",
  "skillOverrides": {},
  "enabledTools": ["QueryNotes", "ReadNote", "CreateNote", "AppendNote", "EditNote"],
  "notifications": { "onTaskEnd": false },
  "execution": { "requestedMode": "foreground" }
}
```

- 系统提示词与 Skill 改写随同一个配置对象通过 Preferences 保存并持久化，首期不拆多份 `.md`，避免“配置已更新但提示词正文未更新”的跨文件一致性问题。
- `skillOverrides` 只保存用户覆盖的行为正文和对应内置版本，允许工具只能是内置边界内的子集；实际启用工具与 Skill 范围取交集。撤销作为恢复入口由执行器保留，不能通过这份 enabledTools 列表关闭。
- `mode=builtin` 时读取当前包内默认文本；`mode=custom` 时使用 customText。更新应用不覆盖自定义提示词；“恢复内置”只改变 Agent 设置相关字段。
- 提示词也是用户私人数据，存私有持久区，不写日志或内容分享包。路径属于应用沙箱不等于额外做过应用层加密；若未来有额外加密需求应单独设计。
- 通知/后台开关保存的是**偏好**。系统授权、设备能力与后台任务状态必须重新查询，不能靠本文件记录 `authorized=true` 假定获得系统权限。
- 运行开始时冻结有效配置到 run/state.json；之后修改设置不追改已经执行的上下文，也不修改历史消息。

## 5. 业务对象、身份与路径责任

| 对象 | 身份/路径 | 改名与删除策略 |
| --- | --- | --- |
| 知识库 | 当前 vaultId 同时承担目录标识；建议增量增加稳定 vaultKey | 保留当前目录规则，不在本稿改成 UUID 库目录；改名只更新目录/注册表映射，Agent 历史通过 vaultKey 继续归属同一库 |
| 笔记 | 当前库内相对路径，不硬编码沙箱绝对路径 | 改名/移动后更新有效引用；历史消息中的旧路径保留为当时证据，跳转先校验现状，不能碰巧打开新建的同名文件 |
| 对话 | conversationId + 所属 vaultKey | 不跨库迁移；切库只切换列表；删除库时一并清理该库私有对话数据；执行前必须弹窗明确告知并提供取消/确认删除 |
| 运行与工具调用 | runId / toolCallId / operationId | 恢复对账依赖稳定 ID；不能删除状态后盲目重放写入 |

**vaultKey 已确认、尚未实现。** 在启用 Agent 持久化前为已有注册表条目一次性分配并保存稳定值；已有 vaultId/目录不变。复制/导入成另一个库则生成新 vaultKey，不能因名称相同接上旧对话。不再采用随库名整体搬迁对话目录的替代方案。

路径职责继续只有一处：现有 VaultPathResolver 负责知识库/回收站/草稿路径；App 私有配置、Agent 数据与导出缓存的规则也应在这个统一解析模块内扩展，不让 UI、工具、Skill 各自拼 `filesDir` 或绝对路径。本稿不要求现在创建另一套平行路径框架。

## 6. 写入、恢复与清理边界

| 数据 | 写入与故障处理 | 可以当缓存清掉吗 |
| --- | --- | --- |
| 正式笔记、App/Agent 配置、对话 JSON | 按已有 AtomicFile 约束保存，Preferences 继续使用系统存储接口；坏 JSON 保留待恢复，不以“空库”静默覆盖用户数据 | 不可以 |
| 编辑草稿 | 沿用当前恢复/匹配清理逻辑，正式保存成功后再清理相应草稿 | 不可以批量按缓存删除 |
| run 状态与 operation 前像 | 写文件前先保存目标、baseHash、预期 resultHash 与前像；文件写入后再登记结果。重启对比实际文件与操作账，状态不明不二次追加 | 未完成/未对账及仍可撤销的操作不可清理 |
| 已结束 run 与旧上下文 | 可制定保留策略；有 UI 显示清理影响，不能声称聊天仍能完整审计却删掉唯一依据 | 不是普通缓存；首期长期保留、用户手动删除，不设静默自动到期或容量淘汰；未来配额另行设计 |
| 分享临时产物 | 独立 exportJobId；完成/取消后在接收方读取窗口结束后清理，启动时清理过期孤儿任务；不能点分享后立即删源文件 | 可以，但须遵守分享生命周期 |
| 搜索/反链索引 | 从笔记重建，schema 或内容变化可失效 | 可以，删除后仍可正常打开笔记 |

相互依赖的多文件操作不声称具备整体事务：每个 operation 的意图、前像与预期结果先原子落盘，笔记写完、结果尚未登记时也能对账。清理对话/运行时，若还有未核实的副作用，应先阻止/暂停该运行，完成对账再删除，不能把“删除记录”当撤销。

不因为目录名叫 app 就采集内容到遥测。当前公开日志中的笔记路径等历史诊断实现若与隐私约束不一致，须单独核查修复；架构稿不把这些记录认可为长期埋点方案。

## 7. 分享、备份与重置各带走什么

| 操作 | 范围 | 明确不涉及 |
| --- | --- | --- |
| 分享单篇笔记 / 文件夹 / 库 | 用户明确选择的正文及被引用附件，按 v0.8 范围生成临时产物 | `app/`、drafts、.trash、.git、内部索引、对话/配置/令牌；现有 .obsidian 是第三方配置，默认不按正文打包，需导出规则明确处理 |
| 应用完整备份/换机 | 当前未实现，单独立项 | 普通知识库 ZIP 不是完整备份；不承诺系统默认备份包含全部目录或 Asset Store |
| 恢复内置系统提示词 | Agent settings 的 systemPrompt 字段 | 不删除对话、笔记、工具开关、Skill 改写或系统通知权限 |
| 恢复选中 Skill | Agent settings 对应 skillOverrides 条目 | 不清系统提示词或其他 Skill |
| 清理缓存 | 允许清理的 cacheDir 产物 | 不动正式库、草稿、配置、对话或撤销前像；这里只定义边界，未新增清缓存按钮需求 |
| 重置所有数据 | 沿用 AppDataResetService：先清本应用 `vault:*:token`，再系统清应用数据，重新打开走首装样例 | 不修改远端仓库，不把这个功能用作验收时自动清数据的手段；原型 localStorage 与设备数据不是同一套 |

当前重置实现仅显式清理 Git 令牌命名空间；以后若增加其他凭据 alias，必须同步清理清单并验证，不能假定系统清应用数据必然代清全部 Asset Store 项。应用包只读默认值不被上述配置恢复操作修改。

## 8. 已确认方案与当前实施边界

2026-10-26 用户确认了本架构的存储选择；之后用户决定本地 Agent View 不需要做。已确认的 Preferences、稳定 `vaultKey`、私有 Agent 数据目录等仍作为未来设计依据，但 Agent 配置/会话持久化、删库聊天联动、Agent 操作账目前没有 App 版本分配，不能按旧计划在 v0.7 实施或验收。

当前仍适用的边界：保留现有 Preferences 与知识库目录；令牌只进 Asset Store；分享导出缓存按 v0.8 需求实施；不替换数据库、不迁移现有 Preferences、不清理历史探针目录。索引等未分配能力不预建空目录。

若未来重新分配 Agent View/集成，再按已确认方案核对新旧安装、配置恢复、稳定库身份、对话草稿、写入对账与删库隔离；失败/恢复继续用单测和存储 mock，设备只做正常操作，不制造崩溃/强杀/写入中断，也不实际重置用户数据。
