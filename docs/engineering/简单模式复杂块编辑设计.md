# 简单模式复杂块编辑 —— 统一设计（2026-11-02）

> 状态：设计稿；共享源码底座已有部分实现，完整交互与版本验收未完成，见 [v1.18](../releases/v1.18/需求文档.md) 与[实施总清单](../releases/实施总清单.md)。本文是**跨版本共享设计**，本身不是交付承诺；
> 各块的交付承诺写在各自版本目录的 `需求文档.md`，本文只定义它们共用的机制与交互。
> 相关：v1.7 17.4 范围边界、v1.14 表格编辑、`docs/releases/README.md` 版本索引。

## 1. 为什么现在需要这份设计

v1.7 17.4 把「表格、代码、公式、图片、链接、HTML、frontmatter、callout…」整类划为简单模式只读，
块内标注「请在专业模式编辑」。这个边界在 **2026-11-02 被用户否决**：复杂块不是「不支持」，
而是「还没做」。用户要求：

1. 所有复杂块**逐类排期**，不再保留「永久只读」的边界声明；
2. 设计稿要先定好**格式栏怎么承载这些块的操作** —— 例如表格「往右加一列」点哪里。

难点不在某一种语法，而在两件共用的事：**怎么把结构操作安全地写回源码**，
以及**在只有「插入型」能力的格式栏里怎么表达结构操作**。

## 2. 目标与非目标

**目标**

- 用户不切专业模式、不看见 Markdown 源码，就能编辑所有复杂块的结构与内容。
- 任何改动只落到目标块的源码区间，区间外逐字不变（沿用 v1.7 的安全不变式）。
- 触控、键盘、读屏三条路径都能完成；三折叠单 / 双 / 三屏都放得下。

**非目标**

- 不做「全语法所见即所得」（那等于重写编辑器，见需求池「所见即所得 Live Preview」）。
- 不在简单模式里鼓励写 HTML / 原始属性语法（见 §6 兜底策略）。
- 不承诺覆盖第三方变体语法（如 Mermaid 的全部图型），只保证不破坏原文。

## 3. 共用底座（v1.18）

每类块各做一遍会各自造轮子，所以先立底座。四件事：

### 3.1 块注册表

当前代码已把块识别抽到 `web/mdeditor/src/blockRegistry.ts`，由 `simpleMode.ts` 投影为既有保护区间；
`web/mdeditor/src/blockModel.ts` 提供 parse / stringify 契约与受限源码回写。它们是 v1.18
18.1–18.3 的部分源码基础，不代表整版完成或交互验收通过。后续仍按本节契约完善：

| 能力 | 说明 |
| --- | --- |
| `match(state) → BlockRange[]` | 每类块一个匹配器，产出 `{ from, to, type, id }`；语法树能识别的走语法树（Table / FencedCode / Link / Image），识别不了的走行模式（callout / 属性 / 公式 / 表格，现状由 `blockRegistry.ts` 的 `customBlockRanges()` 识别） |
| 区间不可变 | `mergeBlockRanges()` 对注册表区间排序并合并重叠，不同类型交错时标记 `mixed`；投影到简单模式保护区间后再由 `mergeProtected()` 合并 |
| 降级 | 语法树未就绪时（现在会整篇保护并提示「正在安全解析」）保持现状：整篇只读，不给结构操作 |

### 3.2 块模型与双向转换

每类块提供一对纯函数，这是「不破坏源码」的关键：

```
parse(source, range) → Model | null      // 解析失败返回 null
stringify(model)     → string            // 只产出该块的源码片段
```

- `parse` 返回 `null` 时该块**降级为只读 + 明确说明**（不是静默保护），例如列数不一致的表格。
- `stringify` 必须是该类型的规范写法；**不保留用户原有的空白花式排版**（例如手工对齐的表格管道符
  会在第一次结构操作后被规范化）—— 这条要写进各版本需求文档的「明确不做」，避免验收争议。
- 转换是纯函数 → 可在 Node 里直接单测（沿用现有 `web/mdeditor/test/*.test.mjs` 的 esbuild harness 写法）。

### 3.3 块操作与回写

```
applyBlockEdit(state, range, op) → { changes, selection } | null
```

- 只产出**落在 `range` 内**的 changes；底座统一校验越界即拒绝（与现有
  `allowsSimpleModeTransaction()` 的安全不变式同一方向，只是把「禁止」缩小到「仅限本块」）。
- 回写后选择位置由 op 指定（如「加列后选中新列同行单元格」），避免光标丢失。
- 撤销 / 重做、草稿、保存链路全部沿用 v1.7 的同一编辑状态，不新增状态机。

### 3.4 块级源码抽屉（兜底）

任何一类块、任何降级场景，都提供「**以源码编辑此块**」：

- 打开一个只显示该块源码的编辑抽屉，保存时回写该区间；
- 它是所有未排期语法的兜底，也是「结构不规范」块的唯一出口；
- 与「切换专业模式」的区别：不切换模式、不暴露整篇源码。

## 4. 复杂块的操作入口（本设计的重点）

### 4.1 现状为什么不够

`entry/src/main/ets/pages/Index.ets` 的 `FormatMenu()` 是 Aa 浮层（宽 `Tokens.formatMenuW = 360`），
三个分组：**段落**（正文 / H1–H6）、**文字**（加粗 / 斜体 / 行内代码 / 代码块 / 链接）、
**列表与引用**（无序 / 有序 / 待办 / 引用）。

它全部是**插入型**操作：作用于光标或选区，往 Markdown 里写标记（`markdownFormat.ts` 的
`formatInline` / `formatBlock`）。而「往右加一列」是**结构型**操作：作用于一个已存在的块，
要改写整块源码。把结构操作塞进上面的格子会有三个问题：

1. 格子没有上下文 —— 光标不在表格里时「加一列」无意义，禁用态又让面板充满死按钮；
2. 结构操作需要参数（左 / 右 / 上 / 下、第几行第几列），一个 40×48 的格子装不下；
3. 读屏读不出「这个按钮现在作用于哪个块」。

### 4.2 方向选型（2026-11-02 用户拍板）

四个候选方向的取舍：

| 方向 | 形态 | 判断 |
| --- | --- | --- |
| A 面板内嵌上下文区 | Aa 浮层顶部加「当前块」网格 | ❌ **已否决**：面板被撑高、按钮密度高，「文字与段落」与结构操作两套语义挤在同一浮层 |
| B 就地手柄 | 块边缘 `+`、块左侧把手 | ◐ **后置为加速项**（另立需求）：零常驻 UI 最直觉，但触控目标小、窄屏挤、读屏难触发 |
| C 上下文浮条 | 光标进块，块下沿浮出一条 | ✅ **采纳**：移动端标准形态，只承载高频二维操作 |
| D 块属性面板 | 半屏上滑，设置式列表行 | ✅ **采纳**：所有块的统一落点，加多少设置项都不乱 |
| E 块级编辑态 | 进入后底栏整条换成专用工具条 | ⏸ **不做**：空间最大但须设计进出态，当前成本不划算；等表格跑通后确实放不下再升格 |

结论是 **C + D 组合**，两者分工不同：

- **C 只服务少数高频二维块**（首版只有表格），一击完成「加行 / 加列 / 删除」；
- **D 是所有块的统一落点**：表格的表头与对齐、代码块的语言、链接的地址、图片的 Alt、callout 的类型、
  frontmatter 的键值，全部是「标签 + 原生控件」的列表行；
- **Aa 浮层保持纯净**，只管文本与段落（见 §4.5）。

根本原因是：不同块的操作形态不同。表格的行列是二维、高频、需要一击到位；而链接、图片、公式、
callout、frontmatter 本质是「填几个字段」。硬塞进同一种 UI 才是 A 方向难看的根因。

### 4.3 C：上下文浮条规格

**触发与消失**

- 光标或选区进入块 → 块描边（`brand` / `line_strong`）；光标 / 选区离开该块或选区被清空时撤销描边。
- 光标或选区进入**已启用浮条的块** → 浮条贴在块的下沿；下方空间不足时向上翻转。
  块滚出可视区或按 Esc 时浮条消失，Esc 后焦点还给块。
- 未启用浮条的块（链接 / 图片 / 公式 / callout / 属性…）不显示浮条，只保留块描边与
  「点块打开属性面板」，避免每种块都浮一条。

**内容**

- 最多 4 个图标按钮 + 「更多」（打开同一块的属性面板）。表格首版：下加行、右加列、删除、更多。
- 每个按钮 `accessibilityText` 带对象与方向（`在右侧插入一列`、`在上方插入一行`），口径同 v1.10。
- **方向语义**：浮条一击用「当前方向」，且**按钮标签直接写出方向**（`右加列` / `下加行`），
  不让用户猜往哪加；四个方向在属性面板里切换，切换后浮条标签同步（面板里同步显示
  `在左侧插入列` / `在上方插入行`）。不把四个方向都塞进浮条 —— 那会突破 4 项上限，
  也会让浮条变成第二个网格。

**定位与避让**

- 复用 v0.9 9.9 已落地的浮层测量能力（栏内宽度 / 可视高度约束、动态上下定位、内部滚动），
  不新造一套；宽度按内容自适应并限制在来源栏内，不跨栏。
- 与 Aa 浮层互斥：打开 Aa 时收起浮条，不出现两层浮层叠加。

**键盘与读屏**

- 键盘 / 读屏不依赖浮条：提供等价的「块操作」入口（菜单键 / Shift+F10 或栏内命令）直接打开属性面板。
  浮条是触控加速，不是唯一路径。

**原型**：`docs/prototype/v2/index.html` 已按本规格给出表格示意（点表格 → 描边 + 浮条；更多 → 属性面板），
只演示交互、不写入笔记内容，不代表原生实现；结构断言见
`tools/tests/test_prototype_block_entry_design.mjs`。

### 4.4 D：块属性面板规格

**形态**

- 半屏上滑面板（ArkUI `bindSheet`，半屏高度，下拉关闭），只作用于当前块；关闭后焦点回到正文中的块。
- 结构：顶部拖拽条 → 标题行（块类型名 + 右上关闭图标）→ 设置行列表（标签 + 控件）→ 底部「以源码编辑此块」。
- 控件只用系统已有形态：开关、分段、步进、单行输入、选择器；列表可滚动，新增设置项不改变布局。

**外观按鸿蒙半模态（bindSheet）**

- 顶部居中的拖拽指示条（细条），暗示可下拉关闭；右上角关闭图标；面板下方压一层遮罩，点遮罩即关闭；
  关闭方式沿用系统：侧滑 / 点遮罩 / 关闭按钮 / 下拉。
- 顶部大圆角、内容区可滚动；分组之间用间距分隔，**不再用小标题分组**（分组标题会让设置面板显得碎）。
- 原生实现用 `bindSheet` 单档 `SheetSize.MEDIUM` + `dragBar: true` + `showClose: true` + `title: { title: <块类型名> }`；
  **不用多档 `detents`** —— 它是设置面板，不需要在半屏 / 全屏之间拖拽切换。
- 依据与两个已知坑（必须 `$$` 双向绑定、宿主节点未挂载时不显示）见
  [api_notes X 组](../harmonyos/api_notes.md) X1；仅有文档核对，无设备证据。

**为什么它是统一落点**

- 各块设置项数量差异极大（表格 6 项、代码块 2 项、frontmatter 任意多行），只有列表形态能同时容纳；
- 「标签 + 控件」天然带读屏语义，不必为结构操作发明新控件；
- 与设置页（v1.13）共用分组与列表行的视觉语言，观感一致。

### 4.5 Aa 浮层保持纯净

- `Index.ets` 的 `FormatMenu()` 不再新增任何区域，保持「段落 / 文字 / 列表与引用」三组与今天一致。
- 理由：Aa 是**插入型**语义（作用于光标或选区的文本标记），结构操作是**块级**语义；两者混在一个浮层
  会让面板高度与按钮密度同时失控 —— 这也是用户否决 A 方向的直接原因。
- 块内文本仍可用 Aa：表格单元格里的加粗、引用里的斜体照旧。

### 4.6 「往右加一列」的完整链路（用户举的例子）

1. 点表格任意单元格 → 桥接回传光标位置，底座 `match()` 命中 Table 区间 → 块描边 + 表格浮条出现在表下方；
2. 点「右加列」→ 按光标所在列右侧插入；要在左侧 / 上方插入就点「更多」，在属性面板里切方向，
   切完浮条按钮变成「左加列」/「上加行」，之后一击即可；
3. `applyBlockEdit(state, range, { type: 'insertColumn', side: 'right' })`：`parse()` 得到表模型
   （含列对齐、表头行）→ 在光标列索引 +1 处插入空列（表头填空串）→ `stringify()` → changes 只覆盖原 Table 区间；
4. 回写后选区落到新列同一行的单元格，用户可直接输入；
5. 撤销一次即回到加列前（走 CodeMirror 原生 history，不额外记录）。

**降级**：列数不一致、含合并单元格写法或 `parse()` 失败 → 浮条不出现，属性面板只显示
「以源码编辑此块」并说明「这个表格结构不规范，暂时只能改源码」。

### 4.7 备选与后置

| 方案 | 处理 |
| --- | --- |
| B 就地手柄（列 / 行边缘 `+`、块左侧把手） | 后置为熟练用户加速项，v1.14 之后另立需求；不作为可发现性的唯一来源 |
| E 块级编辑态（底栏整条替换为专用工具条） | 暂不做；若表格编辑跑通后操作确实放不下，再评估升格 |
| 长按单元格弹菜单 | 不做：隐藏手势，可发现性差，读屏难以触发 |
| 在「文字」组加「表格」格子 | 不做：只有插入能力，做不了加列，会把结构操作混进插入型语义 |

## 5. 各块交互规格

图例：✅ v1 首版要做；◐ 降级或仅兜底；— 不适用。
「浮条」列为空 = 该块不显示上下文浮条，只走属性面板（§4.5 的理由）。

| 块 | 浮条（高频，≤4 项） | 属性面板（完整设置） | 降级 / 兜底 |
| --- | --- | --- | --- |
| 表格 | 加行、加列、删除、更多 | 插入方向（左 / 右 / 上 / 下）、删行、删列、首行为表头、对齐、删除表格、以源码编辑此块 | 结构不规范 → 仅源码抽屉 |
| 代码块（围栏） | 复制（可选，见 v1.19） | 语言选择（常用 + 纯文本 + 保留当前值）、复制、以源码编辑此块 | 语言不在清单内 → 保留原语言，只提供源码抽屉 |
| 行内代码 | — | 转为纯文本（去反引号保留内容） | — |
| 链接 | — | 显示文字、地址、打开、取消链接 | 非标准写法 → 源码抽屉 |
| 双链 / 嵌入 | — | 重新选择目标笔记（复用双链索引）、跳转、移除 | 目标不存在时仍可编辑文字 |
| 图片 | — | 替换图片（复用插入链路）、Alt 文本、宽度、删除 | 外链图片不下载，只改地址 |
| 公式（块级 / 行内） | — | 公式抽屉（LaTeX 输入 + 实时预览） | 渲染未支持前不做，见需求池 KaTeX 条目 |
| callout | — | 类型切换（note / tip / warning / danger…）、标题、折叠开关 | 未知类型 → 保留原类型，只改标题与正文 |
| 属性 / frontmatter | — | 属性面板（键值 + 类型：文本 / 日期 / 标签 / 复选） | 非 YAML 或解析失败 → 源码抽屉 |
| 脚注 | — | 编辑脚注正文（抽屉）、跳转回引用处 | 引用缺失 → 仅编辑正文 |
| 块 ID | — | 复制块链接 | 一般不编辑，只可复制 |
| HTML | — | 仅源码抽屉 | 保持只读；**不在简单模式鼓励写 HTML** |
| 未知 / 混合语法 | — | 只读 + 源码抽屉 + 说明 | — |

## 6. 安全不变式（所有版本共用，验收共用）

1. 结构操作只改写目标块区间，区间外源码逐字不变；
2. 改动前后笔记内容哈希只在该块变化（可单测断言「区间外子串相等」）；
3. 解析失败 = 只读 + 明确说明，**不静默保护、不静默转换**；
4. 模式切换、保存、草稿、撤销继续沿用 v1.7 的同一编辑状态，不新增状态机；
5. 每类块的 `parse` / `stringify` / 操作必须有 Node 单测，覆盖不规范输入。
