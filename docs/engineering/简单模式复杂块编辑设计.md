# 简单模式复杂块编辑 —— 统一设计（2026-11-02）

> 状态：⚪ 设计稿（未实现）。本文是**跨版本共享设计**，本身不是交付承诺；
> 各块的交付承诺写在各自版本目录的 `需求文档.md`，本文只定义它们共用的机制与交互。
> 相关：v1.7 17.4 范围边界、v1.14 表格编辑、`docs/releases/README.md` 版本索引。

## 1. 为什么现在需要这份设计

v1.7 17.4 把「表格、代码、公式、图片、链接、HTML、frontmatter、callout…」整类划为简单模式只读，
块内标注「请在专业模式编辑」。这个边界在 **2026-11-02 被用户否决**：复杂块不是「不支持」，
而是「还没做」。用户要求：

1. 所有复杂块**逐类排期**，不再保留「永久只读」的边界声明；
2. 设计稿要先定好**格式栏怎么承载这些块的操作** —— 例如表格「往右加一列」点哪里。

难点不在某一种语法，而在两件共用的事：**怎么把结构操作安全地写回源码**，
以及**在只有「插入型」能力的格式栏里怎么表达结构操作**。

## 2. 目标与非目标

**目标**

- 用户不切专业模式、不看见 Markdown 源码，就能编辑所有复杂块的结构与内容。
- 任何改动只落到目标块的源码区间，区间外逐字不变（沿用 v1.7 的安全不变式）。
- 触控、键盘、读屏三条路径都能完成；三折叠单 / 双 / 三屏都放得下。

**非目标**

- 不做「全语法所见即所得」（那等于重写编辑器，见需求池「所见即所得 Live Preview」）。
- 不在简单模式里鼓励写 HTML / 原始属性语法（见 §6 兜底策略）。
- 不承诺覆盖第三方变体语法（如 Mermaid 的全部图型），只保证不破坏原文。

## 3. 共用底座（v1.18）

每类块各做一遍会各自造轮子，所以先立底座。四件事：

### 3.1 块注册表

现状 `web/mdeditor/src/simpleMode.ts` 的 `collectSimpleModeRanges()` 已经在做「识别 + 保护」，
但它只产出字符区间，没有块身份。底座把它升级为注册表：

| 能力 | 说明 |
| --- | --- |
| `match(state) → BlockRange[]` | 每类块一个匹配器，产出 `{ from, to, type, id }`；语法树能识别的走语法树（Table / FencedCode / Link / Image），识别不了的走行模式（callout / 属性 / 公式 / 表格，现状就在 `customProtectedRanges()` 里） |
| 区间不可变 | 匹配结果沿用现有 `mergeProtected` 逻辑去重合并；块之间不重叠 |
| 降级 | 语法树未就绪时（现在会整篇保护并提示「正在安全解析」）保持现状：整篇只读，不给结构操作 |

### 3.2 块模型与双向转换

每类块提供一对纯函数，这是「不破坏源码」的关键：

```
parse(source, range) → Model | null      // 解析失败返回 null
stringify(model)     → string            // 只产出该块的源码片段
```

- `parse` 返回 `null` 时该块**降级为只读 + 明确说明**（不是静默保护），例如列数不一致的表格。
- `stringify` 必须是该类型的规范写法；**不保留用户原有的空白花式排版**（例如手工对齐的表格管道符
  会在第一次结构操作后被规范化）—— 这条要写进各版本需求文档的「明确不做」，避免验收争议。
- 转换是纯函数 → 可在 Node 里直接单测（沿用现有 `web/mdeditor/test/*.test.mjs` 的 esbuild harness 写法）。

### 3.3 块操作与回写

```
applyBlockEdit(state, range, op) → { changes, selection } | null
```

- 只产出**落在 `range` 内**的 changes；底座统一校验越界即拒绝（与现有
  `allowsSimpleModeTransaction()` 的安全不变式同一方向，只是把「禁止」缩小到「仅限本块」）。
- 回写后选择位置由 op 指定（如「加列后选中新列同行单元格」），避免光标丢失。
- 撤销 / 重做、草稿、保存链路全部沿用 v1.7 的同一编辑状态，不新增状态机。

### 3.4 块级源码抽屉（兜底）

任何一类块、任何降级场景，都提供「**以源码编辑此块**」：

- 打开一个只显示该块源码的编辑抽屉，保存时回写该区间；
- 它是所有未排期语法的兜底，也是「结构不规范」块的唯一出口；
- 与「切换专业模式」的区别：不切换模式、不暴露整篇源码。

## 4. 格式栏改造（本设计的重点）

### 4.1 现状为什么不够

`entry/src/main/ets/pages/Index.ets` 的 `FormatMenu()` 是 Aa 浮层（宽 `Tokens.formatMenuW = 360`），
三个分组：**段落**（正文 / H1–H6）、**文字**（加粗 / 斜体 / 行内代码 / 代码块 / 链接）、
**列表与引用**（无序 / 有序 / 待办 / 引用）。

它全部是**插入型**操作：作用于光标或选区，往 Markdown 里写标记（`markdownFormat.ts` 的
`formatInline` / `formatBlock`）。而「往右加一列」是**结构型**操作：作用于一个已存在的块，
要改写整块源码。把结构操作塞进上面的格子会有三个问题：

1. 格子没有上下文 —— 光标不在表格里时「加一列」无意义，禁用态又让面板充满死按钮；
2. 结构操作需要参数（左 / 右 / 上 / 下、第几行第几列），一个 40×48 的格子装不下；
3. 读屏读不出「这个按钮现在作用于哪个块」。

### 4.2 改造方案：Aa 浮层增加「当前块」上下文区

不新增第二条浮层，只在 Aa 浮层**顶部**加一个上下文区，光标或选区落在复杂块内时出现：

```
┌──────────────────────────────────────────┐
│ 文字与段落                        完成    │  ← 原有标题行
├──────────────────────────────────────────┤
│ 当前块：表格                             │  ← 【新增】上下文区标题
│ ┌────────┬────────┬────────┐             │
│ │ ↑ 加行 │ ↓ 加行 │ 删除行 │             │
│ ├────────┼────────┼────────┤             │
│ │ ← 加列 │ → 加列 │ 删除列 │             │
│ ├────────┴────────┴────────┤             │
│ │ 首行为表头 ☑    更多 ⋯    │             │
│ └──────────────────────────┘             │
│ 以源码编辑此块                            │  ← 【新增】兜底入口
├──────────────────────────────────────────┤
│ 段落 / 文字 / 列表与引用（原有三组，照旧）  │
└──────────────────────────────────────────┘
```

要点：

- **只在块内出现**：光标在普通段落时该区整段不渲染，面板与今天完全一致，不增加学习成本。
- **上下文区优先于通用格式**：它描述「对这个块能做什么」，下面三组仍可用于块内文本
  （例如表格单元格里的加粗、引用里的斜体）。
- **块选中态**：进入上下文区时，对应块在正文里加品牌色描边（`line_strong` / `brand` 描边，
  沿用现有 token），让用户知道操作作用于哪里；离开时撤销。
- **无障碍**：每个按钮 `accessibilityText` 带对象与方向，例：`在右侧插入一列`、
  `在上方插入一行`、`删除当前列`；上下文区标题读「当前块：表格」。
  与 [v1.10](../releases/v1.10/需求文档.md) 读屏口径一致。
- **键盘**：上下文区是进入面板后的第一站，Tab 顺序在上、原三组在后；Esc 关闭面板并回到块内光标。

### 4.3 「往右加一列」的完整链路（用户举的例子）

1. 用户点表格任意单元格 → `PreviewBridge` 把光标位置回传，底座 `match()` 命中 `Table` 区间；
2. 正文里整表描边；打开 Aa 浮层时上下文区标题为「当前块：表格」；
3. 点「→ 加列」→ `applyBlockEdit(state, range, { type: 'insertColumn', side: 'right' })`：
   - `parse()` 得到表模型（含列对齐、表头行）；
   - 在光标所在列索引 +1 处插入空列，表头行填空字符串，其余单元格填空；
   - `stringify()` 生成新表格源码，`changes` 只覆盖原 Table 区间；
4. 回写后选区落到「新列、同一行」的单元格，用户可直接输入；
5. 撤销一次即回到加列前（走 CodeMirror 原生 history，不额外记录）。

**降级**：表格列数不一致、含合并单元格写法、或 `parse()` 失败 → 上下文区只显示
「以源码编辑此块」，并说明「这个表格结构不规范，暂时只能改源码」。

### 4.4 备选交互（记录但不做主路径）

| 方案 | 为什么不做主路径 |
| --- | --- |
| 长按单元格弹菜单 | 隐藏手势，可发现性差；读屏用户难以触发 |
| 列 / 行边缘悬停 `+` 手柄（Notion 式） | 触控目标小、三折叠窄屏放不下；可作为熟练用户加速项后置，另立需求 |
| 在「文字」组加「表格」格子 | 只有插入能力，做不了加列；会把结构操作混进插入型语义 |

## 5. 各块交互规格

图例：✅ v1 首版要做；◐ 降级或仅兜底；— 不适用。

| 块 | 上下文区操作 | 降级 / 兜底 |
| --- | --- | --- |
| 表格 | 加行（上 / 下）、加列（左 / 右）、删行、删列、首行为表头开关、更多（对齐、删除表格） | 结构不规范 → 仅源码抽屉 |
| 代码块（围栏） | 语言选择（常用 + 纯文本）、复制、**以源码编辑此块** | 语言不在清单内 → 保留原语言，只提供源码抽屉 |
| 行内代码 | 取消行内代码（转纯文本） | — |
| 链接 | 编辑文字、编辑地址、打开、取消链接 | 非标准写法 → 源码抽屉 |
| 双链 / 嵌入 | 重新选择目标笔记（复用双链索引）、跳转、移除 | 目标不存在时仍可编辑文字 |
| 图片 | 替换图片（复用插入链路）、Alt 文本、宽度、删除 | 外链图片不下载，只改地址 |
| 公式（块级 / 行内） | 公式抽屉（LaTeX 输入 + 实时预览） | 渲染未支持前不做，见需求池 KaTeX 条目 |
| callout | 类型切换（note / tip / warning / danger…）、标题、折叠开关 | 未知类型 → 保留原类型，只改标题与正文 |
| 属性 / frontmatter | 属性面板（键值 + 类型：文本 / 日期 / 标签 / 复选） | 非 YAML 或解析失败 → 源码抽屉 |
| 脚注 | 编辑脚注正文（抽屉）、跳转回引用处 | 引用缺失 → 仅编辑正文 |
| 块 ID | 复制块链接 | 一般不编辑，只可复制 |
| HTML | — | 保持只读 + 源码抽屉；**不在简单模式鼓励写 HTML** |
| 未知 / 混合语法 | — | 只读 + 源码抽屉 + 说明 |

## 6. 安全不变式（所有版本共用，验收共用）

1. 结构操作只改写目标块区间，区间外源码逐字不变；
2. 改动前后笔记内容哈希只在该块变化（可单测断言「区间外子串相等」）；
3. 解析失败 = 只读 + 明确说明，**不静默保护、不静默转换**；
4. 模式切换、保存、草稿、撤销继续沿用 v1.7 的同一编辑状态，不新增状态机；
5. 每类块的 `parse` / `stringify` / 操作必须有 Node 单测，覆盖不规范输入。

## 8. 待用户拍板

1. **上下文区放在 Aa 浮层顶部**，还是**块选中时浮一条独立工具条**（更近、但多一个浮层需要避让规则）？
